## Resolution

root_cause: Harness timing, not a product defect. The staff read of a member's answers (GET /v1/members/{id}/profile-answers) is authorised by the composed permission `profile_form.read`, which comes from the API's per-instance 30 s module-flag cache; the member's public read and the gate read the `tenant_modules` row live (`liveModuleOn`). The profile-form specs switch the row with direct SQL, which cannot call `moduleFlags.invalidate`. In a run where the gate spec goes first, the cache was loaded once (gate test 1, a member signing in before `enableProfileForm`, keys without profile_form) and was still fresh 27.8 s later when member test 5's lab admin read arrived (the two-file run takes 44 s), so the route took its bare 404, `loadMemberAnswers` returned `absent` and the page rendered the base profile with no block and no error row. Member spec alone passes because its first API request comes after `enableProfileForm`, so the first cache load already sees the module ON. No privacy exposure: `staffAnswersOf` re-checks the row live, so a stale ON entry with the module OFF still answers 404.
fix: apps/web/e2e/profile-form.ts gets `openMemberAsStaff(page, membershipId)` (opens /membros/{id} with `openUntilReady` until `[data-member-answers="staff"]` is on screen, the `openBuilder` idiom, 75 s ceiling); profile-form-member.spec.ts uses it in test 5 (the lab admin and the support user) and in test 6 (E10 staff block, so the 6s are order-proof too).
verification: before the fix the two-file run (gate, member) failed at member test 5 twice (second time with the temporary logging that showed the single cache load at 15:06:08 and the staff read at 15:06:35 with hasRead=false). After the fix the three-file run (admin, gate, member, mobile-chromium, 1.3 min): gate 6/6, member 1-5 and both 6s (320 and 390) pass (test 5 took 10.4 s: the poll absorbed the cache lag); admin 1-5 pass, admin 6 at 320 fails on the known 42px touch target (orchestrator's finding) and its 390 run is skipped. biome check on the two files clean, `tsc --noEmit --incremental false` in apps/web clean; module row absent and no e2epf- rows or accounts left in the local DB after the run. Temporary API logging reverted (git status clean for apps/api and packages/core).
