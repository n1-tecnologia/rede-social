## Design decision (the three options weighed)

The refusal path is a SYNCHRONOUS pure mapping (`bootstrapRedirectPath`) called from about sixty sites.
Reading the destination needs `await headers()` (Next 16 has no sync accessor), so the destination cannot
be fetched inside the mapping. Options:

- (a) Carry the destination at every loader call site. Rejected: roughly 60 sites in 25 files (listed
  below), every new loader would have to remember it, and a missed one silently regresses.
- (b) Make the loader's PROFILE_FORM_PENDING refusal not redirect, so the guard's redirect always wins.
  Rejected: loaders also run where no guard is in the same Promise.all (components below a page, the
  counters route, server actions) and rely on the redirect; returning null there rethrows the
  ApiClientError and turns a gate into a render error, breaking D-581 "every refused route".
- (c) Await requireBootstrap() before the loader on every page. Rejected: about 35 (app) pages have the
  `Promise.all([... requireBootstrap(), loader ...])` shape, and serialising them adds one full bootstrap
  round trip to each. The constraint is no latency on every page.
- CHOSEN, a form of (a) done once: a request-scoped slot. `requireBootstrap()` reads the validated
  destination as its FIRST statement (a microtask-level `await headers()`, long before any API answer can
  arrive) and parks it in a slot created by React `cache` (the same request-scoped mechanism
  `getBootstrap` already relies on, shared by the layout, the page and everything under them). The one
  function every refusal already goes through, `bootstrapRedirectPath`, reads that slot for
  PROFILE_FORM_PENDING only. Sites that never call the guard (route handlers, the (auth) pages) never
  prime the slot, so their behaviour is unchanged by construction. In route handlers and in unit tests
  there is no React cache dispatcher, so `cache()` returns a fresh object on every call and nothing can
  persist: that is why the new test mocks `react`'s `cache` with a memoising stand-in.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> proxy.ts -> server components | the request path travels in the x-rede-path header; proxy.ts deletes any inbound copy and sets it from the request's own URL, but the value still ends up inside a redirect URL |
