<objective>
Fix the 2026-09-29 production incident on socializando.n1marketingdigital.com.br. An admin picked a story video on an iPhone. Mux, the webhooks and the worker all set the asset to `ready` within 5 s, but the composer kept showing "Processando o vídeo…" forever. The admin waited instead of tapping Publicar, so the story was never published.

Root cause: in `apps/web/app/(app)/stories/publicar/StoryComposer.tsx` (~line 219), `processing` is `true` whenever a video asset id exists. The composer never re-reads the asset.

This plan:
1. Adds a tenant-scoped single-asset read `GET /v1/media/{assetId}` plus a web server action.
2. Adds a small `useAssetReadiness` polling hook with backoff.
3. Drives the composer's processing row from the real status. A failed or rejected video shows an error and cannot be published.
4. Rewrites the processing note so the admin knows they can already publish.

The Mux/webhook/worker pipeline works and is NOT touched.

Purpose: the admin sees the true state of their video. They are told they can publish right away, and they get a clear error when the vendor refuses the video.
Output: new API route + service function + integration tests, web lib fetch + server action, polling hook + tests, composer wiring + tests, catalog copy.
</objective>
