## Discretion choices recorded by the planner

- **C-1 Preflight step.** The first step after checkout in `build` refuses every value that resolves to production, and refuses a config.toml without a matching `[remotes.homolog]`. Without that block, `supabase config push` would push the LOCAL `[auth]` values (localhost site_url, local hook URI) to the hml project. The step only reads `config.toml`, which keeps O-5.
- **C-2 Ref guard.** Both jobs carry `if: github.ref == 'refs/heads/homolog'`. A `workflow_dispatch` from another branch is skipped cleanly instead of failing at WIF.
- **C-3 Health check.** The deep health check takes the URL through `env`, so there is no expression inside `run`. It retries, because `--min-instances=0` means a cold start.
- **C-4 Ignore script rules.**
  - An empty `DEPLOY_ENV` counts as unset.
  - If `DEPLOY_ENV` is unset, ref is `homolog` and `VERCEL_ENV=production`, the script still delegates and prints a warning. Only the project whose Production Branch is `homolog` can produce that combination, so the hml production build survives a missing or invisible `DEPLOY_ENV`.
  - An unknown `DEPLOY_ENV` value always skips. This fails closed and logs the value.
  - Every run prints one `vercel-ignore:` decision line to the Vercel build log.
- **C-5 Production secrets table.** The production GitHub secrets table in DEPLOY.md gains the `SEND_EMAIL_HOOK_SECRETS` row: deploy-api.yml already reads it, and the doc omitted it. Without the row, "same names as production" would not be exact.
- **C-6 Trigger paths.** `on.push.paths` takes production's list with the self-reference swapped: `.github/workflows/deploy-hml.yml` replaces `deploy-api.yml`.
