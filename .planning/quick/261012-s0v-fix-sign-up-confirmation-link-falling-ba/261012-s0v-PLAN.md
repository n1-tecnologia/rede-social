<objective>
Fix the sign-up confirmation link that lands on the platform root (`https://rede-social-woad.vercel.app?token_hash=…&type=signup`) instead of the tenant's `/auth/confirm`, and stop the root cause from recurring.

Purpose: the hosted `uri_allow_list` loses the tenant's `https://<host>/auth/confirm**` entry after every `supabase config push` (`.github/workflows/deploy-api.yml` line 137 re-applies `[remotes.production.auth] additional_redirect_urls` from `supabase/config.toml`). GoTrue then silently drops the `emailRedirectTo` that `apps/web/lib/signup-confirmation.ts` sends and falls back to `site_url`; the Send Email Hook brands the mail correctly (decision row 6a in `packages/core/server/tenancy/mail-tenant.ts`) but builds the CTA from the pathless `redirect_to`; `apps/web/proxy.ts` step 4 then bounces `/` to `/entrar` with the query cleared, so the token is lost and the e-mail is never confirmed. Three independent layers close it: (1) the hook re-homes a hostless signup link onto the tenant's VERIFIED primary host read from `tenant_domains`; (2) the proxy forwards a token link that reached `/` to `/auth/confirm`; (3) the worker reconciles the allow-list at boot so a deploy self-heals the list.

Output: three local commits (one per task), no push, no deploy, no migration.
</objective>
