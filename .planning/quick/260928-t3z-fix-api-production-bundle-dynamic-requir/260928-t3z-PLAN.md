<objective>
Make the `apps/api` production bundle (`dist/main.js`, the Cloud Run image's `CMD`) load under
Node 24 for both roles. Today it crashes on boot because tsup bundles undici (a CommonJS dependency
of `@rede-social/module-feed`, not of apps/api) into ESM output, and esbuild's `__require` shim
throws on undici's `require('assert')` since ESM has no `require`.

Planner probe (2026-09-28, throwaway build into a temp dir, cleaned up): the orchestrator's preferred
`createRequire` banner alone fixes undici, but the next boot then dies with
`Could not load the "sharp" module using the darwin-arm64 runtime` — sharp (dependency of
`@rede-social/core`, also bundled) resolves its native addon `@img/sharp-<platform>/sharp.node` at
runtime relative to its own module, which becomes `dist/`, where the addon is not installed (neither
locally nor in the image, where /app/node_modules holds only apps/api's direct deps). With banner +
`external: ['sharp']` + sharp as an apps/api dependency, the probe bundle logged `api listening`,
answered /v1/health 200, all 10 non-entry chunks imported cleanly, and ROLE=worker failed only on
pg-boss ECONNREFUSED. The probe also found a latent `__require("sqlite")` (tsup strips the `node:`
prefix by default; `node:sqlite` is prefix-only), fixed by `removeNodeProtocol: false`.

So the lockfile change the orchestrator asked to avoid "unless needed" IS needed, but only for
sharp, and it adds no package to the lockfile (sharp@0.35.4 is already locked through core).
