# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** With the `social` module on, members message each other 1:1; a member block changes messaging and following; members report four more kinds of content; the administrator works them in the queue Phase 13 ships (D-719..D-734). This document contracts only what is new or changes on screen:

1. **"Conversas"**, the list behind the top-bar chat bubble, and the bubble itself (UI-D-861..UI-D-863).
2. **The direct conversation** on the shipped thread screen: header, empty thread, lazy first send, the composer's states (open, closed for the blocked member, the blocker's strip, removed), previews (UI-D-864..UI-D-866).
3. **The entry points to start a conversation:** "Enviar mensagem" on the member profile and a message control on each `/membros` row, and what the blocker and the blocked see in their place (UI-D-867, UI-D-868).
4. **Reporting and blocking on every subject:** the new menus (story, story comment, community, direct message), the report sheet variants and the block dialog's new body (UI-D-869..UI-D-872).
5. **The admin "Denúncias" queue** for the four new subjects and its resolve sheet (UI-D-873, UI-D-874).
6. **Notices:** the bell rows "começou a te seguir" and "Nova denúncia", and the three pushes (UI-D-875, UI-D-876).
7. The state matrix (social on/off, staff, member, moderator), loading/error/empty, accessibility, strings and trust rules (UI-D-877..UI-D-881).

Everything else is **reused unchanged**: the thread screen, composer with its voice machinery, bubble and player of `07`, `12.4` and `12.5` (sketches 007, 023, 024); the Seguir button, counts and rows of `09`; the story viewer and community header of `05`, `05.2` and `10`; the report sheet, block dialog, "Membros bloqueados" list and the queue's skeleton of `13-UI-SPEC-ADDENDUM.md`.

**Design authority.** The design team's prototype (`reference/frontend-design/`) has **no direct-message, report or block screen** (checked by CONTEXT, `canonical_refs`). Every surface here is **[designed]** in the prototype's language (Manrope, light `#f5f7fb` ground, white cards, 12px radii, 44px touch targets, the tenant's single accent) from primitives that already ship. Nothing is **[proto]** except the Seguir button, which `09` already ported.

**Phase 13 hand-over (D-616, roadmap amendment of 2026-11-04).** `13-UI-SPEC-ADDENDUM.md` already specifies and `.planning/sketches/017-phase-13-designed-screens/README.md` already draws, still unapproved, the report sheet (UI-D-633), the block dialog (UI-D-634), the "Membros bloqueados" list (UI-D-635), what a blocker sees (UI-D-636), the admin queue (UI-D-637), the resolve sheet (UI-D-638) and the post and comment menus (UI-D-632), with assumptions AD-1..AD-8. Phase 11 takes over the screens of plan 13-20. **They are referenced here by id, never redrawn in words**; § Hand-over lists exactly what Phase 11 changes in each, and nothing else in them changes.

**The design language, spacing scale, typography scale and colour model are inherited unchanged** from `02` to `12.5-UI-SPEC.md`. **Phase 11 adds no token, font, size, weight, library or dependency.**

**Upstream.**
- `11-CONTEXT.md` decisions are cited as **D-719..D-734** (locked, never re-asked, none reopened). Carried-forward ids keep their own numbers. `RESEARCH.md` does not exist yet (plan-phase runs it after this contract).
- **UI decision ids claimed: UI-D-860..UI-D-881.** The highest id in any file under `.planning` is **UI-D-859** (Phase 12.5), checked 2026-11-19 with `grep -rhoE "UI-D-[0-9]+" .planning | sort -t- -k3 -n -u | tail -1`. UI-D-632..UI-D-638 are **reused by reference**, not renumbered.
- CONTEXT's "Claude's Discretion" items that touch the screen (the sketch gate path, the neutral refusal wording, "Membro removido", empty states, how the blocker's profile shows "Desbloquear", the list's order and paging) are answered below. Codes, routes' internals, RLS, limits and the follow-notice storage stay the planner's.

**Sketch gate (D-33, D-365, D-417, UI-04).** The prototype-less screens go through **one** reviewed sketch **before any web plan is written or run**: proposed **sketch 025** (§ Sketch gate), gated by the owner's `approved: true`. This session wrote no sketch, edited no sketch README or MANIFEST and recorded no approval.

**Non-interactive session.** No question could be asked. Every visual detail CONTEXT left to the UI phase is a default in § Defaults chosen (**A-UI-1..A-UI-22**), chosen as the most conservative option consistent with the existing system; Igor overturns any of them with one line at the sketch review.

## Motion & Accessibility

- **Nothing new animates.** Sheets, dialogs and the list reorder use the shipped springs or none; a row changing place and a strip swapping for the composer are instant.
- **Speech is polite, never assertive.** The strips are `role="status"`; a live change of the composer state never moves scroll or focus (UI-D-865).
- **Focus.** After a sheet or dialog closes focus returns to its opener; after "Desbloquear" in the strip focus lands in the composer field; after the first send focus stays in the composer.
- **Touch.** 44px everywhere; the one declared exception is the message trigger at 40px wide on 320px phones.
- **Text safety.** Every string is a React text node; the product never shows a file name, URL or user id.
