# Phase 08.5 Plan 03: Member Writes and Admin Sequence Switch Summary

**Member progress PUT (server-decided 90% / button completion, clamp to the ready duration, one-way `completed_at` by upsert, `admin_tenant` 204), the member's ten-minute material URL behind the one access answer, and the per-lesson `requiresPrevious` write path with `normaliseFirstLesson` after every order-changing write.**

## Accomplishments

- The admin can set "Exige concluir a aula anterior" per lesson through the API. The first live lesson of a course and a free lesson never store it, whatever the body or the order. `normaliseFirstLesson` runs after lesson create, update, reorder and delete, and after module reorder and delete. It writes nothing on a no-op reorder.
- `PUT /v1/courses/learn/lessons/{lessonId}/progress` asks `app.course_lesson_access` first, in the same transaction as the write. A locked or removed lesson answers 404, 403 `lesson_locked` or 409 `lesson_sequence_locked`, and nothing is written. The server clamps the position, decides completion (`ceil(0.9 × duration)` or `completed: true`) and upserts on the primary key, with `completed_at` one-way. A free lesson writes for a non-buyer, and that completion opens the next paid lesson after a purchase.
- `GET /v1/courses/learn/lessons/{lessonId}/materials/{materialId}/url` mints a fresh ten-minute URL with `no-store`, only for a ready material of that open lesson.
- Every route of the member lane is in the isolation inventory and covered by the extended `phase 08.5 sweep: courses learn`. The courses README now documents the member side.

## Decisions Made

Planning decisions 1-5 were implemented as locked (see `key-decisions`). Two readings at execution time:

- `normaliseFirstLesson` uses the evaluator's order key, `(m.position, m.id, l.position, l.id)` over live lessons under live modules. It does not use the admin `LIST_ORDER`, so the lesson it clears is exactly the one the evaluator ranks `course_seq = 1`.
- A body with only `completed: true` keeps the stored position on the update branch (`least(stored, duration)`). A first write of that kind stores 0.
