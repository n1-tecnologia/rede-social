# Phase 08.5 Plan 12: The Store Says What a Product Unlocks Summary

**The product page lists the communities, published courses and non-cancelled lives a product unlocks, each with its own thumb shape and kind line. "Compra concluída" names whatever was unlocked, with "Ir para o curso" / "Ir para a live" when there is one target. A purchase started from a locked course or live brings the member back to it, unlocked, with a toast. The return is steered only by the purchase answer.**

## Accomplishments

- **Unlock list (UI-D-439, STORE-06).** `productPageView` builds one list: community rows as before, then course rows from `unlockedCourses`, then live rows from `unlockedLives`. Course and live rows only appear while `courses` is on.
  - Each `ProductUnlockRow` now carries `kind`, `thumbRatio` and `meta`.
  - The page draws the name 14/700 over the kind meta 12/400. The thumb is the new store UI `UnlockThumb`: a 32px square, a `w-8 aspect-[3/4]` poster or a `w-12 aspect-[16/10]` frame.
  - Rows are static with `Lock` 16 until held, then `<a>` with `ChevronRight` 18.
  - Lives read "Live · qui, 22 de out, 20:00" in the tenant timezone.
- **Back labels.** `?comunidade=` wins, then `?curso=` ("Voltar para {course}"), then `?live=` ("Voltar para {live}"). Each is honoured only for an id in the product's own list.
- **"Compra concluída" (UI-D-440, STORE-07).** `PurchaseDialog` takes `success.items` of three kinds, each with a per-kind thumb box and an optional kind meta.
  - `successView` returns three shapes: one target (gendered sentence plus "Ir para …"), several (communities-only sentence or "Estes conteúdos já estão liberados para você:", plus the list) and none.
  - The confirm body names every target, two names then "e mais {n}".
  - A communities-only list carries no meta, so the dialog draws exactly the 08.2 markup (test 17 compares the two).
- **Return to origin.** `PurchaseControl` gains `fromCourse`, `fromLive` and `timeZone`. On `ok`, after the community check, `purchaseReturnView` looks for the id in the ANSWER's `courses` or `lives`. On a match the control closes, toasts "Compra concluída. {course} está liberado." or "… {live} está liberada." and pushes `/cursos/{id}` or `/cursos/lives/{id}`, built from the answered row.
- **Browser coverage.** `describe('08.5 product unlocks and purchase return')` covers:
  - the three-kind list;
  - the mixed confirm and success;
  - held links;
  - EP-56;
  - the return from a locked course and a locked live;
  - the one-course success;
  - the E13 and E14 backstops at 320px.

  The new cases passed on both projects. The combined `store.spec.ts` + `comunidades.spec.ts` run after a fresh reset is under Verification Results.

## Decisions Made

- Planning decisions 1-3 were implemented as written (see `key-decisions`).
- **Who counts as "held".** The plan says held follows "the shipped rule (`owned` or a manager)". The shipped rule is `product.owned` only, so every kind follows that. A manager viewing an unowned product sees the same padlocked rows a member does, which describes the product rather than the manager's own access.
- **The dialog's kind meta appears on mixed lists only.** UI-D-440 asks for the kind meta on list rows and also for a byte-identical communities-only dialog. Showing the meta only when courses or lives are present satisfies both.
