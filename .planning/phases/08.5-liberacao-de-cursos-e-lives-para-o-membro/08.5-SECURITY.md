## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser/BFF → API | course, lesson, live, material, product and asset ids from a member: attacker-controlled, possibly remembered from another session | ids, cursors, progress positions |
| API lane → Postgres (RLS + definer functions) | the member lane reads through tenant-pinned `SECURITY DEFINER` projections that see rows RLS hides | lesson content, material lists, lock state (high) |
| API → Mux / Storage | playback credentials and signed URLs minted only after the course gate answers | paid video and files (high) |
| browser → BFF route handler `/api/courses/progress` | a cross-request write an attacker page could try to forge | progress positions (low) |
| API → RSC payload | the lock page and the course page must carry no content of a locked lesson | lesson description, asset id, materials (high) |
| store lane → courses tables and functions | access reads by SQL name in the caller's lane or through tenant-pinned definer functions | lock state, unlock lists (medium) |
