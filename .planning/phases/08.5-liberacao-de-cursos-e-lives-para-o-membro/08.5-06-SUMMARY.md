# Phase 08.5 Plan 06: The Member's /cursos Catalogue Summary

**Members now open `/cursos` and see a two-tab catalogue: Cursos shows 3:4 course posters with category chips, the store's "Exclusivo" / "Produto arquivado" tags and the progress bar; Lives shows "Próximas" then "Gravadas" as 16:10 cards. The page splits roles on the server, the admin keeps the hub, and `?ver=aluno` shows the member view.**

## Decisions Made

Planning decisions 1-5 were implemented as written. Decision 5's `MemberLessonThumb` name belongs to plan 07. Three choices were made during execution:

- **The name follows the tag.** The card's ", exclusivo" / ", exclusiva" suffix comes from the store tag, not from the courses API's `locked` flag, so a failed store read never makes the name and the poster disagree.
- **An unknown category id falls back to "Todas".** A well-formed id that is missing from the chip list triggers a second catalogue read without the filter, so it reads as "Todas" rather than as an empty category.
- **Member links keep the preview flag.** Every member href (tabs, chips, cards) keeps `?ver=aluno` while a manager previews (UI-D-437). A member's `?ver=` is ignored.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The "Produto arquivado" pill truncated at 320px**
- **Found during:** Task 3 (E03 long-text backstop)
- **Issue:** `chipBase` is `whitespace-nowrap px-3.5`, so the two words need about 130px. A poster's tag stack at 320px is about 114px wide, and the pill truncated to an ellipsis. That broke the backstop's "both tags readable".
- **Fix:** The archived pill wraps (`whitespace-normal`, `text-left`, `leading-tight`, `rounded-[14px]`, which equals `rounded-full` on one line) instead of truncating. "Exclusivo" is unchanged.
- **Files modified:** apps/web/app/(app)/cursos/MemberCoursesGrid.tsx
- **Verification:** the backstop passes on mobile-chromium. The full run is 86 passed / 0 failed.
- **Committed in:** d13e6137
