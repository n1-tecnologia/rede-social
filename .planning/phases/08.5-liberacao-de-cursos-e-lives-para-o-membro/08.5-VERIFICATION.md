# Phase 08.5: Liberação de Cursos e Lives para o Membro — Verification Report

**Phase Goal:** Members reach the tenant school. A course or a live tied to a product stays locked, with a padlock, until the member buys a product that unlocks it, the same rule private communities follow (08.2). Once a member has access, they watch the lessons and open the materials. A lesson or module marked "exige concluir o anterior" stays locked until the previous one is watched, so the member's lesson progress is written from this phase on.

### Gaps Summary

One gap blocks the phase, and it is narrow. Every live, locked lesson is protected end to end, by route, by RLS and by remembered asset id, and the tests prove it. The hole opens only after the admin reorganises a course. Once a paid lesson is removed, its module is removed, or a material is detached, that material's asset is no longer "governed". `GET /v1/media/{assetId}/original` then serves it to any member of the tenant who knows the asset id. The asset id appears in the path of the signed URLs that buyers received. So a member whose entitlement was revoked, or anyone a buyer passed the URL to, can fetch the file again. Lesson videos are not affected.

Deterministic reproduction. It runs against the local DB, rolls back, and leaves no residue. It reuses the pgTAP 195 fixture, lines 1-131. N is a member who holds neither product Q nor product R:

```sql
select tests.as_tenant('…0001', '…0006');                       -- N
select is(app.course_asset_hidden('…a04'), true);               -- ok: P2 material hidden
reset role; update public.course_lessons set deleted_at = now() where id = '…00f9';
select tests.as_tenant('…0001', '…0006');
select is(app.course_asset_hidden('…a04'), true);               -- not ok: have false
select is(app.course_asset_hidden('…a03'), true);               -- ok: P2 video still hidden
-- same failure after soft-deleting module …00d6, and after deleting the material row
```

How much this matters in practice: a buyer who can pass on an asset id could just as well pass on the downloaded file. The marginal leak is small. The contract is still broken, though. COURSE-20's text, CONTEXT's "airtight" closure requirement, and the "resolved" status of T-08.3-08 all promise more than the code delivers. The fix is about one `create or replace` migration plus three pgTAP cases (code review WR-01 sketches it), so a `/gsd-quick` is enough; a gap plan is not needed.
