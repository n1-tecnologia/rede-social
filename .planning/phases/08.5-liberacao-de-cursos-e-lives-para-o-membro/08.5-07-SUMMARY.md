# Phase 08.5 Plan 07: The Member's Course Page Summary

**Members now open `/cursos/{id}` and get the course's hero, their progress with the right next action ("Começar", "Continuar" or "Rever"), and the whole curriculum as 16:6 module bands with lesson rows that say each state in words. A locked course shows the 08.2 buy section in four variants plus the free-lesson link. An admin previews the page at `?ver=aluno` under a banner. The page is built only from the titles-only course read, so a locked lesson's content never reaches the HTML.**

## Accomplishments

- **Role split** (`[courseId]/page.tsx`). A `courses.manage` holder without `?ver=aluno` still gets the shipped admin page. Everyone else gets `MemberCoursePage`, which makes one `getLearnCourse` read. A 404 or a non-uuid id shows "Curso indisponível". A read failure shows the shipped course error card, whose retry link keeps `?ver=aluno`. `loading.tsx` is now the E05 skeleton (16:10 rect, two bars, the action block, two 16:6 band rects).
- **Progress action zone.** Three variants built by `courseActionView` from the API's numbers. An empty course renders no action and shows "Nenhuma aula ainda".
- **Curriculum.** One `ModuleCover` band per live module. Bands are never disabled, the toggle is instant, and focus stays on the band. Expanded bands hold a `Card` with an `<ol>` of `MemberLessonRow` links, and locked rows are links too. The initial open set follows UI-D-429.
- **Lock labels** come from the pure `lessonLockLabel` / `moduleLockLabel` in `contracts/lock.ts`. The formatter takes no clock, no storage and makes no decision.
- **Locked course** (Task 2, gated by sketch 010):
  - The store's `LockedSection` "Curso exclusivo" with either the one-product link or the several-products button that opens `ProductChoiceSheet`.
  - Otherwise the not-for-sale card or the store-failure card with its retry.
  - "Assistir à aula aberta" appears only when the course has a free lesson.
  - "Exclusivo" sits on the hero, and "Produto arquivado" is an identity pill.
  - All of this is composed in the app tier. The courses module never imports the store.
- **Preview.** `PreviewBanner` renders under the header for an `admin_tenant` at `?ver=aluno`. Every lesson is open, and every internal link keeps the flag.
- **Browser.** `describe('course page')` adds 7 cases. On the first fresh-reset run, the whole spec passed on both projects.

## Decisions Made

All five planning decisions were implemented as written (see `key-decisions`). Four choices were made during execution:

- **Sketch 010 finding 1 (band at 320px).** The band title is `line-clamp-1` below 360px and `line-clamp-2` from 360px, so a long title never collides with the "Módulo" pill.
- **Sketch 010 finding 3 (SectionTitle size).** The page uses the shipped `micro` variant, as the sketch drew it. The UI-SPEC's 16/700 row is what needs correcting.
- **A lock wins over a completion** in a row. The row says why, because the server would not open the lesson.
- **A locked course with the store off** gets variant (c), not (d). The API should not answer that combination. If it does, there is nothing to buy and nothing failed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added `apps/web/app/(app)/cursos/ReadMoreText.tsx` (not in `files_modified`)**
- **Found during:** Task 1
- **Issue:** `MemberCoursePage` is a server component, and the "Ler mais" / "Ler menos" toggle needs client state and a measured clamp.
- **Fix:** A small client component that measures the clamp after mount, so the toggle shows only when the clamp hides text. It is placed at the segment level, so the player (plan 08) and the live page (plan 09) can reuse it.
- **Committed in:** `76c16329`

**2. [Rule 3 - Blocking] Two view signatures widened**
- **Found during:** Task 1
- **Issue:** The 0% line needs the course's total length, and the hrefs need the preview flag. The purchase lock label also prints the lesson's length ("{duration} · Aula exclusiva").
- **Fix:**
  - `courseActionView` became `courseActionView(progress, t, { courseId, durationSeconds, preview })` instead of `(progress, t)`.
  - `lessonLockLabel` takes an optional `duration`.
  - Both stay pure.
- **Committed in:** `76c16329`

**3. [Rule 3 - Blocking] The store access read lives in `MemberCoursePage` (the plan put the action zone in charge)**
- **Found during:** Task 2
- **Issue:** `CourseActionZone` is a client component, because it holds the sheet's open state, so it cannot fetch.
- **Fix:** `MemberCoursePage` (server) reads `getCourseAccess` only when the course is locked, the viewer is not previewing and the store is on. It builds the view and the sheet thumbs, then passes them to `CourseActionZone` as props. `page.tsx` passes `storeOn`.
- **Committed in:** `bc6e787d`
