## Top 3 Priority Fixes

1. **36px tap targets on route controls (WARNING)** — UI-D-443 says "Every control is ≥ 44px". `GHOST_SM_LINK` ("Assistir à aula aberta") and `OUTLINE_SM_LINK` ("Tentar novamente") in `apps/web/app/(app)/cursos/[courseId]/CourseActionZone.tsx:75,77` and the "Voltar para a edição" link in `apps/web/app/(app)/cursos/PreviewBanner.tsx:21` are `h-9` (36px). On a phone the free-lesson door (the main non-buy path on a locked course) is undersized. Fix: keep the 36px visual but add `min-h-11` or a 44px hit area (`relative` plus `after:absolute after:-inset-1`), or change these to `h-11`.
2. **Duplicated button-look class strings (WARNING)** — the brand/outline link styles are re-declared in `CourseActionZone.tsx:71-77`, `lives/[liveId]/LiveStateZone.tsx:41`, `aulas/[lessonId]/LessonNav.tsx:29`, `PreviewBanner.tsx:21` and `MemberCoursesGrid.tsx:42`. They already drift: `MemberCoursesGrid`'s `LINK_OUTLINE` has no `active:bg-bg-tertiary`, the other copies do. A tenant theme or Button change will not reach these links. Fix: export a `buttonClasses({ variant, size, fullWidth })` helper from `@rede-social/ui` (the class builder `Button` already uses) and call it from every `<a>` styled as a button.
3. **Accessible names built from concatenated fragments (WARNING)** — `courses.member.card.ariaExclusive = ", exclusivo"`, `card.ariaProgress`, `lives.ariaExclusive` and `lesson.free = " · Aula aberta"` (leading-space keys) are glued together in code. That makes word order fixed in TSX and is fragile for the "strings centralised for future i18n" requirement. Fix: replace them with one ICU message per name using `select` (`{exclusive, select, true {, exclusivo} other {}}`), so the whole sentence lives in the catalog.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- Spot check of `apps/web/messages/pt-BR/courses.member.json` against the UI-SPEC: "Começar o curso", "Continuar o curso", "Rever o curso", "Comprar para liberar", "Assistir à aula aberta", "Marcar como concluída" / "Marcando…", "Aula concluída.", "Entrar na live", "Começa hoje, às {time}.", "O link para entrar aparece 15 minutos antes do início.", the preview banner, the lock and error toasts. All match the UI-SPEC word for word, and the ICU plurals are in place.
- `scripts/check-ui-literals.sh` exits 0: no literals in TSX.
- WARNING: names are composed from fragments (see fix 3). `lesson.free` and `card.ariaExclusive` start with a separator or a space, so a translator cannot reorder them.
- The empty states are specific ("Nenhum curso nesta categoria" with the "Ver todos os cursos" action), not generic text.

### Pillar 2: Visuals (3/4)
- `CourseCard.tsx` matches UI-D-426: 3:4 poster, `from-black/85 via-black/25` veil, the same box for the gradient fallback, the top-left stack at `top-3 left-3 right-3`, and the bottom block moving to `bottom-4` when the bar shows. The cover is never greyscale.
- `ModuleCover.tsx` matches UI-D-429: a `<button>` with `aria-expanded` that is never disabled, the 16:6 band, the numeral at 24/700 `text-white/10`, and the 32px state disc. It adds a justified deviation: the title is one line below 360px (sketch 010 finding 1).
- `MemberLessonRow.tsx` matches UI-D-430: always an `<a>`, `min-h-14`, the trailing glyphs at 20/18, and `aria-current` on the current row.
- `LiveCard.tsx` matches UI-D-434: status in words with no pulsing dot, and the secondary ink on a cancelled title.
- WARNING: button-styled links are copied as class strings instead of a shared primitive, and the copies have already drifted (fix 2).
- WARNING (minor): the module numeral at `text-white/10` is close to invisible on a light tenant gradient fallback. It is decorative and declared by the spec, so this is informational only.

### Pillar 3: Color (4/4)
- No hardcoded `#hex` or `rgb()` in any phase TSX.
- The single brand fill holds on the player. `CompletionZone` owns the brand button until the lesson is complete. After that it swaps to the `bg-success/10` done block, and only then does `LessonNav` mark "Próxima aula" brand (`LessonNav.tsx:63-64`, `completed ? BRAND : OUTLINE`).
- On the course page at 100%, "Rever o curso" uses outline (`CourseActionZone.tsx:210`), as the UI-SPEC requires.
- Brand use otherwise is limited to the progress fill and ring, `text-brand` on ghost text links, and focus rings. Success green is used only for completion.
- Over-media pills use `bg-black/60` (no gold or emerald tokens, per the porting deltas).

### Pillar 4: Typography (4/4)
- Across member surfaces and the module UI: `text-sm` ×86, `text-xs` ×49, `text-2xl` ×8, `text-base` ×5. Weights: `font-normal` ×90, `font-bold` ×56. That is exactly the inherited 12/14/16/24 scale with 400/700.
- `tabular-nums` is applied to every meta, count and duration, as specified.

### Pillar 5: Spacing (3/4)
- The most common values (`px-4`, `gap-3`, `gap-2`, `pt-4`, `pt-6`, `pb-6`, `gap-6`) match the UI-SPEC frames: the 680px column, `px-4 pt-4` zones and `gap-6 pt-6` sections. The UI-D-423 TopBar fix `gap-1 min-[360px]:gap-3` is in `packages/core/ui/TopBar.tsx:130`.
- WARNING: arbitrary values. `h-[30px]` chip skeletons are in `MemberCatalogue.tsx:23` and `page.tsx:37`, and `rounded-[14px]` is the wrapping "Produto arquivado" pill in `MemberCoursesGrid.tsx:54`. The pill is documented, but it means the pill differs from `ExclusiveBadge`'s `rounded-full` when they stack.
- WARNING: there are 36px `h-9` sm controls (fix 1).

### Pillar 6: Experience Design (3/4)
- State coverage is complete. There are poster and live-card skeletons (4 on first load, 2 on load more), `EmptyState` for empty catalogues and categories and for a course with no lessons, first-load error cards with retry, a load-more error with retry, store-read failure variant (d), all four lock variants, and the preview banner. Toasts for completion and errors use `role="status"`.
- Pending states: `CompletionZone` shows "Marcando…" and disables the button. `MemberMaterials` sets `disabled` and `aria-busy` per row.
- The WR-02 fix in `MemberMaterials.tsx:66-73` opens a blank tab inside the tap and nulls `opener`. That is correct for iOS. However, on failure the member briefly sees a blank tab open and close before the toast. This is an accepted trade-off, but worth noting for real-device UAT.
- Focus moves to the done block only when the button had focus (`CompletionZone.tsx:41-51`), per UI-D-443.
- WARNING: the 36px controls break UI-D-443's ≥44px rule (fix 1).
- WARNING: UAT rows for real devices (iPhone Safari and the installed PWA) are still blocked. The visual-fit checks at 320 and 390px were run only on desktop. Score capped at 3 until verified on a device.

Registry audit: shadcn not initialised (`components.json` absent), so it was skipped.
