## Summary

Scope: the 147 files of `git diff d3aa3190..HEAD`. I read the four migrations in full, plus the courses member lane (`learn-service.ts`, `learn-routes.ts`, the admin `service.ts` diff), the store access reads, the kernel media gate (`serveVariant`, `playbackTokens`), the nav changes and the web member routes under `/cursos` and `/loja`. I traced the earlier gate bodies the new functions call (`app.course_locked_ids`, `app.live_locked_ids`, the restrictive `course_lessons_course_gate` / `course_lives_live_gate`, `courses_select_published_or_admin`).

Overall the tenant isolation holds. Every new SECURITY DEFINER function pins `tenant_id = app.tenant_id()` on every table it reads. `search_path` is empty and EXECUTE goes to `authenticated` only. The `app` schema is not exposed through the Data API (`schemas = ["data_api_closed"]`). The new routes are in the isolation inventory. Each of these paths answers `app.course_lesson_access` before reading any content, so a locked lesson's description, video asset id, materials and room link do not leave the server:

- the member reads,
- the material URL,
- the progress write (route check and RLS `with check`),
- the live page.

Two more things hold:

- **Preview mode writes nothing.** The 204 short-circuit and the RLS `tenant_role() is distinct from 'admin_tenant'` both refuse an admin write, and the preview player gets no `onProgress` and no beacon listener.
- **Server and client stay apart.** No client component imports `@/lib/courses-learn`, `@/lib/store`, `@/lib/api` or `@/lib/bootstrap`.

The defects found:
1. **Material assets lose the course asset gate.** When a material's lesson or module is removed, or the material is detached, the gate stops governing that asset. `GET /v1/media/{assetId}/original` then serves a paid course's file to any member who has the id. Lesson videos do not have this gap.
2. **The member material download regresses a fix already shipped on the admin side** (08.3 WR-07). `window.open` runs after an `await`, so popup blockers drop it on iOS Safari and in the installed PWA.
3. **`app.course_lesson_access` fails open.** When the evaluator has no row for a lesson, the answer is NULL, which means "open". The two liveness predicates match today, but any drift between them would silently unlock content.

## Warnings

### WR-01: The course asset gate stops guarding a lesson material once its lesson or module is removed, or the material is detached

**File:** `supabase/migrations/20261015194825_courses_member_functions.sql:356-397`; the behaviour is reached through `packages/core/server/media/service.ts:760-766` (`serveVariant('original')`)

**Issue:** `app.course_asset_hidden` treats an asset as GOVERNED in two cases:
- its `purpose = 'lesson'` (lesson videos), or
- it is the material of a LIVE lesson. The second `exists` joins `course_lessons` with `l.deleted_at is null` and `course_modules` with `m.deleted_at is null` (lines 366-375).

Materials are `purpose = 'attachment'` (`service.ts:1655`), so they are governed only by the second branch. That branch stops matching in three cases:
- `deleteLesson` soft-deletes the lesson and keeps its `course_lesson_materials` rows (`service.ts:1561`);
- `deleteModule` soft-deletes the module (`service.ts:1174`);
- `replaceMaterials` hard-deletes the detached rows (`service.ts:1661`).

From then on the asset is "ungoverned", the gate answers `false`, and `serveVariant('original')` signs the PDF for any member of the tenant.

How a member gets the asset id: it sits in the path of every signed Storage URL the member route already handed out (`<tenant>/media/<assetId>/original`). So a former buyer whose entitlement was revoked, or anyone that URL was shared with, can fetch a paid course's materials again as soon as the admin reorganises the course.

Lesson videos are not affected: they stay governed by `purpose = 'lesson'`. The migration's own header and RESEARCH line 418 promise the "detached, or its lesson or module removed" refusal, but only for videos. pgTAP 195 has no case for a removed-lesson, removed-module or detached material, so the gap is untested.

**Fix:** Make the GOVERNED test independent of the lesson being live. Keep the liveness requirement only in the "held by an openable lesson" half:
```sql
-- governed: a lesson video, or ANY asset that is (or was) a course material of this tenant
(exists (select 1 from public.media_assets a
          where a.id = p_asset and a.tenant_id = app.tenant_id() and a.purpose = 'lesson')
 or exists (select 1 from public.course_lesson_materials mt
             where mt.tenant_id = app.tenant_id() and mt.asset_id = p_asset))
and not exists ( /* unchanged: a live lesson holding it that app.course_lesson_access opens */ )
```
For the detach path, the material row is gone, so also do one of these:
- retire the asset (soft-delete it, or `deleteAsset`) when `replaceMaterials` drops the last material row that holds it;
- or soft-delete material rows (`deleted_at`) instead of `delete`;
- or give course materials a dedicated purpose (for example `lesson_material`) that the first branch can govern.

Add pgTAP 195 cases: a material of a soft-deleted lesson, of a lesson under a soft-deleted module, and a detached material, each `course_asset_hidden(...) = true` for a member and `false` for `admin_tenant`.

### WR-02: Member material download calls `window.open` after an awaited server action, so popup blockers drop it

**File:** `apps/web/app/(app)/cursos/[courseId]/aulas/[lessonId]/MemberMaterials.tsx:60-66`

**Issue:** `open()` awaits `learnMaterialUrlAction(...)` and only then calls `window.open(result.url, '_blank', 'noopener,noreferrer')`. By then the call is outside the tap's user gesture. iOS Safari, including the installed PWA (the product's main target), and Firefox block it without telling anyone. With `noopener` the return value is always `null`, so the failure cannot be detected either: the member taps "Baixar" and nothing happens.

The admin side hit the same bug and fixed it in 08.3 (WR-07, `LessonForm.tsx:298-324`): it opens a blank tab synchronously, then navigates it once the URL arrives. The member port did not carry that over. Playwright's Chromium allows popups, so the e2e suite cannot catch this.

**Fix:** Reuse the admin pattern:
```tsx
async function open(materialId: string) {
  const tab = window.open('', '_blank'); // inside the gesture, before any await
  if (tab) tab.opener = null;
  setPendingId(materialId);
  try {
    const result = await learnMaterialUrlAction(lessonId, materialId);
    if (result.ok) {
      if (tab) tab.location.href = result.url;
      else window.open(result.url, '_blank', 'noopener,noreferrer');
      return;
    }
    tab?.close();
    if (session.refuse(result.code)) return;
    toast.show({ tone: 'error', message: t('errors.material') });
  } catch {
    tab?.close();
    toast.show({ tone: 'error', message: t('errors.material') });
  } finally {
    setPendingId(null);
  }
}
```
The live replay's materials (`LiveStateZone.tsx` renders the same component) get the fix too.

### WR-03: `app.course_lesson_access` answers "open" (NULL) when the evaluator has no row for the lesson

**File:** `supabase/migrations/20261015194825_courses_member_functions.sql:143-149`

**Issue:** The course-door branch is a scalar subquery: `select case s.lock_reason ... end from app.course_lesson_states(l.course_id) s where s.lesson_id = l.id`. The function uses NULL to mean "open", and a scalar subquery that finds no row also answers NULL. So any lesson the outer join accepts but `course_lesson_states` does not return is OPEN. That covers:
- the progress `with check`,
- `course_lesson_content`,
- `course_lesson_material_list`,
- `course_asset_hidden`.

Today the two liveness predicates (lesson live, module live, same tenant, same course) happen to match. Nothing enforces that. Any later edit that narrows the evaluator would silently unlock content in the one function every gate trusts, for example:
- filtering out lessons with no video,
- excluding a module state,
- a typo in a join.

A security function should fail closed.

**Fix:** Turn "no evaluator row" into `'missing'`:
```sql
else (
  select case
           when s.lesson_id is null then 'missing'
           when s.lock_reason in ('module', 'lesson') then 'sequence'
           else s.lock_reason
         end
    from (select 1) as one
    left join app.course_lesson_states(l.course_id) s on s.lesson_id = l.id)
```
Add a pgTAP assertion that pins this. One way: a lesson the evaluator does not return must answer `'missing'`. Another: assert in `pg_get_functiondef` that the branch handles the null row.

## Info

### IN-01: The asset gate's staff branch lets `support_tenant` replay a DRAFT course's lesson assets, against D-426

**File:** `supabase/migrations/20261015194825_courses_member_functions.sql:359`

**Issue:** `course_asset_hidden` returns `false` for `admin_tenant` and `support_tenant` alike. Meanwhile `course_lesson_access` answers `'missing'` to every role for a lesson of an unpublished course (D-426: "published only, for every role"). Only the admin needs draft assets (the admin course page mints thumbnails for drafts). A support agent holding a draft lesson's asset id can mint a playback token, while the learn routes 404 the same lesson for them.

**Fix:** Short-circuit `admin_tenant` only. Let `support_tenant` take the access path: the evaluator already returns NULL for staff on a published course, and `'missing'` on a draft.

### IN-02: `app.course_lesson_states` is granted to `authenticated` without the published filter its siblings apply

**File:** `supabase/migrations/20261015194825_courses_member_functions.sql:63-120`

**Issue:** `course_outline` pins `c.status = 'published'`, and `course_lesson_access` returns `'missing'` for unpublished courses. The evaluator itself answers for any course id of the tenant, drafts included: lesson ids, module ids, order and the caller's lock reasons. The API only calls it through those two wrappers, so no member route exposes it, and the Data API is closed. Still, it is the one granted member function that does not apply D-426 on its own.

**Fix:** Add `and exists (select 1 from public.courses c where c.id = p_course and c.tenant_id = app.tenant_id() and (c.status = 'published' or app.tenant_role() = 'admin_tenant'))`, or revoke EXECUTE from `authenticated` and call it only from the definer wrappers (they run as the owner).

### IN-03: A completed lesson resumes at its very end

**File:** `apps/web/lib/courses-member-view.ts:752` and `:1127`

**Issue:** The `ended` event writes `lastPositionSeconds = duration`, and the player resumes there (`startTime`). Re-opening a finished lesson or replay shows the player parked on the last frame with a full scrubber, until the member presses play (which restarts from 0).

**Fix:** When `completedAt !== null` and `lastPositionSeconds >= durationSeconds - 5` (or ≥ 90%), pass `startTime: 0`.

### IN-04: Every 400 on a lesson route is mapped to "gone"

**File:** `apps/web/lib/courses-learn.ts:238`

**Issue:** `lessonRefusal` maps any 400 to `{ status: 'not_found' }`, and `refusalCode` turns that into `gone`. In `LessonSession.refuse('gone')` that stops the session, toasts "Esta aula não está mais disponível." and navigates away. The actions pre-validate with the same schema, so this cannot happen today. But a future API-side validation (a new bound, a strict key) would eject a member from a lesson that is fine, instead of dropping one tick.

**Fix:** Map 400 to `{ status: 'error', httpStatus: 400, code }` for the write and material routes. Keep `not_found` only for the GET read, where a malformed id really is a miss.

### IN-05: The beacon route reads the whole body before it enforces the 4 KiB cap when no `Content-Length` is sent

**File:** `apps/web/app/api/courses/progress/route.ts:65-72`

**Issue:** The declared-length check is skipped for a chunked body with no `Content-Length`. `request.text()` then buffers whatever arrives before the byte check. It runs after `getClaims()`, so only an authenticated session can do it, but the cap is not actually a cap.

**Fix:** Read `request.body` with a reader and abort past `MAX_BODY_BYTES`, or refuse a missing or non-numeric `Content-Length` with 411/413 (`sendBeacon` and `keepalive` fetch always send one).

### IN-06: Preview live-card hrefs carry `?ver=aluno` to a route that ignores it

**File:** `apps/web/lib/courses-member-view.ts:222`; `apps/web/app/(app)/cursos/lives/[liveId]/page.tsx:20-25`

**Issue:** In preview, the Lives tab cards link to `/cursos/lives/{id}?ver=aluno`. The live page never reads `searchParams` and sends every `courses.manage` holder to the live edit form. So an admin previewing the member agenda drops out of the preview on the first tap, and the query string suggests a preview that is never applied. 08.5-09 records "no `?ver=aluno` on this route" as a decision, so the misleading part is the decoration.

**Fix:** Drop the preview decoration from `liveCardView`'s href, or honour `?ver=aluno` on the live page the same way the course and lesson pages do.
