### Claude's Discretion
Each item has a stated default. The planner may refine it but should not reverse it without asking.

**Routes and roles**
- **Route layout.** The admin already owns `/cursos/[courseId]`, `/cursos/[courseId]/aulas/[lessonId]` and `/cursos/lives/[liveId]`.
  - Default: one URL per entity, with the view chosen by role. A manager gets the admin page with a "Ver como aluno" toggle (for example `?ver=aluno`), and a member gets the member page. Links from the Loja, notifications and shares then work for everyone.
  - The planner may give the member a flat lesson route (`/cursos/aulas/[lessonId]`, the prototype's flat `/membros/aulas/[lessonId]`) or move the admin pages under a sub-path, if it keeps every 08.3 e2e green.
- **`support_tenant`.** Default: sees the member views fully open (the gate answers `'{}'` for staff claims), and their own progress is written like a member's. Only `admin_tenant` writes none (D-422).

**Progress and locks**
- **Completion threshold and progress cadence.** Default: completion at 90% of `duration_seconds`.
  - `last_position_seconds` is written at most every 15 s while playing, plus on pause, end and `pagehide`, idempotently.
  - The server clamps the position to the asset duration.
  - Completion is one-way in this phase, with no "desmarcar".
- **Error vocabulary.** Default: an unpublished or unknown course or lesson is the bare 404. A lesson locked by purchase is `403` with `details.courses = 'lesson_locked'`. A lesson locked by sequence is `409` with `details.courses = 'lesson_sequence_locked'`, so the web can show the right notice.
- **Sequential lock across modules.** Default: "the previous lesson" is the previous live lesson in course order, which may be in the previous module. The first lesson of a module that has `requires_previous` is governed by the module rule.
- **Where the lock is evaluated.** Default: one SQL function per course (lesson id → lock reason) used by the routes, the playback gate and the progress write. The prototype's `resolveLock` stays in sync with it as a pure helper for the web. The researcher may choose otherwise if one source of truth remains server-side.

**Media and threats**
- **T-08.3-08 closure.** Default: extend `app.media_asset_hidden` to lesson materials (hidden when the lesson is hidden by purchase or by sequence), and have the `/original` path ask it for `file` kinds.
  - Accepting the residual is not an option: SC 3 says the phase closes it.
  - The member's material open goes through the 10-minute signed `…/materials/{materialId}/url`, which leaves `courses.manage` for a member lane with access.

**Edge cases**
- **Replay of a lesson in an archived or unpublished course.** Default: the replay keeps playing from the live page while the lesson itself is live (not soft-deleted), because the live is its own door (D-433). The planner may tighten this to "the course must be published" if the gate stays simpler.
- **A lesson under a soft-deleted module** (the 08.3-05 residual). Default: for a member it counts as deleted. It is not listed, not playable and not counted in progress.
- **Progress write on the live-page replay.** Default: it writes the same `course_lesson_progress` row (it is the same lesson), so a later course purchase sees it.
- **Materials on the live-page replay.** Default: they open through the same door as the video.
- **Live join window.** Default: 15 minutes before `starts_at`, until `starts_at + duration_min`, computed by the shared `liveStatusAt` helper on the server.

## Project Constraints (from CLAUDE.md)

- All business logic goes through the Hono API on Cloud Run; the web never talks to Supabase for data (only Auth via `@supabase/ssr` and read-only Realtime). Member course reads and progress writes are therefore API routes, with the web BFF forwarding the Bearer. [CITED: .claude/CLAUDE.md § Constraints]
- Modularity (MOD-01..05): each feature is a self-contained package depending only on the kernel and on other modules' published contracts. The kernel names seams (`packages/core/db/*-gate.ts`), modules give bodies. No module→module TypeScript import (`pnpm boundaries`). ## Summary

Phase 08.5 is almost entirely a **read-path and authorization** phase over tables that already exist. Nothing new needs to be installed: Hono routes in `@rede-social/module-courses`, SQL functions in hand migrations, one new column (`course_lessons.requires_previous`), one index, a kernel seam stub, store access routes, and Next.js pages that pick a view by role. The hard part is not the UI; it is keeping **one server-side source of truth** for "can this caller open this lesson" and asking it from five places: the course outline, the lesson/player read, the materials URL, the progress write (route AND RLS), and the media asset gate (playback and `/original`).

The 08.3 posture is deliberately strict and **must stay green**: `course_lessons_course_gate` (restrictive) hides a locked course's non-free lesson rows from a member lane, and `course_lives_live_gate` (restrictive) hides a locked live's whole row. Both D-423 (titles-only curriculum) and D-431 (locked live card without `external_url`) need data those policies hide. The recommended mechanism is **not** to loosen either policy, but to add a small family of `SECURITY DEFINER` projection functions owned by the courses module, each pinned to `app.tenant_id()`, each returning only the safe columns, and each delegating lock decisions to one evaluator (`app.course_lesson_states(p_course)` → `app.course_lesson_access(p_lesson)`). This is the exact pattern 08.2 used for `app.feed_locked_post_community` and `app.media_asset_hidden` (definer functions that answer facts about rows the lane cannot see), it leaves every existing 190-courses assertion untouched, and it keeps the payload columns (`description`, `video_asset_id`, materials, `external_url`, `replay_lesson_id`) behind RLS for any lane read a future route might add.

The second structural decision is the **asset gate**. `app.media_asset_hidden` is a kernel stub whose body is owned by the feed module's migration; a courses migration that re-created it would have to inline the feed body (cross-module coupling, and any later feed redefinition would silently drop the lesson branch). Recommended: a **new kernel seam** `app.course_asset_hidden(p_asset uuid) boolean` (kernel stub answering `false`, courses body), exposed as a kernel TS helper next to `LOCKED_COURSE_IDS`, and asked by `playbackTokens` (ORed with the feed answer) and by `serveVariant` for the `original` variant. This honours D-433's intent ("the lesson-asset gate must accept either door") while respecting MOD-02.

**Primary recommendation:** Build a courses-owned SQL function family (`course_lesson_states` → `course_lesson_access` → `course_outline` / `course_lesson_content` / `course_lesson_material_list` / `course_live_cards` / `course_asset_hidden`), add member routes under the literal prefix `/v1/courses/learn/*` with no `courses.manage`, tighten the progress RLS `with check` with `app.course_lesson_access(lesson_id) is null`, mirror the 08.2 community access reads in the store for courses and lives, and split each `/cursos/*` page by role. Leave both restrictive policies and every 08.3 assertion exactly as they are.

### Pattern 1: Definer projection family (the D-423 / D-431 mechanism)

**What:** `SECURITY DEFINER` SQL functions in the `app` schema, `stable`, `set search_path = ''`, fully qualified names, every statement pinned to `app.tenant_id()`, EXECUTE revoked from PUBLIC and granted to `authenticated` only. They return only the columns a member may see and delegate every lock decision to the evaluator (Pattern 3). This is the 08.2 posture. [VERIFIED: supabase/migrations/20261008174609_feed_gate_lookups.sql — header: "Both read rows that RLS hides from the caller on purpose … so both are SECURITY DEFINER … EVERY statement pins `tenant_id = app.tenant_id()` itself (T-08.2-22)"; "Hardening (the T-06-29 posture): `search_path = ''`, fully qualified names; EXECUTE revoked from PUBLIC and granted to `authenticated` only."]

**Functions (recommended names, `[ASSUMED]` design):**

| Function | Returns | Never returns |
|----------|---------|---------------|
| `app.course_lesson_states(p_course uuid)` | per live lesson: `lesson_id, module_id, course_seq, module_seq, lock_reason ('purchase'\|'sequence'\|null), completed_at, last_position_seconds` | content |
| `app.course_lesson_access(p_lesson uuid) returns text` | `null` (open) \| `'purchase'` \| `'sequence'` \| `'missing'` — course door OR live door | — |
| `app.course_outline(p_course uuid)` | course published check; per lesson: module id/title/summary/position/requires_previous, lesson id/title/position/is_free/requires_previous/duration_seconds/has_video + states | description, video_asset_id, materials, thumbnails |

**Why not a lane read for open content?** The restrictive lesson policy already lets an UNLOCKED member read lesson rows, but (a) the sequence lock is not in RLS, and (b) the live door (D-433) must open a lesson whose course is purchase-locked for the caller, which the lane can never read. One definer reader gated by `course_lesson_access` serves both doors with one code path. The `external_url` of an open live, however, CAN be read through the lane (the restrictive live gate lets an open member read the row), so the live page reads it with a plain lane `select` — RLS stays the structural guard for the paid room link.

### Pattern 3: One lock evaluator (D-428, D-429, Claude's Discretion "one SQL function per course")

**What:** `app.course_lesson_states(p_course)` computes, for every live lesson (lesson `deleted_at is null` AND module `deleted_at is null`), its course order and its lock reason, in one statement using window functions and the caller's progress rows. Rules, in order:

1. Staff claim (`admin_tenant`, `support_tenant`) → `null` (never locked). A null/unknown role takes the member branch (fails closed, T-08.3-04 posture). [VERIFIED: packages/core/db/course-gate.ts:26-27 "A null or unknown `tenant_role` claim takes the member branch (fails closed, T-08.3-04)."]
2. Course in `app.course_locked_ids()` and lesson not `is_free` → `'purchase'`.
3. Lesson `is_free` → `null` (D-429: ignores the sequence lock).
4. Module `requires_previous` and `module_seq > 1` and NOT every live lesson of the previous non-empty live module completed → `'sequence'`.
5. Lesson `requires_previous` and `course_seq > 1` and the previous live lesson in course order not completed → `'sequence'`.
6. Otherwise `null`.

Order key: `(module.position, module.id, lesson.position, lesson.id)` — positions are 1..n among live rows but the id tiebreak makes the order total. `module_seq` is `dense_rank()` over modules that HAVE live lessons, so an empty module is never a gate (see Assumption A3). The `seq > 1` guards make a stale `requires_previous = true` on the first lesson/module harmless even if a reorder or delete forgot to normalise it.

`app.course_lesson_access(p_lesson)`:
- `'missing'` when the lesson is not a live lesson of the caller's tenant (removed, under a removed module, foreign id).
- `null` when the **live door** opens: a `course_lives` row of the tenant with `replay_lesson_id = p_lesson`, `cancelled_at is null`, and `id <> all (coalesce((select app.live_locked_ids()), '{}'::uuid[]))` (D-433; ignores the course's status and sequence, Claude's Discretion "replay of a lesson in an archived or unpublished course").
- Otherwise the **course door**: `'missing'` unless the course is `published` (D-426, every role on learn routes), else the lesson's `lock_reason` from `course_lesson_states`.

The web mirrors labels only: a pure helper (ported from the prototype's `resolveLock`) maps a server `lockReason` plus the outline's module/lesson positions to "Libera ao concluir a aula anterior" / "Libera ao concluir o Módulo NN" / the purchase padlock. It never DECIDES a lock. [VERIFIED: reference/frontend-design/lib/members-progress.ts — `resolveLock` label default ``Libera ao concluir o Módulo ${String(mod.order).padStart(2, "0")}``]

### Pattern 5: The asset gate seam (closes T-08.3-05 and T-08.3-08)

**What:** A new kernel stub `app.course_asset_hidden(p_asset uuid) returns boolean` (answers `false`), declared by a KERNEL custom migration, with the courses module's migration giving the body via `create or replace` (same signature, same OID) — the `community_gate_seam.sql` posture. The kernel TS helper lives next to `LOCKED_COURSE_IDS`. [VERIFIED: supabase/migrations/20261008171502_community_gate_seam.sql — "the KERNEL declares the community gate; a module gives it a body … `app.media_asset_hidden(p_asset) -> false (no asset hidden by the gate)`"; packages/core/db/community-gate.ts:38-39 `export const mediaAssetHidden = (assetId: string): SQL => sql\`app.media_asset_hidden(${assetId}::uuid)\`;`]

Body rule (`[ASSUMED]` design):
- staff claim → `false`;
- the asset is **governed** when it is a `purpose = 'lesson'` asset of the tenant, OR a material (`course_lesson_materials.asset_id`) of a live lesson of the tenant;
- a governed asset is hidden unless at least one live lesson that holds it (as `video_asset_id` or as a material) has `app.course_lesson_access(l.id) is null`.

## Common Pitfalls

### Pitfall 1: Function/policy migration order
**What goes wrong:** `supabase db reset` fails with "function app.course_lesson_access(uuid) does not exist" or "column requires_previous does not exist".
**Why:** SQL-language function bodies are validated at `CREATE`; `CREATE POLICY` resolves functions in its expression. Generating the column and the policy change in one `db:generate` puts both in one migration that sorts before the custom functions.
**How to avoid:** the 4-step order in Pattern 12; generate the custom file before editing the policy.
**Warning signs:** a single generated migration containing both `ADD COLUMN "requires_previous"` and `ALTER POLICY … course_lesson_access`.

### Pitfall 2: The coalesce wrapper on the seam
**What goes wrong:** `operator does not exist: uuid <> uuid[]`.
**Why:** `x <> all ((select app.f()))` parses as the subquery form of `ALL`.
**How to avoid:** always `coalesce((select app.course_locked_ids()), '{}'::uuid[])` (the TS constant `LOCKED_COURSE_IDS` already does). [VERIFIED: packages/core/db/course-gate.ts:31-38 "THE COALESCE IS MANDATORY … `export const LOCKED_COURSE_IDS: SQL = sql\`coalesce((select app.course_locked_ids()), '{}'::uuid[])\`;`"]

### Pitfall 3: Stale `requires_previous` after reorder/delete
**What goes wrong:** the new first lesson keeps `requires_previous = true` and the course becomes un-startable.
**Why:** the "first lesson of the course" changes on lesson reorder, lesson move, module reorder, lesson delete and module delete.
**How to avoid:** a `normaliseFirstLesson` mirroring the module's `normaliseFirstModule` in every one of those writes, AND the evaluator's `course_seq > 1` / `module_seq > 1` guards as the authority. [VERIFIED: packages/modules/courses/server/service.ts:1034-1046, 1126 — `createModule`/`updateModule` force `requires_previous = false` on the first module; "The module that becomes first loses `requires_previous` (UI-D-396, `normaliseFirstModule`)"]

### Pitfall 4: Store product page lists no lives for a non-buyer
**What goes wrong:** D-425's product page shows the product's lives only to buyers.
**Why:** `linkedLives` reads `course_lives` in the member lane; the restrictive live gate hides a locked live's row from exactly the people who need to see it on the product page.
**How to avoid:** member lists come from `app.course_live_cards()`; keep `linkedLives` for the manager. [VERIFIED: packages/modules/store/server/service.ts:257-270 `linkedLives` — `join course_lives v on v.id = l.live_id …` in the lane]

### Pitfall 5: A playback integration test plays an orphan lesson asset as a member
**What goes wrong:** `media-playback.test.ts` "a 9 000 s lesson answers an expiresAt 10 800 s out" goes red (404).
**Why:** it seeds a `purpose: 'lesson'` video attached to no lesson and mints with `demoMemberToken`; the new gate refuses an ungoverned-by-any-open-lesson lesson video to members.
**How to avoid:** switch that case to the admin token or attach the asset to an open lesson in the fixture; add the gated-lesson refusal cases beside it. [VERIFIED: apps/api/tests/integration/media-playback.test.ts:284-293 — `purpose: 'lesson'` … `const ttl = await ttlOf(assetId, demoMemberToken);`]

### Pitfall 6: Reels loses its media chrome in the TopBar
**What goes wrong:** with Reels demoted, `/reels` renders with the normal TopBar over the vertical player.
**Why:** `activeTabChrome` only searches tabs.
**How to avoid:** extend the chrome lookup to TopBar items whose href matches (or pass `[...tabs, ...topbar]`), and let the UI-SPEC decide how the bar looks on `/reels` without a Reels tab. ### 1. The evaluator
```sql
-- Source: pattern of supabase/migrations/20261014201954_store_course_links_functions.sql (bodies)
create or replace function app.course_lesson_states(p_course uuid)
returns table (lesson_id uuid, module_id uuid, course_seq int, module_seq int,
               lock_reason text, completed_at timestamptz, last_position_seconds int)
language sql stable security definer set search_path = '' as $$
  with live as (
    select l.id, l.module_id, l.is_free, l.requires_previous as lesson_rp,
           m.requires_previous as module_rp,
           row_number() over (order by m.position, m.id, l.position, l.id)::int as course_seq,
           dense_rank()  over (order by m.position, m.id)::int                as module_seq,
           p.completed_at, coalesce(p.last_position_seconds, 0) as last_pos
      from public.course_lessons l
      join public.course_modules m
        on m.id = l.module_id and m.tenant_id = l.tenant_id and m.deleted_at is null
      left join public.course_lesson_progress p
        on p.tenant_id = l.tenant_id and p.lesson_id = l.id and p.user_id = app.user_id()
     where l.tenant_id = app.tenant_id() and l.course_id = p_course and l.deleted_at is null
  ), mods as (
    select module_seq, bool_and(completed_at is not null) as all_done from live group by module_seq
  )
  select x.id, x.module_id, x.course_seq, x.module_seq,
    case
      when app.tenant_role() in ('admin_tenant', 'support_tenant') then null
      when p_course = any (coalesce((select app.course_locked_ids()), '{}'::uuid[])) and not x.is_free then 'purchase'
      when x.is_free then null
      when x.module_rp and x.module_seq > 1
           and not coalesce((select all_done from mods where mods.module_seq = x.module_seq - 1), true) then 'sequence'
      when x.lesson_rp and x.course_seq > 1
           and (select y.completed_at from live y where y.course_seq = x.course_seq - 1) is null then 'sequence'
      else null
    end,
    x.completed_at, x.last_pos
  from live x
$$;
revoke all on function app.course_lesson_states(uuid) from public;
grant execute on function app.course_lesson_states(uuid) to authenticated;

create or replace function app.course_lesson_access(p_lesson uuid) returns text
language sql stable security definer set search_path = '' as $$
  select case
    when l.id is null then 'missing'
    when exists (select 1 from public.course_lives v

                    and v.cancelled_at is null

  end

    on l.id = p_lesson and l.tenant_id = app.tenant_id() and l.deleted_at is null
   and exists (select 1 from public.course_modules m
                where m.id = l.module_id and m.tenant_id = l.tenant_id and m.deleted_at is null)

                  where m.tenant_id = app.tenant_id() and m.asset_id = p_asset and l.deleted_at is null)
    ) and not exists (
      select 1 from public.course_lessons l
       where l.tenant_id = app.tenant_id() and l.deleted_at is null
         and (l.video_asset_id = p_asset
              or exists (select 1 from public.course_lesson_materials m
                          where m.tenant_id = l.tenant_id and m.lesson_id = l.id and m.asset_id = p_asset))
         and app.course_lesson_access(l.id) is null)
  end
$$;
```
