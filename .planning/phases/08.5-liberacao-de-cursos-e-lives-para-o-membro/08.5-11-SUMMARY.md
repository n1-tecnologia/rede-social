# Phase 08.5 Plan 11: The Cursos Tab and the Reels TopBar Slot Summary

**With the school on, rede-demo's BottomNav now reads Início · Comunidades · Cursos · Eventos · Perfil. Reels has moved to the leftmost TopBar slot (the first row of the rail's bottom group on desktop) and still opens in the dark media chrome. The move is declared in the Reels manifest (`yieldsTabTo: ['courses']`, `topbarOrder: 1`), and the kernel never names either module. With `courses` off (rede-lab) the bar is unchanged.**

## Accomplishments

- **Contract.** `ModuleNav` gains `yieldsTabTo?: readonly string[]` and `topbarOrder?: number`. The bootstrap's nav `z.object` declares both fields, because it strips unknown keys.
- **Yield rule** (`buildNav`): a tab candidate yields when its `yieldsTabTo` names another tab candidate that declares no yield of its own. Yielding entries join the topbar list. That list sorts by `topbarOrder ?? order`, then key. The code part of `nav.ts` contains no `'courses'` or `'reels'` literal (the acceptance grep counts 0).
- **Media chrome.** `activeTabChrome` reads whatever items it is given. `TopBar` and `BottomNav` pass `[...tabs, ...slots]`; `BottomNav` gets a new optional `slots` prop, which `AppShell` fills with `nav.topbar`. `aria-current` still comes from the tabs only.
- **320px fit.** The TopBar's right group uses `gap-1 min-[360px]:gap-3` and is marked `data-shell-slots`.
- **Manifests.**
  - Courses declares the Cursos tab.
  - Reels declares the yield fields.
  - Both READMEs document the new navigation, and the README drift test pins them.
- **Preview.** The mirror carries `courses` and the Reels yield. The preview TopBar now draws the slots it has a screen for, which is Reels. The panel's screen picker lists topbar items too.
- **Browser.**
  - shell.spec covers rede-demo's bar, the order of the slot row, Cursos as the current tab on `/cursos`, rede-lab as the courses-off control, and the 320px backstop.
  - reels.spec reaches Reels through a `reelsDoor` helper and adds case e18.
  - The phase 4/5/6 smoke specs check rede-demo's new row.

## Decisions Made

Planning decisions 1-3 were implemented as written (see `key-decisions`). Three choices were made during execution:

- **One-hop yield.** An entry yields only to a tab that does not yield itself. This means a cycle cannot oscillate, and two entries that name each other both stay tabs.
- **One sort for the whole slot row.** `topbarOrder ?? order` orders every slot, so native slots keep their own order.
- **Readonly array in the bootstrap.** `yieldsTabTo` is `z.array(z.string()).readonly()`. The manifest's `readonly string[]` then types through `enabledModulesForBootstrap` without a cast.
