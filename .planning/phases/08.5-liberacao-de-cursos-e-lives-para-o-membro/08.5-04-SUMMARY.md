# Phase 08.5 Plan 04: Member Catalogue and Lives (API) Summary

**The member catalogue (published courses newest first, locked flags, full counts, own completion count, category chips), the lives agenda in two groups, and each live's page with a server-decided state, the join link only inside its 15-minute window, and the replay through the live door.**

## Accomplishments

- `GET /v1/courses/learn/courses` lists the tenant's published courses for every role, newest published first, with locked and open courses in one list. Each card carries `locked` from the kernel seam (false for staff). It also carries the full `lessonCount` and `durationSeconds` and the caller's own `completedCount`, all from `app.course_catalogue_stats()`. `categories` lists only the categories that hold a published course.
- `GET /v1/courses/learn/lives`: the first page carries the whole upcoming group (live now, scheduled, and cancelled until the planned end), plus 20 recorded lives that have a live replay. Only the recorded group pages after that. Every card comes from `app.course_live_cards()`, and no card carries the room link or the replay lesson id.
- `GET /v1/courses/learn/lives/{liveId}`: the server decides `state`. `joinUrl` is the stored link only in the `open` state, which uses `liveJoinWindowAt` on the server clock. The link is read through the lane under the restrictive live gate. `replay` is read through `app.course_lesson_content` and `app.course_lesson_material_list`, so it opens through the live door. A cancelled live keeps its page. `startsToday` is decided in the tenant's timezone. Every answer is `no-store`.
- The `phase 08.5 sweep: courses learn` case covers all seven member routes. The README documents the three new routes and contract names.

## Decisions Made

Planning decisions 1-5 were implemented as written (see `key-decisions`). I made two choices during execution:

- The agenda's SQL filters compare the live's end at millisecond precision (`date_trunc('milliseconds', starts_at) + duration`) against the request's JS instant. JavaScript `Date` truncates the stored microseconds, so a card's `liveStatusAt` status can never contradict the group it is in (EP-28).
- If the projection says a live is unlocked but the lane read returns no `course_lives` row (the restrictive gate hid it), the page treats the live as locked.
