# Phase 09.3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Size of this contract:** this phase adds no screen and no design primitive. Two disabled placeholders become live controls that open the existing `ConfirmDialog`; one existing label gets a regression test at 50 characters; one editor sends a marker with no visible change. Everything below inherits the shipped tokens, so there are no new colors, sizes or spacing values.

## Not new design (reused, no sketch needed)

| Surface | Why it is not a new surface |
|---------|-----------------------------|
| Delete-event dialog, delete-community dialog | `ConfirmDialog` from `@rede-social/ui`, `tone="danger"`, same shape as "Cancelar evento" (`CancelEventControl.tsx`) and "Arquivar comunidade" (`CommunityForm.tsx`). |
| Refusal dialog "community still unlocked by products" | The same `ConfirmDialog` with its existing `children` slot and `scrollBody` (08.2-10 store lock warning, 09.1-13 gate dialog). A list inside a centred dialog is already shipped. |
| Live "Excluir" trigger | The placeholder's own button, minus `aria-disabled`, `opacity-60`, `cursor-not-allowed` and the "Em breve" pill. |
| Highlight name cut under its circle | Already true in code: `StoryCircle.tsx:348` renders the label as `max-w-16 truncate`. No code change, only a test. |
| Counters at 200 and 50 | Both read the contract constants. Nothing to restyle. |
| App icon editor marker | Request body only. No visible change. |

**Sketch verdict: no sketch needed.** Every visible element has a shipped sibling (`CancelEventControl`, `ReactivateCommunity`, the Loja lock dialog), so the design gate for prototype-less surfaces is not triggered. If the executor finds that the refusal dialog cannot fit 5 names plus "e mais N" inside `scrollBody` at 320px without moving the footer, stop and raise it; that would be the only case that justifies a sketch.

## Live trigger ("Excluir evento", "Excluir comunidade")

Keeps the look of the placeholder, minus the pill and the disabled signals.

| Property | Contract |
|----------|----------|
| Element | `<button type="button">`, never submits the surrounding form |
| Classes | `inline-flex h-11 items-center gap-2 rounded-xl text-sm font-bold text-danger transition-opacity active:opacity-80 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2 focus-visible:ring-offset-bg` |
| Icon | `Trash2`, 20px, `aria-hidden` |
| Label | `events.delete.action` "Excluir evento"; `communities.delete.action` "Excluir comunidade" (both exist already) |
| Attributes | `aria-haspopup="dialog"`, `data-delete-control="event"` or `"community"` on the wrapper |
| Wrapper | `flex flex-wrap items-center gap-x-3 gap-y-1` (keeps the 320px wrap when it sits beside "Reativar evento") |
| Disabled | none. No `aria-disabled`, no `opacity-60`, no `cursor-not-allowed`. While a delete request runs the dialog owns the pending state and the trigger is covered by the modal. |
| Focus | visible ring as above; Enter and Space open the dialog |
| Touch target | 44px tall; width is the label plus icon (about 130px event, 160px community), above 44px |
| Visibility | unchanged from the placeholder: event form in edit mode below the cancel or reactivate row (for any event, active, cancelled or past, D-548); the cancelled-event notice for `canManage` beside "Reativar evento"; the archived community's note under "Reativar comunidade" and the community form's archived branch; members never see it |

**320px:** in the cancelled-event notice "Reativar evento" (outline, about 150px) and "Excluir evento" (about 130px) do not fit one row, so the wrapper wraps "Excluir evento" under the button, left-aligned, 4px gap. On the community page the trigger sits on its own row under "Reativar comunidade" with `className="mt-2"`, as today.

## Copywriting Contract

No em dash anywhere. Catalog is `apps/web/messages/pt-BR/events.json` and `communities.json` only.

### Delete event

| Element | Copy |
|---------|------|
| Trigger | Excluir evento |
| Dialog title | Excluir evento? |
| Dialog body | O evento some das listas e o link deixa de abrir. As confirmações e os check-ins já feitos ficam guardados. Ninguém é avisado. |
| Confirm (danger) | Excluir |
| Cancel | Manter evento |
| Pending | Confirm label stays "Excluir" with the spinner and `aria-busy`; both footer buttons disabled; Escape and backdrop inert. No label swap (`ConfirmDialog` has no pending-label prop and this phase does not add one). |
| Success toast | Evento excluído. |
| Already deleted (404 race) | info toast: Este evento já foi excluído. Then the same landing as success. |
| Generic failure | error toast: Não foi possível excluir o evento. Tente novamente. Stay on the page, trigger still available. |
| After landing | `/eventos` (the list), see Landing. |

### Delete community

| Element | Copy |
|---------|------|
| Trigger | Excluir comunidade |
| Dialog title | Excluir comunidade? |
| Dialog body | A comunidade e as publicações dela, com curtidas e comentários, deixam de aparecer para todos. Não há como desfazer por aqui. |
| Confirm (danger) | Excluir |
| Cancel | Cancelar |
| Pending | Same as the event dialog. |
| Success toast | Comunidade excluída. |
| Already deleted (404 race) | info toast: Esta comunidade já foi excluída. Then the same landing as success. |
| No longer archived (stale page) | error toast: Esta comunidade não está mais arquivada, então não pode ser excluída. Then `router.refresh()` so the page re-renders as active and the trigger disappears. |
| Generic failure | error toast: Não foi possível excluir a comunidade. Tente novamente. Stay on the page. |
| After landing | `/comunidades`, see Landing. |

Why short confirm labels: at 320px the dialog is 256px wide and each footer button 128px. "Excluir comunidade" plus the 24px spinner would wrap; "Excluir" fits with room. The title carries the noun.

### Refusal: the community is still unlocked by active Loja products (D-554)

Shown as a second `ConfirmDialog` that opens when the delete answers the "unlocked by active products" refusal. The delete dialog closes itself on settle, as `ConfirmDialog` always does, so the refusal is a separate dialog rather than a toast: names need room and a toast would run to six lines at 320px.

| Element | Copy and rule |
|---------|---------------|
| Props | `tone="brand"`, no icon, `scrollBody`, `children` = the list |
| Title | Não é possível excluir |
| Body | `{count, plural, one {Este produto da Loja ainda dá acesso a esta comunidade. Tire a comunidade dele primeiro.} other {Estes produtos da Loja ainda dão acesso a esta comunidade. Tire a comunidade deles primeiro.}}` where `count` is the TOTAL number of active products, not the number listed |
| List | `<ul class="list-disc pl-4 text-sm text-text">`, one `<li>` per product name, in the API's order, each `break-words` (names wrap, never truncate). At most 5 names. |
| More line | when total is above 5, a last plain line (no bullet, `text-text-secondary`): `{count, plural, one {e mais 1 produto} other {e mais # produtos}}` with `count` = total minus 5 |
| Confirm (brand) | Ver produtos (goes to `/loja`, the admin product list) |
| Cancel | Fechar |
| Footer at 320px | stays on screen: `scrollBody` caps the body and list at 240px and scrolls inside, title and both buttons never move |

### Landing

| After | What the admin sees |
|-------|---------------------|
| Confirmed delete (event or community) | `router.replace` to the list (`/eventos`, `/comunidades`) so the dead form or detail is not the previous history entry, with the success toast on top (the `CancelEventControl` precedent keeps the toast across the client navigation). The list is the existing page: the deleted row is simply absent. No new banner. |
| List now empty | the existing empty state, unchanged: `events.empty.*` and `communities.empty.title` with `communities.empty.bodyAdmin`. |
| Server action | revalidates `/eventos`, `/inicio`, `/comunidades` (planner confirms the exact paths) so the replaced list is fresh. |
| The form's own exit guard | not involved. The control calls `router.replace` directly, never `leaveForm`, so the form's "Descartar alterações?" dialog does not appear for a form with unsaved edits. |

### Catalog keys

| Key | Action |
|-----|--------|
| `events.delete.soon`, `events.delete.hint` | removed (with the test that reads them) |
| `events.delete.action` | kept |
| `communities.delete.soon`, `communities.delete.hint` | removed |
| `communities.delete.action` | kept |
| `events.confirm.delete.{title,body,confirm,dismiss}` | added (same `dismiss` naming as `events.confirm.cancel`) |
| `events.toasts.deleted`, `events.errors.delete`, `events.errors.deleteGone` | added |
| `communities.confirm.delete.{title,body,confirm,cancel}` | added (same `cancel` naming as `communities.confirm.archive`) |

Error text never contains the event title or community name, and the client logs only `String(error)` (the `ReactivateCommunity` precedent, T-05-06).

## Interaction and accessibility

| Topic | Contract |
|-------|----------|
| Dialog semantics | `role="dialog"`, `aria-modal`, `aria-labelledby` the title, `aria-describedby` the body (all from `ConfirmDialog`, no change). |
| Focus on open | first focusable in the panel, which is the cancel button: the safe default for a destructive confirm. |
| Focus on close without deleting | returns to the trigger that opened the dialog (`useFocusTrap` restores the opener). |
| Focus after a delete | the trigger leaves the page with the navigation; the new list page takes focus through Next's route change. If the delete refuses with "no longer archived", `router.refresh()` removes the trigger and `useFocusTrap` hands focus to the enclosing modal or the document, which is acceptable because the toast announces the reason. |
| Refusal dialog | opens as the delete dialog closes; focus lands on "Fechar"; on close it returns to the trigger. |
| Escape and backdrop | close the dialog, disabled while the request is pending. |
| Double tap | `ConfirmDialog` ignores a second confirm while pending; a repeated delete that reaches the server returns the 404 race and reads the "already deleted" toast. |
| Toasts | `role="status"` `aria-live="polite"`, 3000 ms; error and info toasts for this phase use the default duration. |
| Reduced motion | `ConfirmDialog` already swaps the spring for a fade. |
| Trigger name | "Excluir evento" or "Excluir comunidade" read as the button name; the icon is hidden. |

## Highlight name under its circle (D-560, PEND-09)

| Item | Contract |
|------|----------|
| Rule | the name renders on ONE line, cut with an ellipsis, in a 64px column (`max-w-16 truncate text-xs font-normal text-text-tertiary`), so every circle keeps the same height and a long name never widens its column. About 9 characters show; the rest is cut by design. |
| Where | `StoryCircle.tsx` is the only component that draws a name under a circle (`StoriesStrip` and the stories surface use it); the rows in `HighlightManageList`, `HighlightSheet` and `HighlightEditSheet` already truncate on one line beside a thumbnail. No code change expected. |
| Full name | the circle's button keeps `aria-label={label}` with the full name for screen readers, and the viewer shows the whole name when the highlight opens. No tooltip and no second line. |
| Test | a strip with a 50-character name asserts one line (`truncate` present, no wrap), unchanged column width, and the full name in the accessible name. |

## Counters at the new limits

| Counter | Contract |
|---------|----------|
| Schedule, `events.form.schedule.limit` "Até {max} momentos no cronograma." | `max` comes from `EVENT_SCHEDULE_MAX_ITEMS` (200). At 200 rows the add control is disabled and the line stays visible; the editor must not degrade at 200 rows (planner adds a render test at 200). |
| Highlight title field `limit` prop | reads `STORY_HIGHLIGHT_MAX_TITLE` (50); the counter text must show "50/50" and an over-limit state without clipping at 320px. |

## App icon editor (PEND-11)

`AppIconEditor.tsx` sends the "own art" marker on save. No label, preview, state or copy changes. A failed save keeps the existing error line. Nothing new to the audit.
