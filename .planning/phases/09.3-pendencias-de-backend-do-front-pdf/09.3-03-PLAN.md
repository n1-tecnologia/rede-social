The decision supersedes the approved UI-SPEC's "no code change expected" for this header (noted here only; `09.3-UI-SPEC.md` and `09.3-CONTEXT.md` are not edited). The change is ONE class swap on that span: the ellipsis class becomes `break-words`, the modules' own convention for a name that must stay whole (`CommunityReorderList.tsx`). **Deviation from a two-line cap, on purpose.** Two lines cannot hold 50 characters at phone widths. Estimated, not measured, with Manrope bold 14px at about 8px per character: the name column is about 208px at 390px wide for a member and about 154px for a curator (the item's `menu` button takes 44px plus a 10px gap), and about 138px and 84px at 320px, so a two-line clamp would cut a 50-character name again (about 36 characters for a curator at 390px); only plain wrapping always shows it, and the length is bounded by the 50-character cap. If the owner prefers a ceiling, a `line-clamp-N` token is a one-token change at the price of cutting long names again. Layout: the header row's container `top` is fixed and the progress bars sit 16px above it (`safe-top + 8px`), so a taller row grows DOWNWARD and never overlaps the bars; when the name wraps, the row takes the text block's height (name lines plus the time line, about 56px for two lines) if that exceeds the 44px buttons, and the avatar and the buttons re-centre inside it, which is accepted and only happens for names that wrap. Not measured in a browser here: the manual row "viewer header with a 50-character name" in `09.3-VALIDATION.md` covers a real phone, as a curator (with the menu) and as a member.
</planning_decisions>
