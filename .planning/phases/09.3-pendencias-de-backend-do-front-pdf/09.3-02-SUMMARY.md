# Phase 09.3 Plan 02: Own-art app icon fills the Android maskable icon Summary

**An app icon saved from the "Ícone do app" editor is uploaded as the new kind `icon_art`, marked as `tenants.branding.iconOwnArt`, and the worker's `deriveIconSet` fills the whole `maskable512` square with it when the art has no transparent pixel; a transparent icon, a logo-derived one and an unmarked one keep the 80% margin over the primary, and no existing tenant is touched.**

## Accomplishments

- Tracer through every layer: contract kind and field, the pixel rule in the kernel, the completion write, the worker's `ownArt` argument, and a live integration case where the green art's four corners come out green in the served `maskable-512.png`, with the same bytes sent as `icon` keeping the primary at the corners.
- Every D-563 branch proven on pixels: opaque PNG, JPEG, SVG rect and non-square (cover) fill; transparent PNG, one transparent pixel, SVG circle, logo-derived, `ownArt` false/absent keep the margin; the other four outputs are byte-identical with or without the marker.
- Marker lifecycle on both lanes: reset by a plain `icon`, cleared once by the removal (second call writes nothing), kept through a colour save, a superseded derivation writes nothing, two saves leave two versioned sets with the older objects intact, URL and marker in the same row state as the version bump.
- D-564 held: no migration (`git diff --stat -- supabase` is empty); the seeded rede-demo and rede-lab rows are never marked and have no derivation job; an empty `{}` brand derives nothing.
- The editor (platform and tenant admin Marca tabs share `IconOverrideUpload`) and the wizard (`CreateTenantDialog`) send `icon_art`; `BrandingUploadKind` replaces the two-kind literal in the helper, the hook and both server actions. No catalog or visible change.
