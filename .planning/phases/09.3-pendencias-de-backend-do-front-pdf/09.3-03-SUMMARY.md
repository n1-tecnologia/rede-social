## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's premise about what the contract counts is wrong for Zod 4**
- **Found during:** Task 1 (story-highlight-title.test.ts, case P29)
- **Issue:** the plan (and the old docblocks) say the contract's `.max()` counts UTF-16 code units, so 26 emoji (52 units) would be refused by the contract. Zod 4.6's string `.max()` counts code points: 26 emoji are accepted and only 51 are refused (checked directly against Zod). The database CHECK also counts code points. Only the field's `maxLength` and the service's `updateHighlight` check (`requestedTitle.length`) count UTF-16 units, so on a direct API call a rename (PATCH) to 26..50 emoji is refused `title_invalid` by the service while a create of the same name passes. This predates the plan and is unchanged by it; a name the field accepts is never refused, which is the property that matters.
- **Fix:** the test pins the real behaviour (25 and 50 emoji accepted, 51 refused) and the constant's docblock now states the true unit counts per layer. No design change; the create/rename asymmetry for emoji names between 26 and 50 characters is left for a decision rather than improvised.
- **Files modified:** packages/modules/stories/tests/story-highlight-title.test.ts, packages/modules/stories/contracts/index.ts
- **Committed in:** `2605c4e4`

**2. [Rule 1 - Bug] The positive control read-back used the member list, which hides empty highlights**
- **Found during:** Task 1 integration run
- **Issue:** `GET /v1/stories/highlights` without scope omits a highlight with no stories.
- **Fix:** the case reads with `?scope=all` (the curator's read), as case 05.2-3 does.
- **Committed in:** `2605c4e4`

**3. [Plan criterion flaw, no code change] `grep -n ... | grep -c "[0-9][0-9]"` counts the line-number prefix**
- The Task 1 acceptance check for "no numeric literal bound" in `service.ts` printed 1 because `-n` prefixes the line number `1815:`. Run without `-n`, it prints 0; the check line is `requestedTitle.length > STORY_HIGHLIGHT_MAX_TITLE`.
