## Shared Patterns

### Tenant lane write with bare 404
**Source:** `events/server/service.ts:1106-1170`, `communities/server/service.ts:683-720`. Every service: `withTenantTx(ctx, tx => tx.execute(sql\`... where tenant_id = ${ctx.tenantId}::uuid and ... deleted_at is null\`))`, missing/foreign/deleted all answer `throw new ApiError(404, 'NOT_FOUND')` with no details (D-23 existence-oracle rule). State refusals are `ApiError(409, 'CONFLICT', { community: code })`.

### Permission guard
**Source:** `routes.ts` of each module: `middleware: [requirePermission('<literal>')] as const` (events: `events.event.manage`; communities: `communities.community.manage`).

### Confirmation + toast + error logging (web)
**Source:** `CancelEventControl.tsx`, `ReactivateCommunity.tsx`: `ConfirmDialog` with `onConfirm`, ignored second tap, `onError` logs `String(error)` only (T-05-06, no names/titles).

### Logging
Ids only in log lines (Pitfall 12, T-05-06); no `emit()` on either delete.

### Migrations
Generate with `pnpm db:generate` at execution time; hand-written functions via `--custom`; never edit applied files; file name `^\d{14}_[a-z0-9_]+\.sql$`; run pgTAP before the integration suite; `pnpm test:integration -- x` does not filter (use `pnpm --filter @rede-social/api exec vitest run tests/integration/<file> -t "<title>"`).
