## Shared Patterns

### Tenant transaction and claims
**Source:** `packages/core/db/tenant-tx.ts` (`withTenantTx`, sets `request.jwt.claims` including `tenant_role`, then `set local role authenticated`). **Apply to:** every store service function and every gate check. The tenant is never a parameter.

### Error vocabulary
**Source:** `packages/contracts/src/errors.ts` lines 30-43, `packages/core/server/http/api-error.ts`. Unknown, foreign or hidden resources get a bare `404 NOT_FOUND` with no details (D-23). State refusals are `409 CONFLICT { store: … }`. Input refusals are `400 VALIDATION_FAILED { store: … }`. A locked resource is `403 FORBIDDEN { access: 'community_locked' }`.

### Guard chain
`router.use('*', requireAuth, requireModule('<key>'))` plus `middleware: [requirePermission('<literal>')] as const` on writes (events routes.ts:81, :106). A disabled module answers `404 MODULE_DISABLED`.

### Definer functions
`language plpgsql volatile security definer set search_path = ''`. Every statement is pinned to `app.tenant_id()`, then `revoke all … from public; grant execute … to authenticated` (event_check_in_ceiling.sql:31-37 and tail). The owner bypasses RLS, so the tenant pin is the only isolation.

### Logging
`moduleLogger('module-store')`. Log the SHAPE (ids, counts, outcome) and never names, prices typed by users, or captions (events service :1263-1274).

### Web permission gating
Check `bootstrap.permissions.includes(<PERMISSION const>)`, never the role. A page without the permission is `notFound()` (participantes/page.tsx:22-30; configuracoes/page.tsx:124-127).
