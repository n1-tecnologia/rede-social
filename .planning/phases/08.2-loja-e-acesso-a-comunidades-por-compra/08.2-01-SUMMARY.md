# Phase 08.2 Plan 01: Store Tracer Summary

**A kernel-named community gate (`app.community_locked_ids*`) with store-supplied bodies, four RLS-guarded store tables, a restrictive `feed_posts` policy that leaves a member only the newest post of a locked community, and an `app.store_purchase` definer that snapshots the price, all reached through two Hono routes in the new `@rede-social/module-store`.**

## Accomplishments

- An admin links a product to a community (`POST /v1/store/products`, 201); a member then reads one item, the newest post, with `nextCursor: null`; the member buys (`POST …/purchase` with `expectedAmountCents`) and reads all three posts. Staff read everything throughout. Proved end to end against the local stack.
- The gate lives in Postgres: kernel stub migration first, the generated store migration (tables, arbiters, select-only ledgers, restrictive `feed_posts_community_gate`, widened key CHECK, no backfill), then the store bodies and `app.store_purchase`. `pnpm db:reset` applies them in order.
- `app.store_purchase` copies `amount_cents`/`currency` from the product row (D-361). A replay answers `owned`, and five concurrent calls leave one order and one entitlement. When a concurrent grant wins, the call deletes its own order.
- pgTAP 180 (72 assertions) covers the gate truth table, store-off states, fail-closed claims, the archived-product rule, ledger write refusals, CHECKs, definer outcomes and posture. 010/020/040 were extended (020 now plans 188). The full pgTAP suite passes 1039/1039 and the full API integration suite 944/944.

## Decisions Made

- Entitlement storage is Option B as planned. `community_members` is untouched; this is asserted in pgTAP 180 and in the tracer.
- The lane form of the gate does not consult `memberships` for staff. Only the `admin_tenant`/`support_tenant` claim opens it, so a null or unknown claim fails closed even for an admin user (T-08.2-13). The `_for` form reads the role from `memberships` (the worker path).
- `community_viewer_ids` returns `'{}'` (not null) for a gated community nobody holds, so "gated, nobody" and "not gated" stay distinguishable.
- `priceCentsSchema` carries `price_invalid` as every issue message, so a bad price in either route body becomes `details.store: price_invalid`.
- The product input's `imageAssetId` defaults to null and `communityIds` defaults to `[]`, deduplicated after the 50-item cap.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Revoked write privileges on the ledgers so member-lane update/delete raise 42501**
- **Found during:** Task 2 (writing pgTAP 180 against truth 4)
- **Issue:** With RLS and no write policy, an insert fails with 42501 but an update or delete in a member lane silently touches zero rows, and TRUNCATE is not seen by RLS at all. Truth 4 / P68 require 42501 for all three.
- **Fix:** `revoke insert, update, delete, truncate on store_orders, store_entitlements from authenticated` in the store_functions migration, following the `chat_rls_grants` precedent. Definers (owner) and the admin lane (`service_role`) are unaffected.
- **Files modified:** supabase/migrations/20261008171645_store_functions.sql
- **Verification:** pgTAP 180 and 020 throws_ok 42501 for every member-lane write; full API integration suite green.
- **Committed in:** 29f7b12

**2. [Rule 1 - Bug] pgTAP 040 convention flagged the deliberate `limit 1` of `app.feed_sample_post_ids`**
- **Found during:** Task 2 (running 040)
- **Issue:** Assertion 37 allows `membership_for_user` as the only `app` function containing `limit 1`. The sample function needs `limit 1` per lateral probe (Pitfall 4).
- **Fix:** The assertion now expects `feed_sample_post_ids,membership_for_user`, with a comment giving the reason. A new assertion pins its `order by p.created_at desc, p.id desc`, so the pick cannot become arbitrary. `fetch first` was not used as a disguise. plan(66) became plan(67).
- **Files modified:** supabase/tests/040-schema-conventions.sql
- **Committed in:** 29f7b12

**3. [Rule 3 - Blocking] Existing unit and integration expectations that counted seven module keys or registrations**
