# Phase 08.2 Plan 07: Loja browse UI Summary

**Members now open "Loja" from a TopBar slot that sits first in the right-hand group. The screen is a two-column grid of 4:5 product posters with "Todos · Comprados" chips. A product page shows the price, the owned block, what the product unlocks and, for managers, "Gerenciar produto" plus "Reativar produto" on archived products. Admins also reach the store from Configurações. The seed turns the store on for rede-demo with no products, and every store string of the phase is in the pt-BR catalogs.**

## Decisions Made

- The module gate is in `loja/layout.tsx` (see Deviation 1).
- Price and action are grouped 12px apart, as in the approved drawing. The UI-SPEC's 24px rhythm applies between the other sections.
- A manager on an archived product sees "Arquivado" and the reactivate note even when they also hold it, which matches the card's priority.
- Images use `PURPOSE_WIDTHS.cover` as the ladder, because the store contracts carry no variant widths.
- `PageHeader` keeps its shipped sticky default (the events detail page posture). The UI-SPEC's `stickyTop="0px"` predates the primitive's fix, and its docblock says `0px` now leaves a 7px seam.
- Sketch findings: (1) the 120px logo at 320px is unchanged; it is a plan 12 backstop. (2) The doubled relative time belongs to plan 09. (3) `store.purchase.andMore` is "e mais {n}", which allows the drawing's "A, B e mais 2". Plan 08 composes it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A page-level `notFound()` cannot reach the generic not-found under `loja/not-found.tsx`**
- **Found during:** Task 2
- **Issue:** The plan has `/loja` call `notFound()` when the store is off and also adds `loja/not-found.tsx`. A `notFound()` thrown from a page is caught by its own segment's `not-found.tsx`, so a store that is off would show the store's "Produto indisponível" card. UI-D-387 forbids that.
- **Fix:** Added `apps/web/app/(app)/loja/layout.tsx`, which checks `bootstrap.modules` and throws `notFound()` from the layout. The parent boundary catches it, and the parent has no not-found, so Next's default renders. The pages still map an API `MODULE_DISABLED` to `notFound()` for a flag flip between the bootstrap and the read.
- **Files modified:** apps/web/app/(app)/loja/layout.tsx (new, not in the plan's list)
- **Verification:** `store.spec.ts` UI-D-387 on both projects: rede-lab `/loja` and `/loja/{id}` show "could not be found" and never the store card.
- **Committed in:** a8de206

**2. [Rule 3 - Blocking] The seeded-module pins live in `modules.test.ts` and `platform-tenants.test.ts`, not in `bootstrap.test.ts`**
- **Found during:** Task 3 (verify 2 and the full regression)
- **Issue:** `bootstrap.test.ts` pins no module list. `modules.test.ts` case 1 (the bootstrap order) and case 9 (the platform list), and `platform-tenants.test.ts` case 4 (the tenant detail), pinned rede-demo without `store`.
- **Fix:** Case 1 now expects `store` first and checks its nav entry verbatim (topbar, no badge, order 5). Case 9 includes `store`. Case 4 expects `store` on for rede-demo. `bootstrap.test.ts` is unchanged.
- **Files modified:** apps/api/tests/integration/modules.test.ts, apps/api/tests/integration/platform-tenants.test.ts
- **Verification:** full `pnpm test:integration` 55 files / 1002 tests on a fresh reset and seed.
- **Committed in:** 5208f10

**3. [Rule 2 - Missing critical] Reactivate failure had no catalog copy**
- **Found during:** Task 2
- **Issue:** The Copywriting Contract has no line for a failed reactivate. The only form error says "Revise os campos", which does not fit.
- **Fix:** Added `store.errors.reactivate` with the `communities.errors.reactivate` wording ("Não foi possível reativar o produto. Tente novamente.").
- **Committed in:** a8de206

**4. [Rule 3 - Blocking] `page.tsx` had to call `getProducts(` itself**
- **Found during:** Task 2 acceptance
- **Issue:** The first draft wrapped the read in a `loadProducts` helper, so the acceptance grep (and the plan's key link) failed.
- **Fix:** The page calls `getProducts({ filter })` directly, with the redirect, `MODULE_DISABLED` and error handling inline. The helper was removed.
- **Committed in:** a8de206
