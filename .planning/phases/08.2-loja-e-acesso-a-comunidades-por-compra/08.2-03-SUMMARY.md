# Phase 08.2 Plan 03: The Feed Gate Summary

**The feed now hides every post of a locked community outside its own page (Início, Reels and the lanes). That page shows the newest post as a marked sample with a hidden-post count. Every like, comment, reply and thread call on locked content is refused: 403 `community_locked` on the sample, the bare 404 elsewhere. A shared link to a hidden post answers 403 with the community id. Two restrictive policies and two tenant-pinned definer lookups enforce the same rule in Postgres.**

## Accomplishments

- **Feed reads.** `listFeed` appends `NOT_LOCKED` when communities are on and keeps `community_id is null` when they are off (P75). One predicate covers Início and Reels "Todos". `listVideoCommunities` names no lane for a locked community. `listCommunityFeed` marks the sample `access: 'sample'` and adds `lockedCount = post_count - 1` only when an item exists. `getPost` marks the sample. On an RLS miss it asks `app.feed_locked_post_community` and answers 403 `{ access: 'community_locked', communityId }` or the bare 404.
- **Interactions.** `assertPostInteractive` runs one statement before any write. A post RLS hides gets the bare 404, and the sample gets 403 `{ access: 'community_locked' }`. It guards `likePost`, `unlikePost` and `createComment`, and replaces `listComments`' existing visibility check. `listReplies` checks the root inside its single statement. Comment likes, thread and delete needed no new code: the comment is invisible under RLS.
- **Postgres.** The generated migration adds restrictive `feed_comments_community_gate` (select; the `post_id is null` branch keeps story comments), restrictive `feed_likes_community_gate` (insert) and `feed_post_media_tenant_asset_idx`. The custom migration adds `app.feed_locked_post_community` and the feed body of `app.media_asset_hidden`. Both are SECURITY DEFINER, pin `tenant_id = app.tenant_id()`, and only `authenticated` can execute them.
- **Proof.** `store-gate.test.ts` has 17 cases (`feed reads`, `interactions`, `agreement`). pgTAP 180 section 7 adds 26 assertions (plan 72 → 98). New cases were added to `feed.test.ts` and `reels.test.ts`. The full pgTAP suite passes 1065/1065 and the full API integration suite 963/963 (55 files) on a fresh reset and seed.

## Decisions Made

- `listReplies` returns the bare 404 for any root the lane cannot see. RLS cannot separate "hidden by the gate" from unknown or foreign, so all three get the same answer and none can be used to probe. A removed root still returns the empty page, so the moderation suites did not change.
- The root check shares the page's statement (an `exists()` flag next to a lateral page, outer order `collate "C"` over the ISO text timestamps), so the replies budget stays at one statement.
- The guard runs before `unlikePost`'s delete. A like placed before the lock is never removed through the sample (P59).
- The sample keeps `likeCount` and `commentCount` (the CONTEXT discretion default). Only its comment rows are hidden.
- The suite's P62 fixture is a throwaway tenant with its own verified host (`sg-<run>-vazia.localhost`). The seed tenants have general posts, so "every post locked" cannot hold there.
- The fixture sample is a ready video post. This proves the sample is excluded from Reels "Todos" itself, not only from Início.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The `listReplies` 404 contradicted the isolation suite's "200-only" replies contract**
- **Found during:** Task 2
- **Issue:** The plan requires the bare 404 on a root comment of a locked post (truth 3, and the action's "a root hidden by RLS → bare 404"). `isolation.test.ts` pinned this route as 200-only: a foreign or unknown root got the byte-identical empty page. A hidden root, an unknown one and a foreign one look the same under RLS, so the plan's 404 makes all three 404.
- **Fix:** All three now return the same bare 404. A removed root still returns the empty page. The isolation case now asserts the bare 404 (code `NOT_FOUND`, no `details`) for the foreign root and for a random id, plus that no foreign reply text leaks. The route's OpenAPI description and service docblock record the change. There is still no existence oracle.
- **Files modified:** packages/modules/feed/server/service.ts, packages/modules/feed/server/routes.ts, apps/api/tests/integration/isolation.test.ts
