# Phase 08.2 Plan 09: The Locked Community UI Summary

**A member now sees "Exclusiva" on the cover of every community they have not bought, in colour and in its usual place in the list. Opening one shows its newest post read-only, up to three fading placeholders, the exact "+ N publicações exclusivas", and the way to the product ("Ver produto", or "Ver opções" with a sheet when several products open it). A shared link into a hidden post lands on that page with "A publicação que você abriu faz parte deste conteúdo exclusivo." If access is lost while a page is open, the next like or comment ends in a clear toast and a refresh into the locked view. Admins see the tags and the full community; support sees no tag.**

## Accomplishments

- **Module pieces (Task 1).** `PostCard` has a `readOnly` mode: no action row, plain left-aligned meta, no double-tap heart and no menu. Media, caption, attachments and link previews keep working. `CommunityCard` has a `coverBadge` slot on both cover branches, inside its one link. The store module UI adds `ExclusiveBadge`, `LockedSection`, `LockedCount`, `LockedPostPlaceholder` (static, 100/70/40 %) and `ProductChoiceSheet`. All of them are props-only and import no other module.
- **List and page (Task 2).** The store reads run only when `store` is on. They return `null` on any failure, and the page then degrades to fewer hints. `communityTagsView` encodes who sees what, and `lockedPageView` builds every decision and string of the locked page on the server. The list puts "Exclusiva" on the cover and "Produto arquivado" in the counts row. The page renders `LockedCommunity` when the access read says `locked`, never calls the highlights loader, and shows the sample through a static `CommunityPosts locked` column with no paging.
- **Share and mid-session lock (Task 3).** `loadPost` sends a hidden post (403 `community_locked`) and the sample itself to `/comunidades/{id}?exclusivo=1`. The feed view marks `access: 'sample'` as `readOnly` with no share URL. The feed actions return `community_locked`. The like engine, `FeedList` and `CommentsList` pass the code up. `FeedSurface`, `PostDetail` and `ReelsHost` revert, close the sheet, toast and refresh.
- **E2E.** `store.spec.ts` `locked community` has 9 cases per project, including `-g share` and `-g revoke`. The affected map now runs `store.spec.ts` for the feed-web, feed-module and communities groups.

## Decisions Made

- **Sketch finding 2 (the sample shows its relative time twice):** resolved by keeping the time in the read-only meta row. UI-D-374 lists it as a meta segment, E08 partial requires "only the relative time" at zero counts, and the approved drawing shows it. The shipped normal card already repeats the header's time in its meta row, so dropping it only on the sample would make the read-only card differ from a normal post for no reason. The design team's cheap alternative (omit it) is still one line in `PostCard` if they choose it.
- The sample also redirects from `/post/{id}`. The post page would otherwise show the card and then a comment list the API refuses with 403.
- P80: an archived community gets no store tag and no locked variant.
- `?exclusivo=1` moves above the count body when there is no top section (`LockedCount.extraLine`).
- `destaques/page.tsx` was left unchanged. A member never reaches it (the `stories.story.manage` check comes first), and the curator read already maps a 404 to `notFound()`.
- `registry.tsx` and the community page's unlocked feed host needed no edit: both render through `FeedSurface`, which now owns the reaction.
