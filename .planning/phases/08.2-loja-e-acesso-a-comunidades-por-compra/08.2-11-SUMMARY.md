# Phase 08.2 Plan 11: Compradores, Revoke and "Conceder acesso" Summary

**Admins now open `/loja/{id}/compradores` and see each product's active holders, newest first. Every row is tagged "Comprado" or "Concedido" and dated in the tenant's timezone. Each row has a named revoke control behind a danger confirm with the right body for its source. "Conceder acesso" opens a member search over active members, with a brand confirm before each grant. A grant adds a "Concedido" row at once, and a revoke locks the member out at once. Another community's membership id gets the member-gone toast and writes nothing.**

## Accomplishments

- **Admin client and rows (Task 1).** `lib/store-admin.ts` has `listBuyers`, `grantAccess` and `revokeAccess`. Each returns a discriminated outcome and never throws. A bare 404 is `gone` (or `not-found` for the list), and logs carry only the status and code. In `store-view.ts`, `buyerRowView` sets the name ("Membro removido" when the membership is gone), the stable avatar path, the meta line dated `dd/MM/yyyy` in the tenant's zone, the tag and its tone, and the revoke label. Tests pin the zone: the same instant reads 08/10 in São Paulo and 09/10 in Lisbon.
- **Compradores page (Task 1).** The page checks the permission before any read, then loads the product and the first buyers page in parallel. A missing product, a missing buyers page and a lost permission all render the store's not-found. `BuyersList` holds the toolbar, so the count follows revokes and grants. Rows use the `AttendeeRow` geometry, rebuilt here with no events import. The list has keyset paging, pull-to-refresh, the empty state, both error states and the revoke dialog with four bodies. Focus moves after the dialog has closed.
- **Grant sheet (Task 2).** `GrantAccessSheet` uses the shipped `BottomSheet`, a centred card from `md`, with `scroll="content"` and focus on the search field. The search is debounced 300 ms over `getAdminMembers({ q, status: 'active' })`. The sheet shows a hint, 4 skeletons while loading, result rows that truncate the name and e-mail, `InfiniteScroll` inside the sheet, a no-match state, and a search error with a retry. A brand confirm names the person before each grant. Answers older than the current query are dropped.
- **E2E (Task 2).** `store.spec.ts` has a new `buyers` describe, serial, with 7 cases per project. Its holders are throwaway members. One buys through the real purchase route. After a revoke that member gets the locked page and "Comprar". Another member, found by e-mail, is granted through the UI and then sees the full community. A second grant to that member gives the already-has-access toast. A rede-lab membership id is swapped into the grant request in flight and gets the member-gone toast. A 60-character name is checked at 320px. A member gets the not-found page.

## Decisions Made

See `key-decisions` in the frontmatter. The main ones:

- After a revoke, focus goes to the next row's control, or the previous row's when the last row left, and to "Conceder acesso" only when nothing is left. The plan names only the next row and "Conceder acesso". The previous row covers revoking the bottom row of a list that still has rows.
- An already-revoked 404 removes the row and lowers the count, because the holder no longer has access.
- The grant action formats the new row's date on the server, so the client never formats an instant (UI-D-386).
