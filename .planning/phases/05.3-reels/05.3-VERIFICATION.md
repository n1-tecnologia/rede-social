**Truth 6 evidence (full three-level check):**
- **Exists.** `ReelInteraction`, `withInteraction`, `viewOf`, `interactions`, `likeSeq`, `trackLike`, `onLikeTracked`/`onUnlikeTracked` and `bumpCommentCount` are in `ReelsHost.tsx`.
- **Substantive.** `trackLike` records `{ liked, likeCount }` from the server's `ok` answer to the post's latest request, whether or not its page is still mounted. It does not catch a rejection. The comment count is absolute: it starts from the shown count (`viewOf`) and adds the sheet's server-confirmed deltas.
- **Wired:**
  - `renderOverlay` passes `view={withInteraction(view, interactions[view.id])}` and the tracked wrappers.
  - The sheet's `onCountChange` calls `bumpCommentCount(sheetFor, delta)`.
  - `ReelOverlay` has no comment state of its own, and `ReelBinder` is now `{ likeOnly }`.
  - `useOptimisticLike` re-seeds when the seed props change (LikeButton.tsx lines 63-67), and a remounted engine starts from them.
- **Behavioural.** I ran `vitest run components/reels/ReelsHost.test.tsx -t "CR-01"`: 8 passed. The cases cover:
  - ±2 and back
  - a lane change and back
  - the same post in two lanes, both ways
  - the comment count never counted twice
  - a settle after unmount
  - latest-wins
  - a refused unlike on a remounted page
  - the visit scope

  The e6 browser step exists (`reels.spec.ts` lines 462-479: two drags away, page 0 holds no heart, two drags back, liked, `likeRequests === 1`). The executor reports it 2/2. I did not re-run it, because it needs `db:reset` and two servers.
- **Residual path (WR-04), reproduced by me.** The steps were:
  1. Like, then unlike quickly.
  2. The like answers `ok`.
  3. The unlike answers `{ ok: false }`.

  Then the mounted page read `liked`, which matches the server, but after ±2 and back it read `unliked` with an empty count.

  I rate this a warning, not a FAILED truth, for three reasons:
  - It needs a server refusal (5xx, 429 or a network error) on the second of two toggles sent within one request's latency. That is an error path, and it has already raised the generic toast (UI-D-93d).
  - No data is corrupted. On the stale page the heart and the double tap both send an idempotent like, which answers `liked` and corrects the display, so the viewer's input never does the opposite of what the screen shows.
  - Every success path, and the single-refusal path (CR-01 (f)), holds.

  The prior gap was the ordinary flow (like, keep scrolling, scroll back), and that flow is closed.
