<domain>
## Phase Boundary

A new **Reels** tab plays the tenant's video posts full-screen in a vertical pager: one video post per page, swipe up/down to change video, muted by default with a sound toggle, the author, a community chip and the caption at the bottom, and a right rail with the author's avatar, like (with count), comment (with count, opening the comment sheet) and share. It follows the design team's print (`.planning/phases/05.3-reels/reels-design.png`) and the prototype's `reference/frontend-design/app/(app)/reels/page.tsx` (index pager, not scroll-snap).

Reels is a new *view over the feed*, not new content:
- Every Reels page is an existing feed post whose `media_kind = 'video'`. D-53 guarantees a post carries either a gallery or one video, never both.
- Likes, comments and shares are the feed's own (FEED-04..07). A like in Reels shows on the same post in Início.
- In the MVP the videos are `admin_tenant` posts, visible to every member. Member videos (followers only) arrive with the "Rede social" module, which extends Reels in Phase 9. Nothing in this phase may assume they exist.

**Not in this phase:** posting from Reels (videos are still published through `/criar`), any change to how a feed card plays its video, recommendation/personalisation, admin edit/delete from inside Reels, and member-authored videos.

</domain>

<decisions>
## Implementation Decisions

### Lanes (the top row)
- **D-117:** **The print's lanes ("Para você / Resultados / Bastidores") become "Todos" plus one lane per community.** The first lane holds every video Reels can show. After it comes one lane per community, each holding that community's videos. A horizontal swipe changes lane and a vertical swipe changes video; the dominant axis decides, so one gesture never does both (the prototype's rule). Tapping a lane label also selects it. This uses data that already exists: the chip "Energia de Rainha" in the print is already a community. Admin-chosen tags were considered and rejected for the MVP because they need a new field in the composer and a per-tenant tag list.
- **D-118:** **The first lane is labelled "Todos"**, not "Para você". It is not personalised, and "Para você" would promise a recommendation that does not exist.
- **D-119:** **A community gets a lane only if it is active and has at least one ready video post.** Lanes follow the **Comunidades list order**: most recent post activity first (D-76). Archived communities never get a lane, and no lane is ever empty. When the `communities` module is off there are no community lanes (D-74 applies to "Todos" as well: only posts without a community).
- **D-120:** **When "Todos" is the only lane, the lane row is hidden.** The top shows only the sound button. This covers two cases: no community has a video, or the `communities` module is off. A lone lane is noise, not a choice.

### The tab and its module flag
- **D-121:** **Reels is its own feature module (`reels`), toggled per tenant by `super_admin` like Comunidades and Eventos (MOD-01, MOD-04, ROLE-04).** It requires `feed`: with `feed` off, Reels contributes nothing (no tab, no API access), whatever its own flag says. It reads posts through feed's published contract, never feed internals (MOD-02); how that query is exposed is a research/planning question (see Claude's Discretion). A tenant that never posts video can hide the tab. — **Reversibility:** costly — the new module key lands in the `tenant_modules_key_chk` check constraint through a migration, in the API and web registries and in the registry test lists; folding Reels back into `feed` later needs a second migration and every consumer of the key.
- **D-122:** **The module is on by default for new and existing tenants.** It is the same default as `feed`, and because Reels is in the MVP, the pilot gets it without a `super_admin` step. `super_admin` turns it off where it makes no sense.
- **D-123:** **The tab is called "Reels" with the print's film-reel icon, and it sits between Comunidades and Eventos**, the print's order. With every module on, the tabs read Início · Comunidades · Reels · Eventos · Perfil. Communities is `order: 20` and Phase 6 plans Eventos at `order: 40` (`06-01-PLAN.md` expects "any tab 05.3 added below 40"), so Reels takes an order between them. The label comes from the catalog (`reels.nav`, PWA-03). Navigation is driven by the module flag, never by data (D-40, D-77): with zero videos the tab stays and shows the empty state.
- **D-124:** **A feed video gets no path into Reels.** A video on Início keeps playing inside its card exactly as today, and Reels is reached only from its tab. Nothing in `PostMedia` or the feed's player changes in this phase.

### Playback
- **D-125:** **A video loops until the viewer swipes**, like Instagram Reels and TikTok. Moving on is always the viewer's choice; Reels never auto-advances (that is the stories behaviour, not this one).
- **D-126:** **Sound starts off, and once turned on it stays on for every later video and lane until the viewer leaves Reels.** Every new visit to the tab starts muted again, because iOS only lets a video start by itself when it is muted. This is the same rule as the story viewer, which starts `muted: true` for exactly this reason. The choice is not persisted across visits.
- **D-127:** **A single tap pauses and resumes.** While paused, a play icon sits in the centre. The sound button in the top corner is the only sound control.
- **D-128:** **A double tap likes the post**, with the heart overlay the feed's photos already use (`DoubleTapHeart` in `@tria/ui`). It only ever likes, never unlikes, and it writes the same like as the rail's heart. The known cost is accepted: the single-tap pause waits about 250 ms so the two gestures are not confused.

### The rail, the caption and desktop
- **D-129:** **The avatar and the author's name open the author's profile (D-52), and the community chip opens the community page (D-71).** These are the same destinations as the feed card. A video with no community shows no chip.
- **D-130:** **The rail gains the feed's share button, below comment.** It is the same share as the card: the native share sheet, or copy link on desktop, producing the FEED-07 internal deep link that opens the post after login. The print has no share button; it is added because the feed has three actions and a video is the most shareable content.
- **D-131:** **A long caption is clamped to 2 lines with "… mais".** A tap expands it over a darker veil without pausing the video, and another tap collapses it. Links in the caption stay clickable. This is the feed's `PostCaption` behaviour in a new container.
- **D-132:** **On desktop, Reels is a centred 9:16 column on a dark ground, and the desktop rail stays visible.** The lanes, the rail and the caption live inside the column. Changing video works through on-screen ↑/↓ buttons, the keyboard (↑/↓ change video, Space pauses, M toggles sound) and the mouse wheel.

### Carried forward (not re-asked)
- D-53: one post is one Reels page (gallery XOR video).
- D-73 / D-74: "Todos" shows exactly the videos Início shows: tenant-wide posts plus posts from visible communities, or only posts without a community when `communities` is off. Order is newest first (roadmap criterion 3).
- D-59 / D-62: comments open the feed's one `CommentSheet` in its threaded variant, with replies and comment likes (these are feed posts, not stories). The video pauses while the sheet is open, as the story viewer does (D-82).
- D-43 / D-44: playback goes through Mux with a signed policy and a short-lived per-request playback token.
- D-33: surfaces the prototype does not cover go through a UI-SPEC and mockup approval before they are coded. Here that means lanes as communities, the share button on the rail, the caption expansion, the empty state and the desktop column.
- The prototype hides the TopBar on `/reels` and floats the BottomNav over the video ("media" mode, PROTOTYPE.md). The print shows the same.

### Claude's Discretion
These were offered to the user as defaults and accepted without discussion. Downstream agents may refine them, but should not reverse them without asking.
- **Only `ready` videos appear.** A video post still transcoding or refused (feed allows publishing during transcode, D-53) is skipped. It appears once its transcode is ready.
- **Empty state:** with no video in any lane, Reels shows the ported `EmptyState` with pt-BR copy, and the tab stays (D-123). The copy comes from the UI-SPEC.
- **Changing lane starts at that lane's first (newest) video**, as the prototype does.
- **Where a returning viewer lands:** each visit starts at the top of "Todos". Resuming the last position is not required.
- **No admin "…" menu inside Reels.** Edit and delete stay on the feed card and the post page (FEED-03).
- **The position indicator** on the right edge (the print's dots) must work with a keyset-paged, open-ended list. A windowed indicator around the current page is fine, since a dot per item is not.
- **Paging and preloading:** keyset pages on the feed's existing cursor convention, with the neighbouring pages kept mounted (the prototype mounts ±1). Preloading the next video, including fetching its signed playback token ahead of time, is a research item ("Research needed: light", ROADMAP).
- **Where the video query lives** under MOD-02: a `mediaKind`/video filter on feed's published list contract (`feedPage` already takes an extra predicate) versus a Reels-owned route that calls feed's contract. The community-lane list (active communities with a ready video, in D-76 order) needs the same kind of decision across the `communities` contract.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `packages/modules/feed/server/service.ts`: `feedPage(ctx, query, extraPredicate)`, the keyset page builder behind `listFeed` (main feed) and `listCommunityFeed` (`and p.community_id = …`). A video filter is one more predicate over the same `(created_at, id)` cursor.
- `packages/modules/feed/db/schema.ts`: `feed_posts.media_kind` (`'none' | 'gallery' | 'video'`, a check constraint plus `unique (id, media_kind)`). Video readiness rides on the media payload's `status` (`packages/modules/feed/contracts/index.ts`, `MEDIA_STATUSES`).
- `packages/modules/feed/ui/`: `CommentSheet` / `CommentsList` (the comment surface, threaded variant), `LikeButton`, `PostCaption` (the "… mais" clamp), `sharePost.ts` (native share / copy link), `PostHeader` (author → `profileHref`, community label → `community.href`).
- `packages/ui/src/overlays/DoubleTapHeart.tsx`: the double-tap heart overlay the feed's `PostMedia` and the story viewer already use.
- `apps/web/components/media/VideoPlayer.tsx`: the app-scoped Mux player. It binds the per-request playback token server action (D-44) and is injected into module UI as an element, because a module may not import `apps/web` (see the `PostMedia` docblock).
- `apps/web/components/stories/StoryVideo.tsx` and `packages/modules/stories/ui/StoryViewer.tsx`: the existing full-screen video surface. It shows the muted start (`useState(true)`), the sound toggle, the autoplay-blocked check (`autoplayCheckMs`) and per-segment play binding. These are the closest patterns for Reels' playback and the iOS autoplay pitfall.
- `packages/modules/communities/server/service.ts`: `listCommunities` (the D-76 activity order the lanes follow).

### Established Patterns
- **Module manifest** (`packages/core/server/modules/manifest.ts`): `defineModule({ key, nav: { placement: 'tab', label, icon, href, order }, routes, events })`. Communities registers `order: 20`, and the kernel adds Início first and Perfil last. The label is overridden by the web catalog's `<key>.nav`.
- **Module flags** live in `tenant_modules` (`packages/core/db/schema/tenant-modules.ts`). The `tenant_modules_key_chk` constraint enumerates the allowed keys, so a new module needs a migration that widens it, plus seeding/defaulting rows for existing tenants (D-122).
- **Registries**: `apps/api/src/modules/registry.ts` (sorted keys, mirrored in `apps/api/tests/unit/registry.test.ts`) and `apps/web/lib/registry.tsx` (the web composition point).
- **Every API refusal is a stable machine code** (D-09). Keyset cursors are opaque base64url `{v,n,id}`, `limit` is clamped server-side and pages over-fetch `limit+1` (STATE 03-03).
- **Module packages ship no language**: every label arrives as a prop from the host's pt-BR catalog (PWA-03). `scripts/check-ui-literals.sh` enforces it.
- **Migrations**: Drizzle schema → `drizzle-kit generate` → `supabase/migrations` → Supabase CLI applies. Every new table gets RLS plus pgTAP cross-tenant negatives.

### Integration Points
- A new `packages/modules/reels` package (manifest, contracts, server, ui) registered in both registries. It depends on `feed`'s and `communities`' published contracts only.
- A `/reels` route under `apps/web/app/(app)/` that hides the TopBar and floats the BottomNav over the video. It renders a centred 9:16 column on desktop (D-132).
- A module-flag migration: widen `tenant_modules_key_chk` with `'reels'` and enable it for every existing tenant. Seeds enable it for both seed tenants.
- The `feed` → `reels` dependency: with `feed` off, the `reels` routes and nav must contribute nothing.

</code_context>

<specifics>
## Specific Ideas

- Start from the print and the prototype page, as for every prototype-covered surface. The prototype is the source for the pager, gestures, veils and rail layout, and it is ported, not refactored in place.
- The chip in the print ("Energia de Rainha") is a community. That is why lanes and chips both come from communities (D-117, D-129).
- The user framed Reels as "a new tab that filters the feed to video". Reels adds a view, not a content type.

</specifics>

<deferred>
## Deferred Ideas

- **Admin-defined lanes/tags** (the prototype's "Resultados / Bastidores" as tags chosen at posting time): rejected for the MVP in favour of community lanes (D-117). Revisit if the pilot admin asks for content categories that cut across communities.
- **Personalised "Para você" ordering**: a recommendation feed. It needs signals V1 does not collect.
- **Opening a feed video in Reels** (a full-screen button on the card that lands on that video): declined for this phase (D-124).
- **Member videos in Reels, visible to followers**: Phase 9, "Rede social" (roadmap criterion 3).
- **Remembering the sound choice across visits**: declined (D-126), because the browser may block autoplay with sound on the next visit.

</deferred>
