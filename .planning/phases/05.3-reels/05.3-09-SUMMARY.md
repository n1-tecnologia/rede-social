## Decisions Made

- **Which `AbortError` to retry.** Only one that arrives while the host has not paused the page. That is exactly the case of a source load interrupting the play. A swipe, a tap or the sheet pause first, so their aborts stay final. The retry uses the element's current mute state, so a `setMuted` in between is kept. It is bounded at two, because the vendor sets its source twice on mount.
- **Failing an action in e2e.** Answer it with a 500. With `experimental.useOffline` on, Next 16.3 probes `HEAD /reels?_rsc` and re-sends an action that failed at the network, so an aborted action never rejects. Whether Reels should also surface its errors during a long real network loss is left to verification (`deferred-items.md`).
- **Requirements.** See Next Phase Readiness.
