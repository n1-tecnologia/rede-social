# Phase 05.3 Plan 07: Reels Playback and Data Summary

**`ReelVideo` is the full-bleed Mux element for Reels. It has no vendor chrome, starts muted, loops and fits by aspect ratio, and ignores stored mute preferences. It hands the host a controller the pager's gesture calls synchronously, and it reports sound refusals, blocked autoplay and errors upward. `mintReelPlaybackAction` mints up to three playback credentials in parallel inside one server action. `loadReelsPageAction` serves pages of Reels through `getFeed({ media: 'video' })`, mapped by `reelView` on top of the feed card's own `postCardView`.**

## Accomplishments

- **`ReelVideo` (REELS-06, D-125, D-126, UI-D-83, UI-D-85, UI-D-86).**
  - It uses `StoryVideo`'s bridge: `next/dynamic` with `ssr: false`, and a `MutationObserver` that attaches to the late-mounted `mux-player` and reconciles once immediately.
  - Props on `<MuxPlayer>`: `loop`, `nohotkeys`, `noMutedPref`, `noVolumePref`, `muted`, `playsInline` and `streamType="on-demand"`. There is no `autoPlay` and no `className`. `preload` is `auto` for the current page and `metadata` for a neighbour, and the style carries `--controls: none` and `--media-object-fit`.
  - `reelFit` returns `cover` when `width / height ≤ 0.8` (the boundary counts as cover). It returns `contain` when the video is wider or a dimension is null or not positive.
  - The controller is handed over through `onController(postId, controller)` on attach, and `null` on detach or unmount:
    - `start` rewinds, applies the sound state and plays.
    - `resume` does the same without the rewind.
    - `pause` pauses.
    - `setMuted` sets the flag.
  - Refusals follow RESEARCH Pattern 4:
    - `AbortError` is ignored.
    - A `NotAllowedError` with sound mutes the element, reports `onSoundRefused` and plays again. It reports `onBlocked` only if that retry also fails, and ignores an `AbortError` on the retry.
    - Any other rejection reports `onBlocked`.
  - The 400 ms autoplay check runs after `canplay` on the current page. A `playing` event clears it, and a neighbour or a host-paused page never arms it.
  - `error`, `waiting` and `playing` are forwarded with the post id. The element renders no text of its own.
  - A derived poster that fails to load is replaced with `poster=""`, so no broken-image glyph is drawn. With the fake provider nothing is probed and the frame is black.
- **`getFeed`'s `media` (REELS-03 web half).** `FeedQueryInput.media?: 'video'` is forwarded as `media=video`. Nothing else in `lib/feed.ts` changed.
- **`lib/reels.ts`.**
  - `reelView` is built on `postCardView`. It supplies the author link, counts, liked state and the FEED-07 `shareUrl`, which is null without a verified primary host. It adds the community chip and the first `ready` video, and returns null when the post has no ready video.
  - `loadReelsPage` calls the one feed fetch with `media: 'video'`, `REELS_PAGE_SIZE`, the lane and the opaque cursor. It follows `loadFeed`'s error rule: the redirect happens outside the catch, and any other failure is `null` with a content-free log line.
  - `getVideoCommunities` reads the lanes, and `loadVideoCommunities` returns `[]` on any failure other than a navigation.
- **`announcedCount`.** It formats the count in standard notation and picks the plural with `Intl.PluralRules` on the original count, so 8000 becomes "8.000 curtidas" and zero is null. It lives in the client-safe `lib/reels-count.ts` and is re-exported from `lib/reels.ts`.
- **`reels-actions.ts` (`'use server'`).**
  - `mintReelPlaybackAction`:
    - Input is `z.array(z.uuid()).min(1).max(REELS_MINT_MAX_IDS)`.
    - It runs `Promise.allSettled` over `getPlaybackTokens` inside the one action and answers per asset.
    - A 409 becomes `notReady`.
    - A bootstrap refusal is remembered and redirected to once, after everything has settled.
    - Anything else is `generic`, logged with `{ assetId }` only.
  - `loadReelsPageAction` guards the lane with `z.uuid().nullable()` and the cursor with `z.string().max(512).nullable()`.
  - Neither file contains a caching directive. Likes and comments are not re-exported (the Turbopack rule).

## Decisions Made

- **`announcedCount` has a client-safe home.** See deviation 2.
- **When the autoplay check runs.** It arms after `canplay` on the current page, unless the host paused the page or it has already played since the last start. `start` and `resume` also arm it once `canplay` has been seen, so a neighbour that buffered before it became current is still checked for the Low Power Mode pending-`play()` case.
- **The chip.** The name comes from the post; the href and the accessible name come from `postCardView`'s own community mapping, so the card and the Reel cannot drift.
- **Logs carry shapes only.** `lib/reels.ts` logs a status and code, or an error name, rather than `String(error)`. The mint logs `{ assetId }`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] A failed derived poster is dropped (UI E04 empty)**
- **Found during:** Task 1.
- **Issue:** The plan's truth says the frame is "never a broken-image glyph". media-chrome's `media-poster-image` has no error handling (checked in media-chrome@4.19.2 `dist/media-poster-image.js`). A real Mux thumbnail that fails to load would therefore draw a broken image over the black frame.
- **Fix:** At attach, a poster URL derived by the element is probed once with `new Image()`. On an error, `poster=""` is passed, which the player reads as "no poster" (the verified VideoPlayer case 3). With the fake provider no URL is derived and nothing is probed.
- **Files modified:** `apps/web/components/reels/ReelVideo.tsx`, `apps/web/components/reels/ReelVideo.test.tsx` (two cases).
- **Verification:** The two poster cases pass.
- **Committed in:** 8441fe6 (tests), 8fc913e (implementation).

**2. [Rule 3 - Blocking for plan 08] `announcedCount` in a client-safe module**
- **Found during:** Task 2.
- **Issue:** Plan 08's `ReelOverlay` is a `'use client'` component that calls `announcedCount`. `lib/reels.ts` imports `lib/api`, which reaches `next/headers` and the Supabase server client. A client component importing a value from it would break the build.
- **Fix:** `announcedCount` lives in the new `apps/web/lib/reels-count.ts`, which has no server imports. `lib/reels.ts` re-exports it, so the planned export surface holds. Client code should import it from `@/lib/reels-count`.
- **Files modified:** `apps/web/lib/reels-count.ts` (new), `apps/web/lib/reels.ts`.
- **Verification:** The four `announcedCount` cases pass through the `lib/reels` re-export, and typecheck is green.
- **Committed in:** b0dada3.
