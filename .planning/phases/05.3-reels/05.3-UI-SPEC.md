# Phase 05.3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this phase is.** A new **Reels** tab plays the tenant's ready video posts full-screen in a vertical index pager: one post per page, swipe up/down to change video, swipe left/right (or tap a label) to change lane, muted by default, a right rail with avatar, like, comment and share, and the author, community chip and caption at the bottom (05.3-CONTEXT §Phase Boundary). Reels is a *view over the feed*: every page is an existing feed post, and likes, comments and shares are the feed's own. The design language, spacing scale, type scale, colour model and catalog conventions are **inherited unchanged** from the approved `02`/`04`/`05`/`05.1`/`05.2-UI-SPEC.md`. This document restates them for the checker and records only the 05.3 deltas.

**Sources.** The visual source is the design team's print `.planning/phases/05.3-reels/reels-design.png`. The interaction source is the prototype page `reference/frontend-design/app/(app)/reels/page.tsx`, which is ported, not refactored in place. Values taken verbatim from the prototype are marked **[proto]**. Values taken from the print are marked **[print]**.

**Upstream decisions.** `05.3-CONTEXT.md` decisions are cited as **D-117..D-132** and are not re-litigated. Carried decisions: D-33, D-40, D-43/D-44, D-52, D-53, D-59/D-62, D-71, D-73/D-74, D-76, D-77, D-82. Earlier visual decisions are cited as **UI-D-07..UI-D-80**. Questions CONTEXT left to Claude that are purely visual or interaction questions are decided here as **UI-D-81..UI-D-99**, continuing the numbering as CONTEXT instructs. Phase 6 owns UI-D-200+.

**One deliberate reading of CONTEXT.** D-128 says the single-tap pause waits "about 250 ms". This contract uses the **shipped `DOUBLE_TAP_WINDOW_MS = 300`** from `DoubleTapHeart`, so the product has one double-tap window, not two (UI-D-86). The difference is 50 ms, and the value is one constant if the user wants 250.

**Design review (Phase 2 D-33).** The pager, the veils, the rail's avatar/like/comment, the sound button, the position ticks and the floating BottomNav are **[proto]/[print]**. These surfaces are prototype-less and **must be rendered in a `/gsd-sketch 05.3` package and reviewed with the design team before the UI waves are coded**:
1. the lane row with "Todos" plus community lanes, including the overflowing case (6+ lanes) and the hidden-row case (D-120);
2. the rail with the added share button (D-130);
3. the caption collapsed with "… mais" and expanded over the darker veil (D-131);
4. the paused state and the autoplay-blocked state (UI-D-86);
5. the empty state and the load-error state (UI-D-93/94);
6. the desktop 9:16 column with the ↑/↓ buttons beside it (D-132).

The planner puts that review behind a `checkpoint:human-verify` before the first UI plan, as in 05.2.

## Interaction & Accessibility

- **Links for routes, buttons for actions:** author name, avatar and community chip are `<Link>`s. Lanes (`role="tab"`), sound, play/pause, like, comment, share, "mais"/"menos", retry and desktop ↑/↓ are `<button>`s. The caption paragraph's own tap handler ignores clicks that originate on an `<a>`.
- **Accessible names are catalog strings.** The like count is announced through `LikeButton`'s shipped polite region, and the drawn compact number is `aria-hidden`. The lane state is `aria-selected`. The sound state is carried in the name, not only in the icon.
- **Gestures always have a non-gesture equivalent:** swipe ↕ ↔ desktop ↑/↓ buttons plus arrow keys; swipe ↔ ↔ lane tabs plus ←/→ inside the tablist; tap-to-pause ↔ the pause control plus Space; double-tap like ↔ the rail heart.
- **Focus:** opening the comment sheet moves focus into it and closing returns it to the rail's comment button (BottomSheet). A page change keeps focus on the control that caused it (↑/↓ button, tab), or on the stage when it came from a swipe. Neighbour pages are `inert`, so Tab never reaches an off-screen rail.
- **Motion:** all component motion imports `motion/react`. Reduced motion per UI-D-97. Autoplay and loop are unaffected.
- **Permissions in the web tier:** only the empty-state CTA reads `bootstrap.permissions.includes('feed.post.create')`. No role comparison. The tab and route read the enabled modules (`reels` and `feed`), and the API re-enforces every read and write.
- **No `Date.now()` in render** (UI-D-14). Reels shows no timestamps at all, as in the print.
- **No `dangerouslySetInnerHTML`:** the caption is plain text through the shared `linkify` (D-54).
