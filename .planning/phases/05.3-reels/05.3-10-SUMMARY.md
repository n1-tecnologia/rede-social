# Phase 05.3 Plan 10: CR-01 Gap Closure and the WR-01..03 Ride-Along Summary

**A like or a comment made in Reels now holds for the whole visit. `ReelsHost` owns each post's settled like pair and absolute comment count, keyed by post id, and seeds every page from them, so a page that leaves the ±1 window and comes back, a lane change, and the same post in two lanes all show one state. The heart and the double tap act on that state. The three review warnings are closed, each with a regression that failed first: a desktop drag released over the rail or the caption now ends (WR-01), a re-minted credential remounts the player instead of freezing it (WR-02), and `$` patterns in a display name are announced literally (WR-03).**

## Accomplishments

- **CR-01, the like (Task 1, the tracer).**
  - `ReelsHost` holds `interactions: Record<postId, { like?, commentCount? }>` for the visit.
  - `trackLike` wraps the feed's like and unlike actions. Only an `ok` answer to the post's latest request (`likeSeq`) is recorded, including one that lands after its page unmounted. A refusal records nothing, and rejections still reach the page's engine, which reverts.
  - `renderOverlay` seeds each page with `withInteraction(view, interactions[view.id])`. A post nobody touched gets the same `view` object back.
- **CR-01, the comment count and the matrix (Task 2).**
  - `bumpCommentCount(postId, delta)` writes an absolute count, starting from the count the viewer was shown (`viewOf`: the active lane, else any loaded lane).
  - The sheet's `onCountChange` goes to the host. `ReelOverlay` lost its `commentDelta`, and `ReelBinder` is now `{ likeOnly }`.
  - Seven more cases pin the lanes, the shared post in both directions, settle-after-unmount, latest-wins, a refused unlike on a remounted page, and the visit scope (with a `Storage.prototype.setItem` spy).
- **WR-01.** The stack now uses `onPointerUpCapture` and `onPointerCancelCapture`. This is React's capture phase, not DOM pointer capture, so `DoubleTapHeart` still sees every `pointerup`. The existing tap and double-tap cases pass unchanged.
- **WR-02.** `<MuxPlayer key={playback.tokens.playback}>`. The host test's `ReelVideo` stand-in is now keyed on the token the same way (one controller per credential, plus `data-token`).
- **WR-03.** `labels.position.replace('{current}', () => …).replace('{author}', () => current.authorName)`.
- **e6 in a real browser.** After the like, two upward drags reach video 3, where page 0 holds no heart. Dragging back, page 0 reads `liked` as a neighbour on video 2 and as the current page on video 1. Exactly one like request was sent, and Início still reads liked.
