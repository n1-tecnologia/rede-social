### Auto-fixed Issues

**1. [Rule 1 - Bug] The README's paste-in example could have opened the gate before approval**
- **Found during:** Task 2 (register sketch 005 and write the README)
- **Issue:** The first draft of the README showed the approval lines to paste inside a code block. That included a bare `approved: true` at column 0. The `^approved: true` precondition in plans 05-08 (7 preconditions) would have matched it and released the UI tasks while the frontmatter still read `approved: false`.
- **Fix:** Rewrote the example as a bulleted list with backticks and added a note explaining why (README around line 210).
- **Files modified:** `.planning/sketches/005-phase-05.3-designed-screens/README.md`
- **Verification:** With the approval in place, `grep -c '^approved: true'` on the README prints 1, and the match is frontmatter line 30.
- **Committed in:** `1c9be14` (Task 2 commit)

### Process deviations

**2. [Plan must-have / T-05.3-11] The approval lines were written by the orchestrator, not pasted by the user**
- **Plan text:** "The approval write is the USER's … the executor only verifies them with grep and commits the user's edit." T-05.3-11 mitigates self-approval by having the user write the lines.
- **What happened:** The developer explicitly delegated the edit in chat ("pode alterar vc mesmo"). The orchestrator made the edit, and the executor verified it and committed it unchanged. No executor wrote any approval line.
- **Why it is recorded:** Under the plan's text and the project memory ("gate approvals need the user's hand"), the approval is supposed to be the developer's own edit. Here the authority is a delegation relayed by the orchestrator. The developer should confirm it at `/gsd-verify-work 05.3` (coverage D3 is `human_judgment: true` for this reason). To revoke it, revert `d65b7c7` and `fe7026c`. The gated UI tasks then halt on their preconditions again.
- **Commits:** `d65b7c7`, `fe7026c`

**3. [Measurement] `commits` counted by scope, not with a plain rev-list**
- Plan 05.3-01's seven commits (`9cb12ae`..`c0735f3`) landed on `master` between this plan's Task 2 and Task 3. `git rev-list --count ab9a420..HEAD` would therefore give 11. The frontmatter uses the 4 commits scoped `(05.3-04)` from `git log --oneline ab9a420..HEAD --grep='(05.3-04)'`.
