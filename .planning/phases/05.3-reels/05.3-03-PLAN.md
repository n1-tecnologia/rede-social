<objective>
The shell gets out of the way on Reels, declared by the module and never hard-coded in the kernel.

The prototype and the print hide the TopBar on the video surface and float the BottomNav as a dark
glass pill over it. The kernel learns one generic rule — a tab whose nav entry declares
`chrome: 'media'` hides the mobile TopBar and darkens the BottomNav while it is active — so the
kernel never names a module's route (MOD-02). The same plan updates every e2e pin that counts the
nav or the module switches, because the Reels tab appears the moment plan 01's registry entry
reaches the bootstrap.

This surface is prototype-covered ([proto]/[print]: PROTOTYPE.md's `/reels` row), so it does not
wait for the D-33 review of plan 04.

Purpose: the media chrome every Reels screen sits in, and a green e2e baseline with the new tab.
Output: `NavItem.chrome`, TopBar/BottomNav/AppShell changes with unit cases, and six e2e specs
updated for the seventh key.
</objective>
