| **Estimated runtime** | Quick tier: seconds per package. API integration: seconds after reset and seed. Full suite: several minutes, mostly e2e (the same tiers as 05.2) |

**Plan-file rule:** `<automated>` commands inside PLAN.md XML-escape `&&` as `&amp;&amp;`.

**Video-provider rule (hard):** no validation command may depend on real Mux or a tunnel. Playwright runs are prefixed `VIDEO_PROVIDER=fake`. The fake provider cannot stream and produces no poster, so e2e proves structure, pager, lanes, like parity, the comment sheet and the error states, not real playback (RESEARCH Pitfall 9).

**Seed rule:** Reels e2e creates its video posts per spec through a new `createVideoPostAs` helper with a caption-prefix teardown. The seed is not changed, because that would shift the pinned feed total of 33 (RESEARCH Pitfall 8).

**Disk rule:** the data volume is about 96% full. Every build and gate runs with `TURBO_CACHE=local:r`; check `df -h /System/Volumes/Data` before long e2e runs.

## Sampling Rate

- **After every task commit:** Run the quick run command for the touched package, plus `pnpm boundaries` when a `package.json` changes
- **After every plan wave:** Run the full suite command (with `TURBO_CACHE=local:r`)
- **Before `/gsd-verify-work`:** Full suite green, plus the unchanged-seed feed specs (`feed.spec.ts`, `feed-media.spec.ts`, `comunidades.spec.ts`) to prove no count drift
- **Max feedback latency:** 10 seconds (quick tier)
