# Phase 12.4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** The support chat stops being one endless thread per member and becomes a numbered **case** ("chamado") with a state, an owner, a subject, a category and a priority (D-800..D-815). This document contracts only what is new or changes on screen:

1. **Member, the case in the thread:** the case bar ("Chamado #42" and its state), the **first-message opener** (category chips with `Outro` preselected and the optional subject), the lifecycle inside the thread (first-send confirmation, the `Resolvido` notice, the reply that reopens, the `Fechado` read-only state, live changes) (UI-D-818..UI-D-820).
2. **Member, "Meus chamados":** the list (newest first), the read-only past case, the bell row "Seu chamado #N foi resolvido" and its push (UI-D-821, UI-D-822).
3. **Staff, the inbox:** the three tabs, the filters by owner and priority, the "Aguardando resposta" toggle, the new four-fact-plus row (UI-D-823, UI-D-824).
4. **Staff, the case in the thread:** the case bar, the action matrix per state, the action sheet, the confirm dialogs, the assign and edit sheets, the composer rules, the details sheet with the case history and the member's earlier cases (UI-D-825..UI-D-829).
5. **Realtime and staleness** on every surface (UI-D-830).
6. **Owner's panel:** the "Atendimentos por assunto" card by category and the per-case wording of the "aguardando resposta" cards (UI-D-831).
7. Loading, empty, error, accessibility, catalogs and trust rules (UI-D-832..UI-D-835).

Everything else is **reused unchanged** from `07-UI-SPEC.md` and sketch 007: the member thread header ("Equipe {tenant}", D-222), the bubbles with the staff first name above them, day separators, the gapless message list, the composer (one field, send button, 2.000 characters), the inbox row's avatar and name, the blocked and removed read-only notices, the split card `288px | 1fr` from `lg`, the dot and number badges (D-237, D-238), the top-bar slot and the not-found screen. **Direct messages between members (Phase 11) are not touched.**

**Design authority.** The design team's prototype (`reference/frontend-design/app/(app)/suporte/*`, `types/support.ts`, `lib/support.ts`) is the source of the **look and the copy**; its **model is overridden** by CONTEXT, so these prototype parts are **not ported**: the "Ajuda" hub and its FAQ, the `/suporte/novo` full-page form, protocol codes (`IGA-4F2C81`) in favour of `#42`, the member-picked priority, the attachments (button, strip, lightbox, hint), the event picker, the statuses `em_analise` and `respondido` (replaced by the four states of D-805), "Marcar como resolvido" as a **member** action (it becomes a **team** action). Therefore:

- **[ported]** from the prototype: the "Meus chamados" cards ("Suas conversas" / "Concluídas" split, the `Você:` / `Equipe:` preview prefix), the case summary block, the "Conversa iniciada!" confirmation row, the "Marcar como resolvido" confirm dialog (now the team's "Resolver" and "Fechar"), the category names, the "Sobre o que é?" and "Assunto" labels, the "Resuma em uma frase" placeholder.
- **[reused]** shipped here: `ThreadHeader`, `MessageList`, `ChatComposer`, `InboxRow` (extended), `Tabs`, `Chip`, `StatusPill`, `ConfirmDialog`, `BottomSheet`, `Button`, `IconButton`, `Input`, `Textarea`, `EmptyState`, `Skeleton`, `PullToRefresh`, `InfiniteScroll`, `useToast`, the dashboard's `Collapsible` and `BarList`.
- **[designed]** (no prototype counterpart): the case bars, the opener, the staff tabs and filters, the action sheet, the assign and edit sheets, the details sheet, the "Meus chamados" read-only closing strip, the owner's category card. They are drawn from primitives that already ship.

The design language, spacing scale, typography scale and colour model are **inherited unchanged** from `02` to `10.2-UI-SPEC.md`. This document restates what the checker needs and records only the Phase 12.4 deltas. **Phase 12.4 adds no token, font, size, weight, library or dependency.**

## Server view-model the UI needs

The UI reads **finished facts** and never computes access or transitions. The planner names the fields; the host maps them to strings in `chat-view.ts`. Every key is on the strict chat contracts.

## Motion & Accessibility

- **No new motion.** State changes re-render in place; the shipped sheet and dialog springs honour `prefers-reduced-motion`. No flip, slide, pulse or progress animation exists for a case (UI-D-830).
- **State changes are polite, never assertive**, and only when they arrive while the page is open: one persistent visually hidden `aria-live="polite"` region per thread speaks the resolved, closed, reopened and taken sentences (UI-D-833). The resolved and closed strips are `role="status"`.
- **Stable names.** The case bar's reading unit is "Chamado #42, {state}"; the inbox row keeps the member's name plus the ", aguardando resposta" suffix; chips are `aria-pressed` buttons in a named group; tabs are the shipped roving-tabindex tablist.
- **Focus.** A closed dialog or sheet returns focus to its opener; a live change moves no focus; a failed send keeps focus in the composer.
- **Touch.** Every new control is 44px (`hitArea`, `h-11`, `min-h-11`); sheet rows are `min-h-12`.
- **Text safety.** Subject, member, staff and tenant names and every string are React text nodes; no HTML sink.
