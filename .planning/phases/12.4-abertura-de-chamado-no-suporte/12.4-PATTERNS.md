## Pattern Assignments

### Database layer

**`<ts>_chat_cases_functions.sql` — definers** (analog `20261105152916_reports_blocks_functions.sql`)
Header convention (lines 1-25): explain WHY DEFINER, SQLSTATE list, tenant pin in every statement. Statement form (lines 60-100):
```sql
create or replace function app.member_block_create(p_blocked uuid)
returns boolean
language plpgsql volatile security definer set search_path = '' as $$
declare v_t uuid := app.tenant_id(); v_u uuid := app.user_id();
begin
  if v_t is null or v_u is null then
    raise exception 'member_block_create: refused' using errcode = '42501';
  end if;
  ...
  raise exception 'member_block_create: invalid target' using errcode = 'BL001';
end $$;
--> statement-breakpoint
revoke all on function app.member_block_create(uuid) from public;--> statement-breakpoint
grant execute on function app.member_block_create(uuid) to authenticated;--> statement-breakpoint
```
Apply to `app.chat_case_act` / `app.chat_case_edit`: claims check, live-staff check (`memberships status='active', blocked_at is null, deleted_at is null`), role literal `app.tenant_role() in ('admin_tenant','support_tenant')` (assign: `= 'admin_tenant'`), `select ... for update`, custom SQLSTATEs `CS001..CS005` (CS unused in repo).

**Message trigger replacement** (analog `20260930190229_chat_functions.sql:54-76`): keep name/signature `app.chat_messages_before_insert()`, `create or replace`; trigger binding `chat_messages_seq_trg` stays. Keep the raise shape:
```sql
raise exception using errcode = '23503', constraint = 'chat_messages_conversation_visible',
                      message = 'conversation_not_found';
```
Add `select ... for update` of `(state, owner_user_id)` before the UPDATE; raise `CS004` on closed. The AFTER INSERT half (lines ~78+, `realtime.send(v_signal, 'chat.message', 'tenant:' || ... || ':conv:' || ...)`) is the pattern for the new `chat.case` signals (ids only).

**Sweep function** (analog `20260930142352_notifications_prune.sql:22,41`): `create or replace function app.notifications_prune(p_batch int)` and `revoke all on function app.notifications_prune(int) from public, authenticated;`. Copy for `app.chat_cases_auto_close(p_batch int) returns int`; document the non-tenant-first `(resolved_at)` index as the same documented exception. Name must match `^[a-z_]+$`. Register: `sweepFunctions: ['chat_cases_auto_close']` in chat `module.ts` (as `payments/module.ts:37`).

**Backfill** (analog `20261109191045_store_categories_backfill.sql`): functions file defines `app.chat_cases_backfill(p_tenant uuid default null)`, activation file only calls it; add NOT VALID CHECKs, then validate after backfill, in one file.

**Schema** (analog `schema.ts:74-125`): `uniqueIndex('chat_conversations_one_support_per_member').on(t.tenantId, t.createdByUserId).where(sql\`kind = 'support'\`)` is replaced by a partial unique index `where kind = 'support' and state in ('open','in_progress','resolved')`; `on conflict` in the service must restate that predicate. Keep `chat_conversations_staff_update` and the grant file `20261001004638_chat_rls_grants.sql:20-21` untouched (no column grant). New tables: RLS on, `chat_case_counters` no policy, `chat_case_events` staff SELECT only plus `revoke update, delete, truncate ... from authenticated`. Extend insert policy from `20261001004630_chat_rls_per_command.sql:5`.

## Shared Patterns

- **Definer hardening:** `security definer set search_path = ''`, fully qualified names, `revoke all ... from public`, `grant execute ... to authenticated` only for callables, none for trigger functions (source: reports_blocks_functions header).
- **Tenant pin + live predicate:** every statement restates `tenant_id = app.tenant_id()`; callers must be `active`, unblocked, undeleted.
- **Realtime signals:** `realtime.send(jsonb_build_object('conversationId', id), '<event>', 'tenant:<t>:conv:<id>' | ':support-inbox', true)`; ids only.
- **Closed contracts:** `.strict()`; new response keys optional so the new web tolerates the old API.
- **Expand-only migrations**, applied locally with `pnpm supabase migration up` only.
