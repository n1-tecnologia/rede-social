## Um chamado ou vários por membro

### Q1. When a case is closed and the same member writes again, what happens?

| Option | Description | Selected |
|--------|-------------|----------|
| Opens a new case (Recomendado) | Each service has its own number, start and end; the member gets a list of their cases; replaces the one-per-member index and the dashboard calculation; about 15 to 18 plans | ✓ |

| Você decide | Claude chooses and records why | |

### Q2. What does the member see when tapping the support bubble?

| Option | Description | Selected |

### Q3. Can the same member have two active (not closed) cases at once?

## Estados, responsável e reabertura

### Q1. Which states does a case have?

| Option | Description | Selected |
|--------|-------------|----------|
| Four: Aberto, Em atendimento, Resolvido, Fechado (Recomendado) | Resolved still lets the member answer; Closed is final and the next message opens another case | ✓ |
| Three: Aberto, Em atendimento, Fechado | No Resolvido step; the team closes directly | |
| Você decide | Claude chooses and records why | |

**User's choice:** Four states.

### Q2. Who can take and assign a case?

| Option | Description | Selected |
|--------|-------------|----------|
| Any agent takes; only the admin assigns to another (Recomendado) | support_tenant and admin_tenant take for themselves; only admin_tenant reassigns; anyone on the staff can still reply (keeps the reply half of D-225) | ✓ |
| Any agent takes and assigns to anyone | No difference between roles | |
| Only take, no assigning to another person | Simplest; a case stuck with someone on leave stays stuck | |
| Você decide | Claude chooses and records why | |

**User's choice:** Any agent takes; only the admin assigns to another.

### Q3. How does a Resolvido case become Fechado?

| Option | Description | Selected |
|--------|-------------|----------|
| The team closes, or it closes itself after 7 days (Recomendado) | "Fechar" button plus a background job for cases left 7 days in Resolvido with no member reply; fixed period in code | ✓ |
| Only the team closes, by hand | No job, no period; resolved cases can stay forever | |
| It closes itself only | The team has no button to end a case at once | |
| Você decide | Claude chooses and records why | |

**User's choice:** The team closes, or it closes itself after 7 days.
**Notes:** The question text also fixed that a member message on a Resolvido case reopens the same case and notifies the team.

## Campos do chamado

### Q1. Besides number, state and owner, which fields does a case have? (multi-select)

| Option | Description | Selected |
|--------|-------------|----------|
| Subject (short title) | One line shown in the team's list in place of the last message preview | ✓ |
| Category (fixed list) | Check-in, Eventos, Pagamento, Conta, Outro, as in the prototype; lights up the owner's "Atendimentos por assunto" card | ✓ |
| Priority (low, normal, high) | Set by the team, used to order and filter the inbox | ✓ |
| Image attachments (up to 4) | A new capability for the chat; probably its own phase | |

**User's choice:** Subject, category and priority. Attachments were not chosen and are deferred.

### Q2. Who fills subject and category, and when?

| Option | Description | Selected |
|--------|-------------|----------|
| The member picks the category, subject optional (Recomendado) | Above the composer of the first message; "Outro" is preselected; with no subject it becomes the start of the first message | ✓ |
| The member fills both, required | Like the prototype; the member no longer writes directly | |
| Only the team fills | Cases without a category until someone takes them | |
| Você decide | Claude chooses and records why | |

**User's choice:** The member picks the category, the subject is optional.
**Notes:** The question text also fixed: priority is born "Normal" and only the team changes it; the team can correct category and subject.

## Claude's Discretion

- The shape of the data (case as the conversation row or a case table owning a conversation), the requirement prefix and next decision numbers.
- The inbox tabs and filters, the pt-BR copy, the derived-subject length, the layout of "Meus chamados".
- Realtime events for state changes, the worker job name, the case-events table's columns, the counters' implementation.
- The API surface, error codes and the column grants and policies for the staff-writable columns.
- Four defaults Claude assumed without asking, listed in CONTEXT.md for Igor to confirm or overturn: a staff reply takes an unowned case; the team reopens `Resolvido` only; no new module toggle; blocked and removed members keep their refusal codes.
