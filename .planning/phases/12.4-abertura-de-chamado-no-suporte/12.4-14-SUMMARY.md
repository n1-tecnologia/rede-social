# Phase 12.4 Plan 14: The team's inbox Summary

**The staff inbox now has three tabs, owner and priority radio sheets, the awaiting toggle and Limpar filtros, all driven by the URL (aba, resp, prio, aguardando), with a props-only row that shows each case's number, subject, state, priority and owner, five empty sentences by cause and a live refetch scoped to the current view.**

## Accomplishments

- `inbox-query.ts` is the one place that maps the URL vocabulary to the API's. Every value is asserted as the outgoing query string (`aba=resolvidos` to `tab=resolved`, `resp=eu|sem|uuid` to `owner=me|none|uuid`, `prio=alta|normal|baixa` to `priority=high|normal|low`, `aguardando=1` to `awaiting=1` on the open tab only), so a wrong mapping cannot be swallowed as "no filter". Unknown values fall back to their default; a malformed uuid never reaches the API.
- `SupportInbox` reads the URL with `useSearchParams`, refetches page 1 of any view that differs from the server's default page (six skeleton rows meanwhile, a plain refresh keeps the rows), writes changes with `router.replace` without scroll, passes `{ tab, owner, priority, awaiting }` to `loadMoreInboxAction`, gives every row link the current query string, and listens to `chat.message`, `chat.read` and `chat.case`. A read, refresh or page that returns after the staff changed view is discarded.
- `InboxRow` gains `subjectLine`, `statePill`, `priorityPill` and `metaText`; it is top aligned with no fixed height and the meta line wraps. The module still imports neither `next/link` nor the catalog (the acceptance grep prints nothing).
- `InboxFilters` and `useStaffRoster`: radio sheets with `role="radiogroup"` and `aria-checked` rows, `Check` on the picked row, focus back to the opener, the toggle with `aria-pressed` only on Em aberto, one roster fetch shared by every consumer with three skeleton rows and an inline retry.
- Five empty sentences, one per cause; filters win over the toggle so a subset is never described as "everyone answered".
