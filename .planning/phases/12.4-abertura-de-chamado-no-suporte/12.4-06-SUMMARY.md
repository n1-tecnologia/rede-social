# Phase 12.4 Plan 06: Member case API Summary

**A member's first message now carries a category and a subject and answers its numbered case, the thread read and "Meus chamados" return the member-shaped case by keyset, and a case that is not the caller's is one bare 404.**

## Performance

- **Duration:** about 25 min
- **Started:** 2026-11-17T09:35:00Z
- **Completed:** 2026-11-17T09:50:00Z
- **Tasks:** 3
- **Files modified:** 9 (plus this summary)

## Accomplishments

- The tracer: a real member posts `{ body, category: 'payment', subject: 'Cobrança duplicada' }`; the answer keeps `conversationId` and `message` and adds `case { id, number, state, opened: true, reopened: false }` with `number` equal to the tenant's highest number plus one; `GET /v1/chat/support` then returns `subjectLabel` 'Cobrança duplicada', `category` 'payment', `hasAnyCase` true and no `priority` key; a second message from the same member reports `opened` false and leaves the stored fields alone.
- The creating insert is the only statement that writes `category` and `subject` (default `other` and null); a racing second device does nothing and reads the committed row, so the winner's fields are applied whole (EP-031 asserted with two simultaneous first messages).
- `GET /v1/chat/support/cases` returns the active case as `current`, the closed ones newest first by `(case_number, id)`, `total` of closed cases and an opaque cursor whose number is a digit string re-checked by regex; a `limit=1` walk visits each closed case once and five tampered cursors all degrade to page 1.
- `GET /v1/chat/conversations/{id}` adds the member `case` for any own case, closed ones included; another member's, another tenant's and an unknown id answer one identical bare 404.
- `ISOLATION_INVENTORY` has the `GET /v1/chat/support/cases` row and a `chat cases` cross-tenant case with lab and demo positive controls, a lab bystander and a demo bystander reading empty lists, five bare 404s and three host-mismatch refusals.

## Decisions Made

- `opened` is read from `returning id` of the creating insert and `reopened` from the state read before it, so a message that raced into someone else's new case says `opened: false`.
- The typed subject path collapses whitespace but never cuts; the first-message fallback collapses whitespace runs first and then cuts with `cutOnWord(…, 80)` from `@rede-social/contracts/text`.
- `cases.ts` repeats the one-line `CASE_ACTIVE_STATES.map` spelling instead of importing it from `service.ts`, because a test (EP-013) reads `service.ts` for that text and a cycle between the two files was worse than one duplicated line derived from the same constant.
