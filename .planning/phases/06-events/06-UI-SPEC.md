# Phase 06 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design authority.** `reference/frontend-design/` is the visual source of truth for everything it covers (D-66, UI-01). Values marked **[proto]** come verbatim from `app/(app)/events/page.tsx` (`EventPoster`, the "Nada por aqui ainda" card), `app/(app)/events/[eventId]/page.tsx` (sticky back header, `card-magazine` hero at 16/10, `Info` grid, full-width CTA, "Evento não encontrado"), `app/(app)/event-checkin/page.tsx` (the boarding-pass ticket, the typed-code field, "Check-in confirmado! Realizado às …") and `app/globals.css`. The surfaces the prototype lacks are marked **[designed]** and go through D-33 (this contract, then a `/gsd-sketch 6` mockup review) before they are coded: (1) the create/edit form, (2) the RSVP pair, (3) the code entry inside the ported ticket, (4) the online variant (`Entrar`), (5) the Início "Próximo evento" card, (6) the `Participantes` screen. The design language, spacing scale, type scale and colour model are **inherited unchanged** from the approved `02`/`03`/`04`/`05`/`05.1-UI-SPEC.md`. This document restates them for the checker and records only the Phase 6 deltas.

**Upstream decisions.** `06-CONTEXT.md` decisions are cited as **D-200..D-219** and are not re-litigated. Earlier phases' decisions keep their numbers (D-33, D-39, D-42, D-47, D-55, D-66, D-69, D-77, D-86, D-88, D-90, D-93). Earlier visual decisions are cited as **UI-D-07..UI-D-58**. The questions CONTEXT left under "Claude's Discretion → UI and composition" are decided below as **UI-D-200..UI-D-217** (CONTEXT reserves this block so it cannot collide with 05.2's UI-D-59+ run). No `06-RESEARCH.md` exists yet; nothing here depends on one. No question was put to the user: CONTEXT marks every open UI item "decide, record, do not re-ask".

**Design review (D-33).** The six `[designed]` surfaces above are drawn in the mockup package. Three `[proto]` deltas must also be shown there because they change what the design team drew: (a) the two chips replacing the "Meus / Outros" rails, and the poster grid replacing the horizontal rail (UI-D-200); (b) the pill rule, where the date moves into the poster body and the pill carries state or a relative date (UI-D-201); (c) the cancelled treatment (UI-D-202).

## Action zone contract (UI-D-207)

The zone renders inside the hero card body, after the info grid and the location block. Phases: **P0** `now < starts_at − 1 h` · **P1** `starts_at − 1 h ≤ now < starts_at` · **P2** `starts_at ≤ now < ends_at` · **P3** `now ≥ ends_at`. The server computes the phase from the request instant, and `EventActions` refreshes at each boundary (UI-D-203). **The API and the database enforce every rule. The UI only reflects them.**

## Interaction & Accessibility

- **Links, not buttons, for routes:** the create control, both chip navs, posters, manage rows, "Fazer check-in", `Entrar`, "Abrir no Maps", the calendar pair, "Voltar para o evento" and "Ver evento" are all `<a>`. `Entrar` is never `next/link` and never prefetched (UI-D-209). Buttons are only for in-place actions: segments, "Confirmar check-in", "Ver mais", "Reativar evento", "Cancelar evento", and the form submit.
- **No role comparison in the web tier:** every gate reads `bootstrap.permissions` (`events.event.manage`, `events.attendance.read`, the planner's final keys). The API re-enforces every gate.
- **Accessible names = visible catalog strings.** The poster link's name is "{title}, {when}". The segment group is labelled by "Você vai a este evento?", with `aria-pressed` on each option. The code field is labelled "Código do evento", and its error is linked through `aria-describedby` (the `Input` primitive). The code display carries a spelled-out `aria-label`.
- **Live regions:** the RSVP count cell in the info grid is `aria-live="polite"`, so a refreshed count is announced once. The ticket's done state moves focus to "Check-in confirmado!" (`tabIndex={-1}`). Inline errors are `role="alert"`; toasts are `role="status"`.
- **Clock:** no `Date.now()` in render. Every relative string comes from the server (UI-D-203). The boundary refresh uses `setTimeout` inside an effect and is cleared on unmount.
- **Timezone:** every instant renders in `bootstrap.tenant.timezone`. A Playwright case with `timezoneId: 'America/Manaus'` (or any zone ≠ the tenant's) asserts that the detail, poster and ticket show the tenant's wall clock.
- **Motion:** only the success-circle spring (`motion/react`) is new. Under `prefers-reduced-motion: reduce` it appears without scale. Chip switches are navigations; dialogs use their shipped transitions.
- **Forms:** date/time inputs are native (the OS picker), 16px text, each with an explicit `id` and `label`. The prefilled end is announced through the input's value, with no toast. Discarding a dirty form always confirms.
- **Images:** content covers carry `alt` "Capa do evento {title}". The `thumb` on the Início card is `alt=""` because the title sits next to it.
