<planning_decisions>
1. **Two write verbs instead of one PATCH** (RESEARCH §Pattern 6 left the shape to the planner). `PUT /v1/events/{id}` is the whole-event replacement and takes exactly the create schema, because format, location and URL move together (the 04-09 media-triple precedent). `PATCH /v1/events/{id}` takes only `{ status: 'active' | 'cancelled' }` (`.strict()`), mirroring the communities archive-as-status-write. Each body has one precise contract, and the form's Zod is the create's Zod.
2. **Cancel is refused after `ends_at` (`event_ended`)** because a cancelled past event is meaningless and the UI hides the control then (UI-D-211). Reactivate is refused from `starts_at` on (`reactivate_started`, D-214).
3. **No-op detection is in SQL**: `is distinct from` over the stored tuple after conversion, on both tables, so a replayed save cannot move `updated_at` or announce a change that did not happen.
4. **Every server-computed flag** (`canCancel`, `canReactivate`, `cancelledAndStarted`, the zone helper) is computed in the RSC from the request instant and passed to the client form as booleans and strings (UI-D-14: no clock read in client render).
</planning_decisions>
