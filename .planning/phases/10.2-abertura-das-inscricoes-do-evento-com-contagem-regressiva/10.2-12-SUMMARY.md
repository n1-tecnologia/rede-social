# Phase 10.2 Plan 12: The opening field of the event form Summary

**The admin sets, moves, clears and sees locked the opening of a paid event in the Ingresso section: a pure `openingKey` rule sends the date only when it changed, the form judges it against the typed start, and the server's two refusals land under the pair or re-read the section as locked.**

## Performance

- **Duration:** 8 min
- **Started:** 2026-11-14T11:44:24Z
- **Completed:** 2026-11-14T11:52:00Z
- **Tasks:** 3 (task 1 tracer)
- **Files modified:** 8 (2 created, 6 modified)

## Accomplishments

- `event-opening-form.ts` holds the whole payload table in one place: no key for a host that predates the section, an unchanged pair, a half pair or a locked section; the pair when it changed; an explicit null when the admin cleared a stored date, or when the switch is off with no mapping and a date stored or typed; nothing at all when the switch is off with a saved mapping (the mapping removal clears the date atomically). The same module judges the pair against the typed start with the schema's own fixed-width comparison (a test proves it agrees with `eventInputSchema` on the boundary), classifies the field state (locked, empty, filled, past) and formats the server's wall-clock now with `Intl.formatToParts` on a number, so the source has no `new Date`, `Date.now` or `Date.parse`.
- `TicketSection` draws the fieldset after the price inside the fields block with the sketch's order (legend, pair, error, zone line, helper or Lock line, Info row, clear button), the off-warning row under the shipped off-effect note, and the stale-lock alert row at the top. Every string is a `form.ticket.opensAt.*` key.
- `EventForm` keeps the typed pair in state across switch toggles, discards it at a successful save with the switch off, maps `opening_after_start` under the pair (step 1, focus on the date once the submit ends) and `opening_locked` to a locked re-read with the typed pair reverted, and adds no new disabled reason to the submit.
- Web gate green: 378 test files / 9089 tests, typecheck (which runs `next build`), UI literals, boundaries, biome on the eight files.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A server refusal could not move focus while the form was busy**
- **Found during:** Task 2 (the `opening_after_start` case asserted focus on the date input)
- **Issue:** the refusal set the focus target inside the submit transition, so the shared focus effect ran while the inputs were still disabled and a disabled input cannot take focus; the target was then consumed and lost.
- **Fix:** a dedicated `openingFocus` flag with its own effect that waits for `busy` to end, then focuses `event-opens-date`.
- **Files modified:** `apps/web/app/(app)/eventos/EventForm.tsx`
- **Verification:** the case passes; the clear button's focus (not busy) still uses the shared effect.
- **Committed in:** `bd360ba3`

**2. [Process] Task 2 behaviour was written inside the Task 1 commit**
- **Found during:** Task 2
- **Issue:** the states, errors and refusals share the same three files as the tracer, so the Task 1 commit already carried the implementation and Task 2's tests passed on first run (the focus assertion excepted, which found the bug above). Task 2's commit is tests plus that fix.
- **Impact:** none on the result, but no separate red run exists for Task 2's cases beyond the focus failure.

**3. [Interpretation] "Never send the key for a free event" versus the plan's "switch off, no mapping, typed date sends null"**
- The override and the plan table read differently for a typed date with the switch off and no mapping. The helper follows the plan's table: null is sent only when a date is stored or typed, and nothing is sent when nothing is stored and nothing typed (the free event). The typed case is real: a create whose second write failed leaves the event saved with its date and no mapping, and turning the ticket off must clear it.
