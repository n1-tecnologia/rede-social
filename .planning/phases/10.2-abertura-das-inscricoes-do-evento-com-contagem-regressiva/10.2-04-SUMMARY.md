# Phase 10.2 Plan 04: Opening reads, lock and reset Summary

**The database alone now decides the purchase link by its own clock (`app.event_checkout_url` plus a separate `app.event_sale_ready`), locks the opening date for every writer with a BEFORE UPDATE trigger once a paid presence exists, and clears the date in the ticket reset, all in one hand-written expand-only migration proved by 102 pgTAP assertions.**

## Performance

- **Duration:** about 20 min (20:04 to 20:12 local clock, plus reading)
- **Tasks:** 3 (task 1 tracer, task 2 auto, task 3 gate plus tests)
- **Files modified:** 5 (2 created, 3 modified)

## Accomplishments
- `app.event_checkout_url(uuid)` keeps name, signature, `security definer`, empty `search_path` and grants; it now joins the live event of the tenant and adds `registration_opens_at is null or <= now()`. Equal to now counts as open (boundary trio proved: one microsecond behind, equal, one microsecond ahead).
- `app.event_sale_ready(uuid)` (new, `authenticated` only): mapping, gateway mode and `https:` link on a live event of the tenant, ignoring the clock; equivalence `link is not null = sale_ready and opening not ahead` asserted over ten rows in four states (all on, module off, gateway down, http link).
- Trigger `events_opening_guard` (`before update of registration_opens_at`, row, `when ... is distinct from`) with function `app.event_opening_guard()`: SQLSTATE 23514, constraint `events_opening_locked`, message `opening_locked`; no insert half, no advisory lock; refused for the superuser session, `service_role` and the admin lane.
- `app.event_ticket_reset(uuid)` kept byte for byte plus one statement that nulls the opening of the tenant's event; rides `deleteEventMapping`'s transaction with no kernel change.
- Local stack: `pnpm supabase migration up` only (no reset, no seed); nothing pushed, no hosted project touched.
