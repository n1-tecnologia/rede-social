## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `msToNextMinuteChange` formula in the plan leaves the old minute on screen**
- **Found during:** Task 1 (writing the timer property test)
- **Issue:** the plan says `remaining % 60000, or 60000 when it is a multiple`. The displayed value is `floor(remaining / 60000)`. At `remaining = 61000` a 1000 ms timer fires at `remaining = 60000` when it lands exactly on the millisecond, where the floored count is still 1; re-armed for 60000 ms it would keep showing `1 min` for the whole last minute and skip `Menos de 1 min`. At an exact multiple the value changes after 1 ms, not 60 s.
- **Fix:** `(Math.floor(remaining) % 60000) + 1` (1 ms at an exact minute, up to 60 000 ms in the last minute, 0 when there is nothing to count). A property test proves that for 11 sample values the count is unchanged one millisecond before the delay and lower at the delay.
- **Files modified:** `apps/web/lib/event-countdown.ts`, `apps/web/lib/event-countdown.test.ts`
- **Verification:** `vitest run lib/event-countdown.test.ts` (59 passed)
- **Committed in:** `e763eaf9`
- **For plan 11:** `useCountdownClock` arms `setTimeout(msToNextMinuteChange(remaining))` and recomputes on fire; it must treat `0` as "no timer" (the `now` state).

**2. [Rule 3 - Blocking] Two completeness tests of the existing messages test would fail on the new keys**
- **Found during:** Task 2
- **Issue:** "holds no key under ticket.* / form.ticket.* that the contract does not list" compared the whole prefix against the 10.1 tables, so `ticket.soon.*` and `form.ticket.opensAt.*` broke them (a file the plan already lists).
- **Fix:** both filters exclude the new sub-prefix, which has its own completeness test in the new section.
- **Files modified:** `apps/web/i18n/event-tickets-messages.test.ts`
- **Committed in:** `3fcaf115`
