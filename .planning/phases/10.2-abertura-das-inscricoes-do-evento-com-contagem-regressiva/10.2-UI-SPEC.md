# Phase 10.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** A paid event can have an optional **opening date** (D-780, D-781). Before it the member sees the event with an `Em breve` tag and a live countdown, and cannot buy. At the opening the page swaps to the buy button by itself. After it, a member who holds a presence sees a live countdown to the event. This document contracts only what is new or changes:

1. the **EventForm field "Abertura das inscrições"** inside the `Ingresso` section: empty, filled, past date, errors, locked, ticket turned off, 320px (UI-D-790, UI-D-791);
2. the **poster card** of an `Em breve` event: tag, note, price, accessible name (UI-D-782);
3. the **hero** of an `Em breve` event, and the hero overline of a presence holder (UI-D-783, UI-D-788);
4. the **detail `Em breve` zone**: three count blocks, the exact opening date, the time zone, the reference price, hints, every count variant (UI-D-784, UI-D-785);
5. the **live behaviour** of the counter: server seed, hydration, tick, hidden tab, wrong device clock, the instant of the opening and the swap to the buy zone (UI-D-786, UI-D-789);
6. the **accessibility** of a counter that changes every minute (UI-D-787);
7. the **countdown to the event** for a presence holder: event page hero and `Meus eventos` cards (UI-D-788);
8. the **precedence of states** in the buy zone and on the card, and who never sees `Em breve` (UI-D-781);
9. **Participantes** `Antes da abertura` mark and the **Eventos recentes** marker (UI-D-792);
10. loading, error, stale-tab, themes, glyphs, catalogs and trust rules (UI-D-793 to UI-D-796).

Everything else is **reused unchanged** from `06-UI-SPEC.md`, `10.1-UI-SPEC.md` and sketch 021: the poster, hero, info grid, check-in banner, calendar pair, the `Pago` tag, the buy anchor, the `Esgotado` / `Vendas encerradas` / `Venda indisponível` states, the `Presença confirmada` block, the closed doors, the origin marks, the release sheet, the Pagamentos shell, the bell row. **A free event (no linked product) is not touched by any rule below** (D-780): no field, no tag, no opening countdown, its `Faltam N dias` stays byte-identical.

**Design authority.** `reference/frontend-design/app/(app)/events/[eventId]/page.tsx` has no opening date, no `Em breve` and no countdown to a sale; the only time element it draws is the `Faltam N dias` line already ported in Phase 6. Therefore:

- **[reused]**: the poster/hero tag slot and ground, `StatusPill`, `Zone`, the persistent `aria-live` wrapper, `useBoundaryRefresh`, `useLiveRefresh`, the form's date/time pair and the `Ingresso` section's notice and warning rows.
- **[extended]**: `EventPoster` and `EventHero` (a finished-node note and overline), `eventSaleState` (a new kind), `AttendeeRow` marks, `EventRow` (a marker), `TicketSection` (the new field), `useBoundaryRefresh` (one more boundary).
- **[designed]** (no prototype counterpart): the `Em breve` zone with its count blocks, the live countdown component (text and blocks variants), the form field and its states, the `Antes da abertura` marks. They are drawn from primitives that already ship.

The design language, spacing scale, typography scale and colour model are **inherited unchanged** from `02` to `10.1-UI-SPEC.md`. This document restates what the checker needs and records only the Phase 10.2 deltas.

| **UI-D-786** | **Live behaviour** **[designed]** (one client component `LiveCountdown`, two variants: `text` for card/hero/Meus eventos, `blocks` for the zone; **no ticking counter exists today**, so the pattern is specified end to end). **Seed:** the server renders the string from the **server instant** it carries in the read model (`serverNow`), never from the device clock; the first client render **is that same string** (no `Date.now()` during render, so no hydration mismatch). **After hydration** one effect computes `offset = serverNow − Date.now()` and from then on the displayed remaining time is `target − (Date.now() + offset)`: a device whose clock is **wrong, fast, slow or in another year** shows the right count, and the offset is the only place the device clock is read. **Tick:** no `setInterval`; each instance arms **one `setTimeout`** to its **own next change** (the instant the floored minute count changes, `remaining mod 60 s` ahead), re-armed after each change; at most one timer per mounted countdown, cleared on unmount. **Hidden tab:** the timer is cleared on `visibilitychange` to hidden; on **visible again** the value is recomputed **at once** (no wait for the next tick) and, if the tab was hidden for **more than 60 s**, the page asks one `router.refresh()` to **re-seed** `serverNow` from the server (this also catches an opening that passed meanwhile and a device clock the OS corrected while asleep; ## Motion & Accessibility

- **No motion at all.** Digits change in place; no flip, slide, fade or pulse; the swap is a re-render. `prefers-reduced-motion: reduce` changes nothing because nothing animates (UI-D-787).
- **No per-minute announcements.** The count is never inside a live region; a `role="timer"` hidden element holds the current spoken value silently; the polite wrapper speaks only three unit-threshold sentences and the opening (UI-D-787).
- **Stable accessible names.** The card's `aria-label` carries the **absolute** opening date, never the ticking count; the zone's name is the heading plus the static "Abertura: …" line.
- **Focus.** Ticks, threshold sentences and the swap move no focus; the field's `Limpar abertura` returns focus to the date input it emptied.
- **Touch.** `Limpar abertura` has a 44px hit area; the date and time inputs keep the form's `h-12` rhythm; the zone has no control until the swap.
- **Time and clock.** Display is derived from the server seed plus an offset; a wrong device clock, a tab hidden for hours, a back-forward restore and a device clock corrected by the OS are covered by the offset and the 60 s re-seed rule (UI-D-786).
- **Text safety.** Zone name, tenant name and every string are React text nodes.
