# Phase 08.3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design authority.** `reference/frontend-design/` has **no authoring screen for its LMS** (ROADMAP § Phase 08.3 UI hint, checked 2026-10-13: `app/membros/**` holds only the member catalogue, course page, lesson player, tracks, lives and progress; `components/members/*` holds `CourseCard`, `LessonRow`, `LessonThumb`, `ModuleCover`, `ProgressBar`, `ProgressRing`, `StatBlock`, `VideoPoster`). The prototype is therefore the **vocabulary and the visual family** of this phase — the 3:4 course poster, the 16:9 lesson thumb, the module numeral, the 16:10 hero and live cover, the words in `types/member.ts` — and every admin surface is **[designed]** in that language from primitives that already ship: the store's product form and chip header (`ProductForm.tsx`, `ProductGrid.tsx`), the communities' arrows-only reorder list and picker sheet (`CommunityReorderList`, `CommunityPickerSheet`), the events form's date and time pair (`EventForm.tsx`), the media pipeline's upload zone, readiness hook, asset row and player (`VideoUploadField`, `useAssetReadiness`, `MediaAssetRow`, `VideoPlayer`), and `PageHeader`, `Tabs`, `Chip`, `StatusPill`, `Switch`, `ConfirmDialog`, `BottomSheet`, `EmptyState`, `Skeleton`, `Toast`. The design language, spacing scale, type scale and colour model are **inherited unchanged** from the approved `02`–`08.2-UI-SPEC.md`. This document restates them for the checker and records only the Phase 08.3 deltas. The member-facing side (catalogue, player, progress, certificates, the BottomNav tab) is **out of scope** and is not drawn here (CONTEXT § Deferred).

**Sketch gate (D-365, D-417).** Every surface below is prototype-less and goes through `.planning/sketches/009-phase-08.3-designed-screens/` before any UI task: the `/cursos` hub with its area tabs and the three admin lists; the course form; the course page with the curriculum editor (modules and lessons with arrows, the `requires_previous` lock, readiness pills, the publish-blocked notice); the lesson form (video states, "Aula aberta", materials); the category manager; the track form with the course picker and order; the live form with cancel and the replay picker; the archive, unpublish, publish, remove and cancel confirmations; the Configurações row. The gate is closed until the user pastes `approved: true` into that README (08.2 precedent: `grep -q '^approved: true' …/README.md`), and MANIFEST.md gets row 009. § Sketch gate below lists the frames and the questions for the design team.

**Upstream decisions.** `08.3-CONTEXT.md` decisions are cited as **D-400..D-417** and the roadmap decisions as **SC 1..8**; none is re-litigated. `08.3-RESEARCH.md` is cited as **R-§section** / **R-Pitfall n** and its draft requirements as **COURSE-01..15**. Earlier visual decisions keep their numbers (UI-D-29, UI-D-35, UI-D-69, UI-D-206, UI-D-269, UI-D-288, UI-D-366, UI-D-367, UI-D-377, UI-D-382, UI-D-384, UI-D-385). The UI questions CONTEXT left open are decided below as **UI-D-389..UI-D-412**, continuing after 08.2's UI-D-388.

**Discretion defaults adopted unchanged** (CONTEXT § Claude's Discretion): `lesson` video purpose with `cover` reused for every image and `attachment` for materials; the field caps (course title 120, tagline 160, description 5,000, outcomes ≤ 10 × 120, hours 0–999; module title 120, summary 500; lesson title 120, description 2,000; category name 60; track title 120, subtitle 160, audience 60; live title 120, description 2,000, duration 5–600 min); the fixed optional level enum; no lesson `type` column ("vídeo" vs "prática" derived from the asset); one course cover; soft delete for modules and lessons with the word "Remover"; a category with courses cannot be removed; 10-minute signed material URLs; newest-first course list with a status chip filter; a `member` on `/cursos` gets the kernel not-found.

**Assumptions made in this session** (yolo mode; each is stated rather than asked, and the planner may overturn it with one line):
- **A-UI-1 Materials' kinds.** R-§Open Questions 1 leaves "PDF only at 50 MiB now" vs "widen the pipeline to spreadsheets, slides and images" to planning. The UI contract is written for the widened list and degrades to PDF-only without a copy change: the accept list is `mediaAcceptFor('file', 'attachment')`, the helper reads the kinds and the limit from the contract (`courses.lesson.materials.helper`), and the row's kind label is derived from the mime with "Arquivo" as the fallback.
- **A-UI-2 Reorder writes immediately.** D-414 fixes arrows and a whole-order `PUT`; it does not say whether the admin presses "Salvar ordem" (the communities' reorder MODE) or each move persists. In a curriculum with modules and lessons on one screen, a mode per parent is a chore, so each move writes the parent's whole order at once (UI-D-397). Reversible: the host component is the communities' `ReorderList` either way.
- **A-UI-3 No unarchive in this phase.** D-413 names `draft → published → archived` and unpublish; it names no way back from `archived`. The course page of an archived course shows a note and no reactivation control (UI-D-394); whether "Reativar curso" is wanted is a question for the product owner in the sketch README, not a design choice.
- **A-UI-4 Instructor name is required.** SC 2 lists an "instructor label" among the course's fields and the prototype's `Course.instructor` is a required string; only the photo is optional (D-412).
- **A-UI-5 A live may be created with a start in the past** (the admin registers a live that already happened to attach a replay); its state is simply "Gravada" (D-416).
- **A-UI-6 Area sub-nav is the underline `Tabs`, the status filter is `Chip` links.** D-402 allows either primitive for Cursos · Trilhas · Lives; two chip rows stacked would read as one filter. Tabs for the area, chips for the status (UI-D-390, UI-D-391).

**Contract requirements this document places on the API** (for the planner; each is a projection, not a new rule): the course read answers, per lesson, `videoStatus` (`none | pending | processing | ready | failed`), `durationSeconds`, `thumbnailAssetId`/poster, `isFree`, and per module `requiresPrevious` and the lesson count, so the curriculum editor and the publish-blocked notice render without a second request; the course list answers `moduleCount`, `lessonCount`, `durationSeconds` (sum of ready assets) and `hasUnreadyVideo`; `409 video_not_ready` carries the lesson ids; the track read marks each linked course with its current `status` (so "Não publicado" can render); the live read answers the derived `status`; the category list answers `courseCount`; the material read answers the original file name, mime and byte size. If the planner drops a count, the row omits that meta rather than estimating it.
