## Decisions Made
- **Materials replace keeps unchanged rows.** The plan's "delete the lesson's rows, insert by unnest … with ordinality" cannot satisfy its own P30 ("the same `assetIds` twice leaves the rows, `created_at` unchanged"). `delete … where asset_id <> all (sent)` then `insert … on conflict (tenant_id, lesson_id, asset_id) do update set position = excluded.position where position <> excluded.position` lands exactly the sent set in body order and writes nothing for a row already in place — the 08.3-04 P35 reading applied to positions.
- **P20 without a new contract field.** The plan allowed a `returning`-count field in the answer; `moduleListSchema` / `lessonListSchema` stay `{ items }`. The replay is proved by `updated_at` stamps byte-identical on every row of the parent (the `position <> o.ord` predicate) and the log line `courses.modules_reordered … count: 3, moved: 0` / `count: 4, moved: 0` recorded from the Task 1 run — the second call's `returning` count is 0.
- **A lesson's reachability is its own `deleted_at`.** `lockLesson` and `readLessonDetail` filter the lesson row only; a lesson under a removed module leaves every list (the lists read through the module) but stays reachable by id, so its video can still be detached. Its asset therefore stays "in use" until that happens — recorded under Next Phase Readiness.
- **Two refusal readings coexist on purpose.** A material's unknown or foreign asset id is the bare 404 (the plan's rule, T-08.3-20: the id behaves like a path reference), while a lesson's video keeps the 08.3-01 by-name `video_invalid`; the sweep asserts both and the README states both.
- **`materialsBodySchema` is a sibling of the factory.** `reorderIdsSchema(10)` with `min(0)` would name the field `ids`; the truths name `assetIds`, so the body is written beside the factory with the same `uniqueIds` refine, `too_many_materials` on `.max(10)` and `material_invalid` for a non-uuid.
- **`createLesson` hardened on the way.** Its in-use pre-read left the 23505 of `course_lessons_tenant_video_uq` as a 500 under a race; the same `isVideoCollision` mapping now answers `video_in_use` there too, and the module lock goes through `lockModule`.
- **The two-URL assertion waits 1.1 s.** Storage's signed token carries its issue second, so two `signReadFor` calls inside one second are byte-identical with or without a memo; the case sleeps past the second boundary and then asserts the URLs differ.
