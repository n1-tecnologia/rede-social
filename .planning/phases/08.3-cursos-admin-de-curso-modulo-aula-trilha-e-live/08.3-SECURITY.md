# Phase 08.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser/BFF → API | `/v1/courses/*` bodies, path ids, `productIds`, asset ids, order permutations, cursors, the live `externalUrl` | attacker-controlled input for a direct caller of the public Cloud Run API |
| API (api_user, tenant lane) → Postgres | tenant claims set per transaction; RLS is the structural guard; gate definers run as their owner | tenant-scoped course, lesson, material, track, live and progress rows |
| kernel seam → module body | course, lesson and live policies call the kernel-named `app.course_locked_ids*` / `app.live_locked_ids*` whose bodies the store supplies | entitlement decisions |
| courses module → store tables | `resolveProducts` reads `public.store_products` by name under the tenant lane | product ids and status |
| browser → Storage / Mux | upload bytes go direct; the API sees metadata and reads the object back at `complete` | lesson video, material files |
| API → provider edge | playback tokens and signed material URLs are bearer capabilities | short-lived credentials |
| browser → Next.js server actions | paging, form bodies, ids; validated with the module schema before any request | admin form input |
| review artifact → application code | sketch 009 under `.planning/` must never become a runtime dependency | none (static mockup) |
| human approval → agent execution | the sketch gate approval must come from the user | approval keys |
| release order → production | migrations before API before web | schema/API compatibility |
