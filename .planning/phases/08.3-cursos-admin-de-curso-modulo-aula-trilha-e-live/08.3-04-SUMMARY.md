## Decisions Made
- **Cover and photo references are refused by name.** Plan 01 followed the store (`resolveImageAsset`: a miss is the bare 404); plan 04's truth ("a cover must be a ready `cover` image of the tenant (`cover_invalid`)"), its threat row T-08.3-02 and Task 3's sweep ("400 `cover_invalid` when attaching a rede-demo cover asset") all need the code by name, exactly as `resolveLessonVideo` already answers `video_invalid`. No test asserted the 404; the function, the contracts comment and the `POST /` route descriptions were updated together. A foreign asset id is a body reference, not a path param, so T-08.3-20 (existence through refusal codes) is unaffected: unknown and foreign ids answer the same code.
- **Link replace deletes the difference.** The plan's literal "delete then insert by unnest" cannot satisfy its own P35 truth (same `created_at` after a re-send). `delete … where product_id <> all (sent)` then `insert … on conflict do nothing` lands exactly the sent set, under the row lock, and leaves an unchanged link untouched. The archived-product posture follows from `resolveProducts`: an archived product already linked stays in the detail (read-only, with its `status`) and a save that keeps it must omit `productIds`.
- **Inventory rows travel with their routes.** Task 1's verify runs `pnpm --filter @rede-social/api test`, which includes the inventory gate; adding the rows in Task 3 would have left two red commits. The sweep case the rows name already existed.
- **The seed has the demo store ON.** The plan's "with the store row off for rede-demo" assumed the 08.2 seed; plan 01's matrix test already relied on the store being on. `withDemoStore(false, …)` proves the dormant links, `withDemoStore(true, …)` proves the lock, and the seed row is restored either way.
