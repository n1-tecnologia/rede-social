## Decisions Made
- **TTL formula over the plan's one odd data point.** The must-have states the formula `min(MAX, max(TTL, duration + MARGIN))` and lists `7 199 → 7 200`; the two disagree (7 199 + 1 800 = 8 999). The formula is what RESEARCH Pattern 5 item 4 and Mux's "expiration should be at least the duration" require, and a step at the floor would hand a 7 199 s lecture a one-second margin — the exact Pitfall 5 failure. The function follows the formula and the unit test pins 7 199 → 8 999 with the reason.
- **Rejected/failed videos leave the minutes budget.** `applyReady` writes the measured duration into a `rejected` row (audit trail) and deletes the provider asset; the ceiling summed it anyway, so my own boundary case (a four-hour post video rejected by the cap) refused every later post start in the suite — and would do so in production for the hour the sweeper takes. The sum now carries `notInArray(status, ['rejected', 'failed'])`.
- **Video bytes leave the Storage byte ceiling.** A 4 GiB pending lesson made every image start answer 413: `sum(bytes)` counted video rows against the 800 MiB budget meant for Storage. Video is metered in minutes and its bytes live at the provider (the fake's local copy is a dev artefact), so the byte sum now carries `ne(kind, 'video')`; the integration case proves a photo still starts after the 4 GiB lesson.
- **Images are file-kind attachments routed through the decoder.** RESEARCH suggested excluding images or using `cover`; D-410 names images, so `inspectFile` hands the three image mimes to `inspectMediaImage` (same errors: `format_mismatch`, `not_an_image`, `heic_unsupported`, `too_large`) and the row stays `file`/`attachment` with no ladder.
- **One label vocabulary.** `attachmentKindFor` in the contract replaces three `mime === 'application/pdf'` ternaries (feed-view twice, the composer once) and feeds `MediaAssetRow`; `feed.attachment.type` gains `sheet`/`slides`/`image`/`file` (the old `other` key stays for any stale payload).
- **No core unit test drives `startUpload`/`playbackTokens`.** `tests/media.test.ts` documents that `service.ts` is never imported there (DB-bound); the ceiling and TTL behaviour is proved in the API integration suites against the live stack, and the pure pieces (`playbackTtlSeconds`, the ceiling constants) are pinned in unit. `signReadFor` got its own file so the pure file stays pure.
