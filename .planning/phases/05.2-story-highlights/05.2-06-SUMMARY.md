# Phase 05.2 Plan 06: The Shared Highlight Sheet and "Destacar" in the Viewer Summary

**A curator watching any story can now tap "Destacar" and put it into, or take it out of, any highlight while the story waits underneath. The work has three layers. The module gains `HighlightSheet`, the one membership sheet D-110 asks for (checklist and single-select modes on a shared toggle machine), and a shared "Novo destaque" title step. The web gains one composed server read and one validated action per toggle. The viewer gains the curator-only pill.**

## Accomplishments

- **One sheet, three routes (D-110).** `HighlightSheet` has two modes:
  - **`checklist`** (UI-D-67): place groups under plain 12/700 labels, and a 44px inert row with a 32px round cover or monogram and a trailing `Switch`.
  - **`single`** (UI-D-68): origin group first, then "Nenhum", then Início, then every other place, each ending with "Novo destaque". Confirming a title selects a pending highlight and creates nothing (D-114).

  Both modes are built on `HighlightMembershipList`, which carries UI-D-41's three invariants plus the re-seed rule. It adds a generation guard, so a write still in flight for the previous story cannot revert a switch of the next one. `PinStorySheet` stays exported until plan 07 removes it.
- **The title step (UI-D-72, UI E05).** Trimmed-empty keeps "Criar destaque" disabled. Enter shows "Dê um nome para o destaque." and focus stays on the field. `maxLength` plus clipping hold the title at 15, and the untrimmed counter sits in a fixed `tabular-nums` slot. Submit is single-flight, and a failed submit keeps the typed title.
- **One read opens the sheet.** `loadHighlightSheetAction` reads the catalogue, the story's memberships and the active communities in one `Promise.all`. It returns place groups with their labels, built by `highlightPlacesView`: Início first, communities in list order, and highlights of inactive communities dropped. A member's 403 is `{ ok: false }`.
- **One action per toggle.** `addStoryToHighlightAction` and `removeStoryFromHighlightAction` validate every id and the place with Zod. They answer `{ ok, highlightCount }` or the closed codes `archived | full | generic`. They revalidate only when the caller asks (the viewer never does), and their logs carry ids and the issue code only.
- **"Destacar" in the viewer (UI-D-66).** The pill uses `BookmarkPlus` 16 on the mute toggle's `bg-black/35`, with `ml-auto` at the end of the action row. It appears on every Início group, the community row and the deep link, gated on `stories.story.manage` from the bootstrap. The clock is paused from the tap until the sheet closes.
- **Checked in a real browser.** A production build on :3100 against the seeded API showed the sheet with Início's Bastidores and Aulas and the community "Avisos da diretoria". Aulas toggled on and off with both toasts, and Escape resumed the story. A member gets no pill.

## Decisions Made

See `key-decisions` in the frontmatter. The one with a visible product consequence: **the story pauses at the tap, not only while the sheet is open.** The read takes a round trip, and letting the story advance during it would open a sheet about a story that is no longer on screen.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Test harness] Motion springs rejected after the module run under happy-dom**
- **Found during:** Task 1 GREEN
- **Issue:** all 13 cases passed, but `BottomSheet`'s cancelled springs raised two unhandled `AbortError`s after the run.
- **Fix:** the test file sets `MotionGlobalConfig.skipAnimations = true`, the same line `community-picker-sheet.test.tsx` uses. It is a harness-only edit after RED.
- **Committed in:** `e741c4f`

**2. [Lint] `role="group"` on the place wrappers**
- **Found during:** Task 1 GREEN
- **Issue:** Biome's `useSemanticElements` refused `<div role="group" aria-label>`.
- **Fix:** plain wrappers. Every switch's own name already carries the place ("Destacar em {title}, {place}").
- **Committed in:** `e741c4f`

**3. [Rule 2 - Correctness] Re-seed generation guard in the toggle machine**
- **Found during:** Task 1
- **Issue:** with the sheet kept mounted, a write still in flight for story A that fails after the target moved to story B would flip B's switch.
- **Fix:** a generation counter bumped on every re-seed. A revert applies only in the generation that started it.
- **Committed in:** `e741c4f`

**4. [Rule 2 - Correctness] The pause starts at the tap**
- **Found during:** Task 3
- **Issue:** the plan pauses "while the sheet is open". During the read the story could advance, and the sheet would then open for a story that is no longer on screen.
- **Fix:** `highlightFor` is set at the tap and cleared on close or on a failed read. `externallyPaused = commentsFor !== null || highlightFor !== null`.
- **Committed in:** `8d0f425`

**5. [Environment] Browser smoke on a production build**
- The plan has no e2e task. I built production and ran a throwaway scratchpad spec with `next start -p 3100` and `VIDEO_PROVIDER=fake` (the 05.2-04/05 procedure). With the `aria-modal` sheet open, Playwright hides the viewer dialog from role queries, so the spec reads `[data-paused]` directly. The seed was left as found (Aulas toggled on, then off). The server was stopped, and nothing is listening on 3000, 3100, 8787 or 8788.
