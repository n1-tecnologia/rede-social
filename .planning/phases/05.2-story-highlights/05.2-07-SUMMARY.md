# Phase 05.2 Plan 07: "Seus stories" Curates Highlights, and the Web Pin Model Is Retired Summary

**An admin can now open "Destacar" from any row of "Seus stories", expired stories included. It opens the same checklist sheet the viewer opens, and the row's "Em # destaques" follows each confirmed toggle with no reload. The pin sheet, the pin words and every web-side pin call are gone.**

- **Completed:** 2026-09-25T23:10:14Z
- **Tasks:** 2 of 2 (Task 1 `tdd="true"`)
- **Files modified:** 16 (14 modified, 2 deleted)

## Accomplishments

- **D-110 route 2.** The row menu is now "Destacar" · "Ver story" · "Excluir story". "Destacar" awaits `loadHighlightSheetAction` and opens `HighlightSheet` in checklist mode. If the read fails, nothing opens and the generic toast fires. The empty state links to `/stories/destaques`. Toggles call the shared add and remove actions with `revalidate: true`, so `/inicio` or `/comunidades/{id}` shows the change on the admin's next visit.
- **The live indicator (UI-D-77).** `StoryHistoryRow` has a new `highlighted` prop that shows a `Bookmark` 16 icon and the ICU plural "Em # destaque(s)". It renders only when the count is above 0 and sits in the unchanged `shrink-0` trailing slot. After each confirmed toggle, the row takes its count from the server's `highlightCount`. A reverted toggle changes nothing, and reaching 0 removes the indicator.
- **Reworded delete (UI-D-78).** The dialog now reads "Ele sai do início e de todos os destaques onde está.", with the buttons "Excluir story" and "Manter story".
- **Pins retired on the web (UI-D-79, HIGHLIGHT-05 web half).** Removed:
  - `PinStorySheet` and its test
  - `stories.pin.*`, `history.pinned` and `history.menu.pin`
  - `loadStoryPinsAction`, `pinStoryAction`, `unpinStoryAction` and `togglePinAction`
  - `getStoryPins`, `pinStory`, `unpinStory` and `storyPinIssue`

  `/stories/meus` no longer reads communities. The API routes, the contracts, `loadCommunityHighlights` and the `pin` branch of `storyWriteIssue` are left for plans 08 and 11.
- **Both doors tested in a browser.** The e2e now covers the rewritten "Seus stories" describe and "Destacar" from the viewer. The viewer case checks that the story pauses, resumes after Escape, and that a member's viewer has no "Destacar".

## Decisions Made

See `key-decisions` in the frontmatter. The one with a visible product effect is that **the row's count is the server's number, never a local +1/−1.** A write that lands while another is still in flight therefore cannot leave the row showing a count the database does not hold.
