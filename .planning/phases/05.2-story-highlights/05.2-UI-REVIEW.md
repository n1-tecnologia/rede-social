## Top 3 Priority Fixes

1. **WARNING: `full` refusals tell the admin to retry.** Affects `HighlightManager.tsx:541` (create maps every code except `archived` to `generic`) and `StoryComposer.tsx:278-284` (`full` maps to `publish.errors.failed`). **User impact:** a 51st highlight, or publishing into a highlight that already has 100 stories, gives "Tente novamente" for an operation that will fail every time. **Fix:** add `highlights.errors.placeFull` ("Este lugar chegou ao limite de {limit} destaques. Exclua um para criar outro."). In create, map `full` to it. In the composer, choose `errors.full` or `placeFull` based on `selection.kind` (existing highlight or `newHighlight`).
2. **WARNING: the empty checklist sheet's "Criar destaque" goes to the wrong place.** Affects `StoryViewerHost.tsx:520-525`. The href is hard-coded to `/stories/destaques`, and it is a plain `<a>`, so it does a full reload and drops the open viewer. **User impact:** an admin who is viewing a community story is sent to the Início manage screen. **Fix:** use `next/link` and derive the href from the story's origin (`/comunidades/{id}/destaques` when the origin is a community).
3. **WARNING: the arbitrary skeleton size is off the spacing contract.** Affects `StoriesStrip.tsx:86` (`h-[68px] w-[68px]`). The spec declares 64px circles plus a 2px ring hairline. The value is arithmetically correct, but it is the only arbitrary px value in the phase's UI files. **Fix:** use `size-17`, or wrap a `size-16` skeleton in the same `p-0.5` ring span that `StoryCircle` uses, so the geometry has a single source.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- No hard-coded strings in the audited TSX: a grep for `>Text<` literals returned 0 hits. Strings go through `t()` / the `labels` props from `stories.json`, and the vocabulary follows the contract (Destacar, Início, story/stories).
- **WARNING (WR-03):** `StoryComposer.tsx:279` also maps `archived` to `publish.errors.failed`. The comment says the UI-D-71 branch in `submit` handles archived when a destination is captured, so this is a fallback only. That is acceptable, but it should be verified.
- **WARNING:** the catalog has no place-cap string. The only `highlights.errors.full` string talks about "{limit} stories", so forwarding the place-cap code as-is would show the wrong message.
- The manager's `full` mapping at `HighlightManager.tsx:172-173` is correct for add-story. Only create and the composer are wrong.

### Pillar 2: Visuals (3/4)
- The "Destacar" pill (`StoryViewerHost.tsx:653`) matches UI-D-66 class for class: `ml-auto inline-flex h-11 … bg-black/35 px-4 text-sm font-bold`.
- The dashed manage/upload discs (`HighlightManager.tsx:382-383`) use `border-dashed border-border-secondary` per UI-D-63.
- Icon-only controls have labels: the drag handle has `aria-label={labels.drag(title)}` (`HighlightManageList.tsx:268`), and the viewer mute/close buttons use `IconButton` with a `label`.
- **WARNING:** Fix 2 (the checklist empty-state link) is a visual-flow break inside the one sheet that has no other way forward.

### Pillar 3: Color (3/4)
- 0 hard-coded hex/rgb values in phase UI files.
- Brand usage: 14 occurrences. Nearly all map to reserved items: the tenant ring `border-brand` (StoryCircle:73, item 11), the 24px badge (StoryCircle:141, HighlightEditSheet:565, item 12), the select `Check` (HighlightSheet:336, item 14), the upload bar (HighlightManager:411, item 1), and focus rings.
- **WARNING:** `text-brand` text links at `StoryViewerHost.tsx:522` and `HighlightManager.tsx:526` are not among the elements the UI-SPEC Color section enumerates for 05.2. Confirm they fall under an inherited "link" item, or change them to `text-text-primary underline`.

### Pillar 4: Typography (4/4)
- Sizes: `text-xs` ×24, `text-sm` ×22, `text-base` ×5. These are exactly the declared Caption, Body and Heading steps.
- Weights: `font-normal` ×28 and `font-bold` ×16. Only 400/700, per contract.
- Minor: the viewer caption uses `text-base leading-relaxed` (StoryViewer:~988). This is inherited from Phase 5 and is not a 05.2 regression.

### Pillar 5: Spacing (3/4)
- Distribution: gap-1 ×12, gap-2 ×11, gap-3 ×10, gap-4 ×6, px-4 ×6, px-2 ×6, gap-6 ×1 (edit sheet). These match the xs/sm/md-s/md/lg rows.
- **WARNING:** `h-[68px] w-[68px]` at `StoriesStrip.tsx:86` (see Fix 3).
- **WARNING:** `gap-0.5` (2px) between title and meta in `HighlightManageList.tsx:285`, `HighlightEditSheet.tsx:488` and `StoryHistoryRow.tsx:116`. The spec only declares 2px for hairlines. Either add it to the spec or use `gap-1`.
- Inherited and not counted against 05.2: `gap-2.5` and `px-8` in `StoryViewer.tsx:874/914/948`.

### Pillar 6: Experience Design (3/4)
- Present:
  - skeletons on the strip and the manage list (`HighlightManager.tsx:124`)
  - optimistic reorder that reverts to the last server-confirmed order (`HighlightManager.tsx:147-198`)
  - accessible move up/down alongside the drag handle
  - a `confirmDelete` dialog for highlight deletion (`HighlightManager.tsx:682`)
  - a deliberately confirmation-free removal of a story from a highlight (UI-D-78)
  - a single polite live region in the viewer
- **WARNING:** deterministic refusals are presented as retryable (Fix 1).
- **WARNING:** the full-page navigation out of an open viewer drops the viewer state (Fix 2).
- The 🧪 backstops (320px long-name truncation, E11/E04, and the group crossover E03) can only be checked on a device or in e2e. No screenshots were captured to confirm them.
