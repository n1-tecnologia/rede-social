<planning_decisions>
1. **`motion/react` `Reorder`, no install.** `motion@13.3.0` is a devDependency of the module and a
   dependency of `apps/web` — the `CommentInput` precedent (RESEARCH "Correction to CONTEXT"). Imports
   are `motion/react`, never `framer-motion`.
2. **One host island for both routes.** `HighlightManager` takes the place (`communityId | null`),
   the curator list, the archived flag and the optional `?editar=` target; both pages are thin
   server shells.
3. **Cover uploads reuse the Phase 3 machine.** `useSignedUpload({ kind: 'image', purpose: 'cover' })`
   → on completion `setHighlightCoverAction(id, { assetId })`; an asset not yet `ready` answers the
   bare 404 and the admin retries — handled exactly as `CommunityForm`'s cover handles it.
4. **Curation actions revalidate the place** (`/inicio` or `/comunidades/{id}`) so the row the admin
   returns to reflects the change; the manage screen itself is optimistic and `router.refresh()`es on
   `order_stale`.
</planning_decisions>
