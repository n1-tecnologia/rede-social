# Phase 05.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this phase is.** Wiring, not invention (05.1-CONTEXT §Phase Boundary). Three shipped screens gain controls: the `/comunidades` list, the community page `/comunidades/[communityId]`, and the story composer `/stories/publicar`. Every control is built from components Phase 5 already shipped. The design language, spacing scale, type scale, colour model and catalog conventions are **inherited unchanged** from the approved `05-UI-SPEC.md` (itself inheriting `02`/`03`/`04`). This document restates them for the checker and records only the 05.1 deltas.

**Upstream decisions.** `05.1-CONTEXT.md` decisions are cited as **D-86..D-99** and are not re-litigated. `05.1-RESEARCH.md` patterns, pitfalls and open questions are cited as **R-Pn**, **Pitfall n** and **OQ-n**. Phase 5 visual decisions are cited as **UI-D-25..UI-D-47**. The questions left open (CONTEXT "Claude's Discretion" and RESEARCH OQ-2/OQ-3/OQ-4) that are purely visual or interaction questions are decided here as **UI-D-48..UI-D-58**. Numbering continues from `05-UI-SPEC.md`, as CONTEXT instructs.

**Design review.** No new sketch package. Each delta sits inside a screen the design team already approved: the `[proto]` list and community page, and the `[designed]` composer and archived page from sketch `003-phase-05-designed-screens`, approved provisionally on 2026-09-23. Four deltas change what the design team approved and must be shown at the phase's phone UAT: (1) the title-row create control (UI-D-48), (2) the filter chips and the archived-card pill (UI-D-49/UI-D-50), (3) the Reativar control under the archived note (UI-D-52), and (4) the over-media "Publicar em" row in the composer's black frame (UI-D-54). Delta 4 is the only new drawing. It reuses the processing row's ground (`bg-black/45`), which is already in that frame.

## Interaction & Accessibility

- **Links, not buttons, for routes:** the create control, the chips and the `+` circle are all `<a>` (the `ComposeFab` / `createCta` rule). Only the composer row (it opens a sheet), the Reativar button (it opens a dialog) and the sheet rows are `<button>`.
- **Accessible names are the visible catalog strings:** "Criar comunidade" (the label is `sr-only` below `sm`, so it is never lost), "Ativas" / "Arquivadas" with `aria-current="page"` on the active one, "Publicar em Nenhuma comunidade" / "Publicar em {community}" on the composer row with `aria-haspopup="dialog"`, and "Publicar um story em {community}" on the `+`.
- **Focus:** the sheet returns focus to the composer row on close (BottomSheet). The reactivate dialog traps focus and restores it to the Reativar button on cancel. On success the button is removed by the refresh, and the `role="status"` toast "Comunidade reativada." announces the outcome.
- **Errors:** the composer refusal renders in the existing `role="alert"` card. Reactivation failures render as an error toast (`role="status"`), matching archive's failure path in `CommunityForm`.
- **Motion:** none new. Chip state changes are a navigation; the sheet and dialog use their shipped transitions and honour `prefers-reduced-motion`.
- **No role comparison in the web tier:** every gate reads `bootstrap.permissions` (`communities.community.manage`; `stories.story.publish` plus the OQ-1 permission if the planner adopts it). The API re-enforces every gate (D-89, D-99).
