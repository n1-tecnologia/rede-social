# Phase 05.1 Plan 03: /comunidades create control and Arquivadas filter Summary

**Managers now see a "Criar comunidade" link in the `/comunidades` title row whether or not the list is empty. Two manager-only chips, `Ativas` and `Arquivadas`, switch between lists: the archived list reads 05.1-02's endpoint, marks each card with the neutral "Arquivada" pill, and keeps the status through refresh and load-more. Members see the same screen and send the same request as before.**

## Accomplishments
- **ROADMAP criterion 1.** An admin who already has communities reaches `/comunidades/nova` from the list. The control is one anchor: a 44×44 brand `+` square below `sm`, and `+ Criar comunidade` from `sm`. The label is a `sr-only sm:not-sr-only` span, so the accessible name is always the catalog string. The empty state's own link stays (D-87).
- **ROADMAP criterion 2 (finding half).** Managers get `Ativas` / `Arquivadas` `Chip` links, read on the server. `Arquivadas` shows the server's order (most recently archived first). Each card carries `StatusPill tone="neutral"` "Arquivada" in the new `CommunityCard.statusPill` slot, with no dimming. An empty archived list shows the UI-D-51 state with no call to action.
- **D-89, web half.** The page sends `status=archived` only when `canManage` holds and the query value is exactly the single string `arquivadas`. A member, a repeated value or any other value lands on `Ativas` with no chips and no error. The API's 403 from 05.1-02 backs this up.
- **Pitfall 9.** Refresh and load-more pass the list's status on, validated with the same `communityQuerySchema` the API uses. `CommunitiesList` is keyed by status, so switching chips starts from the server's page 1.

## Decisions Made
- **An array means Ativas.** The status resolution compares `params.status === 'arquivadas'`. A repeated `?status=` arrives as an array and falls to Ativas, as UI-D-49 specifies. This deliberately differs from `/criar`, where the first value wins.
- **Refresh sends `{ status }` only.** `getCommunities` keeps its own default page size, so the active refresh request is exactly today's string.
- **E2E ran against a production server on :3100** (see Issues).

I ran `next start -p 3100` from the Task 2 build (built at 10:53:59, committed 10:54:14, no app edits since) and set `PLAYWRIGHT_{DEMO,LAB,PLATFORM,GENERIC}_URL` to :3100, following the repo's own `playwright.pwa.config.ts` pattern. I did not kill the developer's process. Playwright still started its own API under `VIDEO_PROVIDER=fake` (8787 was free, so the precondition held). I stopped the :3100 server afterwards.
