| **Framework** | Vitest 5.0.0 (module, web, API suites) · Playwright 1.63.0 (e2e) · pgTAP via `supabase test db` (CLI 2.117.0) |
| **Config file** | `apps/api/vitest.config.ts`, `apps/web/vitest.config.ts`, `packages/modules/{communities,stories}/vitest.config.ts`, `apps/web/playwright.config.ts`, `supabase/tests/*.sql` |
| **Quick run command** | `pnpm --filter @tria/module-communities --filter @tria/module-stories test && pnpm --filter @tria/web exec vitest run "app/(app)/stories/publicar" "app/(app)/comunidades"` |
| **API integration command** | `pnpm --filter @tria/api exec vitest run tests/integration/communities.test.ts tests/integration/stories.test.ts tests/integration/isolation.test.ts tests/integration/feed-query-budget.test.ts` |
| **Full suite command** | `pnpm db:reset && pnpm db:seed && pnpm lint && pnpm typecheck && pnpm test && pnpm supabase test db && pnpm test:integration && VIDEO_PROVIDER=fake pnpm --filter @tria/web exec playwright test comunidades.spec.ts stories.spec.ts phase5-smoke.spec.ts` |
| **Estimated runtime** | quick ~3 s; API integration ~5 s; full suite several minutes (e2e dominated) |

**Video-provider rule (hard):** no validation command may depend on real Mux or a tunnel.
- Vitest (API): an exported `VIDEO_PROVIDER=fake` is not enough today — Wave 0 pins `VIDEO_PROVIDER: 'fake'` as the last `test.env` entry in `apps/api/vitest.config.ts`.
- Playwright: prefix `VIDEO_PROVIDER=fake` and make sure nothing is listening on 8787 (`curl -s -o /dev/null -w '%{http_code}' http://localhost:8787/v1/health` → `000`), otherwise `reuseExistingServer` reuses the developer's Mux-configured API.
- New 05.1 e2e flows publish **image** stories only (`e2e/fixtures/post-a.jpg`).

## Sampling Rate

- **After every task commit:** Run the quick run command
- **After every plan wave:** Quick run + API integration command on a freshly reset+seeded DB + `pnpm supabase test db`
- **Before `/gsd-verify-work`:** Full suite must be green (after the reset+seed checkpoint), then a manual phone UAT
- **Max feedback latency:** 10 seconds (quick tier)
