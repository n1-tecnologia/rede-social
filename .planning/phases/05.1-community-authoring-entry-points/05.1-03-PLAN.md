<objective>
Close ROADMAP criterion 1 and the web half of criterion 2 on `/comunidades`: an admin who already
has communities can reach the create form, and can find an archived community without knowing its
id.

Today the "Criar comunidade" link is built in `CommunitiesList.tsx` but rendered only inside the
zero-communities empty state, and the list shows active communities only. This plan puts the create
control in the page's title row (D-86, UI-D-48), keeps the empty state's own action (D-87), and adds
manager-only `Ativas` / `Arquivadas` filter chips as server-read links (D-88, UI-D-49) over the
archived endpoint 05.1-02 built, with the existing `Arquivada` pill on each archived card (UI-D-50)
and an honest empty state when nothing is archived (UI-D-51). Members see today's screen.

Purpose: two of the three Phase 5 UAT reports, closed on the list itself.
Output: the extended card, the status-aware lib and actions, the title row, the chips, the catalog
keys, and unit plus e2e evidence on phone and desktop.
</objective>

<planning_decisions>
1. **Status resolution (UI-D-49):** the page selects `Arquivadas` only when the viewer holds the
   manage permission AND `searchParams.status` is exactly the single string `arquivadas`. A repeated
   value arrives as an array and lands on `Ativas` (UI-D-49's "a repeated value … lands on Ativas");
   so does any other value. Nothing errors.
2. **Members' markup stays today's (D-89 "byte-for-byte"):** the member branch renders the exact
   title block it renders now (`px-4 pt-4 pb-3`, heading, subtitle) and sends the exact request it
   sends now; the flex title row, the control and the chips exist only in the manager branch.
3. **The list remounts per status:** the page renders `CommunitiesList` with `key={status}`, so a
   chip switch starts from the server's page 1 with no state carried across statuses.
4. **The e2e card locator changes:** `cards()` currently matches every `main` anchor whose href
   starts with `/comunidades/`, which would count the new `/comunidades/nova` link as a card on every
   admin screen. It becomes the card's own `data-testid="community-card"` anchor.
</planning_decisions>
