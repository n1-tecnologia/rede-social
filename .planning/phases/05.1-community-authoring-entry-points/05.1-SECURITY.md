## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser → web server action → `POST /v1/stories` | An authenticated caller supplies `communityId`, an untrusted uuid that may name another tenant's row, an archived community or nothing | community id (tenant-scoped identifier) |
| browser → `GET /v1/communities?status=` | Any authenticated member can ask for the archived list | archived community names/metadata (manager-only) |
| URL `?comunidade=` → composer page | Untrusted query value pre-selects a destination | community id |
| API route → service | The permission decision is made once in the handler; the service trusts that the route ran | resolved permissions |
| API service → Postgres | `api_user` under `set local role authenticated` inside `withTenantTx`; RLS plus explicit tenant predicates decide visibility | tenant-scoped rows |
| Vitest / Playwright config → worker | A developer's `.env.local` can carry real vendor (Mux) credentials into automated runs | vendor API credentials, billable calls |

## Residuals (not open threats)

Recorded by the auditor without changing any threat's status:

- **R-1 — archive/pin race (WR-01, medium, below threshold).** `resolvePublishCommunity` (SS:1035-1050) reads `c.status` without `FOR SHARE`, so an archive that commits between the status read and `insertStoryPin` can still land a pin in an archived community. The same pattern exists in `resolvePinTarget`/`pinStory` and feed `createPost`. The declared T-05.1-03 mitigation is present; this is a narrower concurrency window.
- **R-2 — e2e fake-provider guarantee is procedural.** `apps/web/playwright.config.ts:64` keeps `reuseExistingServer: true`, so a pre-running API with real Mux credentials would be reused. The image-only walks are what actually close the cost path for the new specs.
- **R-3 — module toggle not checked on publish-with-destination (IN-02).** `SR:412-423` does not verify the `communities` module is enabled for the tenant when `communityId` is sent. Stays in-tenant, requires the manage permission, and matches existing `pinStory` behaviour.
- **R-4 — review items with no mitigation gap.** WR-03 (a 404/403 keeps the chosen destination: UX dead-end, not a silent change — T-05.1-34 holds); IN-01 (`?comunidade=` beyond 250 communities falls back to none: fail-safe).
