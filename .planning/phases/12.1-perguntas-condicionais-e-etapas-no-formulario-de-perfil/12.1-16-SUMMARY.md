# Phase 12.1 Plan 16: The builder's steps, step sheet, limits and reorder Summary

**The Perguntas tab now has Adicionar etapa and step wells that hold the Phase 12 question cards (a one-step form is still byte for byte Phase 12), a step sheet to create, rename and safely delete, both ceilings shown, and a reorder mode that moves steps and questions over the whole layout and, when a press would break an opener's order, moves nothing and says which two questions conflict.**

## Design gate

The D-635 gate (sketch 018) was closed provisionally before this plan ran: the approval keys in the sketch README were written by the orchestrator on Igor's chat instruction ("Faz você: grave a aprovação"), committed in `54cb4351` and recorded in the plan 05 SUMMARY. Everything here was built against that provisional approval, with `index.html` and `12.1-UI-SPEC.md` as the contract. I did not edit or stage the sketch README, MANIFEST or index.html. The `grep -q '^approved: true'` precondition passed at the start of the run.

## Accomplishments

- **Actions** (`actions.ts`): `createStepAction`, `renameStepAction`, `deleteStepAction` (each validated with the contract schema before the request, the response parsed with `adminStepSchema` or `deleteStepResultSchema`) and `reorderLayoutAction` (body `{ steps: [{ id, questionIds }] }`, `condition_order` carrying `questionId` and `openerId`). Typed unions, no throw for an expected refusal, redirect outside the try/catch, nothing re-exported.
- **`StepWell.tsx`**: the UI-D-643 geometry (`section` labelled by its title, `rounded-xl bg-bg-tertiary p-3 gap-3`, eyebrow, `break-words line-clamp-2` title, ICU plural meta line), the 44px rename button or the two reorder arrows, the empty-step line, and the ghost footer with the step-naming `aria-label`.
- **`StepSheet.tsx`**: one `BottomSheet` in two modes with the 60-character title, live counter, disabled save, pending state, dirty guard (step wording), failure line, and in rename mode the divided delete block in its three states.
- **`QuestionList.tsx` / `QuestionBuilder.tsx`**: the actions row, both limit lines, the note row, the wells with global numbering, the reorder mode over steps and rows, the client D-623 check, and the one-sheet-with-remount-key pattern now carrying the step sheet. The empty state (zero or one step) offers Adicionar pergunta and Adicionar etapa.
- **Catalog**: the `steps` block and `reorder.mustFollow`/`mustPrecede` of `profileForm.admin.json`, every UI-SPEC string verbatim and pinned in `profile-form-12-1-steps-messages.test.ts`; the step limit is built from `{max}`.
- **Page wiring**: `loadAdminForm` returns `steps` and `stepLimit`, `page.tsx` passes them to the builder (the plan 11 hand-off), so the preview now also receives the steps.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `QuestionEditorSheet.tsx` is not in files_modified but must carry the step**
- **Found during:** Task 2 (the per-step "Adicionar pergunta")
- **Issue:** the plan says the builder "passes the id through the existing create action as stepId", but the create action is called inside the sheet, so the builder has no way to add `stepId` to the body.
- **Fix:** an optional `stepId` prop on `QuestionEditorSheet`, merged into the create body only when present (edit and replace ignore it; plan 17 owns the Etapa select and the draft field and will fold this in).
- **Files modified:** `apps/web/app/(app)/configuracoes/formulario-de-perfil/QuestionEditorSheet.tsx` (about 8 lines). Its own test file was not changed and still passes.
- **Commit:** `c74bac0e`

**2. [Rule 3 - Blocking] `lib/profile-form/admin-reads.ts` is not in files_modified but must expose the steps**
- **Found during:** Task 1 (wiring the page)
- **Issue:** the plan lists `page.tsx` but the page can only pass what `loadAdminForm` returns, and it dropped `steps` and `stepLimit` (the plan 11 hand-off names this file).
- **Fix:** `steps` and `stepLimit` on the ok result (7 lines). Its tests still pass unchanged (they assert specific fields).
- **Files modified:** `apps/web/lib/profile-form/admin-reads.ts`
- **Commit:** `c74bac0e`

### Plan-vs-reality notes (not rule deviations)

- **Reorder response is not parsed.** The plan says each action parses its response; the three step actions do. `reorderLayoutAction` does not parse the refreshed list the PUT answers, because the write has already happened, the builder keeps the order it holds and the page re-reads when "Concluir" ends the mode (the existing `reorderQuestionsAction` did the same).
- **Stale step revision has no UI-SPEC sentence.** The contract defines none, so the sheet refreshes the page and shows its existing failure line while keeping the typed title; a retry carries the newest revision (asserted).
- **Empty state gained a button.** PFORM-37 says both Adicionar pergunta and Adicionar etapa must work on a form with zero steps and zero questions, so the Phase 12 empty state's action slot now holds both (sketch 018 has no frame for it; the placement follows the actions row).
- **Disabled save vs the error frame.** The sketch shows "Escreva o título da etapa." on an empty title, which cannot appear if save is disabled for an empty title; resolved as described in key-decisions.
- **Plan 15 has no SUMMARY yet** (it is not a dependency of this plan and no file overlaps).

**Total deviations:** 2 auto-fixed (both Rule 3, both tiny edits to a file outside the list). **Impact on plan:** none on scope.
