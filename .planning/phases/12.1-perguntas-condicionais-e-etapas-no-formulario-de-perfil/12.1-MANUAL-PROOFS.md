# Phase 12.1 manual proofs (M1 to M7)

This file is the ledger of the proofs only the owner can run: a real phone, a hosted tenant project, a browser
run that needs more disk than the build machine had, the reading of choices the design review left open, the
first client's real question list, and the later cleanup. Everything an agent could build is built and proved
on the local stack (plans 01 to 18); what is left here cannot be faked, so nothing in this file is ever recorded
as done by an agent.

**The rule.** Every row ships `pending`. A row becomes `passed` only when Igor pastes the evidence of its steps
and the date, in the row, himself. An agent never edits a Status line and never writes evidence it did not
see. A phase whose ledger has a `pending` row closes `human_needed`, never green.

**The evidence rule.** Paste shapes, counts, statuses, HTTP codes, exit codes and the words the screens show.
**Never** a key, a password, a token, a connection string, an e-mail address of a member, a CSV cell or a
project ref. Replace a ref by `<ref>` and a host by `<host>` in what you paste.

**The procedures** are in `docs/DEPLOY.md`, "Phase 12.1 release (steps and conditional questions)" (written by
plan 19).

## M1 — The stepper and the builder on a real phone

- **Proves:** that the member stepper, the reveal in place, the erase dialog and the builder's step wells, step
  sheet and condition editor work on a real device against the deployed app. Phones cannot reach
  `*.localhost`, so no local run stands in for it.
- **Needs:** the homolog deploy of the release in `docs/DEPLOY.md` "Phase 12.1 release", the module switched
  on for one homolog tenant, an admin account, two member accounts and a phone (a home-screen install is
  welcome, not required).
- **Steps:**
  1. As the admin, build two steps. Put a single-choice question with three options in step 1 and a required
     question in step 2 that is shown only for the first option ("Mostrar só em alguns casos").
  2. Reorder the steps so the step with the dependent question would come first: the builder refuses with the
     sentence that names both questions and nothing moves.
  3. Open "Ver como o membro vê": "Avançar" works with no answer, the status line counts steps and questions,
     "Recomeçar" clears the answers.
  4. As the first member, answer the first option: "Etapa 1 de 2" appears, "Avançar" saves step 1, step 2
     opens with its heading in focus, "Concluir" leaves the form.
  5. As the second member, answer another option: the form ends after step 1.
  6. As the first member, open "Minhas respostas", "Editar": the steps are headings in one scroll with one
     "Salvar". Change the single choice so the second question closes: the dialog lists that question's
     title; "Rever respostas" saves nothing; "Apagar e salvar" saves and the answer is gone.
  7. As the admin, open the member: the closed question reads "Não se aplica".
  8. Look at each screen on the phone at its narrowest: no sideways scroll, every control easy to tap.
- **Evidence to paste:** one line per step ("worked" or what happened), the device and browser, the date.

## M3 — The Playwright spec that was written and not run

- **Why this row exists.** On 2026-11-05 the build machine had about 4.6 GiB free and a browser run needs more
  than 10 GiB (a Next server and three browsers drop about 9 GiB). The spec, its helpers and the
  `profile-form-web` entry of the affected map are written, pass the type check and the linter and are listed
  by `playwright test --list` (6 stories on the phone project); **none of them has been executed**, so the
  browser proof of the stepper, the reveal, the erase dialog, the builder steps and conditions, the preview and
  the 320px backstops (UI-D-661) is not recorded. The spec refuses to start under 10 GiB of free disk.
- **Needs:** more than 10 GiB of free disk, no `next dev` running, the local stack up, and a lab tenant with no
  step of its own (a fresh `pnpm db:seed`) because the 320px stepper story seeds ten steps and a tenant holds
  at most ten.
- **Precondition check:** `test $(df -k . | awk 'NR==2{print $4}') -gt 10485760 && echo enough`.
- **Command (from the repository root), watched by a disk watchdog:**

  ```bash
  rm -rf apps/web/.next/cache apps/web/.next/dev
  pnpm --filter @rede-social/web exec playwright test --project=mobile-chromium profile-form-steps.spec.ts
  ```

  Playwright starts the API and the web itself (`playwright.config.ts`); `SEED_PASSWORD` comes from
  `apps/web/.env.local`. The spec runs on the phone project only. Expect 6 tests; the module row and every
  run-prefixed row (steps included) are put back by the spec itself and it asserts that in its `afterAll`.
- **Evidence to paste:** the final line of the run ("N passed"), and for each failure the test name and the
  first error line. A failure in a spec that was never run is as likely to be the spec as the product: say
  which, and open it.
