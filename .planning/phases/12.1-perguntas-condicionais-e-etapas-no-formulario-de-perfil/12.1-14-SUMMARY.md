## Accomplishments

- **Tracer (Task 1):** one path through every layer: the server action sends `stepId` and returns `{ ok: true, destination: null, missingQuestionIds }` while the gate reports missing; `ProfileForm` walks the path, "Avançar" validates only the step's visible questions with the Phase 12 rules and error summary, saves, moves on with no toast and focus on the new `h2`; "Concluir" runs the success path; a one-step form posts the Phase 12 body and renders one card and one "Salvar".
- **Reveal (Task 2):** `RevealedField` (`AnimatePresence`, `useReducedMotion`, `border-l-2 border-border pl-3`, drops the rule when flagged, never moves focus); one `aria-live="polite"` region announces the catalog strings with titles/counts only; a draft in a closed question is kept in state and not sent; a step whose last visible question closes drops out of the path and the "Etapa x de y" count.
- **States (Task 2):** pending (`Salvando…`, controls and Voltar disabled, `aria-busy`), offline (Avançar/Concluir disabled, Voltar enabled), failure alert, 409 `form_changed` refreshed in place through `mergeFreshForm` (stays on the step or moves to the next path step), the "Falta responder ... Levamos você até lá." status notice and jump after "Concluir", returning-mode path without the jump link.
- **Floor (Task 3):** section named by its `h2`, decorative bar, real buttons in the form, 320px row classes, long-title wrapping, no half-step spacing class, the `stepper` catalog block pinned verbatim with an exact-keys check.

## Decisions Made

See `key-decisions` above. The one with product weight: a non-last step always advances after a good save even if the gate already reports a destination, because a destination at step 1 of a form whose later steps are optional would otherwise whisk the member away without ever showing them.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Hidden conditional questions filtered in every layout, not only the stepper**
- **Found during:** Task 1
- **Issue:** `validateAll`/`wireAnswers` already skip hidden questions; rendering them in the one-card layout (edit, preview) would show controls the save ignores.
- **Fix:** the shared visibility rule filters the list in all layouts; edit still has no step headings or erase dialog (plan 15) and the preview is otherwise unchanged (plan 18). No visible change for forms without conditions.
- **Files modified:** `ProfileForm.tsx`
- **Committed in:** fa412749, 6fd97722

**2. [Rule 2 - Correctness] Pinned steps keep a returning path stable**
- **Found during:** Task 1
- **Issue:** with the plan's `stepPath(view, drafts, 'returning')` alone, answering the missing question on step 1 drops step 1 from the path while the member is on it ("Etapa 1 de 2" would become "Etapa 1 de 1" mid-typing).
- **Fix:** `walkPath` unions the shared `stepPath` with visited steps that still hold a visible question. `steps.ts` is unchanged.
- **Files modified:** `ProfileForm.tsx`
- **Committed in:** fa412749

**3. [Rule 1 - Sibling assertion] Returning notice keeps its link in a one-step form**
- **Found during:** Task 1
- **Issue:** the existing Phase 12 test asserts "Ir para a primeira" in returning mode; UI-D-657 removes the link only because the stepper already starts at the first pending step.
- **Fix:** the link is dropped only when step chrome shows (two or more configured steps), so a one-step form stays exactly Phase 12 and the existing assertion holds untouched.
- **Files modified:** `ProfileForm.tsx`
- **Committed in:** fa412749

**4. [Informational] `turbo typecheck` ran a `next build`**
- **Found during:** Task 3
- **Issue:** the plan's verify command `TURBO_CACHE=local:r pnpm turbo typecheck --filter=@rede-social/web` triggered the web build through the task graph (12s, `apps/web/.next` 387 MB; disk stayed at 6.4 GiB free). No dev server, no Playwright, no Docker. No tracked file changed.
