## Regra da condição

### Which question types can OPEN other questions

| Option | Description | Selected |
|--------|-------------|----------|
| Escolha + sim/não (Recomendado) | Dropdown, multiple choice, single choice and yes/no; what the team asked for, covers the clinic case | ✓ |
| Só escolha única e sim/não | Simpler: one answer per question; multiple choice cannot open anything | |
| Qualquer tipo | Includes number, acceptance and rating; one more rule and test per type, nobody asked | |

**User's choice:** Escolha + sim/não (Recomendado)

### Where the admin defines the condition

| Option | Description | Selected |
|--------|-------------|----------|
| Na pergunta que aparece (Recomendado) | Each question has "show only if [question] is [option]"; the new question appears in place; a step with all questions hidden disappears | ✓ |
| Na etapa inteira | The whole step shows only if the answer matches (Google Forms "go to section"); one rule per group, no single revealed question | |
| Nos dois | Covers both; two rules to prove in the builder, the SQL gate and the member screen | |

**User's choice:** Na pergunta que aparece (Recomendado)

### Chains of conditions

| Option | Description | Selected |
|--------|-------------|----------|
| Só um nível (Recomendado) | The opener must always be visible; the database gate stays without recursion; widening later changes the rule, not the tables | ✓ |
| Cadeia até 3 níveis | Covers "has a clinic → what type → questions per type"; the database must compute chained visibility on every request | |

**User's choice:** Só um nível (Recomendado)

**Notes:** The "more questions or next area" check was skipped to save the user's time; the minor points (any-of for multiple choice, whether "Outro" can open, ordering of opener before shown question) were recorded as defaults in CONTEXT.md and listed to the user before writing.

## Resposta que some

### The member changes the answer that opened the questions

| Option | Description | Selected |
|--------|-------------|----------|
| Apagar ao salvar (Recomendado) | Closed questions' answers are deleted in the same save; stored equals visible; no new read filter, no stale public answer | ✓ |
| Guardar e esconder | Answer kept, ignored by gate, CSV and public profile; reappears if the member goes back; every reader needs a visibility filter; old data kept unseen (LGPD) | |
| Guardar e a equipe vê | As above, but staff still sees it marked hidden; one more state for D-593 | |

**User's choice:** Apagar ao salvar (Recomendado)

### The admin adds a condition to a question that already has answers

| Option | Description | Selected |
|--------|-------------|----------|
| Travar, como o D-587 (Recomendado) | A question with answers neither gains nor changes a condition; create a new question and archive the old one | ✓ |
| Permitir e apagar as que não valem | Condition enters and non-matching answers are deleted by the admin; contradicts D-588; needs an impact dialog | |
| Permitir e guardar escondidas | Condition enters, non-matching answers stay hidden; brings back the filter everywhere | |

**User's choice:** Travar, como o D-587 (Recomendado)

**Notes:** The question "how the member is warned before answers are deleted" was not asked; recorded as D-626 with the shape left to the UI-SPEC.

## Etapas

### What a step is, and a form with no steps

| Option | Description | Selected |
|--------|-------------|----------|
| Toda pergunta tem etapa (Recomendado) | Step = card with title and order; every question inside one; a single step renders as today's single screen; existing questions go to a default step | ✓ |
| Etapa é um separador na lista | Admin inserts a "step break" between questions; lighter but the step has no own title to show | |

**User's choice:** Toda pergunta tem etapa (Recomendado)

### When a step's answers are saved

| Option | Description | Selected |
|--------|-------------|----------|
| A cada "Avançar" (Recomendado) | Avançar validates and saves; the member resumes where they stopped; the save must stop refusing missing required questions of other steps; the gate releases after the last step | ✓ |
| Só no fim, de uma vez | Steps held in browser memory, one save as today; closing the app loses input unless a local draft is kept | |

**User's choice:** A cada "Avançar" (Recomendado)

### Editing later from the profile

| Option | Description | Selected |
|--------|-------------|----------|
| Tela única com títulos (Recomendado) | All steps stacked under their titles with one Save; return after a new required question shows only steps with something missing | ✓ |
| As mesmas etapas, com Avançar | Same experience as the first fill; one screen fewer to design but editing one answer costs many taps | |

**User's choice:** Tela única com títulos (Recomendado)
