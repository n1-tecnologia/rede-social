## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web content (including embedded frames on Android) to the native bridge | any script in the view can call `postMessage` |
| the view to the rest of the internet | links and redirects can steer the view |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-13-48 | Spoofing / Elevation | a crafted or flooded bridge message, or a message from an embedded frame, triggering native actions | medium | mitigate | origin check on the top-level URL, strict schema and byte cap, 20 messages per second, a closed handler table, `share` restricted to the tenant host so the share sheet is no phishing helper, and no handler can read a token or call the API; on Android an embedded frame can still post (the interface is page-wide, accepted at ASVS L1) but can trigger only the bounded actions above |
| T-13-49 | Tampering / Open redirect | a link, a `target=_blank`, a redirect chain or a notification path steering the view to another host | high | mitigate | `classifyUrl` on every navigation and window request; external hosts go to the system browser, never the view; `resolveEntryPath` accepts only `PUSH_PATH` paths and falls back to `/inicio`; table tests with the hostile inputs |
</threat_model>
