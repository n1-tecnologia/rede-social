# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design authority.** `reference/frontend-design/` (git `05f68b1`) is the visual source of truth for everything it covers. Values marked **[proto]** are extracted verbatim from `components/feed/*`, `components/comments/*`, `components/create/CaptionInput.tsx`, `components/ui/DoubleTapHeart.tsx` and `hooks/useInfiniteScroll.ts`. Surfaces the prototype lacks — the composer `/criar`, the edit screen `/post/[id]/editar`, the link-preview card, the attachment row, the composer FAB and its desktop equivalent — are marked **[designed]** and use only tokens and primitives already shipped in `@rede-social/ui` / `@rede-social/core/ui`. The design language, spacing scale, typography scale and colour model are **inherited unchanged** from the approved `02-UI-SPEC.md` and `03-UI-SPEC.md`; this document restates them for the checker and records only the Phase 4 deltas.

**Upstream decisions.** `04-CONTEXT.md` decisions are cited as **D-nn** (this phase owns D-51..D-65); `04-RESEARCH.md` patterns/assumptions as **R-Pn** / **A-n**. Nothing in those documents is re-litigated here. Questions that both left open and that are purely visual are decided below as **UI-D-07..UI-D-24** (UI-D-21..UI-D-24 were raised by the Step 9.5 UI-consideration probe and answered by the user) (numbering continues from `03-UI-SPEC.md`, which used UI-D-01..UI-D-06).

**Review pattern (D-33, UI-04).** The `[designed]` surfaces — `/criar`, `/post/[id]/editar`, the FAB / desktop compose CTA, the link-preview card, the attachment row and the post "…" menu — go through `/gsd-sketch 4` (static HTML mockup rendered from this contract) and design-team approval **before they are coded**. `[proto]` surfaces (the post card family, the comment sheet, the comment list) do not. The same package is the vehicle for telling the design team that PROTOTYPE.md open question 2 is answered "drop titles and type chips" (D-51) and for requesting the composer designs named in open question 3.

## Phase 4 Visual Decisions (UI-D)

| # | Question left open upstream | Decision | Rationale / reversibility |
|---|---|---|---|
| **UI-D-07** | The prototype's `PostActions` icon buttons are `h-9 w-9` (36px) and its comment like button is a bare 14px `Heart` — both below the 44px touch minimum `02-UI-SPEC.md` declared. | Every post/comment action is a **44×44 `IconButton`** (glyph 20 on the card, 16 in a comment row). The card's action row is offset `-ml-2.5` so the leftmost glyph stays optically on the 16px gutter and the row keeps the prototype's density. | WCAG 2.5.5 / Apple HIG outrank the prototype's geometry, and the like control is the single most-tapped target in the product — a 36px heart on a moving list is a miss-tap generator. Same class of departure as UI-D-04 (the 16px search field). Reversible: a size prop. |
| **UI-D-08** | The like heart's colour. `[proto]` hardcodes `text-red-500 fill-red-500`; the repo bans hex/legacy classes and `--color-danger` is reserved for destructive actions. | A **new semantic token `--color-like: #ef4444`** (light and dark) in `packages/ui/src/styles/tokens.css`. The liked heart, the comment-row liked heart and the `DoubleTapHeart` burst use `text-like fill-like`. It is **not** the accent and **not** `--color-danger`. | Same value as danger today, different meaning: a like is affective, not destructive, and a Phase 8 danger-palette change must not move it. Colouring the heart with the tenant accent was rejected — a green or purple heart loses a universally-read affordance, and the brand is already everywhere else in the shell (D-52's reasoning). Reversible: one token. |
| **UI-D-09** | Post image sizing. `[proto]` uses `w-full object-cover aspect-auto`, which reflows as each image decodes. | Every post image renders in a box with an **explicit ratio derived from the asset's stored width/height, clamped to `[4:5, 1.91:1]`**. In a gallery **all slides share one ratio — the first image's clamped ratio** — so swiping never jumps. Ground `bg-bg-tertiary`. | Phase 3's rule ("an explicit aspect ratio so nothing reflows while it loads") is a CLS contract, and a carousel whose slides differ in height is the worst version of it. The clamp stops a 9:16 phone photo from eating a whole screen. The derived axis is exempt from the multiple-of-4 rule (UI-D-06, inherited). Reversible. |
| **UI-D-10** | The carousel dot colour. `[proto]` active dot is `bg-accent` over the photo. | Dots sit inside a **scrim pill** `rounded-full bg-black/45 px-2 py-1 gap-1.5`, active dot `bg-white`, idle `bg-white/45`, 6px each. **Not the accent.** | A tenant hex over an arbitrary photograph has no guaranteed contrast; a white dot on a fixed scrim always does. This is why the dots are absent from the accent reserved list. Reversible. |
| **UI-D-11** | The link preview's pending state (A-7: the unfurl is a worker job, so the card cannot resolve before publish). | **There is no pending card.** While `status = 'pending'`, `'failed'`, or the target carries no OG tags, the post renders the **bare auto-linked URL inside the caption and nothing else**. The preview card appears only on `status = 'resolved'`. In the **composer** the admin sees an inert row "Prévia do link · A prévia aparece assim que carregarmos o link." with a ghost "Remover prévia". | A skeleton card that may never resolve is indistinguishable from a broken one (A-8). One visible transition, zero empty frames. The composer row exists because the admin needs to know the link was recognised and needs the remove affordance — that answers the discretion question "can the admin remove a resolved preview" with **remove yes, override no**. Reversible. |
| **UI-D-12** | YouTube/Vimeo rendering (A-6: no CSP exists in `apps/web` today). | The **same preview card**, thumbnail-only, with a centred 56px `rounded-full bg-black/60 text-white` play badge (`Play` 24, filled) and the provider name in the 12px meta slot. Tapping opens the video **externally** (`target="_blank" rel="noopener noreferrer"`). **No iframe ships in this phase.** | Shipping a third-party frame into a private branded community with no CSP is a Phase 8 problem created in Phase 4. One code path with the OG card. Costly to reverse only in the sense that inline playback needs a real CSP first — which is exactly the point. |
| **UI-D-13** | A URL the SSRF policy refuses at create time. | **Silent.** The post publishes, the link renders bare, and the admin is told nothing about the refusal. | An error that distinguishes "blocked host" from "no preview" is an oracle an admin could use to probe the internal network. It is also indistinguishable, to an honest admin, from a site with no OG tags — which already renders bare. |
| **UI-D-14** | Relative timestamps ("há 2 h") against the no-`Date.now()`-in-render rule (`02-UI-SPEC.md`, hydration). | The relative string is **formatted on the server** and passed as a prop; the DOM is `<time dateTime={iso} title={absolute}>{relative}</time>` with the absolute value from `Intl.DateTimeFormat('pt-BR', { timeZone: tenant.timezone })`. Client-inserted items (a just-posted comment) render "agora". | Keeps every existing hydration guarantee and still gives the prototype's density. Reversible: one formatter. |
| **UI-D-15** | The "editado" marker (Open Question 2). | `edited_at` is set on **any** persisted change, media included. The marker renders as plain "editado" appended to the timestamp with a middot — `há 2 h · editado` — 12/400 tertiary, **no timestamp of its own**. | Matches the prototype's meta-row density and FEED-03's wording verbatim. A second date in a 12px meta row is noise. Pinned by a test so a later change is deliberate. |
| **UI-D-16** | A soft-deleted post's share link vs the cross-tenant link (Open Question 3, D-56). | **404 for both, one identical screen** ("Publicação não encontrada"). The two take distinguishable branches in code; the user cannot tell them apart. | D-23's precedent, already applied to `/membros/[id]` in 03-05: one indistinguishable screen for every miss removes a whole class of "did this exist?" probes. |
| **UI-D-17** | Where the composer entry point lives on desktop (D-57 only fixes the mobile FAB). | Mobile: the 56px FAB. Desktop (`≥ md`): **no floating button** — a `Button variant="brand"` "Criar publicação" sits in the feed widget's header row at the top of the 680px column. | A floating thumb-reach control over a centred column next to a rail has no rationale; it also collides with the desktop `Toast` anchor. Reversible: one branch. |
| **UI-D-18** | Comment-sheet height. `[proto]` `CommentSheet` sets `max-h-[calc(var(--screen-h)*0.7)]`; the shipped `BottomSheet` uses `0.8`. | **0.8** — the shipped primitive's value, unmodified. | One sheet geometry across the app. A per-caller override is the drift `@rede-social/ui` exists to prevent. |
| **UI-D-19** | Does the D-02 profile nudge stay above the feed once the feed has content? | **Yes, unchanged.** The nudge is the server's `needsNudge` flag and disappears on its own when the profile is complete. | Suppressing it whenever the feed has posts would make it permanently invisible on any active tenant — i.e. never shown to the members who most need it. Zero code. |
| **UI-D-20** | What `/inicio` shows a member of a tenant with no posts, given `HomeSlots` already owns an "Em breve" empty. | The feed widget renders **its own** `EmptyState variant="card"`; `HomeSlots`' "Em breve" card no longer appears because a slot **is** registered. Admin variant of the same empty carries the "Criar publicação" CTA. | `HomeSlots`' empty means "no module contributed anything", which stops being true this phase. Two different truths must not share one card. |
| **UI-D-21** | What a post card's meta row shows when both counts are zero (Step 9.5 probe, `empty`/`partial`/`zero-one-many` @ E02). | **Zero counts drop out.** Each of "{n} curtidas" and "{n} comentários" is omitted until it reaches 1; a brand-new post's meta row is the relative time alone. The row joins only the present segments with `<span aria-hidden>·</span>` — never a leading, trailing or doubled middot. | The comment row already hides its own like count at zero **[proto]**, so "0 curtidas · 0 comentários" would be the one place in the product that announces the absence of engagement — on every post in a new tenant's feed, which is exactly when it reads worst. No new copy. Reversible: one conditional. |
| **UI-D-22** | What renders when the **comment list itself** fails to load — opening the sheet, or tapping "Ver N respostas" (probe, `error` @ E10/E11). The spec covered comment *submit* failure only. | **Inline error + retry in both containers.** A 14 `text-danger` line plus an `outline` "Tentar novamente" renders where the rows would be, with the input still usable; a failed replies query renders the same inline retry under the toggle without collapsing it. Two new copy rows. | Falling back to the empty-comments copy would assert something false — the user would read "Nenhum comentário ainda" on a post that has comments, and would have no way to recover. A generic toast alone leaves the sheet showing the same wrong fact. Reversible. |
| **UI-D-23** | Tapping an `AttachmentRow` requests a short-TTL signed download URL — a round trip that can be slow or fail (probe, `loading`/`error` @ E07). | **Row-local pending, generic toast on failure.** The trailing `Download` glyph swaps to a 20px `Loader2` and the row goes `aria-busy` while the URL is fetched; a second tap while busy is a no-op. On failure the glyph returns and the generic error toast fires, leaving the row tappable. No reflow, no new copy. | A tap with no feedback reads as a dead control and invites repeat taps, each one burning a signed URL. Growing the row with an inline error line instead would reflow the card mid-list. Reuses the existing generic-error rule (same as the like failure). Reversible. |
| **UI-D-24** | What a comment renders once its author's membership is soft-deleted (probe, `partial` @ E11). Phase 8 moderation will build on this. | **The row stays; the author reads "Membro removido".** Text and replies are preserved, the avatar falls back to the neutral placeholder, and the name is plain text, not a profile link. One new copy row. | Hiding the comment would orphan every reply under it and force the trigger-maintained counts to be recomputed; keeping the real name would give a removed member continued presence in the community. This keeps threads readable while removing the person. Reversible, and it is the shape Phase 8 (MODER-01) will extend. |

## Spacing Scale

Inherited verbatim from `02-UI-SPEC.md` **[proto]** — the prototype's gutter is `px-4`, list gap `gap-3`, section gap `mb-6`, controls `py-3`. Phase 4 introduces **no new scale value**.

| Token | Value | Usage in Phase 4 |
|-------|-------|------------------|
| xs | 4px | Icon-to-text gaps, dot gaps inside the carousel scrim pill, the meta-row middot spacing |
| sm | 8px | Attachment list gap (`gap-2`), action-row gap (`gap-1` glyph spacing inside the 44px targets), progress-bar inset |
| md-s | 12px | Card gap in the feed column (`gap-3`) **[proto]** `mb-3`; comment row gap (`gap-3`); post header inner gap (`gap-2.5` is the 10px `[proto]` exception below) |
| md | 16px | Page gutter and card inner gutter (`px-4`), comment/post vertical padding (`py-3`), composer field gap |
| lg | 24px | Section spacing inside the composer (`gap-6`), desktop content gutter (`px-6`), `/inicio` slot gap |
| xl | 32px | Composer section break between media and attachments on desktop |
| 2xl | 48px | TopBar height, desktop content top padding |
| 3xl | 64px | `EmptyState` icon circle, `EmptyState` vertical padding (`py-16`), the empty-comment-list vertical padding (`py-10` is the exception below) |

Exceptions — all inherited from `02-UI-SPEC.md` / `03-UI-SPEC.md` unless marked *(new)*:
- **44px** minimum touch target for every icon-only control (UI-D-07 makes this the rule for the whole post/comment action set) — Apple HIG / WCAG 2.5.5.
- **56px** *(new)* the composer FAB diameter; **56px** the link-card play badge; **56px** (`pl-14`) the reply indent **[proto]**; **56px** (`min-h-14`) the attachment row minimum height. All multiples of 4, listed for clarity.
- **40px** *(new)* the attachment row's leading icon square (`rounded-xl bg-bg-tertiary`).
- **10px** (`gap-2.5`) the post header's avatar-to-name gap **[proto]** — rendered verbatim, not normalised.
- **6px** (`h-1.5 w-1.5`, `gap-1.5`) *(new)* carousel dot diameter and dot gap **[proto]**; **6px** (`py-1.5`) pill vertical padding **[proto]**.

Desktop keeps the 680px column and the rail; no TopBar/BottomNav change.

**Share (FEED-07).** The `Send` action calls `navigator.share({ url, title })` when available, else copies the URL and toasts "Link copiado.". The URL is built **server-side from the tenant's verified primary host** (`https://{primaryHost}/post/{postId}`) and handed to the card as a prop — never `location.origin`, so an alias host never leaks into a shared link. A logged-out visitor opening it is routed through login by the existing `(app)` layout + `requireBootstrap()` redirect and lands back here; a member of another tenant, and a soft-deleted post, both get the identical 404 screen (UI-D-16).

## Motion & Accessibility

- Springs and easings are the shipped ones; Phase 4 adds: the like pulse `scale [1, 1.2, 1]` / 300 ms / `easeInOut` **[proto]**, the `DoubleTapHeart` burst (spring `damping 8 / stiffness 200`, 900 ms life, 400 ms opacity exit) **[proto]**, and the `CommentInput` submit spring-in **[proto]**. All import `motion/react`.
- `prefers-reduced-motion: reduce`: the like pulse and the burst scale animations are disabled (the burst still renders and fades), the `Skeleton` shimmer is static, and the carousel uses `scroll-behavior: auto`.
- Every icon-only control is 44×44 with a required `label` (UI-D-07); decorative glyphs and the middots are `aria-hidden`.
- Like/unlike announces through the button's `aria-pressed` state; the count is inside an `aria-live="polite"` region so a screen reader hears the change without re-reading the card.
- The carousel is keyboard-operable (`tabindex="0"`, ←/→), announces "{i} de {n}", and exposes each slide's alt text from the asset (empty `alt=""` when the admin gave none — decorative, never a filename).
- `BottomSheet` keeps `role="dialog" aria-modal="true"` + focus trap + Escape; opening the comment sheet moves focus to the sheet title, closing returns it to the comment button that opened it.
- Errors render with `role="alert"`; toasts with `role="status"`.
- No `Date.now()` in render (UI-D-14); no `dangerouslySetInnerHTML` anywhere in the feed (D-54).
- Images: `loading="lazy" decoding="async"` on every card image except the first card's first image (eager — it is above the fold on `/inicio`).
