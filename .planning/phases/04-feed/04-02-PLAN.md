  <behavior>
    - `useInfiniteScroll({ onLoadMore, hasMore, rootMargin })` returns `{ sentinelRef, isLoading }`. With `hasMore: false` the observer is never created and `onLoadMore` is never called.
    - When the sentinel intersects and `hasMore` is true, `onLoadMore` is called exactly once; a second intersection fired while the first promise is still pending calls it zero additional times (re-entrancy guard on `isLoading`).
    - After `onLoadMore` resolves, `isLoading` returns to false and a subsequent intersection calls it again.
    - When `onLoadMore` rejects, `isLoading` returns to false and the rejection is not rethrown into render (the consumer renders its own retry).
    - The observer's `root` is `useScrollContainer()?.current ?? null`; rendered inside a `ScrollContainerProvider` the constructed observer receives that element, and rendered outside it receives `null` (the document scrolls). An explicit `root` prop overrides both.
    - `InfiniteScroll` with `hasMore: false` renders no DOM node at all (`container.firstChild` is null). With `hasMore: true` it renders the sentinel; while loading it additionally renders exactly one skeleton block, and never two.
  </behavior>
  <action>
    Create `packages/ui/src/hooks/useInfiniteScroll.ts` (`'use client'`) mirroring `usePullToRefresh`'s shape: options `{ onLoadMore: () => void | Promise<void>; hasMore: boolean; rootMargin?: string; root?: Element | null; enabled?: boolean }`, defaults `rootMargin: '200px'` and `threshold: 0` per the UI-SPEC row. Resolve the observer root as `root !== undefined ? root : (useScrollContainer()?.current ?? null)` — the context ref is the default and the prop is the override. Never look the scroll container up from the document; the prototype's hardcoded element lookup is the exact coupling `ScrollContainerContext` was introduced to remove (PROTOTYPE risk 2), and the acceptance criteria grep for it.

    Guard re-entrancy with a ref-backed `loadingRef` in addition to the `isLoading` state, because an IntersectionObserver callback can fire again before React commits the state update: the callback returns early when `loadingRef.current` is true, sets it before awaiting, and clears it in a `finally`. Recreate the observer when `root`, `rootMargin`, `hasMore` or `enabled` changes, and disconnect it in the effect cleanup.

    Create `packages/ui/src/layout/InfiniteScroll.tsx` (`'use client'`): props `{ hasMore: boolean; onLoadMore: () => void | Promise<void>; skeleton?: ReactNode; enabled?: boolean; rootMargin?: string; root?: Element | null; className?: string }`. Return `null` when `hasMore` is false — no terminal spacer and no end-of-list copy (UI-D / E17: the sentinel renders nothing when there is no next cursor). Otherwise render a sentinel `div` carrying `sentinelRef` with `aria-hidden` and, while `isLoading`, exactly one `skeleton` node beneath it. The component holds no copy of its own — a consumer that wants a retry line renders it itself.

    Export both from `packages/ui/src/index.ts` in the existing alphabetical grouping (`InfiniteScroll` with the layout exports, `useInfiniteScroll` with the hooks), exporting the prop and option types alongside, as every other entry does.
