## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| composer input → the post row | every asset id, caption and link in the body is untrusted and is validated against the caller's own tenant before it becomes a row |
| permission → authorship | holding the manage permission is not the same as owning the post; V1 requires both |
| a destructive action → the confirmation | the dialog must not become a content-rendering surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-54 | Elevation of Privilege | one tenant admin editing or deleting another admin's post | high | mitigate | The update statements carry `author_user_id = ctx.userId` in addition to the route's permission guard; zero rows is a bare 404, so a second admin cannot even probe existence; integration-pinned with the author's positive control in the same test |
| T-04-55 | Elevation of Privilege | a member reaching the composer or the write routes | high | mitigate | Both routes carry `requirePermission('feed.post.manage')`; the composer route refuses through the bootstrap path; the create control reads the composed permission, never a role |
| T-04-56 | Tampering | attaching another tenant's asset during an edit | high | mitigate | `updatePost` runs the SAME asset-validation helper `createPost` uses, in the tenant lane, so a foreign asset is invisible and answers the shared refusal code |
| T-04-57 | Tampering | resurrecting or half-updating a deleted post | medium | mitigate | The edit predicate carries the live-row filter, so a delete deterministically wins the race; integration-pinned with the delete performed through the admin connection |
| T-04-58 | Information Disclosure | a caption or filename quoted into a destructive dialog | low | mitigate | All three confirmation bodies are fixed, non-interpolated strings; grep-gated against interpolation tokens |
| T-04-59 | Denial of Service | file bytes routed through the API | high | mitigate | The composer uploads directly to storage with a brokered signed URL; no feed route accepts a file body, gated in 04-04 |
| T-04-60 | Repudiation | who edited or deleted a post | medium | accept | `edited_at`, `deleted_at` and `author_user_id` are on the row and the two events carry the actor; a full append-only moderation log is Phase 8's MODER-03 |
