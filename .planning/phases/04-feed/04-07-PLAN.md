## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member text → another member's screen | a comment body is member-authored content rendered to the whole tenant |
| viewer identity → the delete affordance | `canDelete` is computed server-side; the client rendering it is a convenience, and the API re-checks |
| removed membership → the rendered author | a soft-deleted membership must remove the person without removing the thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-43 | Tampering | stored XSS through a comment body | high | mitigate | Plain-text storage, React's default escaping, the shared auto-linker restricted to `http(s)` with the link relationship attributes; no HTML-injection sink in any comment component, grep-gated |
| T-04-44 | Elevation of Privilege | deleting another member's comment from the client | high | mitigate | `canDelete` is server-derived and the API's update predicate carries the author check independently; an e2e case asserts the control is absent on someone else's row and 04-03's integration case asserts the API refuses it |
| T-04-45 | Information Disclosure | a removed member keeping a presence in the community | medium | mitigate | UI-D-24: the row survives, the person does not — the name is replaced by a fixed label and the profile link is removed; the projection returns a null membership id so the client cannot reconstruct the link |
| T-04-46 | Information Disclosure | a failed list asserting a false fact about a post | medium | mitigate | UI-D-22: the error branch and the empty branch are mutually exclusive by construction, gated in code and asserted in the e2e |
