## Phase Goal

**As a** member of a tenant, **I want to** open my organization's own domain and see its branded, installable app on phone and desktop — branded already on the login page — **so that** the community feels like my organization's, not the platform's. **As** the platform's `super_admin`, **I want to** provision a tenant end-to-end (branding, modules, custom domain, first admin) from the platform panel on the platform domain, **so that** no tenant setup touches the database.

<objective>
Two UI contracts that gate the screen plans: (1) the pt-BR message catalog reorganised into per-namespace files with a deterministic loader and a lint guard for literals, so four wave-3 plans can add strings in parallel (PWA-03); (2) the D-33 design-review gate — a static HTML mockup of every screen the prototype lacks, rendered with the real token file, approved by the design team before those screens are coded (UI-04).

Purpose: keeps the human approval off the API critical path (schema, services, adapters and mail run in parallel in waves 2-3) while making PWA-03 enforceable by a script instead of by review.
Output: `messages/pt-BR/*.json` + `i18n/messages.ts` loader + `check-ui-literals.sh` + web vitest; `.planning/sketches/001-phase-02-designed-screens/` with recorded approval.
</objective>
