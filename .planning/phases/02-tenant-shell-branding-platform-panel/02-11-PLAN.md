## Phase Goal

**As a** member of a tenant, **I want to** open my organization's own domain and see its branded, installable app on phone and desktop — branded already on the login page — **so that** the community feels like my organization's, not the platform's. **As** the platform's `super_admin`, **I want to** provision a tenant end-to-end (branding, modules, custom domain, first admin) from the platform panel on the platform domain, **so that** no tenant setup touches the database.

<objective>
Make the tenant shell an installable PWA (PWA-01): a per-tenant manifest served from a host-authoritative, `no-store` route handler (`name`/`short_name` = display name, `theme_color` = persisted `colors.primary` per D-25, icons from the D-28 derived set with a neutral platform fallback, `id: '/?tenant=<slug>'`, `start_url`/`scope` `/`), `generateMetadata`/`generateViewport` in the root layout so every route — the login page included — links the manifest, icons and `theme-color`; a Serwist service worker built by `@serwist/turbopack` that precaches only the app shell and never stores authenticated data, with a pt-BR `/~offline` fallback and a `useOffline` banner; standalone-mode detection mirrored to `<html data-display-mode>`; the iOS "Adicione à Tela de Início" hint component built and deliberately left unmounted (Phase 7); Playwright coverage on iPhone 14 + Pixel 7 + desktop against a production build.

Purpose: ROADMAP success criterion 4 ("installable as a PWA and runs in standalone mode on iOS and Android") and the PWA half of criterion 1 (`theme-color`, manifest name per host, no cross-tenant leakage). Proving manifest → SW → standalone on one seed tenant first (tracer) catches a wrong route shape or a proxy redirect before the offline/install expansions land.

Output: `apps/web/lib/manifest.ts` + `app/m/[slug]/manifest.webmanifest/route.ts`, `app/sw.ts` + `app/serwist/[path]/route.ts`, `components/pwa/{ServiceWorkerRegister,OfflineBanner,InstallHint}.tsx`, `app/~offline/`, `public/icons/rede-social-*.png`, `messages/pt-BR/pwa.json`, `e2e/pwa.spec.ts` + `playwright.pwa.config.ts`, root layout metadata/viewport, `next.config.ts` (`withSerwist`, `experimental.useOffline`, `headers()`), the `_rede`-admitting widening of the manifest PUBLIC regex in `proxy.ts` (the three PWA entries themselves were pre-registered by 02-08).
