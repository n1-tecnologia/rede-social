Close three defence-in-depth / robustness warnings from 02-REVIEW.md that touch three different layers and no file of plan 02-17 or 02-19, so this plan runs in the same wave as 02-17:

- **WR-05** — `apps/api/src/routes/me.ts` bootstrap selects the membership by `user_id` only. CLAUDE.md's tenant-scoping rule is three independent layers ("one missing `where` leaks tenants") and the schema is born V2-ready; add the explicit `tenant_id` + `deleted_at IS NULL` predicate through a small kernel helper so the rule is greppable and reusable by later phases (profile, members directory).
- **WR-06** — `apps/web/lib/tenant-host.ts` fetches `/v1/public/tenants/by-host` on the request path (`proxy.ts` and every layout's `generateMetadata`) with no timeout; a cold / throttled Cloud Run stalls every uncached host until Node's socket timeout and the fail-open to `generic` never triggers. Add `AbortSignal.timeout(2_000)` (tight: interactive path; the API-side adapters use 10 s) and keep the `catch` → 10 s error TTL.
- **WR-07** — `useSignedUpload.onFile` awaits three async steps without try/catch; a rejected server action leaves `busy.current = true` and the zone stuck in `progress` until a reload. Wrap the body, route every rejection through the existing `fail(t('errors.generic'))`, log `platform.branding.upload_failed`, and prove a second drop is accepted.

Purpose: each fix removes a silent failure mode a real user hits (wrong-tenant risk in V2, a hanging web tier, a stuck upload zone) and pins it with a unit test so the phase's exit gate (`pnpm verify`) keeps it closed.
