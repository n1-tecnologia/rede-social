<objective>
Close the single verified gap of Phase 2 (02-VERIFICATION.md truth #9, review CR-01) and the adjacent review warning WR-01, both in `packages/core/server/platform/domains.ts`:

1. **CR-01 (blocker):** `checkDomain`'s `catch` around `domainProvider.verify` records `lastCheckedAt`/`lastError` and returns `pending` without re-arming the poller and without applying the 7-day deadline; `domains/verify-job.ts` only re-arms when `checkDomain` THROWS, which it deliberately never does. One Vercel 429/5xx/timeout or provider-schema mismatch therefore kills the poller for that host until a super_admin presses "Verificar agora". The fake provider never throws, so no local or CI run reaches the branch. This plan adds a deterministic failure switch to the fake provider (`provider-fails-once`), fixes the branch (deadline → `expired`, else re-arm inside the same admin transaction that records the error), fixes the docblock promise, and proves it end to end: throwing provider → row re-armed → NEW job waiting in `pgboss.job_common` → next run verifies; throwing provider past the deadline → `expired`, nothing re-armed.
2. **WR-01:** `ensureVerifiedSideEffects` writes `last_error = 'allow_list' | 'invite'` on failure but nothing ever clears it after a successful retry, so the Domínios card offers "Verificar agora" forever. It now reports whether both side effects succeeded and the callers clear `last_error` on success in both the `already_verified` and the `verified` branch.
