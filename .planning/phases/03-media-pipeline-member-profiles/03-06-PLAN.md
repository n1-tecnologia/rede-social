## Phase Goal

**As** the tenant's `admin_tenant`, **I want to** upload a phone-recorded video that just plays for everyone, **so that** the platform accepts every kind of media a real community produces without ever leaking one community's files to another.

<objective>
Video ingest (MEDIA-03): the media broker grows a **provider-neutral video seam** — a `VideoProvider` interface with an env-selected `fake` (default everywhere but production) and `mux` implementation, following the `packages/core/server/domains/{types,fake,vercel,index}.ts` precedent exactly. `POST /v1/media/uploads { kind: 'video' }` mints a direct-upload URL, the browser uploads straight to the provider, and a signature-verified webhook lands the provider's `ready`/`errored` events, which a pg-boss job applies to the `media_assets` row idempotently and out-of-order-safely.

Purpose: MEDIA-03's ingest half, and the second half of the 03-01 assumption-delta `promote` decision — the asset is primary and the vendor is one implementation behind the interface, so Cloudflare Stream (the documented cheaper alternative) would be a new file rather than a rewrite (D-43). The playback token, the player and the admin screen are 03-07.
Output: `@mux/mux-node` installed behind a legitimacy checkpoint, five new env vars with their `assertProductionEnv` rule, `packages/core/server/media/video/*`, `media_provider_events` with its migration and zero-policy pin, the webhook route, the event job, the worker registration, `docs/DEPLOY.md`, and unit + integration tests that run entirely against the fake.

**Decision — video upload is `admin_tenant`-only in V1.** ROADMAP criterion 4 is written as an `admin_tenant` capability and PROJECT.md fixes V1 as admin-publishes-only. `startUpload` refuses `kind: 'video'` for any other membership role with `403 FORBIDDEN`. V2's member posting removes one predicate; Phase 5's stories will add a `story` purpose to the same table rather than a second rule.

**Decision — the fake provider uploads into the real private bucket instead of a dev-only sink route.** The obvious fake would accept bytes at a throwaway API endpoint, which would put a body parser in the API and quietly contradict MEDIA-01's structural rule. Instead the fake mints a Supabase signed upload URL under the asset's own prefix in the `media` bucket and simulates transcoding with a deferred `kernel.media-provider-event` carrying a synthetic ready event. Every automated proof in this phase therefore exercises the real browser→Storage path, and no byte-accepting route exists anywhere.

**Open question carried forward (RESEARCH Open Question 1, answered here).** No Mux account exists and Phase 01.1 (cloud provisioning) is deferred to the end of the project. All of this plan's automated proof runs against the fake; the real Mux transcode and the real-device HLS playback become explicit Phase 01.1 runbook items and known-blocked UAT lines, exactly like Phase 2's four blocked items. 03-08 records them.
</objective>
