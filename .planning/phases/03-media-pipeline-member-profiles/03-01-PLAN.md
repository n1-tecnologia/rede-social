## Phase Goal

**As a** member of my organization's community, **I want to** upload my photo from my phone, edit my name and bio, and find the other members by name, **so that** the community is made of recognisable people rather than anonymous accounts — and **as** the tenant's `admin_tenant`, **I want to** upload a phone-recorded video that just plays for everyone, **so that** the platform accepts every kind of media a real community produces without ever leaking one community's files to another.

<objective>
The media broker keystone (MEDIA-01, MEDIA-02, TENANT-04): a tenant-lane `POST /v1/media/uploads` validates kind/purpose/mime/size against the caller's membership and the tenant's storage ceiling, records a `pending` `media_assets` row and mints a signed upload URL into the PRIVATE `media` bucket; the browser uploads the bytes directly to Storage; `complete` re-reads the object from Storage, decodes only the image header, and enqueues a worker job that derives the purpose's WebP width ladder under immutable keys; `GET /v1/media/{assetId}/{variant}` answers a `302` to a freshly signed Storage URL **with zero database reads**, which is what makes cross-tenant access structurally impossible rather than check-dependent.

Purpose: this is the one contract Phases 4–6 reuse for every image, attachment and (from 03-06) video. It is also the isolation keystone: ROADMAP criterion 4's "a tenant-B session cannot obtain a signed URL for a tenant-A object" holds because the object key is a pure function of the **caller's own** tenant id.
Output: `packages/contracts/src/media.ts`, `packages/core/db/schema/media-assets.ts`, the `packages/core/server/media/*` kernel area, `apps/api/src/routes/media.ts`, the worker registration, the private bucket (config + hosted migration), pgTAP `070`, unit + integration tests.

**Decision — the original object key carries no extension.** RESEARCH Pattern 1 writes the original as `<tenant_id>/media/<assetId>/original.<ext>`, which is NOT derivable without a database read (the ext is a row fact). This plan stores it as `<tenant_id>/media/<assetId>/original` and keeps the mime in `media_assets.mime` and in the Storage object's `contentType`. The whole key space — original and every variant — is therefore a pure function of `(tenantId, assetId, variant)` and the serve route needs no row. This is the single change that delivers R-05's "0 DB reads on the hot path" for `original` as well as for `w<width>`.

**Decision — `MEDIA_LIMITS` lives in `@tria/contracts/media`, not in `server/media/limits.ts`.** The browser needs the same table for its pick-time UX gate (the Phase 2 `classifyFile`/`BRANDING_MAX_BYTES` precedent in `apps/web/lib/upload.ts`). `limits.ts` keeps only what must not reach a bundle: the per-tenant ceilings and the sharp decoder guards.

**Decision — the `file` kind (A7) ships at the broker level this phase, `application/pdf` only, with no UI.** The phase goal sentence says "images, files and phone video"; a PDF needs no decoder, only a 5-byte `%PDF-` magic check, so it costs one branch and removes any need for the flagged `file-type` package. The attachment *UI* stays Phase 4 (MEDIA-04 territory).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member session → `/v1/media/*` | a tenant member mints upload targets and read redirects; the ONLY source of the Storage key prefix is `ctx.tenantId` from the verified Bearer's membership of record |
| browser → Supabase Storage (signed upload URL / TUS) | untrusted bytes land in the private bucket without passing through the API; Storage enforces size and mime, the API validates the object afterwards |
| API/worker → Storage (service key) | download of untrusted bytes for header inspection (request path) and full decoding (worker) |
| worker (`sharp` / libvips) | native image decoding of member-supplied files |
| signed read URL → any holder | a 3600 s bearer-free URL that grants read of one object for its lifetime |

## Handoffs to later plans

- **03-02 (profiles)** — `media_assets` exists with `purpose: 'avatar'`; a profile stores `avatar_asset_id uuid references media_assets(id)` and renders `mediaVariantUrl(assetId, 'w128')`. `assetView` is the shape a profile payload embeds if it ever needs more than the URL.
- **03-04 (web upload)** — `POST /v1/media/uploads` body `{ kind, purpose, mime, size, filename? }` → 201 `{ assetId, provider, signedUrl, token, path, maxBytes, resumableThresholdBytes }`; `token` is what TUS needs in `x-signature` and `path` is the TUS `objectName`; refusals 400 `{ media: 'type_not_allowed' | 'heic_unsupported' | 'not_an_image' | 'format_mismatch' }`, 413 `{ media: 'too_large' | 'quota_exceeded', maxBytes }`, 404 `{ media: 'object_missing' }`. Use `classifyMediaFile` + `mediaAcceptFor` from `@tria/contracts/media` for the pick-time gate, exactly as `apps/web/lib/upload.ts` uses `classifyFile` today. Render images with `<img src={mediaVariantUrl(id,'w320')} srcSet=…>` — never an inline signed URL.
- **03-06 (video)** — replace the `501 { media: 'video_provider_missing' }` branch in `startUpload` with the `VideoProvider` adapter; the row's `provider`, `provider_asset_id`, `playback_id`, `duration_seconds` and `aspect_ratio` columns already exist and `mediaAssetSchema` already declares them nullable, so no contract change is needed.
- **03-08 (sweeper + isolation suite)** — objects are deliberately NOT removed by `deleteAsset`; the sweeper collects `status='pending'` older than 24 h (the Supabase TUS URL lifetime) and `status in ('deleted','rejected')` older than 1 h, deleting the object prefix `<tenant_id>/media/<assetId>/` and then the row. The isolation cases in `media.test.ts` are the templates to lift into `apps/api/tests/integration/isolation.test.ts`.
- **Phase 4 (feed)** — the payload contract is `variants: [{ width, url }]` for a direct `srcset`; payloads carry no signed URL and are therefore freely cacheable with `"use cache"`/`revalidateTag`. If the 302 hop measures as a hotspot, `createSignedUrls` batches N keys in one Storage call and the `/v1/media/…` URL stays the contract either way.
