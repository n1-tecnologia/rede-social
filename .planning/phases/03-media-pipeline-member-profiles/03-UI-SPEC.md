# Phase 03 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design authority.** `reference/frontend-design/` (git `05f68b1`) is the visual source of truth for everything it covers. Values marked **[proto]** are extracted verbatim from it; screens and components the prototype lacks are marked **[designed]** and use only the tokens and primitives already shipped in `@rede-social/ui` / `@rede-social/core/ui`. The design language, spacing scale, typography scale and colour model are **inherited unchanged** from the approved `02-UI-SPEC.md` — this document restates them for the checker and records only the Phase 3 deltas.

**Upstream decisions.** `03-CONTEXT.md` decisions are cited as **D-nn**; `03-RESEARCH.md` "Decisions Taken on Claude's Discretion" as **R-nn**. Nothing in those two documents is re-litigated here. Decisions that are purely visual and were left open by both are recorded as **UI-D-nn** below.

**Review pattern (D-33, UI-04).** The `[designed]` surfaces in this phase — the member directory `/membros`, the profile nudge card, the admin media screen `/configuracoes/midia`, and the upload progress/cancel states — go through `/gsd-sketch 3` (static HTML mockup rendered from this contract) and design-team approval before they are coded. `[proto]` surfaces (own profile, edit profile, other member's profile, the directory row, the search field) do not.

## Phase 3 Visual Decisions (UI-D)

| # | Question left open upstream | Decision | Rationale / reversibility |
|---|---|---|---|
| **UI-D-01** | Does the *own* profile `/perfil` keep the role `StatusPill` the Phase 2 stub shipped? | **No.** The pill is removed. `/perfil` shows avatar, display name, e-mail, bio, then the three rows. | The Deferred list states "Role badge on profiles and in the directory — rejected for V1 (D-45)" without qualifying "other members'". Keeping it on one profile and not the other is the kind of drift this contract exists to prevent. The member's e-mail stays as the identity confirmation (D-46 makes e-mail the identity anchor). Reversible: one `StatusPill` and one catalog key. |
| **UI-D-02** | What the directory row shows in the slot the prototype used for `@username` (dropped per PROTOTYPE §11). | The **first line of the bio**, truncated, 12/400 `text-text-tertiary`. Absent bio → the row collapses to a single line and keeps `min-h-14`. | The slot is the only scanning signal left once the handle, follow button and counts are gone; the data is already in the payload (PROF-01). Reversible: delete one `<span>`. |
| **UI-D-03** | Whether the caller appears in their own directory list. | **Yes**, unfiltered (`role='member' and status='active'` is the whole predicate, D-47). `/membros/{own membershipId}` **redirects to `/perfil`**. | Special-casing the list would put a second predicate next to D-47's, which V2-PROF-01's hide-me flag will also touch. The redirect keeps a member from meeting themselves as a stranger. Reversible. |
| **UI-D-04** | Search field geometry vs the prototype's `text-sm` pill. | Pill geometry **[proto]**, but **16px text and `h-11`** (44px) — a deliberate departure. | The Phase 2 typography rule "all inputs 16px (iOS zoom guard)" and the 44px touch-target exception both outrank the prototype's 14px/`py-2.5` here; a 14px input zooms the viewport on iOS Safari on focus, which on a mobile-first PWA is a bug, not a style. |
| **UI-D-05** | Size / duration numbers inside refusal copy. | The copy **never hard-codes a number**: `{limit}` and `{duration}` are interpolated, formatted server-side from `packages/core/server/media/limits.ts` (R-02, R-16). | Criterion 3 wants a *clear* message, not a duplicated constant. When Phase 5's 60 s story rule or Phase 8's tightening lands, no string changes. |
| **UI-D-06** | Where the media-box `aspect-*` heights sit against the multiple-of-4 spacing rule. | Media boxes are sized by **one axis + a ratio** (`aspect-video`, `aspect-square`); the derived axis is exempt from the multiple-of-4 rule, in the same class as icon glyph sizes. | A 16:9 height off any multiple-of-4 width is almost never a multiple of 4; forcing it would distort the frame. Enumerated, not open-ended. |

## Spacing Scale

Inherited verbatim from `02-UI-SPEC.md` **[proto]** — the prototype's gutter is `px-4`, list gap `gap-3`, section gap `mb-6`, controls `py-3`. Phase 3 introduces **no new scale value**.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside pills, hairline offsets |
| sm | 8px | Gap between inline controls (`gap-2` action rows), progress-bar inset |
| md-s | 12px | List/row gaps (`gap-3`), textarea vertical padding, profile header inner gap |
| md | 16px | Page gutter (`px-4`), card padding, form field gap, directory row gap block |
| lg | 24px | Section spacing (`mb-6`), desktop content gutter (`px-6`), edit-form block gap (`gap-6`) |
| xl | 32px | Profile column top spacing on desktop, media-library section gap |
| 2xl | 48px | TopBar height, desktop content top padding |
| 3xl | 64px | `EmptyState` icon circle, `EmptyState` vertical padding (`py-16`) |

Exceptions — all inherited from `02-UI-SPEC.md` unless marked *(new)*:
- **44px** minimum touch target for icon-only controls (`IconButton`, search clear, cancel upload, back buttons) — Apple HIG / WCAG 2.5.5. *(new use)* the `SearchBar` field is `h-11` for the same reason (UI-D-04).
- **14px** `py-3.5` on profile/settings rows; `left-3.5` search leading-icon inset; `px-3.5` pill padding **[proto]**.
- **6px** `py-1.5` pill vertical padding **[proto]**.
- **2px** hairline geometry (borders, rings, the 2px focus ring); **4px** progress-bar height.
- **56px** (`min-h-14`) directory row and media asset row minimum height — a multiple of 4, listed for clarity.
- **80px** `Avatar size="xl"` — a multiple of 4, listed for clarity.
- **320px** (`max-w-xs`) bio measure **[proto]**; **260px** `EmptyState` body measure; **384px** (`max-w-sm`) centred column; **680px** content column.
- *(new, UI-D-06)* **Media boxes are sized by one axis plus a ratio** — `aspect-video` / `aspect-square` on `MediaImage`, the video thumbnail (`w-24 aspect-video`) and the player frame. The derived axis is exempt from the multiple-of-4 rule, in the same class as icon glyph sizes (18/20/28/40). No other derived dimension is exempt.

## Color

Two-layer model inherited unchanged: raw `--theme-*` neutrals (light on `:root`, dark on `[data-theme="dark"]`) and the tenant `--brand-*` set server-side; utilities read them through `@theme inline`. **Phase 3 declares no new colour and no new token.**

| Destructive | `--color-danger` `#ef4444` | "Remover foto" / "Remover vídeo" ghost label and their `ConfirmDialog` confirm, the `Falhou` pill, upload refusal text, `Input`/`Textarea` error border, the over-cap bio counter, the error toast |

**Accent reserved for:** (1) `Button variant="brand"` fills — **"Salvar" on the edit form, "Completar perfil" on the nudge card, and nothing else in this phase**; (2) `ghost` button text ("Alterar foto", "Agora não", "Carregar mais" is `outline` and therefore neutral); (3) the focus border + ring on `Input`, `Textarea` and `SearchBar`; (4) the upload progress bar fill and the `PullToRefresh` loader; (5) the `Loader2` spinner tint on the "Processando o vídeo…" placeholder; (6) the `focus-visible` ring on every focusable element. Everything else — profile cards, directory rows, avatars and their fallback, media placeholders, the media list, status pills, the search field, every row chevron — is neutral. **Brand never colours body text, a border, a page background, an avatar ring, or a member's name.**

Contrast: no new brand-on-surface pairing is introduced; every brand surface in this phase is a `Button variant="brand"` or a 4px bar, both already covered by the Phase 2 `onPrimary ≥ 4.5:1` persistence rule.

## Upload contract — [designed] + [proto] `ImagePicker`

One state machine, shared by `AvatarUploadField` and the admin video zone, driven by the generalised `useSignedUpload`:

| State | What the member sees | Notes |
|-------|----------------------|-------|
| `idle` | The dashed `FileDropZone` (mobile: a tap target; desktop: drag-over highlights `border-brand bg-brand-soft`) or, for the photo, the current `Avatar` + "Alterar foto" | `accept="image/jpeg,image/png,image/webp"` for photos (R-12) — **HEIC is never listed** |
| `preparing` | Photo only: the caption "Preparando sua foto…" with the zone inert | The browser `<img>` → `<canvas>` → `toBlob('image/jpeg', 0.85)` re-encode at max side 2048. **An iPhone HEIC photo passes through here silently — it must never produce an error, a warning or a format mention.** EXIF rotation is inherited from the default `image-orientation: from-image` |
| `progress` | A 4px `rounded-full bg-brand` bar inside the zone (photo: directly under the avatar) + "{percent}% enviado" 12 `text-text-tertiary tabular-nums`, plus a `ghost` "Cancelar envio" | Progress is interpolated between chunk callbacks so a 6 MB TUS chunk (fixed, not tunable) still reads as smooth motion; the bar never jumps backwards |
| `processing` | Photo: nothing — the local preview is already the avatar. Video: the row enters the list with the `Processando` pill immediately | Worker variant derivation (photos) is invisible; Mux transcode (video) is the visible `processando` state criterion 4 names |
| `done` | Success toast; the zone returns to `idle` with the new asset in place | Photo: "Foto atualizada." Video: "Vídeo enviado. Avisamos quando estiver pronto." |
| `error` | The zone returns to `idle`; the message renders **inside** the zone's `error` slot with `role="alert"` in 14px `text-danger`, with a `ghost` "Tentar novamente" for transfer failures | Every refusal message comes from the Copywriting Contract; refusals arrive at **confirmation time** (criterion 3) as well as at pick time |

Cancel aborts the in-flight `PUT`/TUS/UpChunk transfer and returns to `idle` with no message. Navigating away mid-upload does not block: the member is not trapped and the orphan sweeper (R-07) collects the pending asset.

Accessibility: the zone is a labelled `<input type="file">` behind a styled label (already the `FileDropZone` shape); progress is exposed as `aria-busy` plus an `aria-live="polite"` percentage announced at 25/50/75/100 only (not every tick).

## Media rendering contract — [designed], R-05

Every private image renders through `MediaImage`, never through an inline signed Storage URL:

- `src="/v1/media/{assetId}/w320"`, `srcSet="/v1/media/{assetId}/w128 128w, /v1/media/{assetId}/w320 320w, …"` from the variant set the payload declares (`variants: [{ width, url }]`, R-06), `sizes` set per call site.
- Avatar mapping: `Avatar` sm 32 / md 40 / lg 56 → `w128`; `xl` 80 → `w320` (covers 3× DPR).
- `loading="lazy" decoding="async"` everywhere except the profile header avatar (eager — it is the visual anchor).
- The `<img>` sits in a box with an explicit aspect ratio on a `bg-bg-tertiary` ground, so nothing reflows while it loads (no CLS, no spinner over an image).
- `onError` clears `src`, which makes `Avatar` fall back to its neutral `User` icon and any other surface fall back to the plain `bg-bg-tertiary` box. **A broken-image glyph is never shown**, and an expired or cross-tenant asset therefore degrades to the same neutral state as "no photo".
- Payloads are cacheable because they carry no signed URL; the tenant check happens on every image fetch.

## Video contract — [designed], D-43 / D-44 / R-04

`VideoPlayer` renders one of three states:

- **`processing`** — `Card` with an `aspect-video bg-bg-tertiary rounded-xl` frame, centred `Loader2` 28 `text-brand` (spin), 14/400 `text-text-secondary` "Processando o vídeo…" and 12/400 `text-text-tertiary` "Isso pode levar alguns minutos. Você pode sair desta tela.". Under `prefers-reduced-motion: reduce` the spinner does not spin; the copy carries the state.
- **`ready`** — `<MuxPlayer>` at `aspect-video rounded-xl overflow-hidden`, `streamType="on-demand"`, `playsInline`, `poster` from the signed thumbnail token, `tokens={{ playback, thumbnail, storyboard }}` minted per request (D-44), `accent-color` bound to `var(--brand-accent)` so the player's own controls carry the tenant brand. On mobile it opens inside a `BottomSheet`; on desktop inside a centred dialog `max-w-[680px]`.
- **`failed`** — the danger pill and copy from the Copywriting Contract; no player frame is rendered.

A playback token expiring mid-session surfaces as the generic error toast plus a `ghost` "Tentar novamente" that re-mints; it never shows a raw player error.

## Motion & Accessibility (Phase 3 deltas)

Everything in `02-UI-SPEC.md` §Motion & Accessibility still holds. Deltas:

- **Progress** motion is linear and monotonic (`transition: width 200ms linear`); it never animates backwards on a chunk retry.
- **`prefers-reduced-motion: reduce`** disables the `Loader2` spin on the video placeholder and the `Skeleton` shimmer; the textual state remains sufficient.
- **Focus:** the `SearchBar` clear button and the upload cancel control are real 44×44 `IconButton`s in the tab order; the directory row is a single focusable `<Link>` (the avatar inside it is not separately focusable).
- **Live regions:** the upload percentage (`polite`, throttled to quartiles), the video "Vídeo pronto." announcement (`polite`), the directory result count after a debounced search (`polite`, "{count} membros encontrados").
- **Images:** every member photo carries `alt={displayName}`; the fallback `User` icon is `aria-hidden` and the `Avatar` wrapper carries `aria-label`. Decorative media boxes are `aria-hidden`.
- **Forms:** `Textarea` is labelled and `aria-describedby`-linked to its counter; the counter is not announced on every keystroke (`aria-live="off"`) — only the field's `maxLength` boundary matters.
- **The video player's own controls** are `@mux/mux-player-react`'s; they are keyboard-operable out of the box and are not restyled beyond the accent colour.
- **Hydration:** dates are formatted with `Intl.DateTimeFormat('pt-BR', { timeZone: tenant.timezone })`; no `Date.now()` in render.
