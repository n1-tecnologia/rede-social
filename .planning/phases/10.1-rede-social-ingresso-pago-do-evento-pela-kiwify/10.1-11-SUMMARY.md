# Phase 10.1 Plan 11: The admin's Ingresso section in the event form Summary

**The event form gains an Ingresso section (switch, product id, https purchase link, reference price) drawn in every state of UI-D-742 from the server's facts, with the price riding the event save and the gateway product linked by a second server action that is safe to retry, never repeats a create, keeps typed values on failure and reads the real sold count when a stale tab hits the sales lock.**

- **Files modified:** 14 (5 created, 9 modified), 2428 insertions

## Accomplishments

- **Tracer.** In create mode the switch reveals the three fields; a submit sends `ticketPriceCents: 8000` in the event save and then calls the product action once with the created event id, with the trimmed pair, after the event save and before the landing. The action PUTs `/v1/payments/event-products/{id}` after parsing with `eventMappingBodySchema`. Switch off sends `null` and calls nothing; a host without the `ticket` prop draws no section and sends no price key.
- **States.** `TicketSection` renders the six branches of UI-D-742 in precedence, the D-748 existing-presences note, the D-747 switch-off line, field errors in the helper's place, the `role="alert"` lock row and the disabled-while-submitting state. The create and edit pages pass the Pagamentos facts through the new `eventFormTicket()` mapper.
- **Sequence.** Only a real change of the pair calls the endpoint, a price-only edit calls none, a DELETE happens only for a saved product switched off, a retry after a failed second write updates the event it created (`createdId`) and resends only a differing pair, and the lock refusal re-reads the section as locked with the real count.
- **Catalog.** `events.form.ticket.*` (28 keys, one ICU plural, `{gateway}` slot, neutral fallback word) and `event-tickets-messages.test.ts` pinning every key, plural and placeholder for later UI plans to extend.

- **Fix:** `EventFormTicket` and the pure `eventFormTicket()` live in `apps/web/lib/event-ticket.ts` with unit tests in `event-ticket.test.ts`; `EventForm.test.tsx` covers what the section draws from each fact set
