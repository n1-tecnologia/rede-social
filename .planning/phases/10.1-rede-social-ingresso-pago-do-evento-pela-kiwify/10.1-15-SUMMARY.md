## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The tracer lost its signal on a cold dev server and behind a fan-out backlog**
- **Found during:** Task 1 (runs 1, 4 and 5 failed the swap)
- **Issue:** two harness causes, neither a product defect. The live swap ignores the page's first Realtime join, so a delivery sent before the join is lost to a slow-hydrating cold page; and the integration suites leave notification fan-out jobs waiting in the queue (58 at the time), which a freshly started worker drains at its own pace, so the notification behind the swap arrived minutes late. The first failure message could not say which.
- **Fix:** `watchUserTopicJoin` (waits for the `phx_reply` ok of the user topic on the page's sockets), `waitForFanoutBacklog` (drains the queue before the tracer), and a failure message that names the database state (`ticketDiagnostics`).
- **Files modified:** `apps/web/e2e/events-tickets.spec.ts`, `apps/web/e2e/payments.ts`
- **Verification:** run 6, cold and with a 58-job backlog, 8 of 8 passed
- **Committed in:** `71658704`

**2. [Rule 1 - Bug, test side] The 44px tap assertion targeted a 24px shared primitive**
- **Found during:** Task 1 (run 2, test 5)
- **Issue:** the `Switch` primitive (`packages/ui`) is `h-6` app-wide; its row is 44px but the control is not. This phase draws the section, not the primitive.
- **Fix:** the assertion moved to the Ingresso section's own field (`#event-gateway-id`) and the buy anchor; the switch is noted below.
- **Committed in:** `0c2f5612`

**3. [Rule 3 - Blocking] Helpers the plan did not name**
- `eventMappingFor`, `eventIdByTitle`, `labTenantId`, `nameMember`, `ticketDiagnostics` and `waitForFanoutBacklog` are in `payments.ts` (a file the plan lists) because the spec needs to read the mapping the form wrote, find the event it created, and name the throwaway members the release sheet searches for.

- **Two events, not one.** The plan's scenarios (4) name both the online `Entrar` and the venue check-in; they are different formats, so the form creates an online event and the venue event is inserted with `insertEvent` plus `insertEventMapping`.
- **Four commits, not three.** The follow-up fix for the cold-run causes is its own commit.
- **The order in `affected-map.json`.** A new group instead of editing two existing ones.

**Total deviations:** 3 auto-fixed (2 blocking, 1 test-side bug), 3 plan-text differences. **Impact:** none on scope.
