# Phase 10.1 Plan 12: The member's side of a paid event Summary

**A paid event now shows its Pago tag on the card and hero and a single external Comprar ingresso link in a polite live region that refreshes by itself into "Presença confirmada" when the webhook lands, with no Nao vou for a paid or courtesy presence, a danger dialog for a before-the-ticket one, and toasts for a stale tab.**

## Performance

- **Duration:** about 22 min (start time was not recorded; estimated from the first command)
- **Completed:** 2026-11-13
- **Tasks:** 3
- **Files:** 21 touched by the three commits (7 created, 14 modified), 112 KB of diff

## Accomplishments

- `EventPoster` and `EventHero` take one optional finished `tag`; the host passes "Pago" with the price-first note and the longer accessible name that `eventCardView` already built, and a free event renders the same markup as before (pinned by equality tests against the no-prop render).
- `PaidEventZone` draws the member's zone in the order of UI-D-746. The buy control is one `<a target="_blank" rel="noopener noreferrer">` in the shipped gold classes whose href is `safeCheckoutHref` (checked again in the zone, so a `buy` zone with an `http:` or `javascript:` href draws "Venda indisponível" and no anchor).
- Nothing is faked: no processing state, no dialog, no optimistic confirmation, no request on render.
- The detail banner gains `confirmed` in three variants, the checked-in banner draws its refunded line when carried, and the paid cancelled body (with the refund sentence for a holder) renders through the same component, now extracted to `EventBanner.tsx`.
- A paid or courtesy presence has no "Não vou" or "Cancelar inscrição"; a before-the-ticket one keeps the quiet button behind a danger `ConfirmDialog`, answers nothing optimistically and lands in the buy zone when the server agrees.
- `rsvpEventAction` maps `payment_required` and `ticket_locked`; the island toasts the two new sentences and refreshes.
- `useLiveRefresh` is the store's machine extracted without behaviour change (its test file is byte-identical), now also the paid zone's: a `notifications.changed` signal runs `router.refresh()` so the server answers a presence. No toast.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The zone shell and gold classes moved to a shared file**
- **Found during:** Task 1
- **Issue:** `PaidEventZone` needs `Zone` and `GOLD`, which were private to `EventActions.tsx`; importing them back would be circular.
- **Fix:** new `zone.tsx` exports `Zone`, `GOLD_BASE`, `GOLD`, `OUTLINE_CTA`; `EventActions` imports them. The classes are unchanged.
- **Files modified:** `apps/web/app/(app)/eventos/[eventId]/zone.tsx`, `EventActions.tsx`
- **Committed in:** `f3902901`

**2. [Rule 3 - Blocking] The banner moved to its own file so it can be tested**
- **Found during:** Task 2
- **Issue:** `EventBanner` was a private function of the server page, which has no unit test and imports half the app; the plan lists `packages/modules/events/tests/event-detail-ui.test.tsx` for the banner cases, but the banner is not in the module.
- **Fix:** extracted to `EventBanner.tsx` (markup unchanged apart from the new kind and the refunded note) with `EventBanner.test.tsx`; the module test file got the hero tag cases instead.
- **Committed in:** `5af8d3aa`

**3. [Rule 2 - Missing critical] The live region could not live inside the paid body alone**
- **Found during:** Task 3
- **Issue:** the plan puts the wrapper in `PaidEventZone`, but on the swap `EventActions` stops rendering `PaidEventZone`, so the live region would unmount with the content it should announce. The give-up of a before-the-ticket presence also needs the wrapper when the member lands in the buy state later.
- **Fix:** `EventActions` became an outer island (boundary refresh, sticky wrapper decision) plus the old body; `PaidEventZone` carries the wrapper, takes `waiting` and `children`, and holds the shipped zone after the swap. The listener unmounts then. `useBoundaryRefresh` moved to the outer island.
- **Files modified:** `EventActions.tsx`, `PaidEventZone.tsx`
- **Committed in:** `78a5db30`

### Plan-text differences (not defects)

- **The aviso page was not touched.** The orchestrator brief asked this plan to remove plan 08's `ingresso` exclusion in `entrar/aviso/page.tsx`. This plan's `files_modified` and actions do not list it; plan 13 lists `aviso/page.tsx` and draws the fourth reason there (with `enter.ticketRequired.*` and the `entrar/route.ts` mapping). Removing the exclusion here would mean drawing plan 13's screen without its copy keys or tests. `?motivo=ingresso` keeps redirecting to the detail silently until plan 13. This is the one item for Igor or the orchestrator to confirm.
- **Wrapper conditions.** The plan says the wrapper exists for every paid event the viewer is not in; a cancelled or ended one draws nothing at all (see key-decisions).
- **Optimistic state.** `respond` skips the optimistic answer for a paid event (the plan says "nothing is faked"; a before-the-ticket give-up therefore waits for the refetch).

**Total deviations:** 3 auto-fixed (2 blocking, 1 missing critical), 3 plan-text differences. **Impact:** none on scope; the aviso page is left for plan 13.
