<objective>
Close WR-03, the advisory the verifier asked to fix in this round (TICK-09, the "evento encerrado" label; D-750, D-752): in `app.event_gateway_grant` the cancelled and ended returns (step 6) come before the replay check (step 7), so a re-sent approval (different bytes, so the inbox does not dedupe it, for example a manual resend from the gateway panel) of an order that was granted earlier reports `event_ended` or `event_cancelled` once the event is over. The delivery is then listed as ignored with the hint to refund at the gateway although the buyer holds a presence; an admin who follows it refunds someone who attended. After this plan a replay is `already_in` whatever the state of the event.

**Tracer.** Task 1 wires ONE path through every layer: a failing pgTAP pair (grant, advance past `ends_at`, grant the same reference again, expect `already_in`), the hand migration that replaces the function, the local apply and the same pair passing. Task 2 expands to the cancelled and soft-deleted states, the other-member and second-reference replays, the first-time controls and the two cases through the real webhook and apply job. Task 3 runs the gate.

**Consequence worth knowing.** "Liberar manualmente" on a no-account ticket delivery whose order reference already names a presence now settles `applied` / `no_effect` after the event ended (it used to answer 409 `event_ended`); that is the same truth for the same reason and needs no new copy.
