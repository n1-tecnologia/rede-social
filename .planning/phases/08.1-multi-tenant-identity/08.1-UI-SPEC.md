# Phase 08.1 — UI-SPEC delta

> Short delta, not a full contract (D-319). The design language, spacing, type scale, colour model
> and every `(auth)` primitive are inherited unchanged from `02-UI-SPEC.md` (the auth column,
> `AuthBrand`, `AuthInput`, `PasswordField`, `ConsentFields`, `SubmitButton`, `LinkButton`,
> `UnavailableCard`). Nothing here introduces a new component, colour or token. Decisions in this
> file are numbered **UI-D-320..UI-D-327** so they cannot collide with CONTEXT's D-301..D-319.

Every string below lives in the pt-BR catalog (`apps/web/messages/pt-BR/*.json`); no JSX literal
with a diacritic is allowed (`scripts/check-ui-literals.sh`). The root key of each file equals its
filename. `{tenant}` is always the HOST's tenant (B); no screen, URL, alert or e-mail of this phase
ever names another community (D-302, D-309).

## Screens

### UI-D-320 — `/participar` "Participar de {tenant}" (D-305, D-306, D-311)

Route group `(auth)` (the branded column layout already paints B's brand). NOT a public path in
`proxy.ts`: without a session it falls through to `/entrar`.

Composition, top to bottom (the `/aceitar-convite` column shape):
1. `<h1>` 24/700 centred, `break-words`: `join.title` "Participar de {tenant}".
2. Sub-line 14/400 secondary centred, `break-all`: `join.subtitle` "Você entrou como {email}." —
   the session's own e-mail only.
3. Optional `role="alert"` line 14/400 `text-danger` centred (errors below).
4. `<form action={join}>`: hidden `rulesVersion` / `termsVersion` from `GET /v1/public/tenants/{slug}`;
   `AuthInput` `id="name"` icon `user`, `autoComplete="name"`, `required`, `minLength={2}`,
   placeholder and `aria-label` `join.name` "Seu nome nesta comunidade", EMPTY on first render (D-311:
   never pre-filled from another community); helper line 12/400 tertiary `join.nameHint`
   "Os membros de {tenant} verão este nome."; `ConsentFields` with the `signup` labels (both boxes
   unchecked, D-03); `SubmitButton` `join.submit` "Participar" / pending `join.pending` "Entrando…".
5. A second `<form action={declineJoin}>` holding one text-style button (`LinkButton` look, centred,
   14/700 `text-text-secondary`): `join.decline` "Não participar". It signs out of THIS origin only
   (`scope: 'local'`) and lands on `/entrar`.

States:
| State | Trigger | Render |
|---|---|---|
| form | `GET /v1/join/state` → `joinable` | the composition above |
| member | state `member` | `redirect('/inicio')` |
| invited | state `invited` | `redirect('/aceitar-convite')` |
| blocked | state `blocked` | `redirect('/auth/blocked?t=<B name>')` (existing sign-out screen) |
| suspended | state `suspended` | `redirect('/auth/suspended')` |
| platform admin | state `platform_admin` | `redirect('/auth/host-mismatch')` (unchanged, D-316) |
| refused | state `removed`, or `POST /v1/join` answered 403 `FORBIDDEN` | `UnavailableCard` with `join.refused.title` "Não foi possível participar" and `join.refused.body` "Esta conta não pode participar desta comunidade.", then the "Não participar" form relabelled `join.refused.cta` "Sair" |
| old API | `GET /v1/join/state` answers 404 (web deployed before the API) | `redirect('/auth/host-mismatch')` — today's behaviour |
| error: validation | `?erro=validacao&campos=` | alert `join.errors.validation` "Confira os campos destacados e tente novamente."; field line `join.fieldErrors.name` "Informe seu nome." |
| error: consents | `?erro=validacao` with an acceptRules/acceptTerms field | alert `join.errors.consents` "Aceite as regras da comunidade e os termos da plataforma para continuar." |
| error: stale | `?erro=consentimento` | alert `join.errors.staleConsent` "As regras foram atualizadas. Leia e aceite novamente." |
| error: generic | `?erro=falha` | alert `join.errors.generic` "Não foi possível participar agora. Tente novamente." |

Only whitelisted `campos` tokens (`name`, `acceptRules`, `acceptTerms`, `rulesVersion`,
`termsVersion`) map to a message (the T-02-49/T-02-126 rule).

### UI-D-321 — `/cadastro` "já tem conta" state (D-301, D-302, D-303)

Same page and column as `/cadastro` (`/cadastro/{slug}` on generic hosts). Entered only through
`?estado=ja-tem-conta` AND a readable draft cookie (`join_draft`, HttpOnly, 10 minutes, holding the
e-mail and name typed in the sign-up form, never the password). The e-mail never appears in a URL.

Composition:
1. `<h1>` `signup.existing.title` "Você já tem uma conta. Digite sua senha para participar de {tenant}"
   (D-301 wording, verbatim, no trailing period).
2. The e-mail as read-only text 14/400 `text-text` centred `break-all` (NOT an input).
3. Optional alert line (errors below).
4. `<form action={joinFromSignup}>`: hidden versions and (generic hosts only) the slug;
   `PasswordField` `id="password"`, `autoComplete="current-password"`, label `signup.existing.password`
   "Senha" with the existing show/hide labels and NO strength meter text change; `ConsentFields`
   (both unchecked); `SubmitButton` `signup.existing.submit` "Participar" / pending
   `signup.existing.pending` "Entrando…".
5. Links row, 14/400 centred: `signup.existing.forgot` "Esqueci a senha" → `/esqueci-senha` (on B's
   host, so the recovery mail is B-branded, D-303/D-317) · `signup.existing.otherEmail`
   "Usar outro e-mail" → `/cadastro` (the plain form; the draft is discarded).

States:
| State | Trigger | Render |
|---|---|---|
| já tem conta | `estado=ja-tem-conta` + draft | the composition above |
| draft missing | `estado=ja-tem-conta`, cookie absent or unreadable | the plain sign-up form with the info alert `signup.existing.expired` "Por segurança, preencha o cadastro novamente." |
| wrong password | `estado=ja-tem-conta&erro=senha` | alert `signup.existing.wrongPassword` "Senha incorreta. Tente de novo ou use Esqueci a senha." — nothing was written (D-301 step 4) |
| refused | `estado=ja-tem-conta&erro=recusado` (join 403 `FORBIDDEN`; the session was signed out locally) | alert `signup.existing.refused` "Esta conta não pode participar desta comunidade." |
| consents / validation / stale | as `/participar` | the `join.errors.*` lines |

The previous `?erro=email-existente` alert (`signup.duplicateEmail`) is retired: a duplicate e-mail
always enters this state. The 409 itself still names no tenant (D-04, D-302).

### UI-D-322 — `/escolher-comunidade` picker (D-308, generic hosts only)

`(auth)` column, neutral brand (generic hosts carry no tenant brand). Reached from a bootstrap
refusal `TENANT_CHOICE_REQUIRED`, or opened directly on a generic host to switch.

1. `<h1>` `join.picker.title` "Escolha a comunidade".
2. Sub-line 14/400 secondary `join.picker.subtitle` "Sua conta participa de mais de uma comunidade."
3. A list (`<ul>` `flex flex-col gap-3`): one `<form action={chooseCommunity}>` per community with a
   hidden `slug` and a full-width secondary button (the `LinkButton`/`SubmitButton` secondary look,
   min height 44px) whose label is the community's display name (`break-words`). Order: display name
   ascending (pt-BR collation), then slug — stable.
4. `join.picker.logout` "Sair" text button (local sign-out → `/entrar`).

States: tenant host or platform host → `notFound()` (D-309, D-21: the API also answers 404); zero
communities → `join.picker.empty` "Nenhuma comunidade disponível para esta conta." plus "Sair";
choice of a slug not in the list → the page re-renders with alert `join.picker.invalid`
"Escolha uma das comunidades da lista."

### UI-D-323 — `/aceitar-convite` without the password step (D-314, D-306)

Same page. When `GET /v1/me/invite` answers `passwordRequired: false` (the identity already has a
password), the `PasswordField` is not rendered and the sub-line becomes
`acceptInvite.subtitleExisting` "Aceite as regras e os termos para começar a administrar {tenant}."
Heading, consents, submit and errors are unchanged. `passwordRequired: true` keeps today's screen.

### UI-D-324 — `/redefinir-senha` shared-password notice (D-312)

Under the `PasswordField`, before the submit: 12/400 `text-text-secondary` line
`reset.sharedPasswordNotice` "Sua senha é a mesma em todas as comunidades desta plataforma."
(verbatim; names no community). Always shown.

### UI-D-325 — Existing-identity invite e-mail (D-314, D-315)

Server-side template `packages/core/server/mail/templates/invite-existing.ts` (mail strings live in
templates, not the web catalog), rendered through the shared `renderLayout` in B's brand:
- subject: "Convite para administrar {B}" (same as the new-identity invite);
- heading: "Você foi convidado(a) a administrar {B}";
- paragraph: "Entre em {B} com este e-mail e use a senha que você já tem. Depois, aceite as regras da comunidade para começar.";
- CTA: "Entrar em {B}" → `https://<B verified primary host>/entrar` (no token, no magic link);
- closing: "Se você não esperava este convite, ignore este e-mail."
It never names another community.

### UI-D-326 — Platform panel invite refusal copy (D-314, D-316)

The resend toast mapping for `user_in_other_tenant` (`platform.admins.resendUserInOtherTenant`) is
removed with the reason. `email_in_use` keeps its copy; it is now answered only for a platform-admin
identity (D-316).

### UI-D-327 — Accessibility and motion

Every new page keeps one `<h1>`, `role="alert"` for errors, 44px minimum targets and no motion
beyond the shipped `SubmitButton` pending state. The picker buttons expose the community name as
their accessible name. No toast is introduced.
