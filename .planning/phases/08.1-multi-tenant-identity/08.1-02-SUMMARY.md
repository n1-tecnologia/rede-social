# Phase 08.1 Plan 02: The "já tem conta" Sign-Up Join Summary

**An e-mail that already has an account now turns rede-lab's `/cadastro` into "Você já tem uma conta. Digite sua senha para participar de Rede Lab". The e-mail and name travel in an HttpOnly 10-minute draft cookie, the existing password is proven with `signInWithPassword`, and `POST /v1/join` runs with that fresh token. Nothing on the way names the other community, and the duplicate log line now speaks only about the attempted tenant.**

## Accomplishments

- **Draft cookie (`join-draft.ts`).**
  - `join_draft` holds `{ email, name }` as base64url JSON. It is HttpOnly, SameSite=Lax, `Secure` on production builds and lasts 600 s.
  - `decodeJoinDraft` is total and `.strict()`, so a value carrying a `password` (or any other extra key) decodes to `null` (T-08.1-13).
- **`apiFetchWithToken`.** It sends exactly the token it is given plus `x-tenant-host`, and never calls `getSession()` (RESEARCH Pitfall 5).
- **Sign-up action.**
  - A 409 now writes the draft and redirects to `?estado=ja-tem-conta`. The URL never carries the e-mail.
  - `joinFromSignup` applies the host rules, then reads the draft and validates the password and both consents.
  - It then proves the EXISTING password with `signInWithPassword`. A wrong one goes to `&erro=senha`, and nothing is written.
  - It joins with the fresh token and maps the outcome:
    - joined or already_member: clear the draft, go to `/inicio`;
    - blocked: local sign-out, then `/auth/blocked`;
    - invite pending: `/aceitar-convite`;
    - suspended: local sign-out, then `/auth/suspended`;
    - `FORBIDDEN`: local sign-out, then `&erro=recusado`;
    - stale consents: `&erro=consentimento`;
    - anything else: `&erro=falha`.
- **Page.**
  - The UI-D-321 state shows the heading with the host community's name, the e-mail as plain text, `PasswordField` with `current-password`, `ConsentFields` with both boxes unchecked, and "Esqueci a senha" (`/esqueci-senha` on B's origin, D-303) and "Usar outro e-mail".
  - Without a draft, the plain form comes back with "Por segurança, preencha o cadastro novamente."
  - The `email-existente` branch and `signup.duplicateEmail` are gone.
- **D-302 log.** `existingIdentityForEmail(email, tenantId)` returns `{ userId, alreadyMemberHere }` from an `exists` sub-select on the attempted tenant. `signup.duplicate_email` logs `attemptedTenantId`, `alreadyMemberHere`, `raced`, `ip` and `userAgent`, and never another tenant's id.
- **Tests.**
  - Unit: `join-draft.test.ts`, 16 cases.
  - `signup.test.ts`: test 8 cites D-302. New are 8b (409 on rede-lab, then the existing password and `/v1/join` → `joined`, 2 memberships, 2 lab consents) and 8c (the captured log line, and the lookup shape).
  - e2e: the tracer and five error states, run on both projects.
  - `signup.spec.ts` test 3 now expects the state.

## Decisions Made

- **Sign out inside the action on the blocked and suspended refusals.** The plan expected `/auth/blocked` to sign the session out. When a server action redirects there, though, the route handler runs behind the router's fetch: it renders the blocked screen, but its cookie clear never reaches the browser. The action now calls `signOut({ scope: 'local' })` itself before both redirects.
- **The lookup's sub-select is written with an alias.** Drizzle renders a single-table select's columns unqualified, so the first version compared `memberships.user_id` with the membership's own `id`, and `alreadyMemberHere` was always false. Test 8c caught it.
- **Test 8c captures the real log line.** The integration suite had no log-capture pattern. Rather than fall back to a lookup-only assertion, 8c passes a pino logger with an in-memory destination to `signupMember`, the same parameter the route uses. It asserts both the line and the lookup shape.
