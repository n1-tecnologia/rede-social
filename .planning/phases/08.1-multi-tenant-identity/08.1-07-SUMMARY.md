## Accomplishments

- **Tracer (Task 1).**
  - On the demo host, S's bootstrap answers rede-demo, `member`, 'S em Demo'. The full feed walk contains a fresh demo post and none of rede-lab's ids. The publish is refused (403) and nothing is written.
  - On the lab host, the same token answers rede-lab, `admin_tenant`, 'S no Lab'. Its publish lands with `tenant_id` = rede-lab and `author_user_id` = S.
  - That post never appears on the demo host, and its id there gets the same 404 body as an unknown id. The reverse also holds.
- **pgTAP 160 (plan 39).** It runs inside `begin … rollback`, with fixture prefix `16000000-…` and tenants `pgtap-si-a/b/c`. It has four groups:
  1. Memberships, profiles and the feed author join ('S em A' in A's lane, 'S em B' in B's).
  2. S's notifications, chat conversations and messages (member view in A, staff view in B), push rows (the SAME endpoint in both tenants), `app.push_subscriptions_for` and consents.
  3. `app.realtime_topic_allowed`, which appears 8 times: A and B open, C closed. Blocked in A, A closes and B stays open. Invited and soft-deleted memberships in C stay closed.
  4. The post-research tables from the reconcile record: events with category capacity, event photos, community position, moderation log, comments, and `app.notifications_withdrawn` per lane.
- **API matrix (Task 2).** Every case puts a positive control on the same host next to its negative.
  - **SC3 concurrency:** 20 interleaved bootstraps inside one `Promise.all`, each with its own host's tenant, role and name.
  - **SC5 concurrency:** the `si-` sweep leaves exactly this run's identity.
  - **Content routes:** communities; stories, strip and highlights; reels lanes and the video filter.
  - **Events:** S creates a one-seat Workshop event on lab and is refused on demo. RSVP and check-in with the lab's real code land in each host's tenant, and the other tenant's event is the unknown 404. Photos are included.
  - **Notifications:** list, counters, read and read-all.
  - **Chat:** S's demo thread is invisible from its lab staff lane (detail, messages, reply, read), and the lab inbox never lists it.
  - **Member directory and D-309:** the lab admin's search by S's shared e-mail returns only the lab membership, as 'S no Lab' / `admin_tenant`. A search for 'S em Demo' on lab finds nothing.
  - **Profile:** each host returns its own membership. A bio edit on lab leaves the demo profile byte-identical.
  - **Media:** variant, complete, delete and playback each return the unknown 404 across hosts.
  - **Phase 8 admin members:** S's demo membership is the unknown 404 through all four lab routes. A lab admin's block of S refuses S on lab (`MEMBERSHIP_BLOCKED`), while S still bootstraps on demo as an active member.
  - **Moderation:** S never removes demo comments from lab, and the lab log never lists a demo row.
  - **Settings and community order:** rules and name changes made on lab move rede-lab only. A demo community in the lab order gets the unknown 409, and the demo host refuses S every setting.

## Decisions Made

- **Realtime is not bound to the host.** This was decided with the plan and is proved by the closed cases. The web subscribes only to `bootstrap.tenant.id`.
- **Release 1 goes with Phase 8, by hand, with `--include-all`.** `deploy-api.yml`'s `supabase db push --include-roles` would refuse Phase 8's out-of-order migrations as well, so the runbook names the brew CLI path for this release.
- **D-309 is proved through the admin list.** The member directory hides staff (D-47), so S, the lab admin, is not browsable there. Searching the admin list by the e-mail the two memberships share is the strongest D-309 probe: only the host tenant's membership comes back.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `uploadAvatar` could not upload for a two-membership session**
- **Found during:** Task 2 (media case).
- **Issue:** The helper sent no `x-tenant-host`. A session with two memberships on a generic host is asked to choose a community (`TENANT_CHOICE_REQUIRED`).
- **Fix:** An optional `host` option adds the header to the start and complete calls. Single-membership callers are unchanged.
- **Files modified:** `apps/api/tests/integration/setup.ts`
- **Committed in:** `b02aca9`

**2. [Rule 2 - Missing critical] the SC5 sweep could not delete an identity that had written rows**
- **Found during:** Task 1 (cleanup design).
- **Issue:** `feed_posts`, `feed_comments`, `chat_*`, `events`, `event_attendances` and `media_assets` reference `users` with `on delete no action`. An interrupted run would therefore leave an `si-` identity that no later sweep could remove, which breaks the SC5 truth.
- **Fix:** `removeIdentitiesByPrefix` now deletes what those identities authored, children before parents, before it deletes them.
- **Files modified:** `apps/api/tests/integration/setup.ts`
- **Committed in:** `b02aca9`

**3. [Plan adjustment] the directory positive control**
- **Issue:** The plan expected the lab directory to show 'S no Lab'. The directory lists `member` rows only (D-47), and S is the lab's admin.
- **Fix:** The case now asserts the opposite fact: S is not browsable on lab, and is listed as 'S em Demo' on demo. 'S no Lab' is asserted through the direct profile link (openable by D-47) and the admin list.
- **Committed in:** `1c4ec7d`
