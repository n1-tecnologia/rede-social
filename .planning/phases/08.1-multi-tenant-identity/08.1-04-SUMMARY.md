# Phase 08.1 Plan 04: Per-Community Display Names Summary

**The bootstrap's `user.name` and the platform panel's admins list now read the host (or that tenant's) membership's `member_profiles.display_name`, sign-up and the seed write each new membership's name explicitly, and a rename on rede-demo is invisible on rede-lab. `users.name` and both triggers stay for the deploy window (D-318 expand).**

## Accomplishments

- **Bootstrap (D-310).** `me.ts` selects only `{ id, email }` from `users` and builds `user.name` from `profileForBootstrap(tx, ctx)`, read in the same transaction. The contract key stays.
- **Admins list.** `getTenantDetail` joins `member_profiles` on `membership_id` inside the existing tenant, role, status and not-deleted filters. `users` stays joined for the e-mail only.
- **Sign-up (D-311).** `insertMembershipAndConsents` now takes `name`. It inserts the membership with `.returning({ id })`, then updates that membership's profile (scoped by membership and tenant, exactly one row required), then writes the consents, all in one `withAdminTx`. The `consentInsert` seam is still called through the object.
- **Seed.** `nameNewMembershipProfile(tx, tenantId, membershipId, name)` runs after both membership inserts (the `people` loop and the removed-member fixture), only when the insert returned a row. After reset and seed, all 20 profiles equal the seeded names, and a second `pnpm db:seed` exits 0 and changes none.
- **No production reader of `users.name` is left.** The `git grep` over `apps/api/src`, `apps/web/app`, `apps/web/lib`, `packages/core/server`, `packages/modules` and `scripts/seed.ts` finds only comment lines (`perfil/actions.ts:68`, `profiles/service.ts:36`), which 08.1-08 cleans.
- **Tests.**
  - `profile.test.ts` "per-community name tracer": S is 'S em Demo' on rede-demo and 'S no Lab' on rede-lab. S renames itself to 'Novo em Demo' on the demo host. Both bootstraps then answer their own name, and a rede-lab member reading S's lab membership sees 'S no Lab'.
  - `bootstrap.test.ts` case 18: two hosts give two names. `users.name` is set to 'Nome Global' so that a regression would show.
  - `platform-tenants.test.ts` case 22: one identity administers two throwaway tenants under two names, and each detail shows its own name.
  - pgTAP 080: plan 7 → 14, with the D-313 block (assertions 8-14). The R-08 assertion is unchanged.
