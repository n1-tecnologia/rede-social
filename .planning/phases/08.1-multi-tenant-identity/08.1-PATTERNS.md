## Pattern Assignments

### `packages/core/server/auth/require-auth.ts` (CHANGED) and `require-identity.ts` (NEW)

Current order (lines 51-106): verify -> `membershipForUser` -> tenant suspended -> blocked -> host compare -> invited scope -> `c.set('ctx', …)` + child logger. Pattern 1 flips it to host-first: resolve host, then `membershipInTenant(userId, hostTenantId)`. Keep the error codes and the "no details" rule:

```ts
// require-auth.ts:77-84 — keep: body must not name either tenant
if (resolved.kind === 'tenant' && resolved.tenantId !== membership.tenantId) {
  throw new ApiError(403, 'TENANT_HOST_MISMATCH');
}
```
Context and logger tail to copy verbatim (95-105):
```ts
c.set('ctx', { userId, tenantId: membership.tenantId, role: membership.role, requestId: c.get('requestId'), events: [] });
const log = c.get('logger');
if (log) c.set('logger', log.child({ tenantId: membership.tenantId, userId }));
await next();
```
`require-identity.ts` = `createMiddleware<AppEnv>` + `verifyBearer(c)` (exported at 16-30) + `normalizeHost(c.req.header(TENANT_HOST_HEADER))` / `resolveTenantHost` (imports lines 1-9), with no membership lookup. The platform-admin branch (60-68, `isPlatformAdmin`) stays for D-305 platform admins.

### `packages/core/server/tenancy/membership.ts` (CHANGED)

Copy the definer-function wrapper shape (lines 41-59): `db.execute<Row>(sql\`select … from app.membership_for_user(${userId}::uuid)\`)`, the `isTenantRole`/`isStatus` guards throwing on unexpected values, mapping snake to camel. New `membershipInTenant(userId, tenantId)` passes two uuids; `membershipsOfUser(userId)` returns an array (no `rows[0]`). Keep the doc rule: lifecycle semantics live only in SQL ("do not re-implement the rule in TypeScript").

### `packages/core/server/tenancy/join.ts` (NEW) — analog `accept-invite.ts`

- Imports (1-7): `withAdminTx` from `'../../db/admin-tx'` (Biome restricts it to `server/{tenancy,platform}` — join.ts must live in `tenancy/`), schema tables, `ApiError`, `moduleLogger`.
- Input type carries `userId` from the verified Bearer only, `ip`/`userAgent`, optional `logger` (9-21); `asInet` helper (31-32).
- One transaction with lettered steps (65-155): read tenant `rulesVersion` -> stale-consent refusal `400 VALIDATION_FAILED { consents: 'stale' }` before any write -> membership write -> consent pair insert `.onConflictDoNothing()` (119-131) -> invite flip.
- Race safety: accept-invite relies on the row lock of an `update … returning`; for join use `insert … on conflict (tenant_id, user_id)` on `memberships_tenant_user_uq` and treat zero rows like accept-invite's `already_active` branch (97-113).
- Log after the tx (157-168): `log.info({ event: 'join.…', tenantId, userId, outcome }, '…')`.

## Shared Patterns

- **Admin lane:** `withAdminTx` from `packages/core/db/admin-tx.ts:16-21` (only importable in `server/{tenancy,platform}` and `scripts/`). Tenant lane: `withTenantTx(ctx, fn)` `packages/core/db/tenant-tx.ts:20-36`. Join/identity lookups belong in the admin lane or definer functions; anything reading tenant content stays in the tenant lane.
- **Errors:** `throw new ApiError(status, 'CODE', details?)` (`packages/core/server/http/api-error`); codes must exist in `packages/contracts/src/errors.ts` (`ERROR_CODES`). No-leak rule: host/tenant-choice errors carry no details.
- **Trusted client IP:** web action sets `X-Client-IP` from `x-real-ip`; stored via `asInet` (accept-invite.ts:31-32).
- **Logging:** `moduleLogger('<name>')` fallback or `input.logger.child({ name })`; events like `invite.accepted` with ids only, never e-mails/passwords.
- **Next 16 redirects:** always outside try/catch; `'use server'` actions; host is the authority (`getHostTenant()`), form slugs are ignored on tenant hosts.
