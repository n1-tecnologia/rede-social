# Phase 11.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

All 75 threats of the plan-time register are closed and none is open: 69 mitigations were found in the code, the database policies or the tests, and 6 are accepted risks whose rationale the auditors checked against shipped controls. The audit was read-only and split in two (plans 01-11: database, API, contracts; plans 12-20: web, release, gap closure), at ASVS level 1, blocking on high. The owner has not yet confirmed the six accepted risks (AR-11.1-01 to AR-11.1-06); until he does they stay proposals with a verified rationale. Evidence for the pgTAP and integration controls is by source inspection (the policy text and the test source), not by running them: the suites need the local database, and the seeded reset that clears their environmental reds is still the owner's ledger row P33.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| admin product form to the store API | the per-link flags are written only by a holder of `store.product.manage`; the link table accepts admin-claim writes only | five booleans per product and community, the open-to-buyers switch |
| buyer scope function to the row gates | `app.community_buyer_scope`, `community_action_allowed` and `community_action_denied_ids` run as definer, tenant-pinned, fail closed; the union reads active entitlements at statement time | member claim, tenant, entitlement status |
| member write paths to the server and the database | like, comment, post and story-save are refused by a bare 403 in the service and by restrictive row policies; a hidden control is never the enforcement | post and comment rows, likes, highlight items |
| viewer fact to the screen | `community.actions` carries the viewer's own like/comment/share/post/story facts; share has no server gate by design (D-889), so the screen is its only guard | five booleans, never the product, scope or flag names |
| curator reads versus member reads | `openToBuyers` and the flags ride only the manager reads; every member-facing body is serialised in tests to prove no flag, scope or product id leaks | highlight and product bodies |
| release order and the owner's ledger | migrations on every tenant database, then API and worker, then web; no agent records a pass on a manual proof | the 34 ledger rows, deploy order |
