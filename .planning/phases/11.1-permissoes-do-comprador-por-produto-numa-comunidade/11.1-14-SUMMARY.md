# Phase 11.1 Plan 14: The post card actions Summary

**A post card now draws only the controls its facts allow: a false like, comment or share is absent from the DOM, the row closes up in the shipped order, an all-false card shows the row-less meta with the comment count still opening the read-only list, double-tap like goes inert, and the per-post fact rides on the card view so every list and the post detail read one answer.**

## Performance

- **Duration:** about 50 min
- **Completed:** 2026-11-25T15:05:00Z
- **Tasks:** 3 (one tracer, two auto); the behaviours of Tasks 1 and 2 landed in one commit (see Deviations)
- **Files:** 3 created, 6 modified (plus the BASELINE section)

## Accomplishments
- `PostActions` takes an optional `show`; absent is the shipped row, a false control is not rendered, and the comment and send glyphs now carry `data-post-action` so the focus recovery can find them.
- `PostCard` takes an optional `actions` (and reads `post.actions`): row-less meta for all false (marker `data-row-less`, the sample keeps `data-read-only`), `onDoubleTapLike` withheld without `like`, and a per-card focus memory moves focus to the control that took the place of a vanished one, else to the article.
- `postCardBase` sets `actions` from `postActionsView` only when something is withheld, so Inicio, Explorar, the community page (first page and load-more), the post detail and its `?comentario=` deep link all show the same row for the same post, and a post without the fact is byte for byte the shipped card.
- Precondition checked: `grep -q '^approved: true'` on the sketch 026 README succeeded at the start; no approval key was written.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The per-post function on FeedList is replaced by a field on the card view**
- **Found during:** Task 1 (reading FeedList, FeedSurface, the registry and the server actions)
- **Issue:** the plan has `FeedList` take an optional per-post function the host fills with `postActionsView`. `FeedList` is a client component whose first page is built by the server registry and whose later pages are plain data returned by server actions, so a function cannot be passed from the server and the list could not compute the fact itself without importing host code.
- **Fix:** the fact is `PostCardView.actions`, set by the host's single view builder `postCardBase` (the `readOnly` precedent in the same file), and `PostCard` also accepts an `actions` prop that wins. `FeedList.tsx` and `post/[postId]/page.tsx` needed no edit: the list spreads the item into the card and the page already builds its card with `postCardView`.
- **Files modified:** `apps/web/lib/feed-view.tsx`, `packages/modules/feed/ui/PostCard.tsx`
- **Verification:** `post-actions-show.test.tsx` case 2 (FeedList item), `feed-view.test.ts`, `post-card-actions-hosts.test.ts` (three load-more actions), `PostDetail.actions.test.tsx`
- **Committed in:** `caca8ff3`

**2. [Process] Tasks 1 and 2 share one commit**
- The row, the row-less meta, the double-tap guard and the focus rule were written together before the first green run, so one commit carries both tasks' production code and the whole `post-actions-show.test.tsx`. Task 3 has its own commit (tests only: no production file was needed beyond the shared builder).
