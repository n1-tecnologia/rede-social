# Phase 11.1 Plan 02: buyer permissions database foundation Summary

**Five per-link buyer flags, one `app.community_buyer_scope()` union over active entitlements with a real `app.community_action_allowed` replacing the constant-false stub, and a post insert gate that carries its own terms: a buyer now publishes into an organization community through `POST /v1/feed/posts`.**

## Performance

- **Duration:** about 11 min of wall clock (baseline pgTAP and integration runs included)
- **Started:** 2026-11-25T01:05:00Z (approximate; the start stamp was not captured)
- **Completed:** 2026-11-25T01:16:00Z
- **Tasks:** 3 (one tracer, two auto)
- **Files modified:** 19 (3 migrations, 3 drizzle snapshots, 1 journal, 9 source and test files, baseline and this summary excluded)

## Accomplishments

- Expand-only columns on the link (`can_like`, `can_comment`, `can_share` default true; `can_post`, `can_story` default false) and `story_highlights.open_to_buyers` default false. A constant-default `ADD COLUMN`, no UPDATE: every existing link keeps today's behaviour and a link written by the previous API takes the same defaults.
- `app.community_buyer_scope()`: jsonb map keyed by community id with `like`, `comment`, `share`, `post`, `story` (each `bool_or` over every linked product the caller holds an `active` entitlement for) and `openHighlight`. Tenant-pinned, explicit `member` claim, organization communities not soft-deleted, `store` module on, `expires_at` ignored exactly like the access OR.
- `app.community_action_allowed(uuid, text)` replaced with `create or replace` (same signature, same OID, the policy keeps depending on it); true only for the five lowercase names, never for `openHighlight`. `app.community_action_denied_ids(text)` declared as a kernel stub first, then given the store body. Kernel export `deniedCommunityIds(action)` ready for plan 03.
- `feed_posts_social_insert_gate` fourth clause now needs member role, `visibility = 'community'`, `social` on, an active, not-deleted organization community of the caller's tenant and the product grant; a buyer's post can never be stamped `'tenant'`.
- 80-assertion pgTAP truth table (`241-buyer-permissions.sql`) with the map-versus-wrappers equivalence over seven lanes, and an 8-case integration tracer.

## Decisions Made

See `key-decisions` above. The one with product weight: an archived organization community stays in the buyer's map. Excluding it would newly deny like, comment and share there for every buyer, which breaks D-890 ("nothing changes until the administrator edits the product"); the post is still refused by the insert gate (`status = 'active'`) and by `resolveCommunityTarget` (400 `archived`).
