<objective>
The member's side of the support conversation. One tap on the chat slot opens the thread, messages arrive live in order and survive any missed signal, and the dot tells the member the team has answered.

**As a** member of a tenant, **I want to** open my conversation with my organisation's team from the chat icon, see their answers arrive while I wait, and notice a dot when they replied while I was elsewhere, **so that** getting help feels like messaging someone, not filing a ticket. This story comes from ROADMAP Phase 7 SC 3 and CHAT-02, CHAT-04 and CHAT-05.

Purpose: this puts 07-08's ordered, signalled messages on screen through the prototype's bubble pair (minus the ticket extras) and the designed header, greeting and dot. It completes the live badges both chat roles see.
Output: the re-homed linkifier, the chat UI components, `chat-view.ts`, `/suporte` for members with `ThreadPane`, the BFF catch-up and read routes, the dot badge and chat slot labels, and `chat.spec.ts` for the member.

<planning_decisions>
1. **Send through a server action, refetch through BFF GET routes** (RESEARCH anti-pattern). A realtime-triggered refetch must not queue behind other actions, while a send is a user action like `CommentInput`'s.
2. **The BFF routes format on the server.** They call `getBootstrap()` for the tenant timezone and return preformatted `chatMessageView`s plus `todayKey`/`yesterdayKey`, so no client clock is read (UI-D-14).
3. **The linkifier moves to `@rede-social/ui`** (RESEARCH: module → module imports are forbidden). It keeps the same rules (T-04-43) and gains a `linkClassName` option. The feed file re-exports it.
4. **The counters provider listens to chat signals.** `LiveShell` adds the member's `chat.unread` (user topic) to the refetch triggers, and for holders of `chat.support` also joins `support-inbox` for `chat.message`/`chat.read`, so the staff count is live. 07-10 reuses that join.
</planning_decisions>
