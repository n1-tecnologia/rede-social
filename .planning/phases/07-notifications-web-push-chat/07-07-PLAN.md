<objective>
The browser half of Web Push. A member can turn push on from a tap, iPhone users are told to install first, the service worker shows the tenant-branded banner (or stays quiet while the app is in front on Android), and logging out on a shared phone stops the pushes.

**As a** member using the installed app, **I want to** turn on notifications with one tap (and be told to add the app to my Home Screen first on an iPhone), **so that** I get my organisation's news and support replies on my lock screen. This story comes from NOTIF-03, PWA-02 and ROADMAP Phase 7 SC 2 ("on iOS the 'Adicionar a Tela de Inicio' hint is shown first and the permission prompt is gesture-triggered in standalone mode").

Purpose: everything here runs where tests are weakest (service workers, permission prompts, iOS standalone), so every decision lives in a pure, unit-tested module, and the Playwright suite mocks `PushManager` and `Notification`. Real delivery on real phones is a 07-11 UAT deliverable, never an automated pass (orchestrator note 8).
Output: the service-worker handlers with `lib/push-sw.ts`, the subscribe flow `lib/push.ts`, the BFF subscription route, `PushSwitchRow`, `SoftAskCard`, the `InstallHint` push variant, the logout unsubscribe, and `push.spec.ts`.

<planning_decisions>
1. **One client module for both entry points.** `lib/push.ts` is shared by the card and the row (UI-D-255/256), so the gesture rule, the iOS gate and the resync exist once.
2. **The logout hook is a kernel seam for the rail and a web component for Configurações.** `BeforeLogoutProvider` / `useBeforeLogout` in `@rede-social/core/ui` lets the kernel's desktop-rail form await a host-provided cleanup, and the web supplies `disablePush` from `LiveShell`. Configurações uses the web's `LogoutForm`. Both are bounded to 2 s.
3. **`NEXT_PUBLIC_VAPID_PUBLIC_KEY` is optional in the web env.** When absent, every push surface renders the unsupported state instead of failing the build. The local and CI value is a LOCAL-ONLY test public key, generated once with `npx web-push generate-vapid-keys`, with its private half discarded because local push runs `PUSH_TRANSPORT=fake`. It is documented in `.env.example` and set in `ci.yml`. Production gets its own pair (07-11).
4. **The foreground-suppression UA rule is [ASSUMED] (RESEARCH A5)**, pinned by unit tests and confirmed on devices by the 07-11 plan.
