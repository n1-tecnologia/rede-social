<objective>
The design gate that the prototype-less Phase 7 surfaces wait on.

**As a** designer on the pilot tenant's team, **I want to** see the notification, push and support screens the prototype never drew before they are built, **so that** Phase 7 ships in the visual language we already signed off on. The surfaces are the staff inbox, the desktop split, the soft-ask card, the push switch row, the iOS install hint for push, the member thread header and greeting, the actor-less and removed notification rows, the comment highlight and the dot badge. This story comes from the ROADMAP Phase 7 surfaces and from D-33 (CONTEXT Claude's Discretion: "UI surfaces without a prototype go through the D-33 process (UI-SPEC plus a `/gsd-sketch` review)").

Purpose: D-33 makes an approved drawing the precondition for coding a prototype-less surface, and `07-UI-SPEC.md` names exactly nine of them plus two deltas to ported screens. The notification row with an actor, the bubbles and the composer are ports and need no drawing, but their two deltas are shown so the review sees what changed.
Output: `.planning/sketches/007-phase-07-designed-screens/{index.html,README.md}`, registered in the manifest with the gate armed (`approved: false`).

This plan touches no application code and shares no file with 07-01, so the two run in the same wave. `workflow.human_verify_mode` is `end-of-phase`, so the review itself is a `human-check`, not a mid-flight checkpoint. The user setting `approved: true` in the README is what physically releases the six gated tasks. Because execution is sequential, the gate is first consulted by 07-04 Task 3, three plans later, which leaves room for the review.
</objective>
