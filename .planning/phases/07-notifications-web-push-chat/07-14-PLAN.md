Facts verified in the tree at planning time (2026-10-01):

- `apps/web/app/(app)/notificacoes/NotificationsSurface.tsx` (423 lines):
  - **`refresh()`** is called by `PullToRefresh` and by the first-load retry. It awaits `refreshNotificationsAction()`, then bumps `generation.current` and REPLACES the unread rows, the read rows, both cursors, `readStarted` and `locallyRead`.
  - **`loadMore()`** captures `mine = generation.current` and returns without applying anything when `stale()`. It calls `loadMoreNotificationsAction('unread', unreadCursor)` while `unreadCursor !== null`, otherwise `('read', null)` and then `('read', readCursor)`.
  - **`mergeLatest()`** runs on Realtime signals, on `onSubscribed` and on `visibilitychange` to visible. It only PREPENDS rows not yet shown and never bumps the generation.
  - **`markAll()`** records `added` (ids not already in `locallyRead`), opens `tappedDuringMarkAll.current = new Set()`, sets every loaded id read, and POSTs `/api/notifications/read-all`. On a non-ok answer or a throw it removes from `locallyRead` only `added` minus the ids tapped meanwhile, then calls `show({ tone: 'error', message: t('errors.markAll') })`.
  - **`activate(view)`** fires `/api/notifications/{id}/read` (keepalive) for an unread row, adds the id to `tappedDuringMarkAll.current` when a mark-all is open, and adds it to `locallyRead`.
  - **Seen.** At mount, while visible, it POSTs `/api/notifications/seen` once.
- Commit 583619c is the only commit after 779be21 on that file (`git log -- <file>`). It added the generation ref and the scoped rollback (28 insertions, 1 deletion) without changing props, so `583619c^` is a self-consistent pre-fix version with the same props.

<planning_decisions>
1. **A component test, not an e2e.** Both defects are races. Deferred promises in mocked actions and a mocked `fetch` force the exact interleavings deterministically. A browser run would need slowed routes and a synthesized pull gesture, and would only flake around the window.
2. **Only the list-replacing refresh is the hazard.** The verifier's suggested trigger ("refocus the tab or receive a notifications.changed signal") reaches `mergeLatest`, which only prepends and never bumps the generation. That is correct by design, so it becomes the control case. The guarded race is a pull-to-refresh, or the first-load retry, landing during a load-more.
3. **Red evidence against `583619c^`, not TDD.** The fix already shipped. Each case is shown to fail on the pre-fix component (swapped in with `git checkout 583619c^ -- <file>`) and to pass at HEAD, with the file restored and checked byte-identical. The plan is not `type: tdd`.
4. **Partial mocks.** `@rede-social/ui` keeps its real primitives (`ToastProvider`, `Button`, `EmptyState`, `Skeleton`). Only `InfiniteScroll` (a button that calls `onLoadMore` while `hasMore` and `enabled`) and `PullToRefresh` (a button that calls `onRefresh`, plus its children) are replaced. `@rede-social/core/ui` keeps everything except `useRealtimeTopic`, which becomes a no-op.
5. **No schema change: schema push not required.** No package installed; `COVERAGE.md` stands.
</planning_decisions>
