<objective>
Make the bell live. The count a member sees changes the moment their organisation publishes, without a reload, over the one shared Realtime infrastructure every later plan reuses.

**As a** member of a tenant, **I want to** see the bell's count change the moment my organisation publishes, without reloading the app, **so that** I know right away that something new is waiting for me. This story comes from the ROADMAP Phase 7 goal "a notification bell with live unread count".

Purpose: this is the first browser Realtime client in the codebase and the first place a raw user JWT reaches page JavaScript. It proves the whole chain against the real local Realtime service: token route → private join → definer-authorised topic → ids-only signal → API refetch. It also proves every negative ROADMAP SC 4 demands, before chat (07-08..07-10) relies on the same provider.
Output: the kernel `RealtimeProvider`, `useRealtimeTopic`, `LiveCountersProvider` and slot-label context; the BFF token and counters routes; `GET /v1/me/counters`; the live-negative integration suite; and the live-bell e2e.

<planning_decisions>
1. **The provider is kernel UI, not app code.** It lives in `@rede-social/core/ui` (client-safe), so 07-09/07-10's chat panes and any future module join topics through the same client. It takes the Supabase URL, the publishable key and the token URL as props from the host, and never reads env itself.
2. **Slot labels through a client context.** A server layout cannot pass a label function to a client component, and the kernel ships no words. So the kernel exports `SlotBadgeLabelsProvider`, and the web supplies its value from a client component (`apps/web/components/shell/LiveShell.tsx`) that uses next-intl's ICU plural.
3. **BFF GET route handlers for realtime-triggered refetches** (RESEARCH anti-pattern: server actions for these would queue behind other actions).
4. **Hidden-tab hygiene is 60 s** (RESEARCH Pattern 4). It keeps peak connections close to the number of foreground users on the Free plan's 200.
5. **`app.realtime_signal` stays the only publish path for notifications.** This plan adds no SQL; the live tests exercise 07-01's definer and policy.
</planning_decisions>
