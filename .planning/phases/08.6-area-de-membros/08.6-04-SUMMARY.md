# Phase 08.6 Plan 04: The member's tracks and own progress on the API Summary

**Two new member reads come from one shared row read. `GET /v1/courses/learn/tracks` returns every active track. Each track carries the state of each course in it (concluída, em andamento, a seguir or bloqueada), the member's lesson-weighted progress, and the `mine` / `suggested` marks from the overview's own `activeTrack`. `GET /v1/courses/learn/progress` returns the streak, lessons done of the school total, the ring percent, the seconds of the completed lessons' ready videos, the courses completed, and the started courses, last touched first. The admin preview reads zeros. Support reads everything open and counts its own completions.**

## Decisions Made
The four planning decisions were applied as written. The execution-level readings are listed under `key-decisions`. One of them needs the reviewer's attention:
- **A zero-lesson course inside a track.** A track's `percent` is lesson-weighted, so a path made of a complete course and a published course with zero live lessons reads `percent: 100`. Its `coursesDone` is still 1 of 2, and `currentIndex` / `resumeCourseId` point at the empty course, which reads `a_seguir` because it is never `concluida` (EP-21). The unit case "EP-21: a published course with zero live lessons is never concluida" pins this reading. The UI-SPEC "Rever a trilha" CTA keys on 100%, so plan 11 may want to key it on `coursesDone === total` instead.
