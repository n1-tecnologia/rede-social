# Phase 09.2 Plan 18: The project in the 'Novo tenant' wizard Summary

**The wizard now asks for the tenant's Supabase project: one field that turns any copied address into the bare 20-letter ref and pre-checks it, a write-only manual-access block that exists only when the platform cannot get the keys itself and lives in memory alone, a Projeto row in the summary, and a 'Preparar o banco de dados' task in the confirmation that narrates the eight steps, holds the uploads until the database is ready, and hands a failure to the Banco tab**

## Accomplishments

- **Tracer (UI-D-533, DBT-50).** Under the e-mail field, after the `gap-6` break, the 'Projeto Supabase' group: `SectionTitle` group, helper, the `projectRef` `Input` (`Database` 18, `autoComplete="off"`, `autoCapitalize="off"`, `spellCheck={false}`, `tabular-nums`, `maxLength={200}`) and its 12/400 helper. Paste and blur run the shared `normalizeProjectRef`; what reaches the server action is always the normalised value, even if the field never blurred. `validateTenantDraftAction` applies the 20-letter shape (empty and malformed refs never reach the API), then `POST /v1/platform/projects/precheck`, mapping `not_found`, `not_empty`, `in_use`, `paused`, `invalid` to the six field errors (`role="alert"` through `Input error`) and a check that could not run (transport, 5xx, unparsable, a 403 with another code) to the top alert 'Não foi possível conferir o projeto agora. Tente de novo.'. A 401/403 navigates like every platform read. Every edit of the ref clears its error and sets `dataReady: false`; the ref and a `manualAccess` flag join the persisted draft.
- **Manual access (UI-D-534, DBT-21, PR-4a).** `ProjectAccessFields` (props-only) renders the three `type="password"` fields with the documented labels and helper, no `name`, `data-1p-ignore`, no show/hide, and the `KeyRound` info row only with `requireAll`. The first Continuar that learns `manualAccess` only reveals the block (focus on the first field, no errors yet); the next one requires all three, each with its own 'Cole ...' error. The values live in `TenantDraftProvider` state and nowhere else: the mirror writes `PERSISTED_KEYS` (an allow-list), a reload keeps the ref and the flag and asks again, an edit of the ref, a pre-check that no longer asks, a reset or an accepted/definitively refused creation clears them. They never go to the Dados action and travel once, with the creation call.
- **Resumo and guard (UI-D-535).** A 'Projeto' card after Domínio in the summary and a `dt/dd` pair after Domínio in the confirmation, with 'Acesso informado manualmente' only when used; nothing secret is echoed (tests scan the markup). `RequireDraftData need="project"` (the Resumo's guard) sends a draft without a ref, or without the values when manual, back to Dados closed; while the confirmation is open the guard waits, so what the dialog clears never moves the page.
- **The database task (UI-D-535, D-542, E03).** `create → database → logo → icon → domain`. After `create`, the dialog reads `readBootstrapProgressAction(id)` every 2 s; the row narrates 'Etapa n de 8: {step}' (12/400 tertiary, `tabular-nums`, `aria-live="polite"`, `break-words`) and the line disappears when done; a failed read keeps the last state. Logo and icon uploads start only when the database is done; a failed step shows the catalog sentence of its reason code, leaves the logo and icon on `Circle` with 'Não enviado: o banco ainda não está pronto. Envie na aba Marca depois.', still attempts the domain and ends in the partial phase ('Tenant criado com pendências' + the database body) whose brand 'Continuar' is a `Link` to `/plataforma/tenants/{id}/banco`. After 60 s a neutral ghost 'Continuar em segundo plano' and its helper appear; it attaches the domain, forgets the stored draft and replaces to the Banco tab while the preparation keeps running.
