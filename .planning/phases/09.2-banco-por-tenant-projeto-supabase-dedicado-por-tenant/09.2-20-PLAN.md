<objective>
Put the database state where an operator scans for trouble: a Banco column and a 'Banco com problema' filter on the tenant list, a pill in the tenant page header when the database is not ready, and a guard on the Status tab while a move runs.

The list is how a super_admin learns where every tenant stands; one chip isolates trouble without a second filter row. The header pill and the guard are small, but the guard prevents the one obvious button on the Status tab from reopening a tenant halfway through a copy (D-535). All states and tones come from plan 19's single `DatabasePill`, and all data from plan 14's list and overview API.

Tracer: the list renders a tenant's Banco pill and schema line from the live API shape and the new chip filters on the server. Task 2 adds the header pill and the Status guard.
