<objective>
Give members of a tenant that is being updated or prepared two calm, branded screens, and make the login and sign-up forms step aside for the same states.

A migration is not a logout and a bootstrap is not a decision about the member: so the screens keep the session, show the tenant's own brand, say one honest sentence each and offer one outline action that leads back to the app (which comes back here while the state holds). A paused or unreachable project shows the existing 'Comunidade indisponível', so a member never learns whether it was a decision or an outage. The API's three refusals from plan 08 map to these routes in one function, `bootstrapRedirectPath`.

Tracer: an API refusal from any tenant-lane read ends on the right screen. Task 2 adds the form cards, the login action and the host-status plumbing.

Decisions implemented: D-535 and D-545 (the suspended-tenant mechanism reused for the held-out states), D-542 ('em preparação', no login until ready), D-33 (design gate).
