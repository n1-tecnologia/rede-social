# Phase 09.2 Plan 17: The web follows each tenant's own Supabase project Summary

**The proxy's Auth client, the server `createClient()`, the Content-Security-Policy, the icons and manifest, the Realtime props and the upload endpoint are all built per request from the project the host's by-host answer names (exact origins, never a wildcard), a half or foreign address makes the tenant unavailable instead of falling back to the central project, a known tenant survives a transient API outage for ten minutes, and the previous project's session cookies are cleaned on the response.**

## Performance

- **Duration:** about 30 min (approximate; start not recorded)
- **Completed:** 2026-10-23
- **Tasks:** 2 (1 tracer, 1 auto)
- **Files:** 24 changed in the two task commits (1,560 insertions, 96 deletions)

## Accomplishments

- **Tracer.** `getSupabaseCoordinates` turns a resolved host into `{ url, publishableKey, origin, wsOrigin, cookieKey, source }` with no shared state. The proxy builds `createServerClient` from it; `createClient()` resolves the host through the cached by-host answer. Platform, generic hosts and project-0 tenants get the environment pair, so they are unchanged. Two interleaved requests for two hosts keep their own clients and cookie keys (P76).
- **Reject, don't fall back.** One of the two fields alone, `http:` in production, `evil.example.com`, `x.supabase.co.evil.com`, userinfo, a path/query/fragment and a port on a hosted project all return `null`; the proxy sends that tenant to `/comunidade-indisponivel` before any client is built (and serves that page itself without a loop). The log line names the host only.
- **Transient outage (D-537, Pitfall 15).** `resolveHostTenant` keeps a second bounded cache of the last good tenant answer for 10 minutes; errors, timeouts, 5xx and unreadable bodies serve it, a 404 deletes it, and the 60 s hit TTL, the 10 s error TTL and the 1,000-entry bound are unchanged.
- **Stale cookies (D-535).** After the response is assembled every `sb-*-auth-token` (and `.0`/`.1`) of another project is deleted; the rotated cookie of the current project is never touched, and a generic answer deletes nothing.
- **CSP, icons, Realtime, upload.** `cspFor` takes the host's exact origin (`supabaseOrigin`; `null` for none); the root layout and manifest route use the host's origin for the icon allow-list; `(app)/layout.tsx` hands `LiveShell` the host's `url` and key (a refused address redirects to the unavailable screen); `tusEndpointFor(signedUrl)` replaces the build-time constant and refuses any origin outside the allowed Supabase origins.
- **Generic-host sign-up.** `publicTenantSchema` gained `primaryHost`; `getPublicTenant` reads the verified primary host in the same central transaction and answers 404 for a non-central tenant without one. The `/cadastro/[slug]` action, on a generic host, looks the record up first and, for a non-central tenant, sends the person to `https://<primaryHost>/entrar` after the POST instead of resending the confirmation from the central Auth.
- **Guard.** `no-build-time-supabase.test.ts` fails on any mention of the build-time pair in `apps/web` code outside `lib/env.ts` and `lib/supabase-coordinates.ts`.

- **Files modified:** apps/web/proxy.ts, apps/web/proxy.test.ts

- **Files modified:** apps/web/lib/supabase/server.ts
- **Commit:** 00e2982f

**4. [Rule 2 - Missing critical] An existing identity on a generic-host sign-up for a non-central tenant**
