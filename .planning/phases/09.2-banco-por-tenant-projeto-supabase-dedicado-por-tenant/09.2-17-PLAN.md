<objective>
Make the web tier use each tenant's own Supabase project: Auth cookies, the Realtime client, the Content-Security-Policy, the icons and the upload endpoint.

The browser already talks to Supabase on exactly two sanctioned paths (Auth through `@supabase/ssr` in the Next server, and read-only Realtime), both configured by one build-time pair of variables. With a project per tenant that pair becomes per host: the by-host answer (plan 08) carries the project's PUBLIC URL and publishable key for tenants outside the central project, and this plan threads them through the six places that read the build-time values today. Platform, generic and central-project tenants keep the environment values, so nothing changes for them.

This is not new UI: no screen is drawn or changed here (the held-out screens and the panel are plans 18-21), so the plan is not behind the sketch gate.

Tracer: the same code path builds the Auth client, the CSP, the icons and the Realtime props for two hosts of two projects and the central host, and never mixes them.

Decisions implemented: D-538 (explicit values per request), D-537 (the by-host answer is the source and it survives a transient outage), D-535 (stale sessions of an old project are cleaned).

<planning_decisions>
1. **Coordinates are derived, not stored.** A pure function of the resolved host tenant and the environment; nothing is cached beyond `resolveHostTenant`'s own entry.
2. **Reject rather than fall back.** A malformed or disallowed project URL is a hold-out (the tenant is unavailable to the shell), never a quiet fallback to the central project: serving tenant B's sign-in against the central Auth would be the single-database behaviour this phase removes.
3. **Allowed origins.** Production: `https` and a hostname ending `.supabase.co`; non-production also loopback hosts for the local stack and the shim.
4. **Generic hosts are central.** Sessions of tenants outside the central project exist only on their own hosts; the generic-host sign-up redirects to the tenant's primary host.
5. **No bundle-time per-tenant value.** The central pair stays inlined (it identifies the platform project); every per-tenant value is a prop from a server component or a derived string.
</planning_decisions>
