# Phase 09.2 Plan 04: Explicit lanes, the host mirror and the admin-lane inventory Summary

**The kernel now has three explicit lanes (`withTenantTx`, `withAdminTx(target, fn)`, `withPlatformTx(fn)`), the shell's by-host answer is read from the central mirror and survives an unreachable tenant database, all 158 admin-lane call sites are classified in a checked-in inventory with a guard that fails on drift, and `supabaseAdminFor(project)` plus `ensureProjectZero()` give every project a service-key client and project 0 a correct registry row**

## Performance

- **Duration:** about 22 min
- **Started:** 2026-10-22T22:58Z (approximate; not recorded at start)
- **Completed:** 2026-10-22T23:20Z
- **Tasks:** 3 (1 tracer, 2 auto)
- **Files modified:** 23 (task commits, excluding this plan's metadata)

## Accomplishments

- Tracer: for a tenant bound to a project whose tenant pool points at a closed port, `GET /v1/public/tenants/by-host` answers 200 (primary host and verified alias; the alias names the primary) from the central mirror through `withPlatformTx`, while `GET /v1/me/bootstrap` for the same tenant answers 503 `TENANT_UNAVAILABLE`. A counting TCP listener proves the breaker: after the third failed connection the fourth request opens no socket.
- `withAdminTx(target, fn)` takes `{ tenantId }` (resolves the tenant's project) or `{ projectId }` (project-wide work), issues `set local role service_role` on that project's handle and registers the transaction in `projectOfTx`. The single-argument form stays as a `@deprecated` overload meaning project 0, so every one of the existing call sites still compiles and runs unchanged. `tenant-tx.ts` still defines no admin or platform lane.
- Admin-lane inventory: 158 `withAdminTx(` sites outside tests (121 in `packages/core/server`, 37 in `scripts/`; `tenant-host.ts` was the 122nd and migrated in Task 1) classified P/T/S/N/L, all `pending`, each with its migrating plan. The guard scans the source with comments and string contents masked and fails on an unclassified site, a stale entry, an empty inventory, a status that disagrees with the form the site uses, a wrong function name, or an out-of-order area.
- Biome: `@rede-social/core/db/platform-tx` is restricted in all three groups (plan 03 had already added it; verified), and the kernel allow-list gains `server/projects`, `server/migrations`, `server/secrets`. The boundary fixture violates the platform lane through both entry points and `pnpm boundaries:negative` still has both layers reject it.
- `supabaseAdminFor(project)` and `ensureProjectZero()`: project 0 on the local stack now reads `local | http://127.0.0.1:54321` after `pnpm db:seed`, and a second call reports `changed: false`.
