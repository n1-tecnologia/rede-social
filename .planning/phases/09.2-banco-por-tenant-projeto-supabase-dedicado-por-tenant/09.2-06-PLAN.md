## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| control-plane write → tenant database | A central fact (domain, platform admin) written to a tenant project would create a second, unmanaged copy. |
| invite flow → two databases and one Auth | The host comes from the central domains, the invite from the tenant's database, the mail from the tenant's Auth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09.2-27 | Tampering | `tenant_domains` written inside a tenant's transaction | high | mitigate | All 23 domain sites use `withPlatformTx`; the tracer asserts the rows exist centrally and the count in B is 0 |
| T-09.2-28 | Spoofing | an invite issued by the wrong project's Auth (the first admin would belong to another tenant's accounts) | high | mitigate | `supabaseAdminFor(project of the tenant)` for all three Auth calls; `invites-lanes.test.ts` asserts project B's client is used and project 0's is not |
| T-09.2-29 | Information disclosure | a lane nested inside another, holding two databases' rows in one function | medium | mitigate | The two transactions are sequential; the mocked lanes in `invites-lanes.test.ts` throw if one opens while another is open |
</threat_model>
