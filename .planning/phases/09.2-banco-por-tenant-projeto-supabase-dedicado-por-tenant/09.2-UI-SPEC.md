# Phase 09.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope.** Most of Phase 09.2 has no screen: the registry, the routing seam in the kernel, credential sealing, the migration fan-out, the per-tenant queue, the health job and the "move tenant" command are server, CI and command-line work. The user-facing surface is small and splits in two audiences. This phase adds or changes these surfaces:

Platform panel (super_admin only, platform host):

1. the **"Novo tenant" wizard**: the **Dados** step gains the "Projeto Supabase" group (project ref and, only when the Management API falls short, the manual access fields); the **Resumo** gains the "Projeto" row; the **confirmation dialog** gains the "Preparar o banco" task;
2. a new sixth tenant tab, **Banco** (`/plataforma/tenants/{id}/banco`): the overview card (health, project, schema version), the **Preparação** card (the status of each bootstrap step and "Tentar de novo"), the **Credenciais** card (write-only) and its replace sheet;
3. the **tenant list**: a **Banco** column (health pill and schema version), the same pill on the mobile card, and a "Banco com problema" filter chip;
4. the **tenant page header** (a Banco pill when the database is not ready) and the **Status tab** guard while a move is running.

Member and visitor shell (tenant host, tenant brand):

5. two new branded screens, **"Comunidade em atualização"** (D-545) and **"Comunidade em preparação"** (D-542), and the card that replaces the login and sign-up forms for the same two states; a paused or unreachable project reuses the shipped **"Comunidade indisponível"** (D-537);
6. the **retirement** of the Phase 08.1 shared-identity screens (D-533) and the return of the Phase 1 duplicate e-mail line on sign-up.

**What has no UI** (said plainly, not invented): the move command (D-536: no screen, no panel button); "migrar todos" (CI and `--dry-run`/`--tenant`, D-544: the panel only displays the result); the pool cache, the sealing helper, the registry and mirror tables, the per-tenant pg-boss queues, the reconcile job; the fake project provider; token-to-project verification; the Realtime and `@supabase/ssr` project wiring in the web tier. After a move **members sign in again** through the unchanged `/entrar` (a dead session already answers 401 and lands there), so no new "sua sessão terminou" notice is drawn. Cross-tenant statistics, project creation from the panel and a "Mover para projeto próprio" button are Deferred.

**Design authority.** `reference/frontend-design/` has no platform panel, no tenant database screen and no "em atualização" screen (the prototype is the member app only; the panel is `[designed]` since Phase 2, D-33). Every surface here is **[designed]** in the prototype's language from primitives that already ship in `@rede-social/ui`, `@rede-social/core/ui` and `apps/web/components/*`. Nothing is ported, so PROTOTYPE.md's porting rules do not apply; its token rules do (`bg-brand/10`, no hex, no literal text in TSX).

**Inherited design language.** Spacing, type scale, colour model, the wizard (`TenantDraftProvider`, `WizardSteps`, `CreateTenantDialog`), the tenant page frame (`TenantTabs`, `StatusCard`), the tenant table and the `(auth)` column are **inherited unchanged** from the approved `02`, `08.1` and `09.1-UI-SPEC.md`. This document restates only what the checker needs and records the Phase 09.2 deltas. Phase 09.2 declares **no new token, no new primitive and no dependency**.

**Upstream decisions.**
- `09.2-CONTEXT.md` decisions are cited as **D-533..D-547** (quoted copy that is fixed: "Tentar de novo", "em preparação", "em atualização", "temporariamente indisponível", "atrasado", "Novo tenant"). None is re-litigated.
- The UI questions this phase opens are decided below as **UI-D-533..UI-D-548**. They continue after Phase 09.1's UI-D-532, the highest id in any UI-SPEC (checked 2026-10-22 with `grep -rhoE "UI-D-[0-9]+" .planning | sort -t- -k3 -n -u | tail -1` → `UI-D-532`).
- Earlier visual decisions keep their numbers: the wizard and the panel (Phase 02), the suspended screen (D-09/D-32), the shared-identity screens being retired (UI-D-320..UI-D-327), the warning row and the `ConfirmDialog` (UI-D-516, UI-D-524), the write-only secret field (UI-D-514).

**How the open items were closed.** The researcher ran non-interactively and decided every open item with a stated default (**A-UI-1..A-UI-10**). The three that change what the product does are recorded in **§ Pending User Confirmation** with their defaults, for the orchestrator to put to the product owner; none blocks planning. **Research dependency:** D-541 asks research to confirm what the Management API delivers. UI-D-534 (the manual access fields) is written to be correct under either answer: the block is absent from the DOM unless the pre-check says it is needed.

**Assumptions made in this session** (the planner may overturn any with one line):
- **A-UI-1.** The project ref lives in the **Dados** step, not in a sixth wizard step. `WizardSteps` is sized for five labels (`@min-[39rem]` row); a sixth would shrink every label to a bare number on tablets, and the ref is one field about "who the tenant is".
- **A-UI-2.** The ref is checked **read-only at "Continuar"** (exists in the platform organisation, empty, not used by another tenant in production, not paused), through one API call on the same step-gate pattern as the slug. The same facts are re-verified by bootstrap step 1, so the pre-check is a courtesy, never the authority.
- **A-UI-3.** The wizard's confirmation dialog **waits for the bootstrap** (logo and icon uploads need the buckets) and offers "Continuar em segundo plano" after 60 s.
- **A-UI-4.** The Banco tab offers **"Verificar agora"** (one read-only health check, the Domínios tab's "Verificar agora" precedent) and **"Substituir credenciais"**. It offers **no "Atualizar agora"**: D-545 says the job retries by itself and the panel shows "atrasado", and a manual migrate is the command's job (D-544).
- **A-UI-5.** The registry exposes a **move-in-progress** fact (the tool writes an audit row, D-536). While it is true the Status tab refuses "Reativar tenant" and the list shows "Em mudança". Without that fact the guard is dropped and nothing else changes.
- **A-UI-6.** The schema version is shown as **applied of required** ("Esquema 144 de 147"), which holds under either encoding D-545 leaves open (a ledger row per file or a counter).
- **A-UI-7.** Members' "em atualização" and "em preparação" screens **do not auto-refresh and show no countdown or estimate**. A visible "Verificar de novo" is the only retry (the 09.1 A-UI-3 precedent). A timer would promise a time nobody can keep.
- **A-UI-8.** A paused or unreachable project shows members the **existing** "Comunidade indisponível" (the same sentence as a suspension), so a member never learns whether it was a decision or an outage.
- **A-UI-9.** The plan (Pro or Free) is shown as **information only**, never as a gate (D-543).
- **A-UI-10.** The panel never renders a raw provider error, SQL text or stack. A failed step shows a **catalog sentence chosen by a reason code**, plus the code in 12px tertiary for support.
