**The tenant list gains a Banco column (the one shared pill and a 'Esquema 144 de 147' line) and a server-side 'Banco com problema' chip in the same single-select row; the tenant header says 'Banco: {state}' only when the database is not Pronto; and the Status tab disables 'Reativar tenant' with a reason while a move runs, so the one obvious button cannot reopen a tenant halfway through a copy**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Files outside the plan's list**
- **Found during:** Task 1
- **Issue:** `loadMoreTenantsAction` (`plataforma/actions.ts`) types its query without `banco`, so "Carregar mais" under `?banco=problema` would have lost the filter on the second page; and the query parsing the plan puts in the page needed a testable home (a page file may not export helpers).
- **Fix:** `apps/web/app/(platform)/plataforma/actions.ts` gets `banco?: 'problema'` in the query type (the contract schema it parses with already accepts it); the page's `parseQuery` moved to `parseTenantListQuery` in `lib/platform.ts`, with `apps/web/lib/platform.list-query.test.ts` (8 cases: banco wins over status, bad values dropped, first of a repeated parameter, status and banco never serialised together, the row carries the database fact).
- **Commit:** 890b8ec8

**2. [Rule 1 - Bug in an earlier plan's claim] `getTenantDatabase` was not React-cached**
- **Found during:** Task 2 (reading `lib/platform.ts`)
- **Issue:** the plan 19 SUMMARY and this plan both describe the call as the same React-cached read, but it was a plain async function. The header pill, the Banco tab and the Status guard would have made three requests per page.
- **Fix:** wrapped in `cache(...)` like `getPlatformTenantDetail`. No other caller (the Banco actions use `apiFetch` directly), so no semantics change.
- **Files modified:** apps/web/lib/platform.ts
- **Commit:** dffa24b5

**3. [Rule 2 - Missing critical] The chip row would overflow at 320 px**
- **Found during:** Task 1
- **Issue:** the toolbar `nav` was `flex gap-2` with no wrap; a fourth, longer chip ('Banco com problema') does not fit next to the three others in 320 px.
- **Fix:** `flex-wrap` on the `nav` (asserted in `TenantToolbar.test.tsx`). Whether four chips fit on one line at 390 px is the plan 28 measurement.
- **Commit:** 890b8ec8
