<objective>
Teach the three routes that arrive WITHOUT a tenant host (the payment-gateway webhook, the product mapping and the Mux webhook) to find their tenant, and with it their project, through a small central index, and finish the migration of the admin lane by retiring its legacy form.

These are the 'N' sites of the inventory: a delivery names an integration id, a product id or an asset, never a host, so there is no tenant to open a lane with until something resolves one. The index lives in the control plane (`platform.*`), is written BEFORE the tenant row (reserve-then-write, so an orphan answers 404 harmlessly and a conflict is decided centrally), and keeps every URL the operators already pasted into Kiwify and Mux unchanged. Authenticity is untouched: the gateway token's HMAC and Mux's HMAC still decide whether a delivery is genuine; the index only decides where it is recorded.

Tracer: a signed delivery for a tenant in database B is recorded in B, and an unknown integration costs one indexed central read.

Heavy plan, justified: the gateway webhook, the product mapping and the Mux webhook share one idea (a central index in front of a tenant lane), one migration and one test file; the legacy-overload removal belongs here because these are the last pending sites.

Decisions implemented: D-488 (a product id maps globally to one tenant, written centrally before the tenant row), D-486 (the unchanged webhook URL and its cheap rejection order), D-538 (the explicit lane everywhere).

<planning_decisions>
1. **Index first, tenant second.** Every write that creates a webhook-visible handle writes the central row first and compensates it when the tenant write fails; a stale route is harmless (the tenant read finds no integration -> 404).
2. **The URL never changes.** `integrationId` stays the handle; no operator re-pastes anything (RESEARCH Q6, Runtime State Inventory).
3. **Passthrough carries the tenant, the index is the safety net.** The new format avoids a central read on every Mux delivery; `video_asset_routes` serves the legacy bare-uuid assets and the rare event with no passthrough, and is dropped by a later contract release once every pre-change asset is final.
4. **`media_provider_events` has no `tenant_id` and stays that way.** The row is recorded in the tenant's project, so the dedupe by provider event id is per project; the move tool does not copy it (ephemeral).
5. **Legacy overload removed here.** After this plan no `withAdminTx(fn)` form exists in the repository; `ALLOW_PENDING` becomes `false`.
6. **Serialised after plan 13.** The ordering dependency on plan 13 carries no code dependency: both plans add a central Drizzle migration and so edit the generated `meta/_journal.json` and snapshot files, which two plans of one wave must never share.
</planning_decisions>
