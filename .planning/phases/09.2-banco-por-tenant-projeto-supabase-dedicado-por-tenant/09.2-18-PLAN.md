<planning_decisions>
1. **The normaliser is imported, not copied.** `normalizeProjectRef` comes from `@rede-social/contracts/projects` (plan 14), so the web and the API cannot disagree about what a pasted address means.
2. **Secrets are memory-only by construction.** The draft provider keeps the three access values in a `useRef`-backed state that the `sessionStorage` writer never serialises (an allow-list of persisted keys, not a deny-list).
3. **Polling in the dialog.** While `database` runs the dialog calls a server action (`readBootstrapProgressAction(id)`) every 2 s for the overview steps; a failed tick keeps the last state and tries again (UI-D-544); the cadence is documented, the transport is a server action.
4. **Catalog ownership.** Plan 18 creates `platform.database.json` with the `database.steps.*` and `database.reasons.*` keys the dialog needs; plan 19 extends it. `messages.test.ts` lists every catalog and pins plurals and placeholders.
5. **No new token, primitive or dependency** (UI-SPEC).
</planning_decisions>
