<objective>
Give the kernel its three explicit lanes and make the 119+ admin-lane call sites countable, classifiable and guarded, without breaking one of them yet.

Today `withAdminTx(fn)` takes no tenant, so it cannot know which database to open. This plan introduces the target (`{ tenantId }` or `{ projectId }`), the platform lane for the control plane, and the deprecated single-argument overload that keeps meaning 'project 0' so the migration of the call sites (plans 05, 06, 07, 09, 10) is incremental and every plan ends green. It also puts the Biome and boundary-fixture guards in place BEFORE any module could reach for the new lane, adds `supabaseAdminFor(project)` (the service-key client of a project) and registers project 0 from the environment.

Tracer: the shell's by-host answer for a tenant whose database is unreachable still works, because it is read from the central mirror through the platform lane. That is the one fact that makes the control plane worth having (D-537) and it is provable now.

Decisions implemented: D-538 (explicit signatures, no ambient context, the Biome restriction stays and grows, each site classified), D-537 (the by-host answer comes from the mirror), D-539 (a project's service key opens only on demand).

A site whose first argument is a function expression is legacy; one whose first argument is an object literal or a named target is migrated.
