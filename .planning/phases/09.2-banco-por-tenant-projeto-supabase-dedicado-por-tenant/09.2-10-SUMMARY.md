# Phase 09.2 Plan 10: Route indexes for the no-host routes and the single-form admin lane Summary

**A payment-gateway delivery, a gateway product id and a Mux delivery now find their tenant through three small central index tables written before the tenant row (so the operators' pasted URLs never change and an unknown id costs one indexed read), are verified and recorded inside the tenant's own database, and the admin lane has a single `withAdminTx(target, fn)` form with the inventory guard failing on any pending site**

## Performance

- **Duration:** about 45 min (start not recorded at launch; estimated from the first and last tool calls)
- **Completed:** 2026-10-23
- **Tasks:** 3 (1 tracer, 2 auto) plus one test-hygiene fix
- **Files modified:** 43 (4 task commits, excluding this plan's metadata)

## Accomplishments

- Tracer: a signed delivery to `/v1/webhooks/fake/{integrationId}` for a tenant that lives only in `rede_tenant_b` answers 200, writes one `payment_events` row and one `kernel.payment-event` job in B and none centrally; the same bytes again answer `enqueued: false`; a wrong signature is 403 and stores nothing; an unknown uuid is 404 after exactly one platform transaction, no tenant transaction and no decryption (counted by wrapping the two lanes and `openSecret`).
- Three central tables (`payment_integration_routes`, `payment_product_routes`, `video_asset_routes`), generated by drizzle-kit, with a hand-written companion that revokes and grants by name and backfills project 0 (guarded by `to_regclass`, every insert `on conflict do nothing`). pgTAP 214 (52 tests) proves keys, platform-wide uniqueness of a gateway id, cascade, zero-policy exposure with 42501 for `authenticated` and `anon`, and the backfill statements run twice over fixture rows.
- Reserve-then-write for the integration handle (`saveIntegration`) and for every product mapping function; a single upsert statement tells "inserted by this call" from "already mine" from "someone else's", so a re-save by the holder is not 'already used' and only an inserting call ever takes a route back. Two tenants of two projects racing one id: one 201, one 409 that names nobody.
- Mux: the passthrough carries the tenant; the asset route is written before the provider call; the webhook records and enqueues in the tenant's project, resolves older assets and passthrough-less events through the route table, and accepts-and-drops what resolves to nothing (200, a `media.webhook.unroutable` line with a count).
- `withAdminTx(fn)` is gone from `admin-tx.ts` and `lanes.ts`; `ALLOW_PENDING` is `false`; the repository type-checks, lints, and `boundaries:negative` still has both layers reject the fixture.
