<objective>
Turn the copy engine of plan 22 into the operator's tool: a move that suspends the tenant, copies it, verifies, flips the registry pointer, reactivates, keeps the old rows, can be undone, and writes down everything it did.

D-535 and D-536 describe the human experience: Igor runs one command per tenant, members see the branded 'indisponivel' screen while it runs and sign in again afterwards, the old rows wait until he confirms, and a bad cutover is repointed back. Tracer: a throwaway tenant of project 0 is moved to the second database through the real command, served from there, and the source still holds everything.

<planning_decisions>
1. **One compare-and-set per transition.** The state column is the lock-free truth; the lease only keeps two runners from working the same move at once. Both are row operations, so they work through the transaction pooler.
2. **The target is bootstrapped by the tool.** A move target is a project like any other; the tool registers it, runs the plan 13 steps (with the open-move seam) and waits for `ready`, so the target is 'exactly like a new tenant's' (D-534) and no second path exists.
3. **Only one function deletes.** `confirmDeleteSource` is the sole importer of the delete statements; a repository test greps that nothing else in `projects/move/` contains a source delete, and the rollback and recopy modules are written against the TARGET only.
4. **Reactivation passes the move id.** The guard cannot be bypassed by a flag from a route: the id of the open move is an internal argument that only the runner has.
5. **Audit is data, not logs.** `platform.tenant_move_events` is append-only (an update raises), carries counts and codes, and survives the move; logs repeat it but are not the record.
6. **Rollback honesty over convenience.** A rollback that would drop writes made since the cutover refuses by default; `--accept-loss` is explicit and counted.
7. **Waits are parameters.** `MOVE_QUIESCE_MS` and `MOVE_REGISTRY_WAIT_MS` have production defaults and tests pass 0; the real cache-expiry behaviour across instances is a hosted proof (H6).
</planning_decisions>
