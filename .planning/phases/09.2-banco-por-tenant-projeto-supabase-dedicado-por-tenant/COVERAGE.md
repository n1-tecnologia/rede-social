# API Coverage — Supabase Management API (per-project bootstrap, health and credentials)

> Full coverage by default. Opt-outs are explicit, reasoned decisions.

External service: the **Supabase Management API** (`https://api.supabase.com/v1`, OpenAPI document read on 2026-10-22: 169 operations). The platform calls it with one personal access token (`SUPABASE_PAT`) pinned to one organisation (`SUPABASE_ORG_SLUG`) to bootstrap, check and re-credential the project of each tenant (D-541, D-542, plan 12). It never manages a project's lifecycle or billing (prohibition PR-9). Every one of the 169 operations of the document appears exactly once below: as an `INTEGRATE` row (20 operations, one row each, capability = `METHOD path`) or inside a named `OPT-OUT` group (149 operations). The adapter `packages/core/server/projects/management-api.ts` may call only the `INTEGRATE` paths; a test in plan 12 reads this table and fails on any other path.

Decision vocabulary used here. `INTEGRATE`: a method of the `ProjectProvider` interface calls the operation (real adapter) and the fake provider mirrors it. `OPT-OUT`: no code calls the operation; the group's reason says why and, where a human does it instead, where it is documented. `UNCHANGED`: not part of the Management API; listed because this phase touches how it is reached. `NEW`: a route of our own API added by this phase.
