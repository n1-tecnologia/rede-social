### 2. Credential sealing: `projects/secret.ts`

**Analog:** `packages/core/server/payments/secret.ts` (opened in full). Copy: format `v1:<keyId>:<iv>:<tag>:<ciphertext>` (`:25-27,80-96`), AAD = the owning row id (here the `platform.projects` row id), key resolution with the dev-key-only-outside-production rule (`:43-65`), and the content-free error (`:32`). Excerpt (`:80-96`):
```ts
export function sealSecretWith(material, plain, integrationId) {
  const iv = randomBytes(IV_BYTES);
  const cipher = createCipheriv('aes-256-gcm', material.key, iv);
  cipher.setAAD(Buffer.from(integrationId, 'utf8'));
  const ciphertext = Buffer.concat([cipher.update(plain, 'utf8'), cipher.final()]);
  return [VERSION, String(material.keyId), iv.toString('base64url'),
    cipher.getAuthTag().toString('base64url'), ciphertext.toString('base64url')].join(':');
}
```
Open path rethrows only `new Error('... unreadable')` (`:118-121`) so no input reaches a log. New env: a distinct key (`PROJECTS_SECRET_KEY` / `_ID`) validated in `server/env.ts` with `assertProductionEnv` refusing a missing key in production (the WR-01 comment at `:55-56`). Seal each credential (service key, DB password, PAT-derived) separately with the project id as AAD, and add a `credential_version` that bumps on replace so `supabaseAdminFor` memoisation keys on `(projectId, credentialVersion)`. Unlike the payments helper, do not reuse `PAYMENTS_SECRET_KEY` (separate blast radius).
