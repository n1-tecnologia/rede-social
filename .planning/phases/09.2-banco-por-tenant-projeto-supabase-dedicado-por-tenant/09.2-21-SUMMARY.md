# Phase 09.2 Plan 21: The member's held-out screens and form cards Summary

**A refusal because a community is being updated or prepared now ends on a calm, branded sentence with one way back and the session intact: two new public screens, a mapping that never passes through the session-clearing route, and the login and sign-up forms stepping aside with the state's own glyph and sentences, while a paused or unreachable project keeps showing the generic "Comunidade indisponível".**

## Performance

- **Duration:** about 15 min (approximate; start not recorded)
- **Completed:** 2026-10-23
- **Tasks:** 2 (1 tracer, 1 auto)
- **Files:** 24 changed across the two task commits (1,129 insertions, 32 deletions)

## Accomplishments

- **Tracer.** `/comunidade-em-atualizacao` (`RefreshCw`) and `/comunidade-em-preparacao` (`Hourglass`) copy the shipped `/comunidade-indisponivel` frame: an async server component with no props, `EmptyState`, one `LinkButton` `outline lg fullWidth` "Verificar de novo" to `/inicio`. Both are public in `proxy.ts`. `bootstrapRedirectPath` maps `TENANT_UPDATING`, `TENANT_PREPARING` and `TENANT_UNAVAILABLE` straight to their screens and its docblock says why none of them uses `/auth/suspended`. The tests prove the properties the sketch asks for: no timer under ten minutes of fake time, no `meta refresh`, `cookies()`/`headers()`/`useSearchParams()` throw if touched, identical output on every render, and none of the platform's words.
- **Form cards.** `UnavailableCard` gained an optional `icon` (default `TriangleAlert`, structure asserted unchanged). `/entrar` and `/cadastro/[slug]` derive a `held` state from the by-host status and render the card with the state's glyph and sentences instead of the form; suspended and unreachable share the existing sentence and are asserted byte-identical (A-UI-8, PU-3).
- **Actions.** The login action, the sign-up action and the existing-account join redirect a held-out host to its screen before any Auth or API call and clear no cookie. On a generic host (no host status to read) the slug record's and the POST's 503 codes are mapped to the same screens, so a visitor of `/cadastro/{slug}` for a tenant being prepared sees the card, not "não encontrada".
- **Vocabulary.** The member strings live in the new `updating.json` and `preparing.json` catalogs (one root each, pinned verbatim); a catalog test scans all three held-out namespaces for banco, projeto, esquema, migração, Supabase and tenant.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The status table is a new module, with `heldOf` re-exported from `host-brand.ts`**
- **Found during:** Task 2
- **Issue:** the plan puts `heldOf` in `lib/host-brand.ts`, but every existing page test mocks `@/lib/host-brand` with only `getHostBrand`, so a page importing `heldOf` from there would crash in those tests (and in the new ones) unless each mock re-imported the real module, which pulls in the validated env.
- **Fix:** the pure table (`heldOf`, `heldPath`, `heldNamespace`, `heldIcon`, `heldOfCode`) is in the new env-free `apps/web/lib/held-out.ts`; `host-brand.ts` re-exports `heldOf` and the `Held` type (the plan's grep criterion holds) and the pages and actions import from `held-out.ts`.
- **Files modified:** `apps/web/lib/held-out.ts` (new), `apps/web/lib/held-out.test.ts` (new), `apps/web/lib/host-brand.ts`
- **Commit:** `1f3649e3`

**2. [Rule 2 - Missing critical functionality] The generic-host slug 503 and the existing-account join**
- **Found during:** Task 2
- **Issue:** the plan names the host status only, but plan 11's slug routes answer 503 with a code (no host status exists on a generic host), which the page turned into "não encontrada" and the action into a generic validation error; and `joinFromSignup` (the existing-password join on the same page) would have signed a person in on a held-out host.
- **Fix:** the page and `signup` read the envelope code through `apiErrorEnvelopeSchema` and map it with `heldOfCode`; `joinFromSignup` is refused up front and keeps the session if the join itself answers a held code.
- **Files modified:** `apps/web/app/(auth)/cadastro/[slug]/page.tsx`, `apps/web/app/(auth)/cadastro/[slug]/actions.ts`, their tests
- **Commit:** `1f3649e3`

**3. [Rule 3 - Blocking] Two test files outside the plan's list**
- `apps/web/app/(auth)/entrar/actions.test.ts` (new: the login action's held-out redirect had no test file) and an added `host-brand` mock in `apps/web/app/(auth)/cadastro/[slug]/actions.test.ts` (the action now reads the host brand).

**Total deviations:** 3 (1 Rule 2, 2 Rule 3). **Impact:** none on the contract; the screens, strings, mapping and public paths are exactly the plan's.
