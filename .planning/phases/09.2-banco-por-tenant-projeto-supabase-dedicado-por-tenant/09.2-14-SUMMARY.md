# Phase 09.2 Plan 14: The panel API for a tenant's Supabase project Summary

**An operator pastes a project ref and the panel API answers with a pre-check, creates the tenant in one transaction that registers the project, binds it and queues the bootstrap, shows the steps and a derived state, replaces a credential only after trying it against the project, re-derives the whole set from the platform token when the master key is lost, and a self-re-arming job keeps every project's health fresh, with no credential in any answer or log line**

## Performance

- **Tasks:** 3 (1 tracer, 2 auto)
- **Commits:** 3 task commits

## Accomplishments

- **Tracer (DBT-50, DBT-51).** `POST /v1/platform/projects/precheck` answers `{ ok: true, manualAccess }` for an empty healthy project; `POST /v1/platform/tenants` with `projectRef` registers the project `preparing`, binds the tenant with `pending_invite = { email, createdBy: null }`, writes eight pending steps and queues one `platform.project-bootstrap` job, all in one platform transaction under `pg_advisory_xact_lock(hashtext('project:' || ref))`. `GET /tenants/{id}/database` then follows the run (preparing, eight done, `unchecked`, `ready` once a health row exists). The scan over the create answer and every overview finds none of the five opened credentials, the publishable key, their sealed forms, `postgres://` or a registry column name.
- **One state derivation.** `databaseState` (contracts) ranks moving > preparation_failed > preparing > unreachable > paused > behind > unchecked > ready; `summarizeDatabase` gathers its inputs for the overview AND the list, and the SQL behind `?banco=problema` is written from the same facts and tested against the pill for every state.
- **Production refuses a shared project (D-540).** The check and the bind are one transaction under the per-ref lock; the second tenant answers `{ projectRef: 'in_use' }` with the first binding, steps, job and credentials byte-identical, and two creates racing leave exactly one tenant and none of the loser's rows. Outside production any number of tenants bind a project (a ready one is filled inline).
- **Credentials are write-only and replaced safely.** `replaceCredentials` tries each supplied value against the project (a candidate DDL connection, a candidate admin client, a candidate publishable key), then writes the changed columns, the new version and the timestamp in one statement under the project lock; a refusal changes nothing, two simultaneous calls queue and the later wins entirely (mutation-checked).
- **Break-glass.** `pnpm platform:reissue-credentials -- --ref <ref>` re-derives keys, `postgres` password, `api_user` password and hook secret from the platform token alone; it succeeds with every sealed column corrupted, recovers after an interruption, answers `busy` while a step runs or another holder has the lock, and a bootstrap claimed afterwards opens the new URL.
- **Health.** `checkProject` stores healthy, paused, unreachable (with a catalog code) and drops the caches only on a change; `platform.project-health` sweeps four at a time in ascending ref order, bounds each call by a timeout, re-arms 300 s out under a constant key and is armed at worker boot.
