<objective>
The second half of the phase tracer and the heart of the routing seam: a tenant that lives in a database other than the local stack's is served by a real request, its connection string coming out of the registry as a SEALED value, its pool held in a bounded cache, its lane resolved from the tenant id.

Plan 02 proved that any database can receive the tenant set; this plan proves that the API can address it. Heavy plan, justified: sealing, registry resolution, pool cache and lane routing are one chain (a connection string is useless without all four) and the tracer must cross them. Task 1 is the thin path; Task 2 hardens each link with unit tests that inject clocks and fakes; Task 3 extracts the payments sealing primitives (so the scheme exists once) and adds the re-seal command.
