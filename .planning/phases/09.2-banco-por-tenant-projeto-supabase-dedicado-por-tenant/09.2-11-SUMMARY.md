# Phase 09.2 Plan 11: Per-project hook, sign-up by slug and redirect allow-list Summary

**Each Supabase project now has its own Send Email Hook URL and secret, the slug routes tell the web which project's Auth to talk to (and refuse a tenant still being prepared), and the redirect allow-list is an adapter, a lock and a reconcile per project, with the legacy hook URL still serving project 0.**

## Performance

- **Duration:** 21 min (2026-10-23T02:23Z to 02:44Z)
- **Tasks:** 3 (one tracer, two auto) plus one test-inventory fix
- **Files:** 25 changed (1,676 insertions, 130 deletions)

## Accomplishments

- **Tracer (DBT-14).** `POST /v1/hooks/auth/send-email/:hookRef`: `resolveHookProject` reads `platform.projects` by exact `hook_ref` (a malformed or unknown reference answers 404 before the secret is opened), `hookSecretsFor` opens `hook_secret_sealed` per request, `verifyHookRequest` runs with that project's secrets only, and `sendAuthMail({ project })` refuses a tenant of another project (`wrong_project`). A recovery mail for a member of the tenant that lives only in database B is sent through B's URL and secret and branded from the mirror; the foil project's secret at B's URL is a 401. The legacy path is the same handler with the `SEND_EMAIL_HOOK_SECRETS` list and no project.
- **Sign-up by slug (DBT-15).** The slug record names the public `supabaseUrl` and `publishableKey` of a non-central project; `getPublicTenant` ranks the project with the new `hostStatusOf` (shared with `resolveTenantHost`) and answers 503 `TENANT_PREPARING`, `TENANT_UPDATING` or `TENANT_UNAVAILABLE` before any tenant lane opens. `signupMember` starts with `getPublicTenant`, so the POST is gated by the same code.
- **Allow-list per project (DBT-42).** `authAllowListFor(project)`, `withAllowListLock(projectRef, fn)`, `reconcileAuthAllowList({ projectId? })` and the worker's `onProjectStarted` call replace the global adapter, the global lock and the central boot extra.
