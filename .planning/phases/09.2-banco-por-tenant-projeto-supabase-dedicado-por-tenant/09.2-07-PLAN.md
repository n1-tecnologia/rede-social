<objective>
Settle who owns what between the control plane and a tenant's project, then move the sites that straddle both (the 'S' class) onto that rule.

D-537 splits the `tenants` and `tenant_modules` rows: the central project owns status, name, timezone, plan and which modules are enabled; the tenant's project owns the brand, the rules text and the modules' settings. Each side pushes its owned columns to the other side's copy after a commit, and a reconcile function (this plan; the job that runs it is plan 09) heals drift in both directions. A tenant on project 0 has ONE row serving both roles, so every push is skipped for it and behaviour is unchanged.

Tracer: suspending a tenant that lives in database B. The status is decided centrally, copied to B, and the shell's 'indisponível' answer still works with B closed; a push that cannot reach B does not block the operator.

Heavy plan, justified: ownership, the push helper, the five S-class files and the reconcile function are one idea; splitting the files would leave a push helper with no caller or a caller with no ownership table.

Decisions implemented: D-537 (mirror, ownership split, reconcile), D-538 (each S site as two explicit lane calls), D-539 (the brand's Storage objects follow the tenant's project).

<planning_decisions>
1. **One ownership table, as data.** `mirror.ts` exports `CENTRAL_OWNED` and `TENANT_OWNED` as readonly lists of `{ table, column }`; `mirror-fields.test.ts` asserts every column of `public.tenants` and `public.tenant_modules` (read from the Drizzle schema) is owned by exactly one side or marked `local` (`id`, `created_at`, `updated_at`), so a column added by a later phase fails the test until someone decides its owner.
2. **Push after commit, best effort, reconcile heals.** The authoritative write commits first; the push to the other side runs afterwards, logs `platform.mirror.push_failed` with a reason code and never throws into the request. For status the central copy IS the authority (`requireAuth` and the by-host answer read it from plan 08 on), so a failed push cannot leave a suspended tenant serving.
3. **`createTenant` saga is the final shape for the central project.** Plan 14 adds the project choice and hands the tenant-side steps to the bootstrap job for projects other than the default; the compensation here stays for the default-project path.
4. **Rules and settings are not mirrored.** Central never needs them (the panel does not show them), so only the brand is copied back (the by-host answer needs it).
5. **Reconcile never overwrites a tenant-owned column from the central copy** except when the tenant's row is missing entirely (it then seeds from the central copy, the only copy that exists).
</planning_decisions>
