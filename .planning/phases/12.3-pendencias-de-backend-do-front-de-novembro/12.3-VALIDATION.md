# Phase 12.3 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: the `## Validation Architecture` section of `12.3-RESEARCH.md`.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 5.0.0 (unit + integration), pgTAP via `supabase test db`, Playwright 1.63.0 |
| **Config file** | per-package `vitest.config.ts`; `apps/api/vitest.config.ts` (reads `.env.local`); `apps/web/playwright.config.ts` |
| **Quick run command** | `pnpm --filter <pkg> exec vitest run <file>` (per-requirement commands in the map below) |
| **Full suite command** | `pnpm turbo typecheck test` (unit), then `pnpm supabase test db`, then `pnpm test:integration`, then `pnpm e2e` |
| **Estimated runtime** | quick run: seconds; unit full: minutes; pgTAP + integration: needs the local Supabase stack running |

---

## Sampling Rate

- **After every task commit:** run the single package's `vitest run <file>` from the map below, plus `pnpm --filter @rede-social/api exec vitest run tests/unit` when a route or an inventory changes.
- **After every plan wave:** `pnpm turbo typecheck test`, then `pnpm supabase test db`, then the touched integration files by file or title (the integration filter does not take a bare argument, see the repo notes).
- **Before `/gsd-verify-work`:** full `pnpm verify` green; per block, unit + pgTAP + touched integration green and the affected Playwright specs (`e2e-affected`).
- **Max feedback latency:** ~60 seconds for the quick run.
