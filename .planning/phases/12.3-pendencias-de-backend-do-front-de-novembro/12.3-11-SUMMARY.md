# Phase 12.3 Plan 11: Store categories contract, lazy seed, front read and product category Summary

**The store contract now owns the category limits and the one name-guess rule, `GET /v1/store/front` seeds a store's eight built-ins lazily and answers only active promo and featured products, and a product's category (the slug) is written on create (absent key guesses) and edit and read on every list and detail.**

- **Duration:** about 11 min (17:04 to 17:15, local)
- **Tasks:** 3 (one tracer, two auto), all with failing-or-proving tests first
- **Files modified:** 8, no file created

## Accomplishments

- **Contract (`packages/modules/store/contracts/index.ts`).** `STORE_CATEGORY_MAX` 20, `STORE_CATEGORY_NAME_MAX` 30, `STORE_FEATURED_MAX` 5, `STORE_CATEGORY_ICONS` (the 20 glyphs verbatim), `STORE_CATEGORY_SLUG_RE`, `STORE_BUILT_IN_CATEGORIES` (slug, name, icon, in order), the moved pure functions `plainText`, `guessStoreCategory`, `cleanCategoryName` (now counts code points) and `newCategoryId`, `storeCategorySchema`, `storeFrontSchema`, the nine refusal codes, `category` as an optional slug on card and detail and a nullable optional slug on the create and patch bodies. `STORE_PRODUCT_CATEGORIES` and `StoreProductCategory` stay exported as the seed list.
- **Service and route.** `ensureSeeded` (marker read, then the tenant-pinned `app.store_seed_categories()`), `findCategory` and `resolveCategory` (slug resolved under RLS with a key-share lock in the writing transaction), `getFront` (promo only while active; featured via `unnest ... with ordinality`, active only, stored order), and `GET /v1/store/front` behind the router's auth and module guards. The category slug is selected by a correlated subquery in all three list statements and in the detail, so list order and cursor are untouched.
- **Web.** `apps/web/lib/store-categories.ts` re-exports `plainText` and `guessStoreCategory` from the contract: one rule, its own test (6 cases) and `store-setup.test.ts` still pass.
- **Proofs.** 113 contract unit cases (an `it.each` over all 68 corpus rows), 13 front/category integration cases in `store.test.ts` (63 in the file), a cross-tenant case in `isolation.test.ts` and the inventory entry `GET /v1/store/front`.

## Decisions Made

- OQ-2 and OQ-3 recorded as planned (see key-decisions).
- Front categories are ordered `position, slug`: the plan wrote "position, id" and the contract's id is the slug.
