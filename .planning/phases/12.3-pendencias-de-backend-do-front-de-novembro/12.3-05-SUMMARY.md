# Phase 12.3 Plan 05: A module's own card cover and Topo Summary

**A module keeps two optional images, its card cover and its Topo, written on create and edit with the courses cover checker under their own codes (`cover_invalid`, `top_cover_invalid`), read by every admin module view, and carried to the member by ONE extra statement merged by module id, with `app.course_outline` and every migration untouched.**

## Accomplishments

- Contract: `coverAssetId` and `topCoverAssetId` nullable with default null on `moduleInputSchema`, optional on `modulePatchSchema` (the one-key `patch_empty` rule still holds, either image alone satisfies it), and `.nullable().optional()` on `moduleViewSchema` (which `courseDetailSchema.modules` and the reorder answer reuse) and on `learnOutlineModuleSchema` (D-696).
- Admin service: `createModule` and `updateModule` call `resolveCoverAsset` per image in the same transaction (a null performs no lookup; an edit that leaves a key out leaves its column alone, so two parallel one-key edits both land under the module row lock); `readModulesOf` and `readModule` select both columns.
- Member path: `readModuleCovers` runs ONE extra statement in the `getLearnCourse` transaction (`id, cover_asset_id, top_cover_asset_id` of the course's live modules, tenant and course filtered, under the member's RLS); `groupModules(rows, courseLocked, covers)` sets both keys from a map by module id. A module the statement did not see reads null for both. The lesson read still calls `readOutline` alone.
- Tests: a positive control beside every negative (ready demo cover vs pending, wrong purpose, video, rede-lab, unknown, malformed; the lab admin touching a demo module is the bare 404); the five NOVF-03 edges; reorder, removal and empty on the member read; contract unit cases.

## Deviations from Plan

**1. [Rule 1 - plan error] A foreign or unknown module image is a 400 by name, not a bare 404**
- **Found during:** Task 1 (reading `resolveCoverAsset`, per the orchestrator heads-up from plan 04)
- **Issue:** the plan says "a foreign or unknown asset is the bare 404", but the shared helper answers ONE `400 { courses: issue }` for every miss by design (08.3-04, T-08.3-02) and the existing card-cover tests assert it.
- **Fix:** kept the checker unchanged; the tests assert `400 cover_invalid` / `400 top_cover_invalid` for foreign, unknown, pending, wrong-purpose and wrong-kind ids, beside a positive control. The bare 404 stays for the lab admin touching a demo module and for an unknown module id.
- **Impact:** the web of plan 08 maps both codes to its copy; a literal 404 would be a change of the shared helper plus the card cover tests, a separate decision.

**2. [Rule 3 - blocker] The module sheet's create body had to name the two new keys**
- **Found during:** Task 3 (the web typecheck, which runs `next build`)
- **Issue:** `ModuleInput` is the zod output type, where a defaulted key is required, so `ModuleSheet.tsx` (`const body: ModuleInput = { title, summary, requiresPrevious }`) no longer type-checked. Plan 04's SUMMARY said the web stayed green because every new wire key was optional; that holds for read schemas, not for a defaulted input.
- **Fix:** the create body in `apps/web/app/(app)/cursos/[courseId]/ModuleSheet.tsx` now sends `coverAssetId: null, topCoverAssetId: null` with a comment that plan 12.3-08 writes them. Behavior is identical (null is the default). The file is outside this plan's `files_modified`; committed with Task 3.
- **Files modified:** `apps/web/app/(app)/cursos/[courseId]/ModuleSheet.tsx`
