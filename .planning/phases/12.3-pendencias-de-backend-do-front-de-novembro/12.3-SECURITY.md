# Phase 12.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Admin browser → API (second covers, poster) | An admin with `courses.manage` or `events.event.manage` sends an asset id for a Topo, a module cover or an event poster; the API must resolve it inside the tenant | Asset ids issued by the `cover`-purpose upload broker |
| Member → API (track, curriculum and storefront reads) | A member reads the new free text, the second covers and the storefront front; every read stays inside the tenant and the active filter | Track subtitle, audience, description, cover ids, categories, featured list |
| Admin browser → API (storefront setup, phone menu) | An admin with `store.product.manage` or `tenant.manage` saves categories, featured list, promo product and the phone menu | Category names (30 characters at most), product ids, menu keys |
| API → Postgres (RLS, `SECURITY DEFINER` functions) | `store_categories` and `store_front` are admin-write; the lazy seed and the one-time load run tenant-pinned | Tenant id from claims, category and front rows |
| Public by-host answer | The unauthenticated host lookup returns a projection of the tenant brand | Five named brand keys, no phone menu |
| Release path (migrate-all → API → worker → web) | The one-time load runs in every hosted project; the web is released once after block D | Schema, category rows, release order |
