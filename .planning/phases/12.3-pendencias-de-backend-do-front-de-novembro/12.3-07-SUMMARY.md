# Phase 12.3 Plan 07: The Topo of a track and a course as its own image Summary

**`CoverField` gets a real second picker (`topCover`) with its own upload, preview, progress, remove and error, the track and course forms save `topCoverAssetId` next to the card cover, and the member track and course pages draw their hero as Topo, else card cover, else brand gradient through the pure `lib/cover-fallback.ts`.**

## Accomplishments

- `CoverField` (blocks layout): a `topCover` prop replaces the `alsoAs` view of the same image. The Topo block has its own sr-only input named by the new add/change labels (and a camera input), its own drop target, its own progress bar with percent and Cancelar, polite announcement, "Remover imagem do topo" on its label line, and its own `role=alert` error line. Hooks: `data-{hook}-top-cover-preview|local|fallback|error|remove`; the card hooks are untouched. An empty Topo draws the card image cropped to 4:1 with "Sem imagem própria: mostrando a do cartão."; with neither image, the brand gradient. When `topCover` is used, the card block's progress, error and helper move under the card block so each block carries its own status. `alsoAs` still works for the modules (plan 08) and the other forms.
- `TrackForm` and `CourseForm`: a second `useSignedUpload` + `useCoverPreview` pair, `topCoverAssetId` state, dirty and busy gates that count either upload, `top_cover_invalid` mapped under the Topo block, strings from the courses catalog (`coverField.topCover.*`).
- `lib/cover-fallback.ts`: `trackTopCover` and `courseTopCover`, pure, tolerant of a missing key (D-696).
- The member track page (`MemberTracksTab`) and course page (`MemberCoursePage`) draw the hero through the fallback; the member views carry the stored Topo (`topCoverAssetId`, null for an older answer).
- Playwright: the courses admin E08 case now picks a card image and a different Topo through their own inputs, asserts two independent previews and reads both ids from the saved course and the reopened form.

## Decisions Made

- The Topo block keeps `data-cover-block="page"`, the hook the previous second block had.
- On edit, an image id is sent only when it changed; on create both are always sent (see key-decisions).
- The card block's progress, announcement, error and helper render under the card block, not at the foot of the whole field, once a `topCover` exists, so "one block, one image, one failure message".

**1. [Rule 3 - blocker] The Topo had to reach the form defaults and the member views**

- **Issue:** the plan lists no change to `courses-view.ts` or `courses-member-view.ts`, but `TrackFormDefaults`, `CourseFormDefaults`, `TrackDetailView` and `CourseHeroView` carried only `coverAssetId`, so neither the edit forms nor the member pages could see the stored Topo.
- **Fix:** added `topCoverAssetId` (`track.topCoverAssetId ?? null`) to the four shapes; updated the one `toEqual` in `courses-view.test.ts` and added view cases.
- **Files modified:** `apps/web/lib/courses-view.ts`, `courses-view.test.ts`, `courses-member-view.ts`, `courses-member-view.test.ts`
- **Commits:** `9944c004`, `30c6a5f6`

**2. [Rule 3 - blocker] A helper for the E08 case**
- **Issue:** the case must read the saved course's Topo, and `e2e/courses-admin.ts` had only `courseCoverAssetId`.
- **Fix:** `courseTopCoverAssetId` beside it. **Commit:** `8539e9e9`

**3. [Rule 1 - stale assertion] The reopened form's card preview ratio**
- **Issue:** the E08 case asserted the reopened card preview at 0.75 (the 3:4 poster), while the same case already asserted 16:9 for the same frame since the 2026-10-27 redesign.
- **Fix:** the reopened assertion now reads 16:9 (the frame's real ratio). Not run here, so unconfirmed against the stack.

**4. Plan prose vs behavior, "both ids sent on every save"**
- The forms already patch only the changed keys; sending an unchanged id on every PATCH would re-run the asset check for nothing. Create sends both always; edit sends each id when it changed (`null` for a removal). If the product owner wants both ids on every edit too, it is a two-line change per form.

**5. courses-member-area.spec.ts left unchanged**
- The plan names it for "steps that assert the track page banner", but no step in it reads the banner's image or ratio, so nothing in it breaks. It is only listed (compiles).
