# Phase 12.3 Plan 04: The Topo of a track and of a course Summary

**Tracks and courses keep a second image (the "Topo"), written on create and edit with the card cover's checker under its own code `top_cover_invalid`, and returned by the admin detail and every member read as the stored id or null, with no fallback computed in the API.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-11-09
- **Tasks:** 3 (Task 1 tracer for a track, Task 2 for a course, Task 3 the edges and exit check)
- **Files modified:** 9 (4 production, 5 test)

## Accomplishments

- Contract: `top_cover_invalid` in `COURSE_ISSUES`; `topCoverAssetId` nullable with default null on `trackInputSchema` and `courseInputSchema`, optional on both patch schemas (the one-key `patch_empty` rule keeps working, the Topo alone satisfies it), and `.nullable().optional()` on `trackDetailSchema`, `courseDetailSchema`, `learnTrackSchema` and `learnCourseSchema` (D-696).
- Service: `createTrack`, `updateTrack`, `createCourse`, `updateCourse` call `resolveCoverAsset(tx, ctx, id, 'top_cover_invalid')` in the same transaction (a null performs no lookup, an edit that leaves the key out leaves the column alone); `readTrack` and `readDetail` return it.
- Member path: `t.top_cover_asset_id` in the `trackRows` select, `MemberTrackSqlRow`, `memberTrackRows`, `MemberTrackRow`, `TrackView` and `trackStates`; `c.top_cover_asset_id` in `readPublishedCourse`, `CourseHeaderRow` and `getLearnCourse`. Catalogue and course cards keep the card cover only.
- Tests: a positive control beside every negative (ready demo cover vs pending, wrong purpose, video, rede-lab, unknown, malformed; the lab admin's edit of a demo row is the bare 404); the five NOVF-02 edges for both entities; contract unit cases for the optional key on the four read schemas.

## Deviations from Plan

### Plan inconsistency resolved in favor of the existing behavior

**1. [Rule 1 - plan error] A foreign or unknown Topo asset is a 400 by name, not a bare 404**
- **Found during:** Task 1 (reading `resolveCoverAsset`)
- **Issue:** the plan says both "validated like `coverAssetId` with the same `resolveCoverAsset`" and "an unknown or foreign asset is the bare 404". The shared helper answers ONE `400 { courses: issue }` for every miss (wrong purpose, kind, status AND unknown, removed or another tenant's id), by design (08.3-04, T-08.3-02: the answer never tells a foreign id from an unknown one; the store's `image_invalid` is the one that keeps the bare 404). The existing card-cover tests assert that 400.
- **Fix:** kept the single checker and gave it the new code, so the Topo behaves exactly like the card cover. Changing the helper to a 404 for the Topo only would have split one checker into two and broken the "same checker" prohibition. The tests assert `400 top_cover_invalid` for foreign and unknown ids, beside a positive control. No cross-tenant information is disclosed either way. The bare 404 stays where the plan also puts it: the lab admin touching a demo track or course row.
- **Files modified:** none beyond the plan (tests assert the 400)
- **Impact:** the web of plan 07 maps `top_cover_invalid` to its copy like `cover_invalid`; if Igor wants a literal 404 for a foreign Topo it is a one-line change in `resolveCoverAsset` plus the card cover's tests, a separate decision.
