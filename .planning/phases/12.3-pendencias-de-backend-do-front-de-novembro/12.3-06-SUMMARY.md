# Phase 12.3 Plan 06: The vertical poster of an event Summary

**Events keep a vertical 4:5 poster beside the horizontal cover: written on create and on the whole-event PUT with the cover's own checker under the code `poster_invalid`, read back with its variant ladder by the list, the detail, the create and update answers and the admin edit view from one extra `left join media_assets` in the same statement, and a poster-only edit is a real change.**

## Performance

- **Duration:** about 18 min
- **Started:** 2026-11-09T19:14Z
- **Completed:** 2026-11-09T19:32Z
- **Tasks:** 2 (Task 1 tracer, Task 2 the PUT and the edges)
- **Files modified:** 4 (2 production, 2 test)

## Accomplishments

- Contract: `poster_invalid` in `EVENT_ISSUES`; `posterAssetId` (`z.uuid().nullable().optional()`) on `eventInputSchema`; `posterAssetId` and `posterVariantWidths` (optional) on `eventSummarySchema` (so the detail inherits them) and `eventEditSchema`.
- Service: `resolveCoverAsset` takes the refusal code (default `cover_invalid`, the cover is unchanged); `createEvent` resolves and inserts the poster; `eventColumns`, `eventSource` and the edit read add `case when pa.id is null then null else e.poster_asset_id end` and `pa.variant_widths` through one `left join media_assets pa` each (the list, detail and create read-back share the first), so every read is still ONE statement.
- `updateEvent`: `poster_asset_id` in `LockedEventRow` and the locked select, handled like the cover (a different id is resolved strictly, the stored id re-sent and retired is healed to null), in the `next` CTE, the `update ... set` and BOTH `is distinct from` tuples. An absent `posterAssetId` clears the poster, an explicit `null` too; the cover is unaffected either way.
- Tests: integration cases 10 to 15 and contract unit cases 39 to 41 (see Commands).

## Note for plan 17 (the API notes for the web)

An older web that saves an event without the `posterAssetId` key CLEARS the stored poster: the whole-event `PUT` is a replacement and an absent key is "no poster", exactly as an absent `coverAssetId` clears the cover. Acceptable because the web ships last; the new web must always re-send the poster it read.

## Decisions Made

- The refusal for a new poster id is `404` (bare) for a foreign or unknown asset and `400 { event: 'poster_invalid' }` for a wrong purpose, kind or status, because that is what the events module's own cover checker already answers. This matches the plan's text.
- The log lines gain two flags only (`hasPoster`, `posterHealed`); no poster id enters any log field (T-12.3-10).
