# Phase 12.3 Plan 08: Module images and the event poster as real uploads Summary

**The module sheet saves two independent images (card 16:9 and Topo 4:1) through the module routes, the event form saves the vertical poster as its own upload on every whole-event save, and members read both through pure web fallbacks (module card, module Topo, list poster).**

## Accomplishments

- **Module sheet (tracer, NOVF-03, OQ-1, UI-D-691).** `ModuleSheet` replaces its local-preview-only cover with two real pickers on `CoverField` (hook `module`): the card block (16:9, the shipped helper) and the Topo block (4:1, the new module helper "Opcional. Sem imagem própria, o topo usa a imagem do cartão do módulo e, sem ela, a capa do curso."), each its own `useSignedUpload` + `useCoverPreview` pair, progress, Cancelar, announcement, remove and error. Create sends both ids (null for an empty one, never the other's id, never the course's); edit patches only what changed. Save is disabled while either upload runs, and the edit sheet opens with the stored images from `ModuleView`. `cover_invalid` shows under the card block and `top_cover_invalid` under the Topo block, never a toast. Hooks `data-module-cover-*` and `data-module-top-cover-*`.
- **Member readers (NOVF-03, UI-D-692, PU-2).** `moduleCardCover` (own card cover, else the course's, else null) and `moduleTopCover` (own Topo, else own card cover, else the course's, else null) in `lib/cover-fallback.ts`. The course page's module cards call the first; the module page's hero calls the second. `ModulePageView` carries the module's stored ids (null for an older answer); the web parser keys stay optional.
- **Event poster (NOVF-04, UI-D-693).** `EventForm` holds a second upload machine for the vertical poster, independent of the horizontal cover (own progress and Cancelar, `LoaderCircle` veil, announcement, error). `posterAssetId` travels in every payload, null when removed or never set; the stored id is re-sent on an unrelated edit; the dirty check counts the poster. `poster_invalid` shows its sentence under the poster block; the poster helper and refusal strings are in the events catalog. The edit page hands the stored poster to the form. The old object-URL preview and every "front only" comment are gone.
- **Events list (NOVF-04).** `eventListPoster` (poster with its ladder, else the horizontal cover with its ladder, else null) feeds the `/eventos` poster card; `EventCardView` carries the stored poster id and ladder. The event's own page still draws the horizontal cover (pinned by a view test).
- **Specs (D-700).** `events.spec.ts` test 1 uploads a real poster beside the cover, asserts the list card draws the poster and the event page the cover, and test 2 asserts the saved poster comes back in the edit form and survives a rename; the cover button is matched by exact name because "Adicionar capa vertical" also contains it. `courses-admin.spec.ts` asserts the module sheet's two real pickers and helpers. No spec was added.

**4. [Rule 2 - missing critical] The write actions told a bare 404 on a poster from a missing event**
- **Found during:** Task 3 (heads-up (b): the events API answers a bare 404 for a foreign, unknown or retired poster id)
- **Issue:** `coverAwareRefusal` only attributed a 404 to the cover, so a bad poster would show the event's "not found" screen text in the top card.
- **Fix:** it now takes both submitted ids. On create, a 404 is the cover if one was sent, else the poster. On update the event is re-read, and only an image whose id CHANGED can be the refused one (the API tolerates a stored id re-sent): the cover, else the poster (`poster_invalid`); both unchanged stays `not_found`. A previously unchanged cover re-sent on an update no longer reads as `cover_invalid`, which matches the API's tolerance.
- **Files modified:** `apps/web/app/(app)/eventos/actions.ts`; new `apps/web/app/(app)/eventos/actions.test.ts` (8 cases)
- **Commit:** `0a39fc3b`

**5. [Rule 1 - stale selector] The events spec's cover button**
- **Issue:** `page.locator('[data-event-form] button', { hasText: 'Adicionar capa' })` also matches the poster's "Adicionar capa vertical" button (`hasText` is a substring match), a strict-mode violation.
- **Fix:** `getByRole('button', { name: E.form.cover.add, exact: true })`. Unconfirmed against the stack (not run).
- **Commit:** `f7af42f5`

**6. Plan prose vs behavior, "both ids sent on every save" (module)**
- Create sends both always; edit sends each id only when it changed (null for a removal), as plan 07 did for tracks and courses. The event form is the exception by design: it always sends `posterAssetId`.

**7. Spec steps that "relied on the browser-only poster"**
- No step of `events.spec.ts` or `courses-admin.spec.ts` read the local-only poster or module preview, so none broke; the specs were extended in place instead (see Accomplishments). Nothing was added as a new case.
