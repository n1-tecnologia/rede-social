# Phase 12.3 Plan 16: Phone menu web Summary

**The phone menu the admin arranges is now kept by the API in the tenant's brand and drawn on the real phone chrome of every member on the next load; the editor saves and clears it through two server actions with the contract's rules as pre-check, and the per-device menu cookies are deleted.**

## Performance

- **Duration:** about 25 min (18:20 to 18:46 local)
- **Tasks:** 3 (one tracer, two auto), RED commit before GREEN for tasks 1 and 2; task 3 had no code to test
- **Files:** 5 created, 9 modified, 1 deleted

## Accomplishments

- **Read path (tracer).** `savedPhoneLayout(branding)` returns the brand's `phoneMenu` as a `PhoneLayout` or `null`; `layout.tsx` passes it to `withPhoneLayout` for every member and `configuracoes/menu/page.tsx` seeds the editor from the same value. `phone-nav-layout.ts` keeps only `PhonePlacement` and `placementAllowed`, now over `PHONE_MENU_BAR_ONLY` and `PHONE_MENU_NEVER_TOP` from the contract. `phone-nav-layout-cookie.ts` is deleted and `grep -rn "rede_nav_layout\|rede_nav_order"` over web app, components, lib, e2e and `packages/core` prints nothing (comments included). The `ShellNav.phoneLayout` doc comment says the layout arrives through the brand (comment only).
- **Write path.** `lib/phone-menu.ts` (`PUT` and `DELETE /v1/admin/branding/phone-menu`: a 400 with `details.phoneMenu` in `PHONE_MENU_ISSUES` is `rules`, 401/403 the app knows is a navigation, a lost permission leaves for Configurações, anything else `error`, shape-only logging) and `configuracoes/menu/actions.ts` (`savePhoneMenuAction` parses with `phoneMenuSchema` then `validatePhoneMenu` before any request, `clearPhoneMenuAction`, `revalidatePath('/', 'layout')` on success, `redirect` outside any try/catch).
- **Editor.** Same markup, preview, drag, arrow keys and live regions. "Salvar" sends `{bar, top, hidden}` (hidden holds only known items) or, for a draft equal to the shell's own menu, clears; the button shows "Salvando…" in place and the restore button is disabled while pending; success toasts "Menu salvo." and refreshes; a rule refusal or any other failure shows its sentence in a `role="alert"` line above the buttons and keeps the draft; the scope line "Vale só no celular. Todos os membros veem este menu." is 12/400 tertiary above the footer row; no per-role or per-language control.
- **Catalog.** `admin.menu.device` is now `admin.menu.scope`; `saved` reads "Menu salvo."; `saving`, `errors.rules` and `errors.generic` added. `grep "neste aparelho" admin.json` prints nothing.
- **Selection.** Group `phone-menu` in `affected-map.json` (the menu page directory, `PhoneMenuEditor*`, `phone-nav-layout*`, `phone-menu*`) to `shell.spec.ts` and `courses-member-area.spec.ts`.
