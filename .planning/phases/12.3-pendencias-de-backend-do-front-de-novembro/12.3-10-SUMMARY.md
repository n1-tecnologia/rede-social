# Phase 12.3 Plan 10: pgTAP for the store categories, seed, load and guess rule Summary

**One 165-case pgTAP file proves the two new store tables, the once-only seed, the one-time load and the SQL guess rule against all 68 rows of the shared corpus, and the two house lists (010, 020) now carry both tables.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-11-09
- **Tasks:** 3

## Accomplishments

- `228-store-categories.sql` (165 cases, fixture prefix `28000000-0000-4000-8000-`, ends in `rollback;`, leaves 0 rows in the local database, checked by `psql` after the run):
  - Shape and CHECK boundaries: slug 24 ok and 25 refused (also 1 char ok, uppercase and leading or trailing hyphen refused), name 1 and 30 ok, 0 and 31 refused, icon 32 ok and 33, empty and a bad icon refused, negative position refused, 5 featured products ok and 6 refused (update and insert), the featured default empty, unique slug and unique `lower(name)` per tenant (x then X refused), the same slug and name allowed in a second tenant, a rename or delete in one tenant never touching the other, and both `on delete set null` keys proved by constraint type and by behaviour.
  - Seed once: the seam inserts 8 rows with the built-in slugs, names, icons and positions, 0 the second time, 0 after a delete-all (marker stays), 0 after a partial first run; a front row with no marker is claimed and an admin-made `cursos` row is kept; a null tenant does nothing.
  - Lazy seed: a tenant-B admin seeds B and leaves A at 0; a member of A seeds A with the definer's rights; a second call seeds nothing; a claimless session does nothing; an emptied store is not refilled.
  - Privileges: `anon` cannot run the lazy seed, `authenticated` can; the seam and the load are refused to `authenticated`, `service_role` and `anon` (has_function_privilege) and an admin lane calling either gets 42501.
  - Policies: positive controls for the admin of A (read, insert, rename, delete, set promo product) beside member, support and cross-tenant negatives on both tables, a tenant-B session reading none of A's categories or front row (T-12.3-03), A's rows intact afterwards, 4 policies per table, RLS on, TRUNCATE revoked from `authenticated` (T-12.3-07).
  - Guess parity: 68 corpus rows (the file quotes them into a temp table through a script, never retyped), a mismatch-listing `is_empty`, an ordered `results_eq`, `led` equipamentos and `ledger` outros; whole-word boundaries (29 cases), empty and null names, accents and case (17 cases), the priority order for adjacent pairs both ways and a descending chain (19 cases).
  - Known divergence pinned: `unaccent` also folds letters NFD does not decompose, so `Łed` is `equipamentos` in SQL and `outros` on the web; a second assertion proves no corpus row exercises the difference.
  - Initial load on a 23-product fixture: LA (8 products, an admin-made `especiais` category, one already categorized, one archived, an empty name) gets each product in the guess category and keeps its `especiais` product; LB (already seeded) and the seeded A and B are skipped with their products still uncategorized; LC (emptied by its admin) is not re-seeded; LD (store module on, no product) gets no category and no front row; O1 and O2 (opposite storage orders) land identically; no `updated_at` of the 23 products changed; the counters are 3 tenants and 17 products net of a baseline; a second run returns 0, 0 and leaves products, categories and marker rows set-equal.
- `010-rls-coverage.sql`: `('store_categories'), ('store_front')` added to the explicit list of the fourth assertion; `plan(4)` untouched.
- `020-tenant-isolation.sql`: one category and one front row seeded per tenant, eight cases per table (own read, adjacency, own identity, detail by key, cross insert 42501, cross update 0 rows, member write to its own tenant 42501, TRUNCATE not granted), `plan(280)` to `plan(296)`.
- `040-schema-conventions.sql`: passes unchanged, no count moved, not touched.
