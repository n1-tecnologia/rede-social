## Decisions Made

- `events` rides `events_tenant_isolation` (`for all`, tenant only), so the database does not distinguish a member from an admin on the poster column; that rule is `requirePermission('events.event.manage')` in the service. 227 therefore asserts only the cross-tenant refusals for the poster and says so in its header instead of claiming a refusal the database does not make.
- The header of 227 states that the foreign key is plain and the database does not refuse a foreign asset id (T-12.3-01, accepted, services own it).
