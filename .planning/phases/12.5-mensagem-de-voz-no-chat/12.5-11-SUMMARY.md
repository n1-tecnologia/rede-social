# Phase 12.5 Plan 11: Voice send plumbing on the web server side Summary

**A recording now goes from the browser to a stored voice message through two typed API clients, two strict-validated server actions and a pure `runVoiceSend` that uploads once, waits out the worker's normalization and retries by re-sending the same asset, while the service worker stops sitting in the path of audio and video requests.**

## Performance

- **Duration:** 8 min (20:36 to about 20:44 local)
- **Tasks:** 3 (task 1 the tracer)
- **Files:** 11 (7 created, 4 modified); no TSX file, no module UI file, no SQL

## Accomplishments

- **Clients and actions (Task 1, tracer).** `sendSupportVoice` and `replyVoice` in `lib/chat.ts`; `sendSupportVoiceAction` and `replyVoiceToConversationAction` run `voiceSendInputSchema` / `voiceReplyInputSchema` before any request, read the translator and the bootstrap before the write, answer the finished `ChatMessageView` (with the API's `case` passed through) and map every refusal to one closed word. The failing orchestration test was written first and seen to fail (module missing).
- **Orchestration (Tasks 1 and 2).** `runVoiceSend(deps, take, handlers, resume?)` strips `;codecs=...`, starts an `audio`/`voice` upload with the take's size, PUTs, completes, then repeats the same send every 700 ms for at most 20 s on `not_ready`. `classifyVoiceFailure` and the resume path were added after their tests failed (21 red, then green). `voiceSendDeps` wires `startMediaUploadAction`, `completeMediaUploadAction`, `uploadBytes`, the caller's send action, a real timer and `Date.now`.
- **Service worker (Task 3).** `lib/sw-rules.ts` holds rule (a) as `isNetworkOnlyRequest`; `sw.ts` calls it and the header comment records the Safari Range reason. A mutation check (removing the audio clause) turned the audio test red, so the test really guards it.
- **Media route (Task 3).** The first test of `app/v1/media/[assetId]/[variant]/route.ts` pins the Range behaviour and every shipped answer. It passed at once: the handler never reads request headers and forwards only `location` and `cache-control`, so it needed no change.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] The 20 second cap ignored send latency**
- **Found during:** Task 2
- **Issue:** T-12.5-45 says one send loop of at most 20 seconds; counting only the injected sleeps lets 29 slow round trips stretch the loop well past it on a real network.
- **Fix:** an optional `now()` dependency; the loop gives up when the larger of the slept total and the real elapsed time plus one poll passes 20 s. Without `now` (the unit tests) the plan's counts hold: 29 sends, 28 sleeps of 700 ms. `voiceSendDeps` supplies `Date.now`.
- **Files modified:** apps/web/lib/voice-send.ts, apps/web/lib/voice-send.test.ts, apps/web/app/(app)/suporte/voice-deps.ts, apps/web/app/(app)/suporte/voice-deps.test.ts
- **Commits:** 3a5ff48d, 3d056be4

**Total deviations:** 1 auto-fixed (missing critical). **Impact:** none on the plan's contracts; one optional dependency added.
