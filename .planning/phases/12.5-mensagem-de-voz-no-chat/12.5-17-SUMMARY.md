# Phase 12.5 Plan 17: The end-to-end voice spec Summary

**`chat-voice.spec.ts` walks a voice message from Chromium's fake microphone to the team's audio element across two browser contexts and checks the media gate from another member, the deleted state, the refused microphone and the too-short discard. It was written, listed (8 tests on the two Chromium projects) and typechecked. No Playwright test was run.**

## Performance

- **Duration:** about 20 min
- **Started:** 2026-11-18T00:52Z
- **Completed:** 2026-11-18T01:13Z
- **Tasks:** 2 (task 1 the tracer)
- **Files:** 4 (1 created, 3 modified)

## IMPORTANT: this spec was not run

No agent ran a Playwright test, `pnpm e2e` or `pnpm verify`, started the web server, the API, the worker or the local stack, or touched the database for it. The only Playwright command used was `playwright test --list`, which loads the file and prints the tests. The run is a ledger row of plan 12.5-18 and happens on Igor's word. Everything the spec claims about behaviour is therefore unproven until then.

## Accomplishments

- **Tracer (Task 1).** `1. voice tracer`: the member records about two seconds (the wait is the recording counter matching two seconds or more, role `timer`, no fixed sleep), taps send, sees `[data-chat-bubble="own"][data-pending]` and then the settled bubble (an `audio` element, no pending mark, a `0:0N` length). The support user in a second context, with the same device preset, finds `a[data-inbox-row]` of that conversation, sees the preview match the catalog template `voice.preview` and one glyph inside the preview line, opens the thread, taps the play disc and waits with `page.waitForFunction` on the element's handle for `!paused && currentTime > 0`, then pauses and sees the play disc return. Before tapping it checks `canPlayType` for AAC and fails with a message that names the cause.
- **The rest (Task 2).** `2. the gate` (uploader 302, another throwaway member 404, no `location`), `3. a deleted recording` (helper soft-deletes, reload, `[data-chat-voice-deleted]` reads the catalog sentence, zero audio elements), `4. refused microphone and too short` (the at-once send discards with the catalog notice, no bubble added and no asset row; a no-permission context shows the blocked sentence, keeps the microphone enabled and sends a text message).
- **Helpers.** `conversationIdOf`, `voiceAssetIdsOf`, `softDeleteVoiceAssets` (the same statement as the account-deletion step: status `deleted`, `deleted_at`, filename blanked) and `deleteVoiceAssetsOf`, each scoped by one throwaway member's own id and tenant.
- **Cleanup.** `beforeEach` and `afterAll` delete the two `e2evoice-` members' conversations first (messages and cases cascade, and the messages hold the asset key), then their voice assets, then the members.
- **Affected map.** The spec joined the `chat`, `catalog-chat`, `media` and `pwa` groups; `apps/web/lib/voice-send.ts` joined the chat globs and `apps/web/lib/sw-rules.ts` the pwa globs.

**2. [Interpretation] The refusal test does not use a denied permission**
- **Found during:** Task 2
- **Issue:** the plan says "a context WITHOUT the permission". With `--use-fake-ui-for-media-stream` on the launch, Chromium answers the prompt, so an absent permission would not refuse.
- **Fix:** the context has no permission and the capture call answers `NotAllowedError`, exactly what a denial raises. Named in the spec header.
- **Commit:** 241a5f91

**3. [Addition] An optional `PLAYWRIGHT_VOICE_CHANNEL` environment variable**
- **Issue:** the stored file is mono AAC `audio/mp4`; Playwright's bundled Chromium may not decode AAC, which would fail the play step for a reason unrelated to the feature.
- **Fix:** `test.use({ channel })` only when the variable is set, a fail-fast message at the play step naming the cause, and a line in `fixtures/README.md`. No package added.
- **Commit:** e9b1d02c, 241a5f91
