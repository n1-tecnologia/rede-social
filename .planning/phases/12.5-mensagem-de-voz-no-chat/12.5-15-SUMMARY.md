# Phase 12.5 Plan 15: The thread host of a recording Summary

**The shared support thread now sends a recording for the member and for the team: an own pending bubble at once, takes posted one at a time in tap order, retry that re-sends the same stored asset, the shipped refusals, the case flows, and Igor's own sentence when the team has blocked the member.**

## Performance

- **Duration:** about 14 min (21:51 to 22:05 local)
- **Tasks:** 3 (one tracer)
- **Files:** 8 (1 created, 7 modified); no SQL, no server code, no package

## Accomplishments

- **One host for both viewers.** `ThreadPane` builds the composer's `voice` bundle from the catalog and hands it to the composer only in the branch where the composer renders, so no strip or notice ever shows a microphone. `onRecordingStart` is `pauseAllVoice`. The recording's send is named "Abrir chamado com a mensagem de voz" while the opener shows. A staff pane without `onSendVoiceAction` has no microphone either.
- **The optimistic bubble and the queue.** `onSendVoice` appends the pending voice view and resolves `true` at once; the take waits in a ref keyed by its temporary id and runs `runVoiceSend` through a promise chain, so only one is in flight and the order is the tap order. The footer shows the percent while bytes move and the plain "Enviando…" while queued or finishing.
- **Failures.** A retriable failure keeps the bubble (no dimming) with "Tentar novamente" and "Descartar"; the retry re-runs for the same take and skips the upload when the failure carried its asset. A permanent refusal offers only "Descartar" and the one sentence. Blocked and removed discard every queued take, toast the notice, refresh once and show the strip; closed and not-found remove the bubble and refresh.
- **Case flows.** The success tail of a send moved into one function (`adoptSent`) that the text and the voice path both call, so the case swap, the reopened toast and the switch to a new case are the same code. The text path itself is untouched: the shipped first-send, member and staff tests pass with no edit.
- **Smaller pieces.** `chatRuns` takes an optional `voiceFor` and `voiceProgress`; a catch-up that returns a known recording with its deleted flag updates it in place; the speed pill speaks "Velocidade 1,5x." through one polite `role="status"` region (the pane had none for this, so one was added).
