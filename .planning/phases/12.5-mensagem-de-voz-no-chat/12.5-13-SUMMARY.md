# Phase 12.5 Plan 13: The recorder and the composer's voice states Summary

**A MediaRecorder hook with a pure reducer (300 s stop measured from the recorder's own start and re-checked on every chunk, 1 s floor, interruption by ended/mute/error, microphone released once on every exit) and the shared composer's microphone slot, recording row, notice line and polite status region, opt-in by a `voice` prop bundle and inert for a host that passes none.**

## Performance

- **Duration:** about 12 min
- **Started:** 2026-11-17T20:47 local
- **Completed:** 2026-11-17
- **Tasks:** 3 (one tracer, two auto)
- **Files modified:** 8 (5 created, 3 modified); plan 14 and later own the host wiring

## Accomplishments

- **The hook** (`useVoiceRecorder.ts`): a pure `voiceRecorderReducer` (idle, requesting, recording, stopped, plus a problem field) and a per-hook controller. The capture call exists once, inside `start`, which only the tap on the microphone calls. Mime probe order `audio/webm;codecs=opus`, `audio/mp4`, `audio/ogg;codecs=opus` (or the browser's choice, read from `recorder.mimeType`), `audioBitsPerSecond` 32000, `start(1000)` with a plain `start()` fallback, zero-size chunks ignored, the take handed over as `{ blob, mime (parameters stripped), seconds }`.
- **The composer** (`ChatComposer.tsx`): one slot button (`ref` kept, never remounted) is the microphone (`Mic` 20, `type="button"`), the usual send (`Send` 20, `type="submit"`) or the recording's send (`type="button"`) by the trimmed field; `LoaderCircle` under `motion-safe:animate-spin` with a dimmed `Mic` under reduced motion while the prompt is open; the recording row `[trash 44] [pill flex-1] [send 44]` with the 8px dot under `motion-safe:animate-pulse`, the word, and a `role="timer"` `aria-live="off"` counter; the field hidden (`hidden` plus the container class) and still mounted; the notice line above the row (`MicOff` 16 for the four problems, `Info` 16 for 4:30, limit, interruption and too short, neutral ink, no role); one persistent `role="status"` `aria-live="polite"` `sr-only` region.
- **Opt-in:** with no `voice` prop the composer renders exactly today's DOM; `chat-composer.test.tsx` passes with no edit (`git diff` empty).
- **Test doubles** (`voice-fakes.ts`): `FakeRecorder`, `FakeTrack`, `FakeStream`, `installRecording`, `fakeClock` (stubbed `performance.now` plus four faked timer functions) and a sentinel `voiceBundle`. 76 new tests; two mutations (not stopping tracks, not starting the tick) were run against them and fail 20 and 3 tests respectively.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Detection moved to a new file `ui/voiceSupport.ts`**
- **Found during:** Task 1 (acceptance criterion: `grep -n getUserMedia useVoiceRecorder.ts` prints only the call in `start`)
- **Issue:** the support probe reads the capture API's presence, which would add a second grep hit in the hook.
- **Fix:** the probe is `isVoiceRecordingSupported()` in a 13-line file (not in `files_modified`); the hook's grep prints one line (the call in `start`), `ChatComposer.tsx` prints none.
- **Files modified:** `packages/modules/chat/ui/voiceSupport.ts` (new)
- **Verification:** the grep; the no-support, no-recorder and insecure-context tests.
- **Committed in:** `05105831`

**2. [Rule 2 - Missing Critical] The module README lists the voice surface**
- **Found during:** Task 3 (the module-readmes check named in the gate)
- **Fix:** the `./ui` export row of `packages/modules/chat/README.md` now names the opt-in `voice` bundle and `useVoiceRecorder`. No kernel import, event or job was added, so nothing else changed.
- **Committed in:** `48122f52`

**3. Plan wording interpreted, not a code deviation: the "no chunk arrives" fallback.** The plan says the recorder "falls back to `start()` if no chunk arrives". A started `MediaRecorder` cannot be started twice, so the fallback is: if `start(1000)` throws, call `start()`; and a recorder that never emits a periodic chunk still delivers the whole take at `stop()`, while the 300 s limit is enforced by the 250 ms tick regardless. Both paths have a test.

**Total deviations:** 2 auto-fixed (1 blocking, 1 missing critical) plus 1 interpretation.
