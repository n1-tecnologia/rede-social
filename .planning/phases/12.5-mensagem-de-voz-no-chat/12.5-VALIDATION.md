# Phase 12.5 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Seeded from the Validation Architecture section of `12.5-RESEARCH.md`; the planner fills the Per-Task Verification Map when the plans exist.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 5 (happy-dom per file), pgTAP through `supabase test db`, Playwright 1.63 (Chromium) |
| **Config file** | one `vitest.config.ts` per package (module-chat, contracts, core, web, api); `apps/web/playwright.config.ts` |
| **Quick run command** | `pnpm --filter @rede-social/module-chat test` and `pnpm --filter @rede-social/contracts test` (add `--filter @rede-social/web` or `@rede-social/api` for the package a task touches) |
| **Full suite command** | `TURBO_CACHE=local:r pnpm turbo typecheck test --continue --concurrency=4`, then `pnpm supabase test db` before `pnpm --filter @rede-social/api test:integration`; `pnpm e2e` for the chat voice spec |
| **Estimated runtime** | about 90 seconds for `turbo test` alone; 4 to 5 minutes with typecheck and the web build |

---

## Sampling Rate

- **After every task commit:** the package's own quick run, plus `pnpm --filter @rede-social/api test` whenever a module README, a route or the isolation inventory changed.
- **After every plan wave:** `TURBO_CACHE=local:r pnpm turbo typecheck test --continue --concurrency=4`, `pnpm boundaries`, `bash scripts/check-ui-literals.sh`, `pnpm guard:lanes`, `apps/api/tests/unit/module-readmes.test.ts`, and the chat integration files by name (turbo runs no integration).
- **Before `/gsd-verify-work`:** the full suite green; `next build` once (through `turbo typecheck --filter=@rede-social/web`), because only it catches a `node:fs` leak into the contracts index; delete `apps/web/.next/cache` and `.next/dev` afterwards.
- **Max feedback latency:** 5 minutes (the shared machine can slow it; check `uptime` before calling a failure real and rerun the named file alone three times).
