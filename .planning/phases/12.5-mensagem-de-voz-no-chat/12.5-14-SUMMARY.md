# Phase 12.5 Plan 14: Bubble player and voice bubble Summary

**A props-only voice player (play disc, native range bar, time line, 1x/1,5x/2x pill) that loads nothing until the first tap and plays one message at a time, plus the shared bubble's voice branch with ready, pending, failed and deleted variants on both sides.**

## Accomplishments

- **The first tap is the only request.** The audio element has `preload="none"` and no `src`; the tap assigns the host's same-origin path and calls `play()` in the same synchronous handler. The bar's maximum is the stored duration, and the component never reads the element's length or asks what it can decode.
- **One at a time, positions kept.** `voice-playback-controller.ts` registers a pause callback per player: starting one pauses the rest (they keep their position), `pauseAllVoice()` is ready for plan 15's `onRecordingStart`, unmounting pauses, releases and drops the download. No autoplay, no auto-advance, no mini-player, no Media Session.
- **Every state and recovery path** of UI-D-849: loading (a tap cancels, 15 s with no sound becomes error), playing, paused, seeking (drag shows the live time and commits on release, a playing message keeps playing), ended, error (`RotateCw`, thumb stays, a tap re-assigns `src` with a cache-buster query and resumes on `loadedmetadata`), unsupported (inert disc and sentence). A seek made while idle is remembered and applied when the file loads. Keys: arrows 5 s, page keys 15 s, Home and End, all clamped.
- **The bubble.** `MessageBubbleProps` is now `text | voice` (the type forbids both, proved by a `@ts-expect-error` that `tsc` checks). Own side on `bg-brand` with `bg-on-brand` ink; other side on neutral ink with the button-pair disc and no brand-coloured text or fill; `w-70` capped by `max-w-[85%]`; one `role="group"` named by the host's spoken phrase. The pending upload keeps the player geometry at `opacity-70` with a determinate `role="progressbar"`; the failed bubble shows the danger line with `CircleAlert` and the two ghost buttons (discard only for a permanent refusal); the deleted bubble reads only the host sentence.
- **Text bubbles are untouched**: the shipped message-list tests pass with no edit beyond additive tests, and a test pins the text bubble's class string byte for byte.

## What plan 15 gets (host contract)

`MessageBubble` takes `voice`: `{ status: 'ready', src, durationSeconds, spokenLabel, player }` | `{ status: 'pending', progress: { percent | null, label }, durationSeconds, spokenLabel, player }` | `{ status: 'failed', failure: { text, retriable, retryLabel, discardLabel, onRetry, onDiscard }, ... }` | `{ status: 'deleted', text }`. `player` is `{ labels, formatClock, nextRate, rateLabel, onRateChange }`, where `labels` = `play, pause, loading, retry, seek, error, unsupported` plus `speed(rate)` and `seekValue(current, total)` functions (catalog `voice.player.*`). `spokenLabel` is the finished group name (`voice.group` with `spokenVoiceDuration`). The footer text for a pending bubble is the bubble's existing `pendingLabel` ("Enviando... 62%", or the shipped label when the percent is unknown). `src` is `/v1/media/<id>/original` built by the host. The player's retry appends `?r=<n>-<timestamp>` to that path (or `&r=` when a query exists): the route must ignore an unknown query key. `pauseAllVoice` is exported from `@rede-social/module-chat/ui`.

## Decisions Made

See `key-decisions` above. In short: code 4 after a good play is the link, not the format; a `NotSupportedError` rejection is unsupported; the pending footer reuses `pendingLabel`; the deleted bubble stays on the neutral surface on either side.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A MediaError code 4 after the file already played is the error state, not unsupported**
- **Found during:** Task 2 (designing the error path)
- **Issue:** The plan reads every code 4 as the inert unsupported state. Chrome reports an expired or refused signed link (403/404) as code 4 too, so an hour-old message would die inert and could never be retried, contradicting UI-D-849's "the link expired after its hour" error and V48 ("every retry shows the error state").
- **Fix:** Code 4 is unsupported only before this element ever reported metadata or played; afterwards it is the error state with the retry disc. A test pins both sides of the rule.
- **Files modified:** `packages/modules/chat/ui/VoicePlayer.tsx`, `packages/modules/chat/tests/voice-player.test.tsx`
- **Committed in:** `1d652b84`

**2. [Rule 2 - Missing critical] Unmount also drops the download**
- **Found during:** Task 2
- **Issue:** The plan asks only that unmounting pauses and releases; a paused element with a source still holds its network request.
- **Fix:** The cleanup also removes the `src` attribute and calls `load()`.
- **Files modified:** `packages/modules/chat/ui/VoicePlayer.tsx`
- **Committed in:** `1d652b84`

**3. [Rule 3 - Blocking] `VoicePlayerGhost` and a README line are outside the plan's file list**
- **Found during:** Task 3
- **Issue:** The pending and failed bubbles need the player's geometry without an audio element or a source; extending `VoicePlayer` with those modes would break its "never given a `src` before a tap" invariant.
- **Fix:** A second component `VoicePlayerGhost` in the same file (listed in `files_modified`) and the `./ui` row of `packages/modules/chat/README.md`.
- **Committed in:** `26774f18`
