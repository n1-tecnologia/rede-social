## Phase Goal

**As an** `admin_tenant`, **I want to** run my community from my phone (brand, members and roles, moderation and community rules), **so that** every action takes effect immediately, is logged, and the pilot can pass its go-live gate. Each slot is taken from the ROADMAP Phase 8 Goal line.

<objective>
The second half of ADMIN-02: change a member's role (member / support_tenant / admin_tenant) under D-332's two guards, logged as `role_changed`. The admin can reach the same sheet from a member's profile (D-340), and the UI degrades honestly when the admin loses a permission mid-session (UI-D-284).

**Plan story:** **As an** `admin_tenant`, **I want to** promote someone to support or admin, or take those tools away, from the members list or from their profile, **so that** I can share the work of running the community without ever locking it out. Taken from ADMIN-02, D-332 and D-340.

Claude's Discretion "Should role changes also go in the log?": yes. The log's action CHECK already allows `role_changed` (08-01) and the screen renders it (08-03).

Purpose: finish member management with the strongest invariant in the phase: the community always keeps an active admin, whatever happens concurrently.
Output: `setMembershipRole`, `PUT /v1/admin/members/{id}/role`, the role list, the profile trigger, the UI-D-284 handling, and the concurrency proof.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Next server action | membership id and the target role are untrusted |
| API → admin lane | RLS bypassed; `tenant_id = ctx.tenantId` is the isolation |
| a role change → the next request's permissions | permissions are recomposed from the membership row on every request |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-26 | Elevation | `PUT /v1/admin/members/{id}/role` | critical | mitigate | `requirePermission('members.manage')`, the role enum, `tenant_id = ctx.tenantId` in the admin lane, bare 404 cross-tenant; integration cases for support, member and lab ids |
| T-08-27 | Denial of service | self-demotion, last active admin, concurrent demotions | high | mitigate | Guards under `for update` on the active-admin set plus target; the concurrency case proves one active admin always remains |
