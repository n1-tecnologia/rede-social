## Phase Goal

**As an** `admin_tenant`, **I want to** run my community from my phone (brand, members and roles, moderation and community rules), **so that** every action takes effect immediately, is logged, and the pilot can pass its go-live gate. Each slot is taken from the ROADMAP Phase 8 Goal line.

<objective>
MOD-05 and D-347: every module documents its public interface in a README that a test keeps honest, and one module is proven reusable on an app that provides only the kernel contracts.

**Plan story:** **As a** developer starting another Rede Social project, **I want to** copy one module and wire it to the kernel by following its README, **so that** I reuse a feature without dragging the others along. Taken from MOD-05 and ROADMAP SC 4.

Why the events module (RESEARCH Pattern 9): its schema references only kernel tables. Feed has hand-written foreign keys into the communities and stories tables, and reels `requires` feed.
Deviation from RESEARCH and VALIDATION, recorded: the drift check is a unit test in `apps/api/tests/unit` rather than a `scripts/check-module-readmes.ts` run by `pnpm lint`. That test file already loads every manifest under placeholder env (`registry.test.ts` does), whereas a root `tsx` script would need its own env stubs. It runs in `pnpm turbo test`, CI's static job and `pnpm verify`.

Purpose: turn "modules are reusable" from a claim into a CI check.
Output: `packages/reuse-fixture`, eight READMEs, and the drift check.
</objective>
