# Phase 08.4 Plan 01: Store-owned course and live links Summary

**The store now owns `store_product_courses` / `store_product_lives` (carried over from 08.3 with a set-difference guard, gate bodies re-pointed), the product routes are their only writer via `courseIds` / `liveIds`, and the course and live forms show "Liberado/Liberada pelos produtos: …" read-only.**

## Accomplishments

- Two store tables cloned from `store_product_communities` (four tenant-read, admin-write policies, RLS, unique and gate-lookup indexes), a generated create-only migration, and a custom migration: hand FKs to `courses` / `course_lives` (cascade), TRUNCATE revoked, the 08.3 rows copied with `created_at`, a guard that raises `store_course_links: … link sets differ after the carry-over`, then the four gate bodies replaced with the same signatures (EP-15 ordering checked by awk).
- Store service: `resolveCourses` / `resolveLives` (linkable or already linked to this product, one 400 per miss), `linkedCourses` / `linkedLives` (live status projected in SQL with `make_interval(mins => v.duration_min)`), `replaceCourseLinks` / `replaceLiveLinks` (delete-difference over linkable targets only, under `lockProduct`), all wired into create, update and the manager branch of `readDetail`; no entitlement or order is touched.
- Courses: the link key, its field rule, cap and two issue codes are gone; every link writer is deleted; the course and live detail `products` and the lesson `hasProducts` read the store tables by SQL.
- pgTAP 190/160 fixtures re-pointed with the truth tables byte-identical, plus four `pg_get_functiondef` pins; the `08.4 tracer` course and live integration cases pass on a fresh reset.
- Web: `communityAccessSegments` takes the catalog key, the course and live forms render the read-only line (edit mode, non-empty only), `ProductPickerSheet` and `listCourseFormProducts` are deleted, catalog keys swapped and pinned.
