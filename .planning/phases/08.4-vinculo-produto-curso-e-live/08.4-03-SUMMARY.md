## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Re-sending the same communityIds rewrote the community link rows**
- **Found during:** Task 1 (case EP-02 / EP-04)
- **Issue:** `replaceLinks` (08.2) deleted every active community link and re-inserted the sent set, so a save that re-sent the same `communityIds` beside a `courseIds` edit gave the community rows a new `created_at`. The plan's EP-04 truth says it must not.
- **Fix:** the delete now also requires `l.community_id <> all(sent ids)`, the same delete-difference the course and live replaces use. The final set, the CR-02 kept links and the row-lock serialisation (P13) don't change.
- **Files modified:** packages/modules/store/server/service.ts
- **Verification:** store.test.ts 45/45, including the unchanged D-363, CR-02 and P12/P13 cases. The store module unit tests pass (57/57).
- **Committed in:** 7ceba27a

**2. [Interpretation] The D-413 lifecycle case was kept, not deleted**
- **Found during:** Task 2
- **Issue:** the plan says to delete "the create-with-links case around 1560". At that line is the D-413 lifecycle case, which only uses create-with-links as setup. Deleting it would have dropped the lifecycle and row-count coverage.
- **Fix:** the case now creates the course without links, links it through `PATCH /v1/store/products`, and counts links from `store_product_courses`. The course-route replace and concurrency cases (D-404, P11/P36) were deleted, with a comment pointing to their twins in store.test.ts.
- **Committed in:** ea6b909e

**3. [Rule 2 - Robustness] courses.test.ts pins the demo store on**
- **Issue:** links are now written through the store route, which answers 404 when the store is off. The suite had relied on the seed leaving the demo store on.
- **Fix:** `withModuleEnabled('demo', 'store')` in the file's `beforeAll`, restored in `afterAll`.
- **Committed in:** ea6b909e
