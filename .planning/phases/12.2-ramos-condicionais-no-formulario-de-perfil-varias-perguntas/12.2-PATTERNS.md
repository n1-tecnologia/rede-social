**Analog:** `packages/core/db/schema/profile-form-steps.ts`

Table shape (41-89): `tenantId` references `tenants.id`, `revision` default 1, `unique('..._tenant_id_uq').on(t.tenantId, t.id)` (target of the questions' composite FK), CHECKs that read `PROFILE_FORM_LIMITS` through `sql.raw(String(...))` (name <= 60, `array_length(open_values) between 1 and 20`), index with `tenant_id` first, four `pgPolicy` (select = tenant + KNOWN_ROLE; insert/update/delete = TENANT_ADMIN). Add `openerQuestionId`, `openValues text[]`, `name` nullable, `archivedAt`. Do NOT declare the circular FK pair in Drizzle: `branches.opener_question_id -> questions` and `questions.branch_id -> branches` are hand SQL, DEFERRABLE (see migration below). Every policy needs a cross-tenant negative in 226.

## Shared Patterns

### Per-tenant admin lock + canonical lock order
**Source:** `packages/core/server/profile-form/admin.ts:72-79`, `layout-store.ts` header. **Apply to:** every branch/question/layout write. Order: `adminLock`, steps, questions (`position, created_at, id`), branches. The member save also locks branches `FOR SHARE`.

### Coded refusals (service first, trigger as backstop)
**Source:** `condition-rules.ts` + `lock-rules.ts` + guard in `20261105195403_…functions.sql`. **Apply to:** branch rules, guards, routes (`ApiError(409, ...)` with `details.profileForm`).

### RLS and tenant-first
**Source:** `profile-form-steps.ts` policies. **Apply to:** the branches table; `tenant_id` first in every index; cross-tenant negative pgTAP per policy.

### Expand-only SQL
**Source:** header of `…195403_…functions.sql` (new function when a row type changes; same-signature `create or replace`; old columns and `_v2` stay one release).

### Privacy of reads
Answer `value` is never selected into an admin result; branch `name` never leaves the admin API; nothing logs titles, labels, values.

### Contracts as single source
Pure visibility and tree-order live in `@rede-social/contracts`; the chain parity table extends `PROFILE_FORM_VISIBILITY_CASES` and is replayed in 226 (rule: new case = row in the constant AND a line in the pgTAP section).
