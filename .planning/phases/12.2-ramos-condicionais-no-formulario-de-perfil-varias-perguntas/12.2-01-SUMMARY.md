# Phase 12.2 Plan 01: Branch contract, chain visibility rule and tree order Summary

**Additive branch vocabulary for the profile form: a bounded, fail-closed chain visibility rule pinned by an 11-row parity table, the branch bodies/reads/limits/five refusal codes, and an idempotent pure tree order, with no consumer edited and all five dependent packages still typechecking.**

## Performance

- **Duration:** 14 min
- **Started:** 2026-11-06T17:12:52Z
- **Completed:** 2026-11-06T17:27:00Z
- **Tasks:** 3 (all TDD: RED then GREEN each)
- **Files modified:** 7 (2 created, 5 modified)

## Accomplishments

- `isQuestionVisibleInTree` walks the branch chain in a loop bounded by `PROFILE_FORM_LIMITS.branchDepth` (3 hops) and is true only when every branch on the chain is open; an unknown branch or opener, a missing token set, a cycle or a chain of four is hidden. `branchChainOf` shares the same bounded walk. No recursion.
- `PROFILE_FORM_CHAIN_CASES` (11 rows, clinic wording, ids prefixed `24000000-0000-4000-8000-`) pins visible, owed and purged keys for depth 1, 2 and 3, a stale deeper answer, a stale middle answer, any-of, "Outro", a string `'true'` and a broken tree. Plan 07 replays rows 1..9 in pgTAP; rows 10 and 11 are TypeScript only.
- `profile-form.ts` gains the three limits, the five codes (appended last, order pinned by test), `createBranchBodySchema` (blank or missing name is `null`, empty values is `condition_invalid`), `updateBranchBodySchema`, `adminBranchSchema`, strict `memberBranchSchema` without a name, `undoBranchResultSchema`, the dependents `branches` list, `undo_branch`/`reactivate_branch`, `impactQuerySchema.branchId` and the `answerEtag` branch parts. Every new key on an existing read or body is optional.
- `treeOrder` (stable pre-order of each step's forest, sibling units by smallest requested index then branch list index, nested blocks inside the parent, foreign-opener runs as unconditional units, cycles cut, explicit stack) is idempotent and preserves the id multiset; a 200-round randomized forest property test backs it.
- The module's `contracts/index.ts` re-exports the branch schemas and pure rules; the README lists them.
