## Findings for the next plans and for Igor

1. **The name field's `maxLength` counts UTF-16 units.** The plan says `maxLength` 60 and the counter counts code points. In a real browser 60 emoji cannot be typed (only 30 fit), although the counter, the schema and the server accept 60. The jsdom tests set the value directly. If 60 emoji must work on a phone, `maxLength` has to go and the inline "Use até 60 caracteres." line carries the rule; this needs a decision, not a guess.
2. **"A pasted control character is refused as invalid" is only true for NUL and a lone surrogate.** The contracts' `hasUnsafeChars` (plan 08) is the single definition; a BEL is accepted like in every other text of the form. The tests use NUL and a lone surrogate.
3. **Replace mode and the Ramo select.** The server keeps the replacement in the old question's branch and ignores `branchId` in a replace body. The select is shown and enabled in replace mode like the Etapa field (the 12.1 precedent); choosing another branch there has no effect on the server. Disabling it would be more honest; left for plan 18 or Igor.
4. **A required question that moves from one branch to another** has no impact kind on the server (only leaving a branch does), so no count is read for that move.
5. **A draft branch cleared by a step change is silent**: no approved sentence exists for it; the select reads "Nenhum" and no alert is shown.
