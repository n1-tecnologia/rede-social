# Phase 12.2 Plan 08: The admin's branches API Summary

**Five routes under /v1/profile_form (create, edit under the revision and the answer lock, undo, archive and reactivate as a block with one timestamp) behind the module guard chain, with every limit, depth and race answered by the same coded 409s the SQL guards use, branches with aggregate counts on both builder lists, and every route in the isolation inventory and sweep.**

## Performance

- **Duration:** about 35 min (the start time was not recorded at launch)
- **Completed:** 2026-11-06T20:20:00Z
- **Tasks:** 3 (Task 1 tracer, Task 2 TDD, Task 3 auto)
- **Files modified:** 8 (2 created, 6 modified)

## Accomplishments

- `createBranch`: `adminLock`, live module check, `checkBranch(creating)` over the tenant's questions, branches and locked layout, an insert inside a savepoint (PF008/PF009 and 23503 map to the coded 409), re-read as `AdminBranch`. The new branch is empty (`questionCount` 0, `answerCount` 0, `revision` 1) and reads after the opener's others.
- `updateBranch`: 404 bare, `already_archived`, `stale_revision`, then the answer COUNT after the row lock (`condition_locked` on an opener or SET change, a rename always passes), then `checkBranch` for a real change; a no-op answers 200 without a bump.
- `undoBranch`: questions first (`branch_id` null, revision +1 for the active ones), then the branch row, in one transaction; answers and a nested branch are untouched.
- `archiveBranch` / `reactivateBranch`: the subtree from `subtreeOf`, branches first then questions with the transaction's `now()`, one set-based `writeLayout` (drop on archive; append to own step, `normalizeToTree`, `assertLayoutOrder` on reactivate). `checkArchiveBranch` names the openers (`has_dependents`), `checkReactivateBranch` names the opener to bring back first; `limit_reached` and `branch_limit` count the restored rows only.
- `admin.ts`: `branchId` on `toAdminQuestion`, `branches` on `listInTx`, `listQuestions` and `listArchived`; `condition` and `opensCount` are emitted as before. `attempt`, `hasSqlState` and `textArray` are now exported for `branches.ts`.
- Test support: `seedProfileFormBranch`, a `branchId` parameter and a shim for the retired pair on `seedProfileFormQuestion`, `removeProfileFormByPrefix` and the new `deleteProfileFormTenantData` in one deferred transaction.

**3. [Rule 2 - Missing detail] An archived branch refuses an edit with `already_archived`; a no-op edit is 200 without a bump**
- **Found during:** Task 2
- **Issue:** the plan names neither case. The question edit refuses an archived question and does not bump on a no-op, so the branch edit follows it.
- **Commit:** bd0cbda7

**4. [Rule 1 - Bug in my test] `questionCount` of an archived branch expected 4, correct is 3**
- **Found during:** Task 2 GREEN

**5. [Plan wording vs contract] A control character in a branch name**
- **Issue:** the plan says "a control character is `invalid`". The contracts' `hasUnsafeChars` (plan 01, shared by every text of the form) refuses only NUL and an unpaired surrogate; a BEL is accepted like in every other text of the form.
- **Fix:** none in code; the test asserts NUL and a lone surrogate. If a wider control-character refusal is wanted it belongs to the shared helper, for every text at once.
