# Phase 12.2 Plan 19: The Fluxo and the preview that follows branches Summary

**The builder gets a Lista | Fluxo selector that exists only when the form has a branch and a read-only vertical tree by branch whose nodes and edges open the editors already built, and the "Ver como o membro vê" preview now maps the builder's branches to the member form (no name), so it follows the chain exactly as the member does; the 9 PreviewSheet tests that were red since plan 14 are fixed and the whole web suite is green.**

## Accomplishments

- **Task 1 (tracer).** `FlowView` renders `flowTree(tree)` as a `section` named by an sr-only `h3` "Fluxo do formulário": the `Info` note row, the 12/700 tertiary eyebrow "Todos os membros veem", the root list, and under each opener one rail (`ml-1 border-l-2 border-border-secondary pl-3`) per branch holding the edge button and, when the branch has questions, a `ul` named "Perguntas do ramo: {label}" (the label is the branch name, else the "Se “opener” for ..." sentence, from `useBranchLabeler`). `FlowNode` is a `min-h-11 w-full rounded-xl bg-bg-secondary` button (title 14/700 `line-clamp-2 break-words`, trailing `ChevronRight` 16, line 2 type name · Obrigatória/Opcional · No perfil, plus a neutral `Layers` 12 "Etapa {n}" pill from two steps; name "Editar pergunta: {title}", line 2 as its description). `FlowEdge` is a `min-h-11 w-full rounded-xl bg-bg-tertiary` button with `CornerDownRight` 14, the admin's name 12/700 on line 1 when it has one and "Se for {options} · {count plural}" below it, the options capped at 4 then "e mais N" and the plain words Sim or Não for yes/no. `QuestionList` gets `view`, `onViewChange` and `flow`: the `SegmentedControl` ("Lista" / "Fluxo", `w-full max-w-xs`, named by an sr-only "Como ver as perguntas") renders only with an active branch, is disabled while Reordenar is on or a write runs, and in the Fluxo the actions row keeps only "Adicionar pergunta" and "Ver como o membro vê". `QuestionBuilder` keeps the view in component state (Lista by default, back to the Lista in the same render when the last active branch goes away and it does not come back on its own), builds the tree from the same read, hands a node tap to the question sheet in edit mode and an edge tap to the branch sheet in edit mode through the existing one-sheet-at-a-time paths, and gives focus back to the tapped element when no sheet is showing.
- **Task 2.** Every state of the drawing is pinned from the one tree: the step pill as the only step cue (no step headings), three rails on the path to the deepest question, several edges of one opener in the order members meet them, overlapping answers of different branches, an empty branch and a branch whose questions are all archived as "sem perguntas" with no child list, archived branches not drawn (their questions are roots), the 4-answer cap ("e mais 16" for 20, a 4-answer list keeps "ou", 5 shows 4 and "e mais 1"), yes/no words, a very long title clamped to two lines and a 60-character name wrapped, 31 nodes and 15 edges at the ceiling, hostile text rendered as text, no sideways scroll or half-step spacing class, and the same output for the same tree. `branch-tree.ts` needed no change (`flowTree` already carries the step ordinal and the public flag), so it is listed in the plan's files but untouched.
- **Task 3.** `previewForm(questions, steps, branches)` builds the member shape field by field: `branches` (id, openerQuestionId, values) for the ACTIVE branches only, each question's `branchId` (null when its branch is archived or unknown) and `condition: null`. `PreviewSheet` takes `branches` and `QuestionBuilder` passes them. The sheet, banner, "Avançar", "Recomeçar" and the status line are untouched. The 9 baseline failures are fixed by moving the 12.1 fixtures to branches; new cases cover one wrapper per block, a nested wrapper, the status line through the chain (2 etapas e 3 perguntas, 3 e 5 with the opener ticked, 3 e 6 with the nested opener, back to 2 e 3 when the root opener changes even though the nested draft still says Sim), the status line equal to `stepPath` and `visibleQuestionIds` for the same answers, Recomeçar closing the blocks, and no branch name in the serialized form, the sheet, the block or any live region.

## Deviations from Plan

### Auto-fixed Issues

**1. [Interpretation] Task 2 has no real RED**
- The plan marks Task 2 `tdd="true"`, but the Task 1 drawing already renders every state (the step pill, the cap, the empty edge, the rails), so the new cases passed on the first run against it. I did not invent a stub to fake a RED. One expectation of mine was wrong (a space between an edge's name and its sentence, which is deliberate so the accessible name reads "Quem tem clínica Se for ..."), and I fixed the test, not the code. To prove the tests can fail, I temporarily mutated `FlowView.tsx` (answer cap 4 to 6, the `line-clamp-2` removed, the pill guard loosened): 7 of the 29 cases turned red; the file was restored byte for byte and the next run was 29 of 29.
- **Commit:** `2320848b`

**2. [Interpretation] `condition` still appears in `PreviewSheet.tsx` (3 hits)**
- The acceptance says 0 except in a comment. The hits are 2 comments and the line `condition: null`: `memberQuestionSchema` still requires the key (it is `@deprecated`, plan 20 removes it), so the member shape cannot omit it. A test pins that nothing else in the file names `condition`.
- **Commit:** `87afb1b9`

**3. [Interpretation] The preview hands over active branches only**
- The plan says "the builder's branches". An archived branch is not drawn by the Lista or the Fluxo and its questions are roots there, so the preview does the same (`branchId` null) instead of handing the member component an unknown branch, which fails closed and hides the question. In the real data an archived branch carries its questions out with it, so this is a race-only edge.

**4. [Interpretation] Focus return is explicit**
- The plan says "restore focus to the node that opened a sheet". The shipped trap returns focus to `document.activeElement` at open, which is the body in Safari (a tap does not focus a button). `QuestionBuilder` now remembers the tapped element and focuses it once no sheet is showing, if it is still in the document. A hand-off between the two sheets keeps one showing, so focus waits for the last close.

**5. [Interpretation] The wording the UI-SPEC does not give is mapped onto approved sentences (open items for Igor)**

| Situation | What the Fluxo shows |
|---|---|
| an edge whose answers cannot be named (the opener no longer holds any option of the branch) | the count alone, from the shipped `branches.count` ("Sem perguntas", "1 pergunta", "N perguntas") |
| the "Etapa {n}" pill | the shipped `steps.eyebrow` ("Etapa {n}"), no new key |
| the accessible name of an edge | its own text, so it does not reuse "Editar ramo: {label}" (that is the Lista pencil's name and would hide the answers) |
| the accessible name of the Lista's group lists | unchanged (`aria-labelledby` the strip label); plan 18 offered to switch them to `flow.childrenLabel` and I did not, since nothing asks for it |

**6. [Interpretation] Small layout calls**
- The selector sits right before the micro-title, after the limit lines. The Fluxo hides the step-limit line and the wells note (they belong to the hidden button and the hidden wells). A question node carries the shipped Card shadow and dark border, as sketch 019 draws it. `FlowView` takes `steps` as the plan says and uses only its length for the pill.

**Total deviations:** 6 (all interpretations). **Impact:** none on the contracts; items 5 and 3 want a look from Igor.
