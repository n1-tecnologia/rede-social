## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Latent Phase 09.2 move-engine defect fixed in three files outside the plan's list (approved by the orchestrator)**
- **Found during:** Task 3 (the real copy of a tenant with a profile form)
- **Issue:** `copy-rows.ts` copies each group in one target transaction: `set constraints all deferred` (only when the group has more than one table), `alter table ... disable trigger user` for each table with user triggers, the inserts, then `alter table ... enable trigger user`. In a deferrable group the inserts queue pending deferred foreign-key check events, and Postgres refuses `ALTER TABLE` on a table with pending trigger events. The bug was latent because the only multi-table group before this phase (`events` and `event_secrets`) has no user triggers, so nothing was silenced. `profile_form_branches` and `profile_form_questions` now carry user triggers (`profile_form_branches_guard`, `profile_form_branches_tree_guard`, `profile_form_questions_guard`, `profile_form_questions_default_step`, `profile_form_questions_tree_guard`, `profile_form_questions_legacy_condition_guard`). The same pattern exists in `delete-source.ts` (the confirm-delete) and `rollback.ts` (the recopy), which fail the same way for deletes.
- **Why it matters:** a real move of a tenant with the `profile_form` module on would have failed at that group (the group's transaction rolls back, so no data leaks, but the move cannot finish). The module is OFF for every tenant in production today, so no production move has been affected; the defect would have surfaced the first time the module is turned on for a tenant that is later moved.
- **Fix:** in the three group loops, `set constraints all immediate` (only when `group.length > 1`) immediately before the `enable trigger user` loop, with a two-line comment saying why.
- **Files modified:** `packages/core/server/projects/move/copy-rows.ts`, `packages/core/server/projects/move/delete-source.ts`, `packages/core/server/projects/move/rollback.ts`
- **Proofs:** the four move-copy cases that failed now pass; two new cases in `apps/api/tests/integration/move-rollback.test.ts` (outside the plan's file list too, extended with the orchestrator's approval): "recopy wipes a profile form ... and recopies it" (a source answer changes after the copy, the recopy wipes and recopies, the target holds the new value) and "confirm-delete removes a profile form from the source ... and leaves the target copy" (1 step, 1 branch, 2 questions, 2 answers on both sides before, 0 on the source and unchanged on the target after). The file's `afterEach` now removes the throwaway tenant's form with `deleteProfileFormTenantData` first (the form keys are NO ACTION, so the tenant cannot be deleted before its form).
- **Committed in:** `d362987e`
