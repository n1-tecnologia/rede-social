# Phase 12.2 Plan 09: Question writes on the branch tree Summary

**The admin's question writes (create, edit, move, reorder, archive, reactivate, replace, delete) now run on the branch tree: branchId on the question routes, every layout write normalised to tree order and renumbered in one statement, opener refusals that list branches, the WR-06 public-under-private rule in the service, and the whole 12.1 per-question condition code (condition-rules.ts, addQuestionAfterOpener, the conditions test file) deleted.**

## Accomplishments

- **Task 1 (tracer).** `readTree` in `layout-store.ts` (steps, active questions in `position, created_at, id`, branches, facts) beside the unchanged 12.1 `readLayout`. `createQuestion` accepts `branchId` (null or absent means none), judges it with `checkMoveIntoBranch`, adds the question at the end of the requested step, runs `normalizeToTree` and `assertLayoutOrder`, and writes with the set-based `writeLayout`. The insert carries `branch_id` and no condition columns. A non-null `condition` is 400 `condition_invalid` before anything is read; an unknown or foreign `branchId` is 400 `unknown_branch`. The new integration file proves it on a clinic depth-2 tree.
- **Task 2 (TDD).** `updateQuestion` takes `branchId` (the answer lock, depth, order and privacy checks, then the end of the new branch's run in its own step; null leaves in place). `reorderQuestions` applies the requested layout, normalises to tree order and writes under `lockRows`. Archive, retype and option removal on an opener with an ACTIVE branch are `has_dependents` with `details.branches`; `opensCount` counts active questions in active branches. Reactivate returns a question to its own step and branch at the end of the run (`branch_archived`, `condition_invalid` naming the opener, `limit_reached`). Delete of a never-answered opener of only archived branches dissolves them (their questions get `branch_id` null, then the branch rows are deleted); replace copies `stepId` and `branchId`. `public_under_private` is refused in the five entry points and a PF006..PF010 SQLSTATE maps through `guardIssueOf` in every guarded write. `COLUMNS` no longer selects the retired pair and `toAdminQuestion` emits `condition: null`.
- **Task 3.** `condition-rules.ts`, `profile-form-condition-rules.test.ts` and `addQuestionAfterOpener` with its core cases are deleted, `readTree` is renamed `readLayout` (the 12.1 version dropped), and `profile-form-conditions.test.ts` (-1455 lines) is deleted after its cases moved.
