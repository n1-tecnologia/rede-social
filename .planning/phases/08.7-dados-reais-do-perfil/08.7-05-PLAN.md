<planning_decisions>
1. **Flags travel from the page.** `ownerPanelFlags(modules)` in `apps/web/lib/owner-panel.ts` (`feed`, `stories`, `communities`, `events`, `store`, `chat`, `notifications`) is computed once on `/perfil` from `bootstrap.modules` and passed through `OwnerPanelSection` and `TenantOwnerPanel` to the areas; plan 12 reuses it for the area row.
2. **One continuation island for every list.** `OwnerListMore` takes `{ kind, params, cursor, labels, renderRow }`-style serialisable props (`kind` in `band`, `member-list`, later `content-people`, `content-interactions`, `finance-buyers`) and calls one server action that validates `kind` and params, calls the matching loader and returns `{ rows, nextCursor } | { error: true }`; later plans add kinds, not islands.
3. **The server renders the first page,** the island only appends; without JavaScript the shipped first rows and "e mais N" line stay (progressive enhancement).
4. **Disabled actions get one shared wrapper.** `DisabledAction` gains an optional `pill` label rendered as `ComingSoonPill` beside it (UI-D-478), so every later plan reuses it.
</planning_decisions>
