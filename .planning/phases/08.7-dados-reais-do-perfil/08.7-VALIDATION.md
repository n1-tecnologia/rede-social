# Phase 08.7 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 5.0.0 for unit tests, web components and API integration; pgTAP via `supabase test db`; Playwright 1.63 for optional e2e |
| **Config file** | One `vitest.config.ts` per package (`packages/modules/dashboard`, `apps/web`, `apps/api` with `tests/unit` and `tests/integration`); `supabase/tests/*.sql` for pgTAP |
| **Quick run command** | `pnpm --filter @rede-social/module-dashboard test && pnpm --filter @rede-social/api test && pnpm --filter @rede-social/web exec vitest run components/dashboard components/profile/activity lib` |
| **Full suite command** | `TURBO_CACHE=local:r pnpm turbo typecheck test --continue --concurrency=4 && pnpm supabase test db && pnpm test:integration` |
| **Estimated runtime** | ~60 s quick; ~6 min full (pgTAP ~90 s, integration ~3 min) |

---

## Sampling Rate

- **After every task commit:** run the quick run command.
- **After every plan wave:** run `pnpm supabase test db`, then the dashboard integration files. pgTAP runs before integration, because integration residue trips pgTAP.
- **Before `/gsd-verify-work`:** the full suite must be green.
- **Max feedback latency:** 120 seconds.
