<planning_decisions>
1. **Lists read live, bounded by the snapshot.** Band membership comes from the latest member rows (so a list has exactly its band's count); the rows behind a member's numbers are read live in the admin's lane between the snapshot's `from30At` and `untilAt`, never `now()` (R-§Lists).
2. **One paging helper.** `server/paging.ts` wraps `@rede-social/core/server/paging` with the limit clamp and an ISO-instant check on the cursor's `n` (closing for these routes the R-1 residual that a non-date `n` answers 500).
3. **Module-gated parts are omitted, not zeroed.** The detail drops `events`, `purchases`, `support`, `communities` and `topCommunity` when their module is off; flags read before the lane.
4. **Ids at the API, slugs at the web.** The API uses band ids (`at_risk`) and list ids (`active-days`); the web keeps its pt-BR URL slugs (plan 05).
</planning_decisions>
