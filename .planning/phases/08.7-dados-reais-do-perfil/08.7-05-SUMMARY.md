# Phase 08.7 Plan 05: Membros on real data Summary

**The admin's Membros area now reads the tenant's snapshot end to end. It shows real growth (with "Saíram" and "Saldo" as "Em breve" tiles), the six bands with exact counts, movement and retention with their empty sentences, and scope tabs that follow the communities and events modules. Capability actions stay disabled with the "Em breve" pill.**

## Decisions Made

Planning decisions 1-4 were followed as written (see `key-decisions`). These choices were made during execution:

- **Finished row views on the server.** The first page and every appended page go through `lib/owner-list-view.ts`. The shared row components take no translator, so the client island formats nothing.
- **A member opens only with the levels above it.** It needs a band, plus the opened item outside Por membro. The id itself is the API's to judge.
- **The detail's band pill.** Opened from Por comunidade it reads "{band} na base toda", because the answer carries the whole-base band only. The community-band split pill is gone; the URL's `faixa` is no longer trusted for it.
- **Por membro reads every band with members.** A closed native `<details>` opens without a request, so its list must already be there. That is up to six band-list requests per render.
- **Member list rows are not links (as shipped).** Conteúdo's post detail still parses fixture ids until 08.7-07, so a `&post=` link would only fall back.
