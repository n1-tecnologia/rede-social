<planning_decisions>
1. **Product, not offer.** There is no offer table (`needs_offers`); every path, purchase and list that the fixture keys by offer is keyed by product, and offer blocks are "Em breve".
2. **One floor pass per answer.** The service runs a single `applyFinanceFloor(payload)` (pure, unit-tested in `finance-floor.test.ts`) that walks every group listed in the floor truth, so a new block cannot forget it.
3. **Active holder** = a live `store_entitlements` row of the member for a product linked to the community, the 08.2 rule the store already uses for access; `expires_at` is never filled (D-465), so no holder is "expiring".
4. **Associations are 7 days after the member's own interaction** (like or comment on the post; check-in at the event), counted once per order — association, never cause (the web words it so, PR-6 in plan 10).
</planning_decisions>
