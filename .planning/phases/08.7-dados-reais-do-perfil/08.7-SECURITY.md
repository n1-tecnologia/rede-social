## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser/BFF → API | the admin's session; the overview route takes no parameter | tenant-scoped ids, counts, instants; member names to admin only |
| API lane → Postgres (RLS + definer) | the owner read goes through admin-only RLS; the build runs a tenant-pinned definer | tenant-scoped ids, counts, instants; member names to admin only |
| worker → Postgres (admin lane) | the kernel dispatcher enumerates tenants in the admin lane; the build job runs in a tenant lane with the zero user | tenant-scoped ids, counts, instants; member names to admin only |
| API lane → Postgres | the admin reads the members payload through admin-only RLS | tenant-scoped ids, counts, instants; member names to admin only |
| build definer → source tables | the definer reads every member's actions and push subscriptions of one tenant | tenant-scoped ids, counts, instants; member names to admin only |
| browser → Next.js server action | the island sends a list kind, params and a cursor; untrusted | tenant-scoped ids, counts, instants; member names to admin only |
| Next.js → API | the BFF forwards the admin's session; the API enforces role and tenant | tenant-scoped ids, counts, instants; member names to admin only |
| API service → JSON | the floor is applied between the parsed payload and the response | tenant-scoped ids, counts, instants; member names to admin only |
| build definer → events tables | one tenant's events and attendances | tenant-scoped ids, counts, instants; member names to admin only |
| build definer → store tables | every order and entitlement of one tenant | tenant-scoped ids, counts, instants; member names to admin only |
| build definer → chat tables | every support thread of one tenant | tenant-scoped ids, counts, instants; member names to admin only |
| API → JSON | counts, minutes and staff names only | tenant-scoped ids, counts, instants; member names to admin only |
| browser → `/perfil?area=` | the area and every deeper parameter are untrusted | tenant-scoped ids, counts, instants; member names to admin only |
| hourly sweeper → Postgres (admin lane) | the retention function deletes old tenant rows | tenant-scoped ids, counts, instants; member names to admin only |
| repository → production | the developer deploys by hand following DEPLOY.md | tenant-scoped ids, counts, instants; member names to admin only |
