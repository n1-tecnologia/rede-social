<planning_decisions>
1. **Storage shape (Claude's Discretion "storage").** One `dashboard_snapshots` row per tenant per local day (`payload` jsonb keyed by area: `overview`, later `members`, `content`, `events`, `finance`, `support`; ids and numbers only) and one `dashboard_member_snapshots` row per member, latest build only. Materialized views are rejected (no RLS, all-tenant refresh, R-Alternatives). Both tables are created here with every column the phase needs, so later plans add functions, never columns.
2. **One builder, one function per area.** `app.dashboard_build_snapshot(p_day)` assembles `payload` from `app.dashboard_area_<area>(p_day)` functions. Each later area plan adds its function and replaces the builder (`create or replace`), bumping the builder's `v_version` constant so the dispatcher rebuilds every tenant within the hour (R-Risk 6).
3. **An area is preparing when its key is missing or fails its schema.** The API never compares versions: it zod-parses each area key it serves; absent or unparseable → that area answers `{ state: 'preparing' }` (UI-D-469, R-Pitfall 3).
4. **Deltas are computed by the web.** The API sends `current` and `previous` raw integers; the web derives the chip with the shipped `changeDelta` (README: "percents and per-post figures are computed from the raw counts, never typed").
5. **Members KPI definitions.** `count` = role `member`, `status = 'active'`, `blocked_at is null`, `deleted_at is null`, `joined_at < untilAt`; `newMembers` = the same with `joined_at >= from30At`; `previous` = role `member`, `status <> 'invited'`, `deleted_at is null`, `joined_at < from30At`, and `blocked_at is null or blocked_at >= from30At`.
6. **System lane.** The build job runs in `withTenantTx` with the zero user and role `support_tenant` (the courses precedent); the claim role is irrelevant to the definer, the zero user is the guard. The job sets `set local statement_timeout = '120s'` (R-A8) and runs at concurrency 1.
7. **No scheduler (R-Pitfall 10).** The kernel dispatcher re-arms itself (the sweeper pattern) and names only `tenants`; the dashboard queue is registered by the app tier, so the kernel never names a module (MOD-02).
8. **Mid-phase surface.** Until plan 12 the other Visão geral cards and the bell keep reading the fixture; D-459 is a phase-close property guarded in plan 12. All 08.7 plans ship in one release, so no intermediate contract is ever deployed alone.
</planning_decisions>
