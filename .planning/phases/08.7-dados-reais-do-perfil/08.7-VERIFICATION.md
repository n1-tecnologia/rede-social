### SC-4 re-check: does a floored finance group still come back by subtraction?

**The mechanism (`packages/modules/dashboard/server/finance.ts:116-155, 206-286`).**

- `leaksBySubtraction(parent, parts)` returns true when four things hold:
  - the parent is shown;
  - it has orders;
  - a part is floored;
  - either exactly one part is floored, or some shown part has orders.
- `partToWithhold` then picks the smallest shown part. The remainder an admin can compute is therefore the floored part(s) plus one group of at least 5 buyers.
- The withholding applies to these splits:

| Split | Exact? | What is withheld | Where it would otherwise reappear |
|---|---|---|---|
| Area `revoked.current` → each product's `revoked` | exact: one product per order | the smallest shown product's `revoked` becomes `null` (product detail omits the card) | nowhere. Product revoked numbers appear only in the product detail, and the store module never lists revoked rows (`store/server/service.ts:1399`, "a revoked row is history and never listed") |
| A post's sales → its products | exact: one product per order | the smallest shown product leaves `post.products` | the product detail builds `posts` from the same filtered `post.products` (`finance.ts:562-565`), so that cell is gone there too |
| `contentSales.total` / `eventSales.total` → posts / events | near-split (one order can touch two posts) | the total becomes `null` | the web drops the total line when it is null |
| Area `byBand` → `totals.current` | exact | merged by `mergeBandsBelowFloor` on buyers, each group floored (WR-05) | n/a |

**The verifier's own evidence.**

- **Unit tests:** `pnpm exec vitest run` in `packages/modules/dashboard` passes, 27 files and 503/503. This includes `finance-floor.test.ts` "no floored group comes back by subtraction (C-1, CR-01)", which subtracts the shown parts from the parent for the revoked, post→product and association-total cases, and checks that no floored part comes back.
- **Randomized probe:** run against the real function with placeholder env, from the verifier's scratchpad (`floor-probe.ts`).
  - It covered 20,000 random payloads × 2 splits. 1-5 products had 0-9 buyers each, orders ≥ buyers, and the parent's distinct buyers fell anywhere between the largest part and the sum.
  - 10,433 of those splits had a floored part beside a shown parent.
  - **Leaks found: 0.** A leak is a hidden remainder with orders > 0 whose buyers sum to < 5, or a single hidden floored part.
- **Negative control:** the same probe with withheld parts treated as shown, which simulates the pre-fix code, finds **13,330 leaks**. It reproduces the previous report's cases, e.g. parent {15 orders} − shown {8} = floored {7 orders, 4 buyers}. So the probe discriminates, and the fix is what closes it.
- **Integration:** `dashboard-owner-finance.test.ts` passes 21/21 against the local DB, which has both new migrations applied.
