## Phase Goal

**As a** person invited by an organisation that runs a Rede Social community (a tenant), **I want to** sign up through that organisation's public link, log in with e-mail and password, stay logged in, recover my password and log out, **so that** I reach my organisation's private community at my organisation's own web address and the API only ever serves my organisation's data.

<objective>
Provision the remaining cloud surfaces with CLIs/APIs — GCP (Cloud Run prerequisites, Artifact Registry, Secret Manager, WIF), Vercel (project, Git integration, root directory, env vars, the platform domain and the two seed tenant domains — D-21/D-24) and Resend (domain + API key) — write the per-remote Supabase auth/SMTP configuration (D-13) with the per-host redirect allow-lists (D-22/D-24) that CI pushes on the first deploy, publish the three hostnames as GitHub environment variables for the seed, document (not implement) the Phase 2 customer-domain attach flow, and stop exactly once for the human-only steps (DNS records — three CNAMEs + Resend — and the ES256 key rotation if a project still has none).

Purpose: PWA-04 (automated deploys to Vercel and Cloud Run), D-13 (Resend SMTP), D-15 (regions, secrets in Secret Manager, WIF), D-21/D-24 (platform + seed tenant domains on Vercel and in the auth allow-lists).
Output: GCP resources, GitHub vars (incl. host variables), Vercel project + env + three domains, Resend domain/key, `config.toml` remotes, `DEPLOY.md` identifiers + Custom domains runbook, DNS + JWKS verified.
</objective>
