# Phase 09.1 Plan 03: Per-tenant sign-up and join gate, coarse hooks, allowlist retired Summary

**Sign-up and join now ask the tenant's own payment gate instead of a global hand-filled list, the two GoTrue hooks keep their names but answer a tenant-blind "does this e-mail have some door open" from access_grants (admitting every member of an ungated tenant), and the old email_allowlist rows migrate to manual accesses.**

## Accomplishments

- Tracer proven against real GoTrue: on rede-lab with the gate on, an e-mail with no usable access gets `403 EMAIL_NOT_ALLOWED` with no details and nothing is created; the same request after a manual active row answers 201; with the gate off or no `payments` row an unlisted e-mail signs up exactly as before (this closes review finding WR-01 of quick 261018-owq: the pre-check no longer bites before the hooks are on and no longer depends on a global list).
- `joinTenant` has a new gate check (step d2) placed after the existing-membership branch and before the insert, reading the joiner's e-mail from `public.users` by the session's user id; replay on an active member, blocked and removed members, and platform accounts keep their own answers.
- Hook bodies replaced under the same names. Token hook order: platform admin, active access in any tenant, live staff membership, live membership in a tenant whose gate is off (A-P1), else 403. Creation hook: active access row only. Both stay `security definer`, `search_path = ''`, 4xx only, uuid-format guarded, EXECUTE for `supabase_auth_admin` only. `memberships_user_idx` keeps the ungated clause an index lookup (pgTAP asserts the plan uses it).
- `public.migrate_email_allowlist_to_access_grants()` ran once on the local database (18 manual active rows from a 182-row list) and is idempotent and owner-only. The table stays (the API revision serving during `db push` still reads it).
- Harness, seed and e2e helper retargeted with unchanged names and signatures; `signupMember`/`isEmailAllowed` no longer read the old list; `isEmailAllowed` survives as a compatibility function (active access anywhere) for `createTenant` until plan 04.
- pgTAP 175 rewritten (75 assertions); `access-hooks.test.ts` has 23 cases (10 hook/API cases, 8 tracer cases, 5 token-hook cases); `join.test.ts` gained 5 join-door cases.
