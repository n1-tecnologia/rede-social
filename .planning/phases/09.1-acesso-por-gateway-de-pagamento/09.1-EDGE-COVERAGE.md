# Phase 09.1 — Edge coverage ledger (spec-less probe fallback, §C)

> Companion to the twenty PLAN.md files. The phase has no SPEC.md, so the orchestrator ran the deterministic
> edge probe over the researcher's draft PAY-01..PAY-32 texts (74 applicable edges, all `unresolved`). While
> finalising the requirements, two rows were added: **PAY-33** (the Kiwify adapter accepts all ten triggers and
> records the four that change nothing as ignored) and **PAY-34** (the open product page refreshes into its
> owned state through the Realtime user signal). The draft wording of PAY-01..PAY-32 was kept verbatim, so the
> engine's 74 rows hold, and the four rows the two new requirements produce (P75..P78) are appended in the
> engine's own category vocabulary. Every item has an id (P1..P78 in report order), a resolution and the plan
> whose `must_haves.truths` carries it, so the checker can confirm the no-silent-drop equality:
> **78 = 68 authored as `explicit` truths + 0 `backstop` + 10 flagged assumptions (`unclassified`, never
> auto-resolved: P10, P11, P24, P25, P27, P36, P58, P71, P74, P78)**.
>
> The UI-SPEC `## UI Considerations` lift (62 covered → truths, 7 backstop → flat-scalar markers, 8 dismissed →
> nothing lifted) and the recalled prohibitions are tabled below for the same reason.
