# Phase 09.1 Plan 08: Kiwify adapter behind the neutral seam Summary

**The first real gateway adapter: HMAC-SHA1 verified over both documented signed materials (raw bytes and re-serialised JSON), a tolerant never-throwing normalise that maps the ten triggers and the instalment events onto neutral grant/suspend/revoke/none events with amounts in integer cents, the cancel semantics isolated in one constant, and the coverage matrix pinned to fourteen fixtures.**

## Accomplishments

- Tracer through the real route: the approved-purchase example signed either documented way answers `200 { received: true, enqueued: true }`, stores one `payment_events` row with the neutral fields the adapter produced and one `kernel.payment-event` job (`{ eventId }`); a one-byte change, an unsigned body, another tenant's token and a malformed signature are 403 and store nothing. The request log carries `"variant":"raw"` or `"variant":"reserialised"` and no signature, token or buyer data.
- `kiwify.ts` is the only file with gateway field names (plus `adapters.ts`, one line). `verify` HMACs every candidate (no early exit), compares each with a length-checked `timingSafeEqual` over lower-cased hex, and labels the match. `normalise` reads a closed field set, never throws, and degrades unknowns to `other` / `none`.
- Mapping per assumption A-P2: `order_approved` with `paid` or absent status, `subscription_renewed`, `_late`, `_canceled` (`CANCEL_EFFECT`), `order_refunded`, `chargeback`, `order_rejected`, `billet_created`, `pix_created`, the flat abandoned cart, and `scheduled_installment_access_removed` / `_restored`. `externalRef` is the subscription id for a recurring sale and the order id otherwise; `amountCents` only when an integer; `validUntil` read as UTC-3; `occurredAt` always null.
- Fourteen synthetic fixtures with a `_fixture` provenance key, a unit table over all of them, the P75-P77 edge cases, and `payments-kiwify-coverage.test.ts` which parses the phase's `COVERAGE.md` and requires a fixture and a matching decision for every `trigger:` and `payload:` row (and a row for every fixture).
- `CAPTURE.md`: the ordered runbook for plan 20 (inspector as the sink, never this system's database; ten triggers; real one-off and recurring purchases; mid-period cancel; redaction; fixture replacement; signature-variant check; the answers table; the A-P2 decision tree).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A body without `order_status` was degraded to `other` by the whole-object parse**
- **Found during:** Task 2 RED run (the approval-rule case "accepts paid in any case and an absent status")
- **Issue:** Task 1's schema declared `order_status: z.unknown()`; Zod 4 refuses an object whose `unknown` key is missing, so `safeParse` failed and an otherwise valid approval without the key became `other` / `none`. The plan's own mapping says an absent status is accepted. The six Task 1 fixtures all carry the key, so the tracer did not expose it.
- **Fix:** `order_status: z.unknown().optional()` with a comment saying why.
- **Files modified:** packages/core/server/payments/kiwify.ts
- **Verification:** the approval-rule case passes; 131 unit cases pass.
- **Committed in:** `c72ac769`

**2. [Rule 1 - Bug] The plan-05 adapter-list assertions broke when a second adapter was registered**
- **Found during:** Task 1 GREEN (core suite)
- **Issue:** `payments-fake.test.ts` asserted `Object.keys(ADAPTERS)` and `enabledProviders(undefined)` equal `['fake']`; registering `kiwify` is exactly what plan 05 said plan 08 would do.
- **Fix:** both expectations now list `['fake', 'kiwify']`.
- **Files modified:** packages/core/tests/payments-fake.test.ts
- **Committed in:** `ac5d9f5c`

**3. [Process] db:reset and db:seed not run**
- **Found during:** the Task 1 and Task 2 integration verify blocks
- **Issue:** both begin with `pnpm db:reset && pnpm db:seed`; the local database holds the user's own account and manual test data and nobody can be asked mid-run (as in plans 02-06). This plan adds no migration and touches no table, so the already migrated database is the same one a reset would produce.
- **Result:** the kiwify and fake webhook integration files (28 cases) pass on the existing database. A clean reset-and-seed full run remains owed at the phase level.
