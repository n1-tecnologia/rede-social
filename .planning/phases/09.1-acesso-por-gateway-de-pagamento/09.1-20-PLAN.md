<planning_decisions>
1. **The capture sink is never this system.** The vendor's panel points at an inspector the person controls, so the raw bytes and the real signature can be read once, off the repository and off the database; the executor only ever sees files the person hands over.
2. **Redaction is a script plus a test, not care.** The executor redacts with a short throwaway script kept outside the repository, writes only the result, and the committed guard test is the permanent defence against a later fixture added carelessly.
3. **One adapter file absorbs the difference.** The neutral event and everything downstream were designed so that a real payload can disagree with the documented one without a migration; if the capture shows a difference that cannot be absorbed there, the task stops and reports it instead of widening the neutral layer.
4. **The cancel decision is evidence-led and reversible.** The locked reading stays the default; the alternative is offered only with what the capture shows, and either choice is a constant and table rows.
</planning_decisions>
