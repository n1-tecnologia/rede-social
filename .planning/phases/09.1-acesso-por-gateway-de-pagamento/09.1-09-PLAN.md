<planning_decisions>
1. **Tables in the kernel, surface in the module.** The module owns routes, contracts and (plans 13-14) props-only UI; every table and every admin-lane write is kernel code, because the Biome rule keeps the admin lane out of module packages (assumption A-P7).
2. **DTOs live in `@rede-social/contracts/payments`.** Kernel services and module routes share them; `packages/modules/payments/contracts/index.ts` re-exports them and adds the permission constant and the closed issue vocabulary, the shape every module contract has.
3. **The webhook handle is derived, not stored first.** A name-based UUID of `(tenant, provider)` means the screen can show the URL the admin must paste into the gateway BEFORE the token exists, and saving the token creates the row with that id; no placeholder row ever flips the store into gateway mode.
4. **Mappings through the tenant lane, switch and token through the admin lane.** `payment_products` carries `admin_tenant` policies (defence in depth over `ctx.tenantId`), while `tenant_modules.settings` and `payment_integrations` have no tenant-lane write path, so those writes are explicit-predicate admin-lane statements in the kernel.
5. **Release inserts are set-based.** One `insert … select` for the whole tenant, never a per-member loop (a tenant of thousands must not hold a transaction open per row).
6. **No `storeProductsWithoutLink`.** Computing it would need the kernel to read the store's tables; the product form warns from the per-product `purchase` field (plan 06) instead.
7. **Default provider.** `defaultProvider()` returns the first non-test adapter in `enabledProviders()` and falls back to the test adapter only when it is the only one enabled, so a local stack with every adapter picks the real one and a CI stack with only the test adapter works; tests choose a provider explicitly.
</planning_decisions>
