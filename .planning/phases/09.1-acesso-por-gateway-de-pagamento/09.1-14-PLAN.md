<planning_decisions>
1. **The Membros machine is copied, not shared.** The list reseeds from the server's page for the new URL during render, guards stale pages with a generation counter and appends keyset pages; Acessos needs the same behaviour on a different row, and a shared abstraction would couple two admin screens that change for different reasons.
2. **State words live in one component.** `AccessStatePill` maps a state to its tone and catalog word once; the list row, the sheet, the Eventos row and (plan 16) the Membros badge use the same mapping (UI-D-520).
3. **Finished strings in, handlers in.** The module components never format a date, a plural or a name: `lib/payments-view.ts` produces `accessRowView` and `eventRowView` (validity in the tenant timezone, the relative 'recebido há 3 min' from `serverNow`), so the clock is read on the server and nothing renders `Date.now()`.
4. **The gate state comes with the page.** The Acessos page also reads the overview once for `gatewayName` and `gate.required`, which the sheet needs for the A-P10 note and the source pill word.
5. **One sheet component for the four cases.** `AccessSheet` renders actions by the row's source and state; there is no second sheet for the blocked case.
</planning_decisions>
