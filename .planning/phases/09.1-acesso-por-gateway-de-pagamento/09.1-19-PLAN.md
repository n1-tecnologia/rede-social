<planning_decisions>
1. **One gateway in the e2e servers.** Setting the provider list in the Playwright config, exactly as `INSTALL_GATE` and `CSP_MODE` are set, makes the Pagamentos screen connect the test gateway through its normal button, so the walk uses the real UI for setup and a signed request only for the part that comes from outside.
2. **The webhook URL is read from the screen.** The spec copies the read-only field's value and swaps the host for `127.0.0.1`, as every Node-side helper must, instead of computing the deterministic integration id, so a change of the URL shape fails the spec.
3. **Setup through the UI, state through SQL.** The module switch and the cleanup go through a superuser connection (the harness is not a lane, the `store-admin.ts` precedent); everything the admin does in the product goes through the screens.
4. **Waits are on events, not time.** After each delivery the helper polls the event row until it reaches a terminal state, then the spec asserts the screen; there is no fixed sleep.
5. **The 320px cases assert geometry, not pixels.** `scrollWidth <= innerWidth`, the box heights of the controls and the visibility of the chevron and the footer buttons; the frames of sketch 013 remain the visual reference.
</planning_decisions>
