# Phase 09.1 Plan 13: Pagamentos, the Configuração tab Summary

**An admin can now connect the gateway (copyable webhook URL, write-only token), register access products in a sheet, and switch on "Exigir assinatura para entrar" through a deliberate dialog that names the members it would cut and defaults to releasing them, all from the Configurações "Pagamentos" row, with the screen answering `notFound()` to anyone without `payments.manage`.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The ConfirmDialog test could not live where the plan put it**
- **Found during:** Task 3 (RED)
- **Issue:** the plan lists `packages/ui/src/overlays/ConfirmDialog.test.tsx`, but `packages/ui/vitest.config.ts` only collects `tests/**/*.test.{ts,tsx}`, so a file under `src/` would never run (a silent green).
- **Fix:** the slot cases are in `packages/ui/tests/confirm-dialog-children.test.tsx`; `overlays.test.tsx` (which holds the existing dialog cases) is untouched.
- **Files modified:** packages/ui/tests/confirm-dialog-children.test.tsx
- **Committed in:** 006a2217, 129a5de0

**2. [Rule 1 - Bug] The relative formatter ends with a full stop**
- **Found during:** Task 1 (view test)
- **Issue:** `relativeFrom` returns "há 3 min." (the pt-BR narrow format carries a period), and the contract line is "Último evento recebido {when}.", which would print two full stops.
- **Fix:** `payments-view.ts` drops the formatter's trailing period before interpolating; "agora" yields "Último evento recebido agora.".
- **Files modified:** apps/web/lib/payments-view.ts
- **Committed in:** 4f6c7e5b

**3. [Rule 2 - Missing critical] A lost permission and a stale screen**
- **Found during:** Tasks 1-3
- **Issue:** UI-D-528 requires "a lost permission mid-session toasts the shipped forbidden line and refreshes into notFound()", which the plan's closed code set did not carry; the overview read could also meet 404/403 after the bootstrap.
- **Fix:** every action maps a 403 `FORBIDDEN` to a `forbidden` code (toast `admin.errors.forbidden` plus `router.refresh()`), and the page treats a 404/403 on the overview read as `notFound()`.
- **Files modified:** actions.ts, page.tsx, the three client components
- **Committed in:** 4f6c7e5b, a4cd6bab, 129a5de0

**4. [Rule 2 - half-step spacing rule] `mt-1.5` not copied into the new dialog branch**
- **Found during:** Task 3
- **Issue:** the dialog's existing body paragraph carries `mt-1.5`; the UI-SPEC forbids half-step classes in Phase 09.1 markup, and the children branch needs its own copy of that paragraph.
- **Fix:** the new branch uses `mt-2` (8px instead of 6px, only when children are passed). The no-children branch is byte-for-byte the previous markup (asserted).
- **Files modified:** packages/ui/src/overlays/ConfirmDialog.tsx
- **Committed in:** 129a5de0

**5. [Plan wording] Two small places where the plan text and the code disagree**
- `overviewView(overview, t, ctx)` takes `{ tenantName }` and also returns the products and the gate flags; the `gateView` passthrough was added in the Task 2 commit (with its test in the Task 3 RED commit) because the products card needs the gate flag for its pre-check.
- Task 1's `files_modified` lists no `SetupPanel` change for Tasks 2-3 beyond what each task names; the panel grew one section per task as the plan describes.
