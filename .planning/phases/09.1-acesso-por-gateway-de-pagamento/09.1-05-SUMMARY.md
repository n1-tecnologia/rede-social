# Phase 09.1 Plan 05: Signed webhook front door, secret custody and neutral gateway seam Summary

**A tenant's gateway delivery is now verified (HMAC over the received bytes against a token stored only AES-256-GCM-sealed and bound to its row), recorded exactly once and queued exactly once through a provider-neutral seam resolved per integration row, with no payload column, no brand name outside the adapters, and the store seam functions and 180-day prune ready for the plans that follow.**

## Accomplishments

- Tracer proven against the live stack through the real route: a delivery signed with rede-lab's token answers `200 { received: true, enqueued: true }`, writes one `payment_events` row for the INTEGRATION's tenant with the normalised neutral fields and one `kernel.payment-event` job whose payload is `{ eventId }`; a resend answers `enqueued: false`; a forged, unsigned, tampered, foreign-token, unknown, malformed, wrong-provider or oversized request stores nothing.
- `GatewayProvider` (the `VideoProvider` shape per integration row) with a `fake` adapter: `verify` takes the exact bytes, the `signature` query value and the opened secret and throws `GatewayError` (no message argument); `normalise` never throws and degrades any unreadable or unknown shape to `other` / `none`. `adapters.ts` is the only list of adapters, `gatewayAdapter(name)` matches the whole name against own keys and honours `PAYMENTS_PROVIDERS`, and `payments-neutral.test.ts` keeps every neutral file free of a brand name.
- `sealSecret` / `openSecret` (AES-256-GCM, 12-byte random IV, integration id as AAD): a value copied to another row, a flipped byte, a truncation, an unknown version or key id all fail with `payment secret unreadable` and no input in the message. `assertProductionEnv` demands a 32-byte `PAYMENTS_SECRET_KEY` whenever `PAYMENTS_PROVIDERS` lists a real gateway.
- Three tables: `payment_integrations` and `payment_events` with RLS on and ZERO policies and no privilege for `anon` / `authenticated`; `payment_products` with the global `unique (provider, external_product_id)`, the per-target partial unique and four `admin_tenant` policies (no TRUNCATE for the tenant lane). `payment_events` has no payload column and no buyer name, CPF, phone, address or IP.
- `app.payments_gateway_mode()` and `app.payments_checkout_url(uuid)` (definer, pinned to the claim tenant, EXECUTE to `authenticated`) for plan 06, `access_grants_mapping_fk` (`on delete set null`), and `app.payment_events_prune(int)` (180 days, `service_role` only) for the sweeper plan 09 registers.
- pgTAP 205 (129 assertions) proves the shape, CHECKs, global uniqueness (P1, P2, P3), exposure, cross-tenant negatives with set comparison (P67-P70), the seam and the prune.
