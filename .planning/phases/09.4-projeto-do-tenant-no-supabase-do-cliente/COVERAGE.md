# API Coverage — Supabase Management API (Phase 09.4: customer-owned projects, one scoped token per project)

> Full coverage by default. Opt-outs are explicit, reasoned decisions.

External service: the **Supabase Management API** (`https://api.supabase.com/v1`, OpenAPI document of 2026-10-27: 169 operations, the same count as the 09.2 matrix). Phase 09.4 adds a second way to authenticate the SAME surface: a project of the customer's own Supabase account is reached with a **scoped personal access token limited to that one project** (sealed per project, AAD `<project id>:mgmt_token`, D-566..D-576), while projects of the platform's organisation keep `SUPABASE_PAT` and `SUPABASE_ORG_SLUG` byte for byte. Per the full-coverage rule a second integration against the same need starts from the full baseline and every capability is re-decided for the new surface: all 20 operations of the 09.2 matrix stay `INTEGRATE` (now through the per-project provider), `GET /v1/projects` moves to `INTEGRATE` (registration only, D-570), `GET /v1/organizations/{slug}` is split out of its OPT-OUT group with its own reason (D-572), and every other OPT-OUT group was re-read for the customer-token surface and stands unchanged: a narrower credential for the same operations never widens what the platform may do. The permissions each operation needs (docs table and the OpenAPI `x-fga-permissions`, read 2026-10-27) are the thirteen of D-569, except the two rows called out below. The adapter `packages/core/server/projects/management-api.ts` may call only the `INTEGRATE` paths; `packages/core/tests/management-api.test.ts` reads THIS table (re-pointed from the 09.2 file, which stays as the record of what 09.2 sealed) and fails on any other path.

Decision vocabulary used here. `INTEGRATE`: a method of the `ProjectProvider` interface calls the operation (real adapter) and the fake provider mirrors it. `OPT-OUT`: no code calls the operation; the group's reason says why and, where a human does it instead, where it is documented. `UNCHANGED`: not part of the Management API; listed because this phase touches how it is reached. `NEW`: a route of our own API added by this phase.
