# Phase 09.4 Plan 11: The owner-change and register command Summary

`pnpm platform:set-owner` adopts a project that Supabase transferred to the customer (one validated, sealed, pinned token, a version bump and an `owner_changed` event, nothing copied), re-pins after a legitimate organisation change, and registers a customer project as a move target ahead of the move.

## Accomplishments

- **Tracer (Task 1, CTK-03).** `setProjectOwner` in `token.ts`: `findOwnerTarget` reads the tenant's project and refuses `tenant_not_found`, `project_central` and `tenant_moving`; `validateCustomerToken` runs WITHOUT a pin so the first read teaches the project's current organisation; then, under the project advisory lock and `for update`, ONE `update` sets `owner = 'customer'`, `org_slug`, the sealed token (AAD `<id>:mgmt_token`), the typed expiry, `secret_key_id` (coalesce) and `credential_version + 1`, and the audit event rides the same transaction. The open-move check is repeated inside the lock. After the commit the registry cache, the provider and the allow-list adapter are dropped, one log line carries ids only, and a best-effort `checkProject` runs through the `afterChange` seam. No move function is called.
- **Command.** `scripts/set-project-owner.ts` (modelled on `reissue-credentials.ts`): strict hand-rolled parser, the database facts first, then the hidden prompt, then the kernel; one JSON line of ids, event kind and closed codes; exit 0 / 1 / 2 / 130; run-only-as-command guard and a content-free `.catch`. `"platform:set-owner"` added to `package.json`.
- **Re-pin and register (Task 2, CTK-04).** A project already owned by the customer takes the same path and reports `repinned: true` with a `repinned` event; ordinary replacement (plan 10) still refuses a different organisation. `--register --ref` registers through `registerCustomerProject` (state `preparing`, no tenant, no move); a known ref is refused as `already_registered` before the prompt through the new `projectIsRegistered`. `--dry-run` validates through `validateCustomerToken` only.
- **Discipline (Task 3).** Table tests: `--token`, `--pat` and every other unlisted flag, a positional argument and the `=` forms are unknown arguments (exit 2, nothing echoed); a source test pins that the script has no `process.env` and no `process.stdin`; a sweep runs 18 outcomes and scans output, logs and audit rows for every fake token, its first 8 characters, `sbp_`, `Bearer`, `eyJ`, both organisation slugs and the refs. I confirmed the sweep catches a leak by adding the ref to the log line (the test failed on a 13-character shape) and reverting.
