# Phase 09.4 Plan 07: The token kernel Summary

The customer-token kernel: `validateCustomerToken` runs the typed date, the `sbp_fc` prefix, `describe` and the account-wide listing in a fixed order and learns or checks the organisation pin, `registerCustomerProject` seals the token with that pin in one locked transaction with its audit event, and the re-seal and the logger now cover the management token.

## Accomplishments

- **Tracer (Task 1, CTK-09, CTK-10, CTK-12).** `validateCustomerToken` stops at the first refusal: (1) `token_expiry_invalid` before any other work, (2) `token_account_wide` for a token without `sbp_fc` with no provider built, (3) `describe` mapped to `token_invalid`, `token_forbidden`, `not_found`, `org_mismatch` or `unchecked` by code and kind only, (4) any listed ref other than the target is `token_account_wide`, a listing 403 passes, a timeout or 5xx is `unchecked`. With no pin the first read teaches the organisation; with a pin a different slug is `org_mismatch`. `TokenRefusal.message` is its code. `todayInSaoPaulo` reads "today" where the operator is.
- **Registration (Task 2, CTK-12, CTK-28).** `registerCustomerProject` validates outside any transaction, then under `pg_advisory_xact_lock(hashtext('project:' || ref))` refuses an existing ref as `already_registered` and otherwise inserts the `customer` row (pin, `mgmt_token_sealed` with AAD `<id>:mgmt_token`, typed expiry, state `preparing`, current key id) and an `ok` audit event in the same transaction. A refused token writes no project and one best-effort event with a null project. One log line with the project id and the actor label, nothing else. The shared `apiUrlFor` now lives in `projects/access.ts`; `tenants.ts` and `move/target.ts` keep their private copies for plans 09 and 12.
- **Re-seal and redaction (Task 3, CTK-25, CTK-21).** `mgmt_token_sealed` joined the column array, the select, the `coalesce` update and the counters in `scripts/reseal.ts` (`credential_version` untouched, a platform row skipped for it); `mgmtToken`, `projectToken` and `managementToken` joined the redaction keys (top level and one level down).
