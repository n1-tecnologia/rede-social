# Phase 09.4 Plan 16: Token UI, operator half Summary

**The Banco tab now says who owns a customer project and where it lives, shows a Token de acesso card with its seven states and plain notices, lets the operator replace the token from a write-only sheet that validates server-side, and flags a dying token with a "Token: ..." pill on the tenant header and list.**

## Accomplishments

- `DatabaseOverviewCard` gains **Dono** after Projeto and, for a customer project only, **Organização** (the pinned slug, `break-all` in the `minmax(0,1fr)` column); an answer without the new fields renders as a platform project with just the one extra row. The customer-Free notice (`planNotPro`) is in place but fires only when the plan reads Free, so never today (D-572).
- **TokenCard** (server component, state only): the key glyph and body, the pill, the expiry line (Vence em / Vence em N dias, em D de mês de AAAA / Venceu em / Sem data de vencimento informada), the check line, the state notice (a warning for Vencendo, `role="alert"` danger rows for the four others, none for Válido and Não verificado) and the closed how-to. It is placed by the page between Preparação and Credenciais for a customer project that has a token summary.
- **ReplaceTokenSheet** + **replaceTokenAction**: the sheet opens empty every time, "Salvar token" waits for a token, "Salvando…" locks the fields and the sheet, there is no confirmation dialog, and the refusals land under the token (four codes), under the date, or as the two sheet alerts. The action sends one PUT and returns `{ ok }` or a closed code.
- **TokenCardActions**: after a good save the status block is `aria-busy` and reads "Verificando…" until a second `router.refresh()` 3000 ms later (timer cleared on unmount, a failed refresh keeps the last state).
- **Header and list pill**: `tokenNeedsAttention` (five states) drives a third header `StatusPill` ("Token: Vencendo") from the one overview read the layout already makes, plus the same pill in the list under the Banco pill and schema line and in the mobile pills line.

## Decisions Made

- The card and the sheet take a server-supplied `today`; the page derives it with `toLocaleDateString('sv-SE', { timeZone: PANEL_TIME_ZONE })`, the same zone the wizard uses, so the days left and the date bounds agree.
- Card dates read "8 de novembro de 2026" (Intl in UTC over the typed `YYYY-MM-DD`), matching the sketch; the wizard Resumo keeps its `DD/MM/YYYY` from plan 15.
- The four token refusals under the token field and the date refusal reuse the shipped `platform.new.errors.*` sentences, so there is one wording of each across the wizard and the sheet.
- The header pill follows UI-SPEC row E08 (sketch finding F-2): Não verificado shows no pill on the header, the list or the chip.
