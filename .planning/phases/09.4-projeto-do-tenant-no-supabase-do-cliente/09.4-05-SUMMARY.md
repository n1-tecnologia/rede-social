# Phase 09.4 Plan 05: Customer token in the provider seam Summary

The Management API adapter now serves one scoped customer token per project (learn-and-pin organisation, 401/403 refined by code only, own limiter, `GET /v1/projects` as the 21st operation), the reason catalog has thirteen codes, and the fake provider mirrors all of it with a per-token view and a token-kind call log.

## Accomplishments

- **Tracer (Task 1, CTK-12, CTK-15, CTK-23).** `tokenKind: 'customer'` makes `orgSlug` optional; the first `describe` pins the organisation, a later project of another one throws `forbidden 403` with `code: 'org_mismatch'` and `customerToken: true`. A 401 or 403 from a customer provider keeps `kind: 'forbidden'` and message `forbidden <status>` and adds `token_invalid` or `token_forbidden`; the platform provider's errors are unchanged (`code` undefined, `customerToken` false). The customer provider builds its own `createLimiter({ perMinute: 100 })`, proven by a second provider answering while the first sleeps on a 429.
- **listProjects (Task 2, CTK-11).** `call('GET', '/v1/projects', ...)` with `params.ref` now optional, a `{ref}` template with no ref still `invalid`; entries are `ref ?? id` filtered by the 20-letter pattern. The matrix test reads the 09.4 `COVERAGE.md` (21 INTEGRATE rows, 13 literal calls, `21 + 148 = 169`); the 09.2 file is untouched.
- **Reason codes (Task 2, CTK-29).** `BOOTSTRAP_REASONS` appends `token_invalid`, `token_forbidden`, `org_mismatch`; `reasonOf` returns a code first only for `customerToken` errors that have one, so a platform `forbidden` and the platform `org_mismatch` stay `access_denied`. The core mirror test that plan 03 left red is green again.
- **Fake (Task 3, CTK-30).** Methods are built per view over one shared world; `forToken(token, { orgSlug? })` answers `token_invalid` (unknown or dead), `token_forbidden` (forbidden state or out-of-scope ref), learns and pins the organisation, and scopes `listProjects`. `calls.tokenUses` records `{ ref, kind }` per call that names a well-formed ref.

Verification: core vitest 86 files / 1218 tests pass; `tsc --noEmit` clean for core, api and web; biome check clean on the touched files.
