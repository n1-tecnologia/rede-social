## Phase Goal

**As a** person invited by an organisation that runs a TRIA community (a tenant), **I want to** sign up through that organisation's public link, log in with e-mail and password, stay logged in, recover my password and log out, **so that** I reach my organisation's private community on one URL and the API only ever serves my organisation's data.

<objective>
Deliver the first step of the user story end-to-end: the public sign-up link `/cadastro/{slug}` (D-01) with name/e-mail/password (D-02), two explicit consents recorded as LGPD evidence in `consent_records` (D-03, one-way decision already taken by the user), autoconfirmed identity creation through the API admin lane with duplicate-e-mail handling (D-04), immediate sign-in, and the tenant memory that survives the register → login round trip (D-06).

Purpose: AUTH-01, AUTH-04, ROLE-02 (one membership per user is what makes the duplicate rule correct).
Output: shared auth Zod schemas, legal texts + versions, `consent_records`, `signupMember`, public API routes, sign-up page + actions + client widgets, legal pages, integration + e2e tests.
</objective>

| Boundary | Description |
|----------|-------------|
| Browser → Next server action | Untrusted form data (name, e-mail, password, checkboxes) |
