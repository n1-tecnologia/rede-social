## Phase Goal

**As a** person invited by an organisation that runs a Rede Social community (a tenant), **I want to** sign up through that organisation's public link, log in with e-mail and password, stay logged in, recover my password and log out, **so that** I reach my organisation's private community at my organisation's own web address and the API only ever serves my organisation's data.

<objective>
Retire the phase's hardest constraint early (Constraint Analysis): prove on the local transaction pooler that `set_config(..., true)` + `SET LOCAL ROLE authenticated` never leak across pooled transactions, install the CI grep guard that keeps every setting LOCAL, and document the session-pooler fallback as a configuration switch. In the same plan, land the V2-safe Foundation deliverables that no later module may reinvent: `platform_admins` (ROLE-01 `super_admin`), the chat/notification table stubs, and the schema-conventions doc.

Purpose: TENANT-03 (lane safety under pooling), ROLE-01 (`super_admin` outside memberships), ROADMAP Phase 1 notes (stubs + conventions doc are Foundation deliverables).
Output: spike test (local run green; staging run repeated in 01-12), guard script, lanes README, three schema files + one migration, SCHEMA-CONVENTIONS.md.
</objective>

<assumption_delta_decision>
- **Noun:** the tenant lane abstraction `withTenantTx` (the primary) versus the pooler mode behind it (a detail: Supavisor transaction 6543, session 5432, local PgBouncer).
- **Decision:** `no-change` — the `fallback` signal in the ROADMAP ("fallback is a per-request Supabase client with the user JWT") must NOT become a second lane implementation. The lane abstraction already hides the pooler mode: the only supported fallback is `DATABASE_URL` → session pooler, identical code. The PostgREST-per-request client is recorded as not recommended (RESEARCH "Fallback #2") because it would be an `add-alongside` that forks transactions, typing and RLS semantics. If the staging spike (01-12) fails on BOTH pooler modes, that is a `## PHASE SPLIT`-level surprise to raise with the user, not a silent switch.
- **Invariant:** `scripts/spike-supavisor.test.ts` is parameterised only by `SPIKE_DATABASE_URL`, so the same test proves either mode.
</assumption_delta_decision>
