**As a** person invited by an organisation that runs a TRIA community (a tenant), **I want to** sign up through that organisation's public link, log in with e-mail and password, stay logged in, recover my password and log out, **so that** I reach my organisation's private community on one URL and the API only ever serves my organisation's data.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Next.js server (Vercel) | Form posts (server actions) and cookies from an untrusted client |
| Next.js server → Supabase Auth | `signInWithPassword` / refresh with the publishable key |
| Next.js server → API | Access token forwarded as Bearer; API re-verifies |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information disclosure | session cookies | high | mitigate | `@supabase/ssr` writes `sb-*` as HttpOnly/Secure/SameSite=Lax; no token ever reaches client JS or localStorage; e2e asserts `httpOnly` |
| T-02-02 | Spoofing | `proxy.ts` gating | high | mitigate | `getClaims()` (signature verified) decides access; `getSession()` is used only to forward the token to the API which re-verifies (RESEARCH anti-pattern) |
| T-02-03 | Tampering | `tenant_slug` cookie | medium | mitigate | Display-only; API never reads it; TENANT-01 adjacency test proves independence |
| T-02-04 | Tampering | CSRF on server actions | medium | accept | Next.js Server Actions enforce same-origin (Origin/Host check) and cookies are SameSite=Lax; documented, no extra token in V1 |
| T-02-05 | Information disclosure | login error message | low | mitigate | Single generic "Email ou senha incorretos." regardless of which field failed |
| T-02-06 | Denial of service | login brute force | medium | accept | Supabase sign-in rate limit (30/5 min per IP) in the pilot; stronger limits deferred to Phase 8 per CONTEXT Deferred Ideas |
